# 每日预警接口 · 前端对接文档

> 版本：2026-10-15 ｜ 线上地址：`http://47.121.183.81:8200`
> 自检：`GET /health` 里 `ok=true` 才可用。
> **本文只讲接口。展示形式由你们定。**

---

## 一 这个接口干什么

**每天 8:00 调一次**，传**登录人的账号**，返回**这个人今天该办的事**。

- **一件事一条**，每条一句话（≤44 字）。**只陈述事实**；这条话**是什么预警**由 `alert_label` 说明（如「预算预警」）。
- **只返回有异常的**；没事就返回空数组。
- **角色和范围我们自己查库算**，你们**不用传角色、也不用传范围**。
- **第一期没有点击跳转**。等你们给路由规则，我们再加 `route`/`params`。

**你们要做的**：登录后拿 session 里的账号 → 调这个接口 → 拿 `alerts[].title` 展示。

---

## 二 请求

```
POST /api/alerts/daily
Content-Type: application/json; charset=utf-8
```

```json
{
  "account": "sngdssz",
  "today": "2026-10-16",
  "when": "2026-10-16 08:00",
  "limit": 10
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `account` | **是** | 登录账号，就是 `t_employee.login_name`（如 `sngdssz`、`xgscwb`、`sz013`）。也兼容传 `uid` |
| `today` | 建议 | **业务日期** `YYYY-MM-DD`。所有"截至今日 / 年度 / 停留天数"都按它算；不传按服务器当天 |
| `when` | 可选 | 触发时刻，仅回显 |
| `limit` | 可选 | **明细条数**，默认 10、上限 50。只影响 `items`，不影响 `title` 和 `total` |

> ⚠️ **不要传 `scope` / `role`**：传了也会被忽略。范围只能由账号决定（这是鉴权，不是参数）。

### 3.1 顶层字段

| 字段 | 说明 |
|---|---|
| `status` | **`abnormal`** 有预警 ／ **`ok`** 无异常（`alerts=[]`）／ **`unknown`** 账号解析不了（`alerts=[]` + `error`） |
| `account` / `name` | 账号 / 姓名（`name` 可能为空串，库里有些账号是占位名） |
| `role_code` / `role` | 角色码 / 角色中文名（`sz` 所长、`xgscwb` 县财务、`sgscwb` 市财务、`master` 市领导…） |
| `scope` / `scope_type` | 数据范围名 / 类型（`station` 单个所、`county` 县公司、`city` 全市） |
| `station_ids` | 本次统计覆盖的供电所 id 列表（`unknown` 时为 `null`） |
| `today` / `triggered_at` / `checked_at` | 业务日期 / 触发时刻回显 / 实际检查时刻 |
| `elapsed_ms` | 本次耗时（线上实测 100~160 毫秒） |
| `suppressed` | 因**每人最多条数**被截掉的预警类型名（只给类型名，便于排查） |
| `error` | 仅 `unknown` 时出现：`empty_account` / `no_such_account` / `account_disabled` / `no_role` / `no_station` |

### 3.2 `alerts[]` 每条

| 字段 | 说明 |
|---|---|
| `alert_type` / `type` | **这一句是什么预警**（类型码，见 §四）。前端靠它决定标签与样式 |
| `alert_label` / `name` | 类型中文名（如「预算预警」「待审批积压预警」） |
| `level` | `high` / `mid` / `low` —— **数组已按它排序**（high 在前） |
| **`title`** | **要展示的就是这一句**，≤44 字。**只陈述事实**：不带【类别】前缀、不写「请…」；这句是什么预警看 `alert_label` |
| `total` | 命中总数（**不是** `items` 的长度） |
| `amount` | 涉及金额（单位**元**，原值；折万元由你们定） |
| `data` | 该类型的明细字段，见 §四 |
| `items` | **只有部分类型有**（金额异常 / 金额存疑）；`returned` 是实际返回条数 |

### 3.3 状态码

| 场景 | 返回 |
|---|---|
| 有预警 / 无预警 | **200**（无预警也是 200 + `status=ok`） |
| 账号为空或查不到 | **200** + `status=unknown` + `error` |
| 请求体不是合法 JSON | 服务端按现有约定处理（其余接口为 400） |

> **永远不会因为"今天没事"返回 4xx/5xx，也永远不空返回。**

## 四 预警类型一览（每个角色收到的不同）

**`alert_label` 与 `type` 的对应**（前端按它分类、做样式；正文里不带【】前缀）：

| `type` | `alert_label` | 等级 | 判据（一句话） |
|---|---|---|---|
| `budget_underspend` | 预算预警 | high | **按当前审批速度外推到年底，预计用不到分配的 60%** → 报；花得完 → 不报 |
| `zero_execution` | 零审批预警 | mid | 该所今年**一单都没通过审批**（县/市级才报，报"几个所零审批"） |
| `approval_backlog` | 待审批积压预警 | high | 未审批（草稿 / 提交审核 / 驳回已修改）的件数与金额 |
| `node_stay_overdue` | 审批滞留预警 | high | **停在本角色对应节点**且滞留 **>90 天** 的件数 |
| `node_backlog` | 审批环节积压预警 | mid | 待审批集中在哪个环节 |
| `approved_not_started` | 待开工预警 | mid | 审批通过待施工、且已等 **>30 天** |
| `extreme_amount` | 金额异常预警 | mid | 单笔预算 **≥100 万**（疑录入有误，需人工核） |
| `data_quality_amount` | 金额存疑预警 | mid | 工程费或物资费为 **0** |
| `data_quality_status` | 状态未登记预警 | low | 状态在原系统未登记（无法计入统计） |
| `data_quality_missing` | 数据缺失预警 | low | 未填计划完工日期 |
| `metric_deteriorated` | 指标预警 | mid | **只推跳闸次数、线损率**（年度同比） |

### 4.1 每个角色收哪几类（实测）

| 角色 | 收哪几类 | 实测条数 |
|---|---|---|
| **所长** `sz` | 预算 · 待审批积压 · 审批滞留 · 审批环节积压 · 待开工 · 金额异常 · 金额存疑 | 4~6 条 |
| **县财务** `xgscwb` | 预算 · 零审批 · 待审批积压 · 审批滞留 · 审批环节积压 · 指标 | 4~6 条 |
| **县运检** `cto` | 审批滞留 · 审批环节积压 · 待开工 · 待审批积压 | 2 条 |
| **县营销** `yxb` | 审批滞留 · 审批环节积压 | 1~2 条 |
| **市财务** `sgscwb` | 上面全部（全市口径）+ 金额异常 + 数据质量汇总 | 最多 7 条 |
| **市领导** `master` | **只有全市预算 + 指标** | **最多 2 条** |

> 每人条数上限：所长/县财务 6 条、市财务 7 条、市领导 2 条。超出按等级截断，被截掉的类型名在 `suppressed`。

## 六 你们要注意的 6 件事

1. **每天只需调 1 次、每个账号 1 次**。要覆盖全部人就是循环 121 个账号各调一次（或只调需要的角色）。
2. **无预警也是 200**，请按 `status` 判断：`ok` 就别显示，`unknown` 建议记日志（说明账号没解析成功）。
3. **不要缓存太久**：判据是现算的，数据每天在变。建议按 `today` 缓存当天结果。
4. **`level` 可以用作排序/配色**（high/mid/low），数组已经排好序，直接按顺序展示即可。
5. **金额单位是元**（`amount`/`data.*`），要显示"万元"请自己除 10000。
6. **账号传错不会泄露数据**：未知名账号只回 `unknown`，不会回全市数；传 `scope` 无效。
