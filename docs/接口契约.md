# 接口契约

> 统一知识库与智能问数平台 · 对外接口说明书
> 版本：v1.0（2026-10-15）
> 在线版：启动后访问 **`http://127.0.0.1:8200/docs`**（Swagger，可直接试调）

---

## 一、先看这张"能力地图"

系统功能看着多，但对外的**能力只有三条**。记住这三条就够了：

| # | 能力 | 接口前缀 | 用途 | 契约状态 |
|---|---|---|---|---|
| ① | **认证** | `/api/v1/auth/*` | 换 JWT 令牌 | ✅ 规范 |
| ② | **知识库** | `/api/v1/*` | 建库 / 传文档 / 检索 | ✅ 规范（有 OpenAPI 文档） |
| ③ | **问数** | `/api/*` | 给一句话问题 → 返回答案 | ✅ 已补契约 |

```
统一后端 :8200
├── /api/v1/*   ← ① 认证 + ② 知识库（管理面）
├── /api/*      ← ③ 问数（智能问答）
└── /agent/*    ← 页面（问答 / 语音 / 技能台），不是接口
```

**分区规则**：`/api/v1/*` 是知识库，`/api/*` 是问数，两者互不覆盖。

## 二、认证（所有接口的统一入口）

### 1. 换令牌

```http
POST /api/v1/auth/login
Content-Type: application/json

{ "username": "kbadmin", "password": "Kb@123456" }
```

**响应**（节选）：
```json
{
  "access_token": "eyJhbGciOi...",
  "expires_in": 43200,
  "user": { "id": 2, "username": "kbadmin", "display_name": "知识库测试管理员" },
  "roles": ["admin"],
  "permissions": ["kb:read", "doc:upload", "..."]
}
```

### 2. 之后每个请求都带上

```http
Authorization: Bearer <access_token>
```

| 项 | 说明 |
|---|---|
| 账号来源 | 人力资源系统 `t_employee`（本系统**不存密码**） |
| 令牌有效期 | 默认 720 分钟（12 小时），过期需重新登录 |
| 角色 | `admin`（管理员，19 个权限点）/ `user`（普通，10 个） |
| 权限点 | 决定能调哪些接口、能看哪些数据；返回在 `permissions` 里 |

**错误**：`401` 未登录/令牌无效 · `403` 无该权限

## 三、① 知识库能力

### 3.1 知识库列表

```http
GET /api/v1/kb?page=1&page_size=50
Authorization: Bearer <token>
```

**响应**（`items[]` 每项）：
```json
{
  "id": 3,
  "name": "通用知识库",
  "description": "……",
  "embedding_model": "online/text-embedding-v4",
  "embedding_dim": 1024,
  "status": "active",
  "qa_enabled": true,
  "document_count": 12,
  "chunk_count": 340,
  "visible_document_count": 12
}
```

| 字段 | 说明 |
|---|---|
| `status` | `active`（启用）/ `archived`（归档） |
| **`qa_enabled`** | **是否参与「智能问答」的默认检索范围**（2026-10-15 新增） |
| `visible_document_count` | 当前登录用户可见的文档数（区分"空库"与"无权限"） |

### 3.2 建库 / 改库 / 删库

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `POST` | `/api/v1/kb` | `kb:create` | 建库（`name` 必填） |
| `PATCH` | `/api/v1/kb/{id}` | `kb:update` | 改库；**`{"qa_enabled": true}` 即加入问答范围** |
| `DELETE` | `/api/v1/kb/{id}` | `kb:delete` | 删库（级联删文档与切片） |

### 3.3 上传文档（异步）

```http
POST /api/v1/kb/{kb_id}/documents
Content-Type: multipart/form-data

file=<文件> & is_public=true & tags=["安全制度"]
```

**响应** `202`：
```json
{ "task_id": "3274700f-...", "status": "pending" }
```

然后轮询任务：

```http
GET /api/v1/tasks/{task_id}
```
```json
{
  "status": "done",
  "stage": "ready",
  "progress": 100,
  "error": null,
  "result": {
    "doc_id": 42,
    "chunk_count": 87,
    "conflict_status": "done",
    "conflict_count": 1,
    "conflict_docs": ["差旅报销制度.md"]
  }
}
```

#### ⚠️ 任务分两段完成（2026-10-15 起）

入库与冲突检测**不再一起结束**，`status` 和 `result.conflict_status` 要分开看：

| 字段 | 取值 | 含义 |
|---|---|---|
| `status` | `pending` / `running` | 解析 → 切片 → 向量化中 |
| `status` | `done` | **文档已入库、可立即检索**（此时冲突检测可能仍在后台跑） |
| `status` | `failed` | 失败，`error` 里是原因（如"内容与已有文档完全相同"） |
| `result.conflict_status` | `checking` | 冲突检测仍在后台继续，稍后重查同一任务可见结论 |
| `result.conflict_status` | `done` | 冲突检测已完成，`conflict_count` / `conflict_docs` 此时才有效 |
| `result.conflict_status` | `failed` | 冲突检测未完成（文档本身已入库，不受影响） |

**调用方约定**

- 看到 `status=done` 即可认为**文档可用、可检索**，不必等冲突结论；
- 要拿冲突结论，继续轮询到 `result.conflict_status != "checking"`，或稍后重查该任务；
- ⚠️ **不得**把 `status=done` 时的 `conflict_count=0` 当成"没有冲突"—— 那只是"还没判完"。

### 3.4 检索（★ 对外最常直接用的一条）

```http
POST /api/v1/search
Authorization: Bearer <token>

{ "query": "信息安全 保密管理", "kb_ids": [3], "top_k": 5 }
```

**响应**：
```json
{
  "total": 3,
  "results": [
    { "doc_name": "信息安全管理制度.md", "content": "……", "rerank_score": 0.87, "heading_path": "第三章 保密" }
  ]
}
```

> 检索结果**已按登录用户的可见范围过滤**（公开文档 + 自己上传的），调用方无法绕过。

## 四、③ 问数能力（智能问答）

### 4.1 提问

```http
POST /api/ask
Authorization: Bearer <token>
Content-Type: application/json

{
  "question": "环潭供电所上个月的线损率",
  "session_id": "可选，多轮对话时回传",
  "kb_ids": [3]
}
```

**请求字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| `question` | ✅ | 用户原话，**不需要预处理**（错字、简称、漏时间地点都能理解） |
| `session_id` | | 会话 id；首次不传由服务端生成，多轮**必须回传** |
| `kb_ids` | | 本次检索的知识库 id 列表；不传则用 `qa_enabled` 标记的库 |
| `model` | | 指定模型；不传用默认 `qwen3.8-max` |
| `today` | | 业务日期（`YYYY-MM-DD`）；不传按系统当天 |
| `profile` | | 用户画像文本（可选） |
| `history_turns` | | 读同一会话最近 N 轮做上下文；`0` = 不用上下文 |

**响应字段**

| 字段 | 说明 |
|---|---|
| **`answer`** ★ | 回答正文。**外部集成只需依赖它** |
| **`session_id`** ★ | 会话 id，下一轮原样回传 |
| `question` | 补全后的问题（补了时间/地点/口径） |
| `unverified` | `true` = 证据不足而拒答（**正常行为，不是故障**） |
| `db_query_count` / `kb_query_count` | 查库次数 / 知识库检索次数 |
| `elapsed_ms` | 耗时（毫秒） |
| `trace` | ⚠️ 工具调用轨迹，**仅调试用**，外部集成可忽略 |

**错误码**

| 状态码 | 含义 | 处理建议 |
|---|---|---|
| `200` | 成功（即使 `answer` 是"没查到"也算成功） | 直接展示 `answer` |
| `401` | 未登录 / 令牌过期 | 重新登录换令牌 |
| `403` | `kb_ids` 全部不可用（不存在 / 已停用 / 无权限） | 检查传的库 id |
| `500` | 服务异常 | `answer` 里会是"服务异常：…"，可重试 |

> ⚠️ **注意**：真正的"系统故障"目前也走 `200` + `answer="服务异常：…"`。
> 外部集成时如需要严格区分，请以 HTTP 状态码为主、`answer` 前缀为辅。

### 4.2 会话与历史

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/sessions` | 我的会话列表（按当前登录用户过滤） |
| `GET` | `/api/history?session_id=xxx` | 某场会话的历史消息 |
| `POST` | `/api/feedback` | 给某次回答打分（`{"qa_id": 1789, "feedback": 1}`，1=赞 / 0=踩） |

## 五、将来"嵌入别的系统"要看的三件事

1. **不要让外部系统直接用 UI 接口**
   本文件的 `/api/ask` 目前同时服务自家前端。若外部系统接入，建议**另加一层薄封装**
   （如 `/api/v1/integration/ask`），字段固定、错误码标准、默认不返回 `trace`——
   这样前端改版不会影响外部调用方。

2. **知识库引用不要用自增 id**
   `id` 会因删库/建库漂移（删除不复用、新建拿更大值）。外部系统若要长期引用某个库，
   应改用**不可变的业务编码**（如 `general`）。本期通过 `qa_enabled` 标记解决了
   "默认范围"的漂移问题；对外编码可等接入时再加。

3. **认证沿用员工账号**
   外部系统调本平台，用**专用对接账号**走正常登录流程拿 JWT，
   权限与审计就自动统一到用户体系里（不需要额外的 API Key 机制）。

## 六、快速验证（复制即用）

```bash
# 1. 登录拿令牌
TOKEN=$(curl -s -X POST http://127.0.0.1:8200/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"kbadmin","password":"Kb@123456"}' | jq -r .access_token)

# 2. 检索
curl -s -X POST http://127.0.0.1:8200/api/v1/search \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"query":"信息安全","kb_ids":[3],"top_k":3}' | jq

# 3. 问数
curl -s -X POST http://127.0.0.1:8200/api/ask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"环潭供电所上个月的线损率"}' | jq .answer
```
