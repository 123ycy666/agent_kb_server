## 0. 一句话

v4 优化的是"我有没有走流程"，你的痛点是"我有没有答到点上"。指标错了，所以越优化越复杂。

## 1. 为什么 v4 没用（这一节决定 v5 长什么样）

`rules-can-be-rationalized-away` 那次实测已经写明：规则可以被"讲道理"绕过去，三轮 5/5 → 3/5。
但更根本的问题是**验收指标选错了**：v4 验的是"技能调了几个、计划文件在不在"，这正好是
`proxy-metric-drift` 里我自己记下的坑 —— 技能调够了 ≠ 活干好了。

结果就是：流程都走了，你还是要问「你不懂什么是流程图吗」「你给我这个是什么意思」「你编辑代码干啥」。

存量能说明问题：**40 个技能 / 40 条记忆 / 34 份计划 / 5 处 hook / AGENTS.md 26 行**。
规则不缺，缺的是一条你和我都在同一时刻能看到的信号灯。

## 2. 三条核心改动（只做这三件也能见效）

### 改动一：hook 减负 —— 治"简单问题复杂化"

| 现在 | 改成 | 为什么 |
|---|---|---|
| `read` 同一文件第 4 次就 deny | **删掉这条** | 诊断类任务必须重读。现在它逼我瞎猜 |
| 第 1 个代码文件就要"24h 内计划" | **第 3 个不同代码文件**才要 | 改一个字不该写计划 |
| `planDir` 默认 `docs/plans`，实际计划在 `docs/04-计划` | **统一到 `docs/04-计划`** | 两套并存 = 现有 bug，`.dsh/guard.json` 和 `guard.mjs` 默认值不一致 |
| 同文件第 3 次 edit 要求"根因"段 | 保留 | 这条是对的，别动 |

### 改动二：回答形状 —— 治"答非所问 / 黑话 / 只列证据"

写进 `AGENTS.md`，四句话，不带例子：

1. **第一行给结论或动作**，不给背景、不给数据。
2. **问"怎么做"就只给怎么做**；数据最多 2 行，放最后。
3. **并列项不超过 3 个**；第 4 个说明我没想清重点。
4. **出现"应该 / 差不多 / 基本 / 优化一下 / 相关"= 谎话信号**，停下重写。

对应你今天骂的原话：「你给我这个是什么意思，我又看不到代码」「说了一大堆没用的废话」「不要用这种不知道什么意义的话来说」。

### 改动三：入口报路数 —— 治"分不清简单复杂 / 闷头做"

每次回答的第一个词是下面之一（不写在正文里绕）：

| 标记 | 含义 | 硬约束 |
|---|---|---|
| `[答]` | 直接答 | 不查文件、不写文件、不动 hook |
| `[问]` | 需求不清 | **一次只问 1 个问题**，问完停 |
| `[设计]` | 只出方案 | 不碰代码，等你点头 |
| `[做]` | 动手 | 先复述 2 行（做什么 / 怎么算完成），你点头才动手 |

为什么这条有用：**你能一眼看见我走错路，不用等十分钟。**
为什么不指望我自觉：`skill-gate-only-triggers-named-skills` 已证明"技能目录可见 ≠ 会被用上"。
所以 `[做]` 前面的复述和 `[答]` 的"不查文件"是可观测的，你能当场判。

## 3. 配套（跟着上面三条走，不单独加规矩）

- **技能表从 8 行砍到 3 行**：`systematic-debugging`（报错/结果不对）、`test-driven-development`（写码）、
  `verification-before-completion`（说完成前）。其余 37 个改成"Fred 点名才用"。
  理由：40 个技能里模型只会用被点名的那几个，多写等于噪音。
- **文档跟着路数走，不再一律写**：
  - `[答]` / `[问]` → 不写任何文档
  - `[设计]` → `docs/03-设计/` 一份，含目标 / 边界 / 不改什么
  - `[做]` → `docs/04-计划/` 一份，含目标 / 验收判据 / 步骤→verify
  - 只有 `[做]` 且动了 3 个以上文件，才补需求文档
- **画图前置检查**：`[做]` 且产出是图 → 先查 mermaid 官方语法 + 写出"这图回答什么问题"一行，再画。
  节点 ≤15 个，每个节点写「谁 + 做什么 + 给谁」，不写字段名、函数名、`qa_log.load_context` 这种代码话。
  依据：你两次骂图（10-20「不要用这种不知道什么意义的话来说」、10-30「你不懂什么事流程图吗」），
  上次的错是**没查标准就画**，不是画得不够细。

## 4. 验收（这次不用代理指标）

不看"我调了几个技能"。只做两件事：

1. **空白窗口实测**：改完后新开一个会话，不提任何流程，给 3 个任务 ——
   一个简单问答、一个改码、一个画图。你直接看结果判，我不做自评。
2. **连测 3 轮**：`rules-can-be-rationalized-away` 里第 2 轮过、第 3 轮挂过，所以一轮达标不算数。

判据（你能一眼判真假的）：
- 简单问题有没有被拖成多步？（问一句、答一句，没查文件）
- 需求不清时我有没有先问，而不是直接开工？
- 交付时第一行是不是你要的动作？
- 画图那轮有没有先查标准？

## 5. 明确不做（防止 v5 又变复杂）

- 不加新的 hook 类型（Stop / PostToolUse 都不加）
- 不新写审计脚本、不搭度量基建（`six-real-failure-modes` ④⑥ 的坑）
- 不新增记忆条目来"记住这些规矩"，规矩只住一处：`AGENTS.md` + `guard.mjs`
- 不提高技能调用率作为目标
