产出《供电所精益预算数智问答 · 使用说明》——一份**带目录的问答对**，交甲方。

同时：回答暴露出的规则缺失，补进 skills/判据规则.md —— 这是内部的事，不写进交付文档。

## 2 怎么测

1. 服务：本地起 `py -X utf8 secretary/server.py`（8200，新代码）。测试**只打 8200**，不打 8299 上的旧进程。
2. 接口：`POST /api/ask`；同一格的多轮用同一个 `session_id`；`today=2026-10-14`。
3. 顺序：3.1 → 3.2 → … → 5.5，一条一条往下走；**同一句不重问**。
4. 每条落盘（逐轮一行）：
   - 原话 / 补全后的问法 / 回答
   - **用时**：总耗时 elapsed_ms、页面生成耗时 page_ms、各阶段 timings、是否超时
   - 题型 qtype（分析 / 查数）、步数 steps、查库次数 db_query_count
   - **页面**：是否生成 page_html、同步还是异步（page_mode）、异步拿到的 token 与 `/api/page` 结果
5. 规则改过之后：换**同一格、没问过**的问法再问，用来验证规则是否真生效。
6. 证据目录：`output/test_results/2026-10-14-问答全功能测试/`，一条一行，可回查。

## 3 判据（开测前定死，测完只对判据）

每条问题逐项判 ✓/✗。判据来源：skills/判据规则.md 十五（输出格式）、十六（硬规则）、十七（阈值）、十八（比较与排名）、十九（问法归一）、二十（回答方向）、二十一（角度库）。

### A 通用（每条都要过）
| # | 判据 |
|---|---|
| A1 | 第一句就是结论（数字或判断），没有铺垫、没有过程话术 |
| A2 | 没有 Markdown 符号（#、**、表格、代码块） |
| A3 | 没有表名、字段名、SQL、返回行数 |
| A4 | 没有「数据来源」「口径声明」「AI」「工具」「查询过程」这类技术说明与自我声明 |
| A5 | 金额万元两位小数、比率两位小数、期次写「截至 2026 年 9 月」 |
| A6 | 状态、缺陷类型等编号翻成中文 |
| A7 | 同一次回答里同一个数只有一个值；概览合计 = 逐条相加 |
| A8 | 查不到写「未查得 / 无法判定」，不估算、不补 0 |
| A9 | 逐条清单 ≤30 条全列（不出现「等」「其余」）；超 30 条写明「共 N 条、其余 N−20 条合计 X」 |

### B 统计类（3.1 / 4.1 / 5.1 基础问答与查数）
| # | 判据 |
|---|---|
| B1 | 数的对得上：与**直接查库**算出的真值一致（金额容差 ±0.01 万）；真值不经过问答链路 |
| B2 | 答了「范围 + 期间」（如「全市 · 截至 2026 年 9 月」） |
| B3 | 比较、排名题给了两边的数 + 差 + 参照（第二名或中位数） |
| B4 | 不越界：查数题不给判断、不给建议 |

### C 分析类（3.2–3.4 / 4.2–4.4 / 5.2–5.4）
| # | 判据 |
|---|---|
| C1 | 四段齐全：结论 → 依据 → 判断标准 → 建议 |
| C2 | 依据里的数字与库一致（同 B1） |
| C3 | 判断挂在《判据规则》某一节上；没有标准的写明「无判定标准，仅呈现事实」 |
| C4 | 说「未达标 / 偏慢」必须同时给：差多少、剩多少时间、按当前速度能不能完成 |
| C5 | 用内部的 0.6 系数换成人话（已过 X%、执行 Y%、缺口 Z 个百分点），不许暴露系数 |
| C6 | 建议有对象和量，不出现「加强管理」「提高效率」 |
| C7 | 原因与建议一一对应（无项目→补储备 / 卡审批→清积压 / 批了没完工→推施工） |
| C8 | 预警：先给越阈清单 + 分档（≤15 天正常 / 16–90 天偏慢 / >90 天积压）；没越阈要写「未越阈」，不许硬编异常 |
| C9 | 预测：给缺口量化（多少单 / 多少万元 / 什么时候），不许只写「有难度」 |
| C10 | 涉及成效一律带同期对比；取不到时按降级链写明用了哪一档 |

### D 多轮追问（3.5 / 4.5 / 5.5）
| # | 判据 |
|---|---|
| D1 | 追问轮继承上一轮的对象与范围（回答里出现上一轮对象名），不许反问「你指哪个」 |
| D2 | 对象换了必须写明本轮范围 |
| D3 | 同一场会话里同一个数只有一个值 |

### E 补全（6.2 素材）
| # | 判据 |
|---|---|
| E1 | 残缺问法被补成完整口径（补全后的问题含时间与范围） |
| E2 | 补全结果符合 19.1 三条缺省约定（时间用统计范围、范围用身份范围、对象按默认对象） |
| E3 | 补全没有改变问题的原意 |

### F 生成的页面（分析类问题）
| # | 判据 |
|---|---|
| F1 | 分析类问题生成了页面（qtype=分析 → 有 page_html）；查数题不生成，保持快 |
| F2 | 同步与异步两种模式都能拿到页面（异步先回 token，`/api/page` 从 202 变 200） |
| F3 | 页面里的关键数字与回答一致；页面上不出现表名、字段名、SQL |
| F4 | 页面能正常渲染（截图检查）：无乱码、排版正常、图表明细能看清 |
| F5 | 页面生成耗时记下来（page_ms），超过 60 s 记「慢」 |

### 判定口径
- 一条问题算**过**：A 全过 + 该格对应的 B/C/D 全过。
- 算**没过**：任一项 ✗；没过必须落到「改规则 / 改问法 / 待业务方定口径」三选一，不许悬空。
- **不拿来做判据**（这些是代理指标，只记录）：工具调用次数、查库次数、耗时、步数。

## 4 规则怎么改

1. 一条 ✗ 先归因，四选一：规则缺失 / 规则有但没说清 / 模型没照做 / 数据本身没有。
2. 只有前两类改文档，改在对应节：
   - 口径、状态、公式 → 三、四、五、七、八、九节
   - 该答的方面没答 → 二十节对应类（20.2–20.10）
   - 角度漏了 → 二十一节
   - 残缺问法没归一 → 十九节
   - 输出格式与硬规则 → 十五、十六节
3. 一次只改一条根因；禁止加特例词、加分叉来凑过。
4. 改完验证：换**同一格、没问过**的问法重问，看是否真修好。
5. 模型没照做 → 不改规则，记入「模型行为」清单。
6. 数据没有 → 记入「待业务方定口径」清单，交甲方。

## 4.5 跑批循环（每批都走这五步，不一次全跑完）

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 取批 | 按批号取 8 个左右的场景（同维度优先） | 本批题目清单 |
| 2 跑 | 批内 ≤3 路并行；每场景一个 session_id，逐轮问；**记录原话 / 补全后 / 回答 / 用时** | raw-batch-NN.json |
| 3 判 | 逐条按判据对，分成四类：✅过 ／ ❌答错（数字不对、口径不对、缺段、越界、编数）／ ⚠️偏差（答了但浅、答非所问、格式不对）／ ⏱超时 | judge-batch-NN.md |
| 4 归因改 | 按类分流（见下表），一次只改一条根因 | 改动清单 |
| 5 复跑 | 只把这批里 ❌⚠️⏱ 的条目改完重跑；通过的进《使用说明》 | 复跑记录 |

**四类分流**

| 分类 | 怎么处理 | 谁定 |
|---|---|---|
| 规则缺失 / 没说清 | 改 skills/判据规则.md 对应节 | 我改，逐条留证据 |
