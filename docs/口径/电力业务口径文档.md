# 随州市电力业务口径文档

## 1. 文档目的

本文档是本项目面向新开发人员、测试人员和内网运维人员的业务与技术交接文档。它说明系统有哪些业务对象、数据表分别做什么、表之间如何关联、接口如何同步、指标如何统计、审批如何流转，以及部署和排查时必须注意的事项。

它重点回答“这张表为什么存在、谁写入、谁读取、字段代表什么、数据能不能直接汇总或修改”等交接问题，作为后续开发、测试、部署和需求确认的共同依据。

用户自然语言如何被 AI 修正为标准查询，请参阅《用户提问标准化规范.md》；本文件不替代该规范。

适用范围：随州市整体、县公司、供电所、线路、台区，以及与这些对象关联的预算和运行成效数据。

## 2. 业务组织范围

本项目的业务范围按以下层级理解：

```text
随州市
└── 4 个供电公司
    └── 47 个供电所
        ├── 线路
        │   └── 台区
        └── 台区
```

业务说明：

1. 随州市是本次统计分析的最高区域范围。
2. 随州市下设 4 个供电公司。
3. 4 个供电公司合计下辖 47 个供电所。
4. 供电所管理线路和台区。
5. 台区通过线路连接，线路是台区供电关系和定位分析的重要关联对象。
6. 一个台区应能够追溯到所属供电所；涉及线路分析时，还应能够追溯到所属线路。

当前代码可以确认供电所、线路、台区都存在独立数据对象，并且线路、台区、工单数据都带有供电所归属信息。四个公司和 47 个供电所属于本业务统计范围，实际名称和数量应以当前数据为准，不在代码中写死。

## 3. 统计时间口径

### 3.1 今年

“今年”指当前自然年度，即当前日期所在年份的 1 月 1 日至统计截止日期。

如果业务页面指定统计月份或截止日期，应优先使用页面指定值；没有指定时默认使用当前自然年度。

### 3.2 月度数据

月度统计字段统一使用 `yyyy-MM` 格式，例如 `2026-09`。

月度数据用于供电所成效、台区成效和趋势分析。跨月汇总时，应明确使用累计值、平均值或期末值，不能把不同聚合方式混用。

### 3.3 数据有效性

统计时应排除已删除数据，并按数据实际归属关系去重。相同资源在同一统计月份原则上只保留一条有效记录。

## 4. 精益预算分配

### 4.1 业务定义

“精益预算分配情况”是指今年的预算分配情况。

因此，用户询问“今年精益预算分配了多少”“各公司预算分配情况”时，默认查询当前自然年度的预算分配数据，而不是历史年度累计数据。

### 4.2 分析维度

预算分析至少支持以下维度：

| 维度 | 说明 |
| --- | --- |
| 年度 | 默认当前自然年度 |
| 供电公司 | 县公司或供电公司级别的预算归属 |
| 供电所 | 预算关联的基层管理单位 |
| 线路 | 工单或项目关联线路 |
| 台区 | 工单或项目关联台区 |
| 预算项目 | 预算项编号、名称和分类 |
| 金额 | 预算总额、施工预算、物料预算及明细金额 |

### 4.3 预算展示建议

预算页面或问答结果应优先展示：

1. 今年预算总额。
2. 4 个供电公司的预算金额及占比。
3. 各供电所预算金额及排名。
4. 预算项目数量和预算分类分布。
5. 施工预算、物料预算及其合计关系。
6. 预算已分配、已使用、剩余金额（只有系统存在对应实际使用数据时才展示）。

### 4.4 当前代码依据

项目已有工单预算总额、施工预算、物料预算、预算项、预算分类、公司预算、预算分配和预算结果等业务对象。工单查询还支持发布年份、供电公司、供电所、线路和台区等条件。

实现预算查询时，应以工单或预算记录的业务年份过滤“今年”，不能只按创建时间推断年度。

## 5. 供电所成效

### 5.1 统计范围

供电所成效覆盖：

- 随州市整体
- 4 个供电公司
- 47 个供电所

结果应支持从市级逐级下钻到公司和供电所，并支持按月份查看趋势。

### 5.2 指标范围

供电所成效只包含以下 6 个指标：

| 序号 | 指标 | 单位或表现形式 | 方向 |
| ---: | --- | --- | --- |
| 1 | 售电量 | kWh 或系统统一展示单位 | 越高通常越好 |
| 2 | 线损率 | % | 越低通常越好 |
| 3 | 意见工单 | 件 | 越少通常越好 |
| 4 | 故障报修工单 | 件 | 越少通常越好 |
| 5 | 用户平均停电时长 小时/户 | 越低通常越好 |
| 6 | 故障跳闸次数 | 次 | 越少通常越好 |

除非后续明确增加指标，供电所成效不应混入用户数、台区数、低电压次数、停电影响户次数、优先级分数等辅助字段作为成效指标。辅助字段可以用于解释结果，但不计入这 6 个指标。

### 5.3 计算和展示原则

1. 售电量按统计范围内有效数据求和。
2. 意见工单和故障报修工单按有效工单数量统计，并按工单编号去重。
3. 故障跳闸次数按有效事件数量统计。
4. 用户平均停电时长应明确统计单位，并在页面统一换算后展示。
5. 线损率不能简单平均所有明细记录；跨台区或跨供电所汇总时，应按系统既有统计口径确认加权方式。
6. 排名时应标明统计月份或年度截止时间。
7. 指标缺失时显示“暂无数据”，不能默认当作 0，避免影响排名。

### 5.4 当前代码依据

项目存在供电所月度指标汇总表，字段包括售电量、线损率、用户平均停电时长、故障报修工单数、故障跳闸次数和意见工单数；相关推送表也分别保存售电量、线损、停电、跳闸和意见工单数据。

## 6. 台区成效

### 6.1 指标范围

台区成效只看以下 2 个指标：

1. 售电量。
2. 线损率。

台区成效不纳入意见工单、故障报修工单、用户平均停电时长和故障跳闸次数。这 4 项只属于供电所成效口径，除非后续另行确认。

### 6.2 分析维度

台区成效支持按以下维度查看：

- 随州市
- 供电公司
- 供电所
- 线路
- 台区
- 统计月份

### 6.3 当前代码依据

项目已有台区基础数据、线路基础数据、台区同期售电量数据和台区同期线损数据。台区记录包含所属供电所信息，售电量和线损数据按资源编号与统计月份保存。

## 8. 推荐业务问法

### 8.1 预算

- 查询今年随州市精益预算分配总额。
- 查询 4 个供电公司的今年预算分配情况，并按金额排序。
- 查询今年各供电所预算分配情况。
- 查询今年预算金额最高的供电所及其预算项目。

### 8.2 供电所成效

- 查询随州市 4 个供电公司的 6 项成效指标。
- 查询 47 个供电所本月成效排名。
- 查询某供电公司的意见工单、故障报修工单和故障跳闸次数。
- 查询用户平均停电时长最高的供电所，并展示另外 5 项指标。

### 8.3 台区成效

- 查询某供电所下台区售电量和线损率。
- 查询线损率最高的台区及其所属线路。
- 查询某线路下所有台区的售电量和线损率。

## 9. 待数据确认事项

以下内容需要以实际业务数据或业务方进一步确认，不应由程序自行猜测：

1. 4 个供电公司的正式名称和编码。
2. 47 个供电所的正式名称、所属公司和有效状态。
3. 台区与线路的直接关联字段或关联规则。
4. 今年预算使用“发布年份”“预算年度”还是其他业务年度字段。
5. 用户平均停电时长最终统一使用分钟/户还是小时/户。
6. 线损率跨台区、供电所和公司的汇总加权规则。
7. 成效排名的正负向规则、并列规则和缺失数据处理规则。

在这些事项确认前，系统应保留原始值和统计月份，查询回答应明确统计时间和数据范围。

## 11. 表之间的核心关联

```text
t_power_supply_company（县公司）
        1 ─── N
t_power_company（供电所，parent_id）
        1 ─── N
t_power_area / t_power_line（台区、线路）
        ↑
中台推送表通过 resource_id / obj_name / area_code 映射到本地主数据

t_power_work_order（工单）
        1 ─── N t_work_order_audit_task（审批任务）
        1 ─── N t_power_work_order_log（操作日志）
        1 ─── N t_power_work_cost（预算/成本）
```

工单关联台区时优先使用工单保存的台区主键；查询中台线损和售电量时，再通过台区 `area_code` 或中台记录的 `resource_id` 匹配。公司维度不能把公司 ID 直接当供电所 ID，必须先展开公司下的供电所集合。



查询接口：`POST /otherSystem/dataPush/faultTicket/statistic` 和 `POST /otherSystem/dataPush/opinionTicket/statistic` 传 `year` 后应同时返回当年与上一年字段；`GET /stateGridAgentApi/powerCompany/assessment/summary?year=YYYY` 用于大屏年度成效；`GET /stateGridAgentApi/power/area/benefit/list` 用于台区治理窗口。


## 15. 缺陷治理与预算执行闭环

### 15.1 业务闭环

每年的预算先按预算分配规则分发到各供电所，再由供电所根据发现的缺陷录入缺陷工单。系统根据工单中的工程和物资明细生成工单预算金额。缺陷工单的目标是通过治理改善供电所成效指标，工单必须审批通过后才能实施。

```text
年度预算分配
    -> 供电所获得预算额度
    -> 供电所录入缺陷工单
    -> 系统生成工程/物资预算
    -> 多级审批
    -> 审批通过，允许施工
    -> 施工中
    -> 施工完成，待验收
    -> 验收及效果跟踪
```

预算金额与成效的关系是“投入支持治理、治理改善指标”，不能直接把预算金额当作成效指标。预算分析回答投入情况，成效分析回答治理后的指标变化。

### 15.2 缺陷工单类型

当前代码定义两类缺陷：

| 缺陷类型 | 业务含义 | 主要对象 |
| --- | --- | --- |
| 线缆类-导线 | 线路或导线相关缺陷治理 | 线路；工单表单中的关联设备字段按代码逻辑识别为线路 |
| 台区线损 | 台区线损治理 | 台区 |

当前代码还定义两个工作专业：运维检修类、营销类。营销类工单在供电所内部审核后进入营销部审核，其他专业默认进入县公司运检部审核。

## 16. 缺陷工单审批流

### 16.1 通用规则

1. 工单处于草稿或修改后待重新提交时，可以继续编辑。
2. 只有提交审核后，工单才进入审批流。
3. 审批任务按审批轮次管理，当前任务必须属于工单当前审批轮次。
4. 审批人必须拥有对应节点角色；未指定具体人员的节点采用抢单方式，先成功抢到任务的人办理。
5. 审批通过后才允许进入施工；审批驳回后工单变为已驳回并结束本轮流程。
6. 驳回工单修改后可重新提交，重新提交应形成新的审批轮次并保留历史记录。
7. 每次审批都会记录审批节点、办理人、审批意见、审批结果和操作时间。

### 16.2 当前实现的节点顺序

| 顺序 | 节点 | 作用 |
| ---: | --- | --- |
| 1 | 缺陷录取 | 供电所或录入人员登记缺陷，关联公司、供电所、线路或台区，填写缺陷说明和预算明细 |
| 2 | 供电所内部审核 | 供电所内部审核缺陷真实性、治理必要性、范围和预算明细 |
| 3 | 县公司运检部审核 | 运维检修类工单的专业审核 |
| 4 | 营销部审核 | 营销类工单的专业审核；不是所有工单都会经过此节点 |
| 5 | 县公司财务部审核 | 审核预算金额、工程和物资费用及预算合规性 |

### 16.3 按专业分流

提交后，工单先进入供电所内部审核。供电所内部审核通过后：

```text
工作专业 = 营销类       -> 营销部审核
其他工作专业             -> 县公司运检部审核
```

营销部审核或县公司运检部审核通过后，统一进入县公司财务部审核。县公司财务部审核通过后，当前代码将流程标记为完成，并把工单置为“审核通过，待施工”。

### 16.4 审批结果

| 审批结果 | 工单变化 | 后续动作 |
| --- | --- | --- |
| 通过 | 当前任务完成，进入下一节点 | 最后一节点通过后进入待施工 |
| 驳回 | 工单变为已驳回，流程状态结束 | 修改工单后重新提交 |

### 16.5 重要流程差异

数据库中的流程节点配置还出现“市公司财务部审核”和“市公司领导审批”两个节点，但当前 `WorkOrderAuditTaskServiceImpl` 的流转逻辑在县公司财务部审核、或市公司财务部/市公司领导节点时直接结束，没有继续创建下一个节点任务。

因此当前业务文档应以“县公司财务部审核通过后允许施工”为实际实现口径，同时将市公司财务部和市公司领导是否需要启用列为待确认事项。若业务要求继续走市级审批，需要同步修改流程节点配置、下一节点流转逻辑、角色权限和测试数据。

## 17. 工单状态与施工控制

当前代码状态如下：

| 状态值 | 状态名称 | 业务含义 |
| ---: | --- | --- |
| 0 | 草稿 | 可编辑，尚未提交 |
| 1 | 提交审核 | 已提交，等待审批流处理 |
| 2 | 审核中 | 当前存在审批任务 |
| 3 | 审核通过，待施工 | 审批完成，可进入施工 |
| 4 | 已驳回 | 审批未通过，需要修改后重新提交 |
| 5 | 已取消 | 工单已取消 |
| 6 | 施工中 | 已开始施工 |
| 7 | 施工完成，待验收 | 已填写或进入施工完成阶段，等待验收 |
| 9 | 已修改，待重新提交 | 驳回后已修改，等待再次提交 |

当前代码把状态值 7（“施工完成，待验收”）作为台区治理成效的“已完成”分支。业务上如果要使用“验收完成”才算已施工完成，需要明确状态 7 是否代表实际施工结束，还是必须新增独立的“验收完成”状态。

施工状态只能从“审核通过，待施工”或“施工中”进入施工相关状态，未审批通过的工单不能直接施工。

## 18. 台区治理成效时间窗口

### 18.1 核心指标

台区治理成效只展示：

- 售电量
- 线损率

### 18.2 已完成工单

当工单状态为当前系统定义的“施工完成，待验收”（状态值 7）时，以工单实际完成时间 `actualEndTime` 所在月份为基准，查询：

```text
完成时间前一个月 + 完成当月 + 完成时间后一个月
```

例如实际完成时间为 2026-08-15，则查询 2026-07、2026-08、2026-09 的该台区售电量和线损率。

代码中的时间来源优先级为：

1. 实际完成时间 `actualEndTime`。
2. 实际完成时间为空时，使用计划结束时间 `planEndTime`，并标记为估算。
3. 前两者为空时，使用工单创建时间 `createTime`，并标记为估算。
4. 三者都为空时，返回业务错误，不生成成效窗口。

### 18.3 未完成工单

当工单不是状态值 7 时，查询当前月份之前的 3 个完整月份，不包含当前未完整结束的月份。

例如当前月份为 2026-09，则查询 2026-06、2026-07、2026-08 的该台区售电量和线损率。

### 18.4 结果解释

| 工单状态分支 | 时间窗口 | 结果阶段标识 |
| --- | --- | --- |
| 施工完成，待验收 | 实际完成月份前 1 月、当月、后 1 月 | after |
| 其他状态 | 当前月之前 3 个完整月份 | before |

成效结果应同时返回工单状态、台区、月份、售电量、线损率、时间基准来源和是否估算，便于用户理解查询结果。

## 19. 大屏成效数据口径

### 19.1 展示指标

大屏展示随州市、4 个供电公司和 47 个供电所的 6 项指标：

1. 售电量
2. 线损率
3. 意见工单
4. 故障报修工单
5. 用户平均停电时长
6. 故障跳闸次数

### 19.2 时间范围

大屏的 6 项指标统一展示当年 1 月至当前月份的累计结果。

“至今”应解释为当前统计截止时间，而不是把未来月份补成 0。页面应显示数据截止月份或最后更新时间。

### 19.3 数据来源和限制

当前大屏直接展示中台提供的结果性数据，不在本系统内重新计算线损率和用户平均停电时长。

原因如下：

- 线损率的中台过程性数据在本系统侧缺少完整计算所需的数据，不能由本系统简单平均或自行推导。
- 用户平均停电时长同样不具备在本系统侧可靠重算的完整条件。
- 本系统主要记录供电所级别数据，但实际公司组织下还存在大客户班组等组织，供电所数据简单累加不一定等于公司数据。
- 因此公司级和市级结果必须优先采用中台提供的结果性数据，不能用 47 个供电所的简单加总替代。

### 19.4 指标处理原则

| 指标 | 大屏当前处理 |
| --- | --- |
| 售电量 | 直接展示中台结果性数据的当年累计值 |
| 线损率 | 直接展示中台结果性数据，不在本系统重新计算 |
| 意见工单 | 直接展示中台结果性数据的当年累计值 |
| 故障报修工单 | 直接展示中台结果性数据的当年累计值 |
| 用户平均停电时长 | 直接展示中台结果性数据，不在本系统重新计算 |
| 故障跳闸次数 | 直接展示中台结果性数据的当年累计值 |

### 19.5 汇总注意事项

1. 市公司、供电公司和供电所是不同统计层级，不能默认通过同一公式互相汇总。
2. 工单数、跳闸次数等计数指标是否可加总，要以中台结果口径为准。
3. 线损率和用户平均停电时长属于比率或平均类指标，不能直接相加，也不能对下级简单平均。
4. 公司级结果包含本系统没有记录的大客户班组等组织时，应在结果中标明“中台全口径结果”。
5. 大屏应保留数据来源和截止时间，避免用户误以为所有数值都由本系统实时计算。

## 20. 系统重要业务对象

| 对象 | 作用 |
| --- | --- |
| 供电公司 | 公司级预算、组织和成效汇总维度 |
| 供电所 | 基层预算承接、缺陷录入、审批和 6 项成效统计主体 |
| 线路 | 线缆类缺陷治理对象，也是台区关联和下钻路径 |
| 台区 | 台区线损治理对象，台区治理成效只看售电量和线损率 |
| 缺陷工单 | 描述缺陷、治理对象、施工内容和治理目标 |
| 预算明细 | 工程预算、物资预算、数量、单价、预算小计和实际核算 |
| 审批任务 | 保存每个节点的办理人、状态、结果、意见和时间 |
| 流程历史 | 支持查看审批轨迹和驳回原因 |
| 中台结果数据 | 大屏市级、公司级和供电所级成效结果来源 |

## 21. 业务查询回答模板

系统回答业务问题时建议固定包含：

1. 统计范围：随州市、某公司、某供电所、某线路或某台区。
2. 统计时间：今年累计、指定月份或台区治理时间窗口。
3. 数据来源：中台结果性数据、供电所月度汇总或台区月度数据。
4. 指标范围：明确是供电所 6 项指标，还是台区 2 项指标。
5. 工单条件：工单类型、状态、审批结果和治理对象。
6. 结果说明：缺失数据、估算时间、公司口径与供电所加总差异。

示例：

> 查询某台区治理成效时，说明该工单当前状态、实际完成时间、对比月份，以及每个月的售电量和线损率；不要附带展示意见工单、故障工单、停电时长或跳闸次数。
