# 已定案：规则库与对话链路（2026-09-24）

> 这份取代原来的《待决策-分析规则知识库》。下面每条都是拍过板的，不要再按旧稿做。

## 一、四条决定

1. **对话不带技能 ID**。`/api/ask` 没有也不该有 `skill_id` —— 前端从来没传过，「调用方告诉我们这是哪个技能」是上一轮臆造出来的，已删。
2. **规则只维护一篇**：`skills/判据规则.md` 是全系统唯一的规则文档（判断标准 + 比较 + 问法归一 + 回答方向）。原来的《分析规则》《问法归一》已并入，文件已删。
3. **知识库里只放这一篇规则**。技能文档不进知识库 —— 它们不是判断标准，进了会跟规则文档抢检索名额（实测问「是哪些项目」，技能文档拿 0.972、规则文档只有 0.785，模型就照技能文档的模板答）。
4. **两条路各走各的**：对话走 `/api/ask`（检索规则文档）；技能走 `/api/skill/*`（整篇注入规则文档 + 读技能文档）。不为对方做适配。

## 二、问答怎么用规则

- 每次问答先按「本轮问句 + 上一轮原始问句」检索规则文档，命中的切片**直接当本次的判断标准与回答方向**交给模型。
- 为什么由服务先检索：实测让模型「要判断时自己查」会时查时不查，不查就给不出判断。
- 分流（分析 / 查数）由模型按规则第零节做；`qtype` 只用来决定要不要出分析页面。

## 三、维护

    py -X utf8 tools/deploy_update.py     # 上服务器（技能路径直接读）
    py -X utf8 tools/kb_sync.py           # 同步进知识库；本地删掉哪篇，库里也一并清掉

改口径只改 `skills/判据规则.md` 一处。

## 四、不做的事

- 不新建知识库索引（现索引 `r57xtq9ypm` 已授权，零运维）。
- 不做「一条条具体问题条目」—— 那是旧稿的做法；规则按判断类型组织。
- 不为「看到提醒再追问」做专门适配：提醒之后就是普通提问，效果一样。
