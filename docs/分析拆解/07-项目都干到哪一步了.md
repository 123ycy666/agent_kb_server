# 分析问题拆解 · 07「今年立的项目都干到哪一步了？」

## 一、谁问、问谁
市领导 / 县领导 / 所长；对象：全市 / 本县 / 本所。

## 二、想要什么答案
**阶段分布 + 卡在谁那里 + 什么时候能完工**。不是列一张状态数量表。

## 三、思维链
1. **阶段归并**：草稿（0）→ 提交审核（1）→ 审核中（2）→ 审核通过待施工（3）→ 施工中（6）→ 施工完成待验收（7）；4/5 作废、9 驳回已修改；**-1 字典里没有 → 单列"状态未登记"**。
2. **每个阶段：几条、多少钱**。
3. **每个阶段的停留**：用 `t_power_work_order_status` 取**最后一次进入当前状态的时间**，算停留天数。
4. **找卡点**：按 `node_type`（如"县公司财务部审批"）分组看条数与停留 → 哪个环节堵住。
5. **预测完工**：用**往年同类项目**从立项到完工的实际周期（同样来自状态流转表）推算 → 今年这批大概什么时候完，哪些年内完不成。
6. **结论 + 该推谁**：卡在哪个环节、谁该动。

## 四、回答要出现什么
结论（整体到哪一步、堵在哪）→ 阶段分布（条数+金额）→ 最久的前几条 → 预计完工/年内完不成 → 该谁动。

## 五、数据可得性 / 坑
- 「施工中」（6）**实测当前 0 条** → 别把它当成"漏查"
- 计划完工日实测绝大多数为空 → **不许据此判"逾期"**，改用状态流转算的实际停留
- 状态流转表同一状态可能多次进入（驳回重提）→ 取最后一次
