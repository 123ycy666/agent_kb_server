# 分析问题拆解 · 05「今年六项指标比去年好了还是差了？」

## 一、谁问、问谁
- 角色：市领导 / 县领导 / 所长；对象：全市 / 县公司 / 所

## 二、想要什么答案
**逐项说清升还是降、哪项拖后腿、为什么** —— 不是把六个数字念一遍。
**特别注意：数字涨不等于变好**（跳闸、停电时长是越小越好；售电量是越大越好）。

## 三、思维链

**第 1 步 · 取六项指标的本期与对比期**
- 本期：`t_power_ai_metric_snapshot`（对应 scope_type + 最新期次；**必须钉住 `source_summary_type`**，同一期次可能有两组值）
- 对比期：`t_power_ai_metric_comparison`（当期同比）；**这一档 `base_value` 常为空 → 退到最近一个有值的年度同比，并写明用的是哪一年**

**第 2 步 · 用 `better_direction` 判"好不好"，不是看数字升降**
- 线损率、停电时长、跳闸、报修、意见工单 → 降为好
- 售电量 → 升为好

**第 3 步 · 逐项给：本期值 / 对比期值 / 差 / 好还是差**

**第 4 步 · 排"拖后腿的"**
- 恶化的项排前面；再叠加"跟全市比排第几"判断是不是特别差

**第 5 步 · 恶化项归因**
- 查这个方向**往年投过多少钱**（`t_power_work_order` 按 `defect_type` 分组、分年度）
- 判断：**没投 / 投了没效果 / 投的方向不对**

**第 6 步 · 结论 + 建议**
- 哪几项在改善、哪几项在恶化、先抓哪个

## 四、回答要出现什么
1. **结论**：整体改善 / 整体恶化 / 有升有降（一句话）
2. **逐项**：本期 vs 对比期 + 方向（好/差）—— 这是依据
3. **拖后腿的项**：哪几项、差多少
4. **为什么**：往年投入与效果的关系
5. **建议**：先抓哪项

## 五、数据可得性 / 坑
- 期次口径：所级用 `yearToDate`；不同 scope_type 的期次键不同
- 年度表 `t_governance_effectiveness` 15 行（县公司×年）可直接做跨年对比，但**所级没有** → 所级走快照+同比
- 对比期为空不许当 0；宁可写"该口径未查得"
