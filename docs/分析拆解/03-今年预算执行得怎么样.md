# 分析问题拆解 · 03「今年预算执行得怎么样？」

## 一、谁问、问谁
- 角色：市公司领导 / 县公司领导 / 所长（问本所时是 01）
- 对象：全市 或 一个县公司
- 场合：月中月末看进度、被上级问
- 原话：「今年预算执行得怎么样」「执行率多少」「进度如何」

## 二、想要什么答案
**不是报一个执行率。** 是：**快还是慢（跟时间进度比）→ 差多少 → 慢在哪一环 → 最该抓什么**。

## 三、思维链

**第 1 步 · 先定口径（口径错，后面全错）**
- 分配 = `t_power_company_budget_result` 该范围各所之和（当年 + `deleted_flag=0` 的唯一有效行）
- 已审批 = `t_power_work_order` 当年 + 状态 **2/3/6/7** 的 `budget_total` 合计
  （2 是"所长已审核通过、在上级审批中"——**必须算进来**，否则会把一堆已启动的项目算成 0）
- 执行率 = 已审批 ÷ 分配
- ⚠️ 分配与已审批必须**同年同层级**；出现负余额或 >100% → 先自查年度对齐

**第 2 步 · 判"快还是慢"**
- 算已过时间比例 = 已过天数 ÷ 全年天数 → 拿执行率跟它比
- **不把内部分数换算成"基准线"写给人看**，直接给两个数让领导自己看
- 得出：**慢了 X 个百分点 / 超了 / 基本跟上**

**第 3 步 · 看是"普遍慢"还是"个别所拖"**
- 各所执行率排序 → 有多少所是 0%、有多少所已跟上
- 得出：**结构**（普遍没启动 / 少数所掉队）

**第 4 步 · 归因（这一步是"分析"和"查数"的分界线）**
逐所/整体判断卡在哪一环，三条支路：
- **没项目可批**：当年该范围项目数很少，或全是草稿 → 储备不足
- **项目够但卡审批**：有状态 1/2 的工单 → 去 **`t_power_work_order_status`** 看卡在哪个节点、停留多少天
- **批了没完工**：状态 3/6 停留久 → 推施工

**第 5 步 · 跟去年同期比**
- `t_power_governance_effectiveness`（年度）或 `t_power_ai_metric_comparison`（退档链）
- 得出：今年比去年快还是慢

**第 6 步 · 给下一步**
- 按第 4 步的归因一一对应给动作（补储备 / 清审批 / 推施工），带对象和量

## 四、回答要出现什么（模板由提示词控制）
1. **结论**：快还是慢、差多少个百分点（一句话）
2. **依据**：分配多少、已审批多少、执行率多少、已过时间比例多少
3. **结构**：多少个所 0%、多少个已跟上、最慢的是哪几个
4. **卡在哪**：三条支路里的哪一条，依据是什么
5. **下一步**：该谁做什么

## 五、数据可得性
| 数 | 在哪 | 状态 |
|---|---|---|
| 分配额 | budget_result（所+年+deleted_flag=0） | ✅ |
| 已审批 | work_order 状态 2/3/6/7 | ✅ |
| 卡点停留 | **t_power_work_order_status** | ✅ |
| 同期 | governance_effectiveness / comparison | ⚠️ 退档链 |
| 实际投入 | t_power_work_cost.reality_total_price | ⚠️ 有值率先测 |

## 六、坑
1. 把状态 2 漏掉 → 执行率假低。
2. 分配额取到旧版本 → 数字对不上。
3. 只报率不判快慢 = 没答。
4. 空集就是答案：真没有就写"按某口径没有记录"，不要为了凑数放宽条件。
