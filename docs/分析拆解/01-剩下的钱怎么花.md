# 分析问题拆解 · 01「剩下的钱怎么花」

> 拆法样板。每个问题都按这个格式拆：**谁问 → 想要什么答案 → 思维链（查到什么→算出什么→推出什么）→ 输出样张 → 数据可得性 → 坑**。

## 一、谁在问、问的是谁

- 角色：供电所所长（也可能是县公司领导替他问）
- 对象：本所（一个供电所）
- 场合：年中/年末看到执行率低、被催进度时
- 原话大概是：「我们钱还剩这么多，该怎么花」「剩下的怎么安排」

## 二、想要什么答案（一句话）

**不是一个"要注意什么"的清单**，而是一份**能直接执行的用钱方案**：
这 X 万元 → 投哪 2~3 个方向、各多少 → 具体立哪几个项目、各多少钱 → 做完哪个指标会变成什么样。

## 三、思维链（每步：查什么 → 算出什么 → 为什么）

**第 1 步 · 确定"还剩多少、剩多久"**
- 查：`t_power_company_budget_result`（本所 + 当年 + deleted_flag=0）→ 分配额
- 查：`t_power_work_order`（本所 + 当年 + 状态 3/6/7）→ 已审批预算合计
- 算：剩余 = 分配 − 已审批；剩余月数 = 12 − 已过月数（今天 9 月 → 剩约 3 个月）
- 得出：**剩 X 万、剩 N 个月 → 每月至少要花 X/N**
- ⚠️ 只到这里就写"每月要花 50 万"＝没做完（这就是我前几轮犯的错）

**第 2 步 · 判"按现在的节奏能不能花完"**
- 查：`t_power_work_order` 当年本所项目数 → 月均立项数 = 项目数 ÷ 已过月数
- 查：当年本所单项目金额的**中位数**（不用均值，均值会被大项目拉飞）
- 算：需要几个项目 = 剩余 ÷ 单项目中位；还能做几个 = 月均立项数 × 剩余月数
- 得出：**差几个项目 / 差在哪一环**（下面三条支路）
  · 项目数不够 → 储备不足（去 `t_power_area` 找高损台区、频繁跳闸线路、低电压台区）
  · 项目够但没批 → 卡审批（去 `t_power_work_order_status` 看卡在哪个节点、卡多久）
  · 批了没完工 → 推施工（去 `t_power_work_order_status` 看施工阶段停留）

**第 3 步 · 找"这钱最该投哪几个方向"**
- 查：`t_power_ai_metric_snapshot`（本所 + yearToDate + 六项指标本期值）
- 查：`t_power_ai_metric_comparison`（本所同比；**这一档没值就退到年度的 2025 vs 2024**，写明用哪一档）
- 对照：全市 / 同类所的本期值 → 算**偏重度**（高出多少、排第几）
- 查（可选）：`t_power_company_budget_profile`（本所线路/台区/用户/线损/停电画像，判断"欠在哪"）
- 得出：**最该治的 2~3 个方向**（如线损、停电时长、跳闸），并说清每个方向现在差多少

**第 4 步 · 算"每个方向要多少钱"**
- 查：`t_power_work_order` 往年本所/同类，按 `defect_type` 分组 → 各方向的**单项目金额分布（最低/中位/最高）**和一年能做几个
- 算：方向 A 要治到什么程度 × 单价 → 需要多少个项目、多少钱
- 得出：**每个方向的预算区间**（不是拍脑袋给个比例）

**第 5 步 · 分配这 X 万**
- 规则：**短板越重、见效越快的方向先投**；单方向的钱不超过"该方向往年的单项目金额 × 可做项目数"
- 算：把剩余 X 万按第 3、4 步的权重切分 → 如「线损 25 万 / 停电 15 万 / 机动 8 万」
- 得出：**明确到金额的分配**

**第 6 步 · 落到具体项目**
- 查：`t_power_work_order` 现有储备（草稿/提交审核的）里能治这些方向的有哪些
- 查：不够就从 `t_power_area`（高损/低电压/频繁跳闸台区）+ `t_power_line` 里挑对象
- 排：目标匹配度 → 金额（小的往后排便于凑满）
- 得出：**立哪几个项目、每个多少钱、治哪个台区/线路**

**第 7 步 · 校验（不做这步就会给人一份不能执行的方案）**
- 是否超可用余额；剩余月数是否做得完（施工周期）；有没有一个方向投过头（边际效益递减）
- 查：`t_power_work_order_status` 看同类项目从立项到完工实际要多久 → 判断"剩 3 个月来得及吗"
- 得出：**调整后的最终方案**

**第 8 步 · 说清做完会怎样**
- 把方案里的项目和它要改善的指标挂上：投完预计线损率/停电时长会降到什么水平（参照往年同类项目做完后的变化）
- 得出：**预计效果**（能算就算，算不了就写"按往年同类项目推算"）

## 四、回答要出现什么（**回答模板由提示词控制；这里只定"必须出现什么"**）

一份合格的回答是**三段**，**不是把每个方向该花多少钱摊成一张表**（金额是内部推算，不是给人看的重点）：

1. **重点**：还剩多少、剩多久、按现在的节奏差多远 —— 一两句说清。
2. **为什么是这几个方向**：要带"**根据以往数据分析**"的依据 —— 这几个方向现在差在哪（跟全市比、跟去年同期比）、**往常投过同类方向之后是改善还是没动**。
   （是"为什么先投线损"的原因，不是"线损分 25 万"的数字）
3. **花完预计提升到什么程度**：按往年同类项目做完后的变化，推算哪个指标会变成多少。

**不写的**：把内部推算的金额分配表直接摊出来；也不要只写"要注意线损、停电"这种没有依据的清单。

## 四·附 输出样张（**只是示例，回答不固定**）

> 环潭所还剩 48.20 万、剩 3 个月，要花完每月得批 16.07 万。按现在的立项节奏（月均 1 个、单项目 6.12 万）只做得完 3 个、约 18 万，**差 30 万，卡在没项目可报**。
> 建议这 48.20 万这样用：
> ① 线损治理 25 万（线损 3.65%，全市 2.61%，排全市第 2；去年同期 3.90% 一直没降）→ 从高损台区里挑 4 个，参考往年台区线损类单项目 6 万左右；
> ② 停电时长治理 15 万（6.60 小时/户，全市 1.93，全公司最高）→ 挑跳闸最频的 2 条线路换开关、换缆；
> ③ 留 8 万机动。
> 按往年同类项目施工周期，3 个月能做完前两批；做完预计线损率可降到 3.3% 左右。

## 五、数据可得性（实测，写方案前必须确认）

| 要用的数 | 在哪 | 状态 |
|---|---|---|
| 分配额 | t_power_company_budget_result（所+年+deleted_flag=0） | ✅ 一所一年 1 行 |
| 已审批预算 | t_power_work_order（状态 3/6/7） | ✅ |
| 实际投入 | **t_power_work_cost.reality_total_price** | ⚠️ 字段有，有值率**没测**，要先测 |
| 单项目金额分布 | t_power_work_order.budget_total | ✅ |
| 六项指标本期 | t_power_ai_metric_snapshot | ✅ 三级 scope 都有 |
| 同期 | t_power_ai_metric_comparison | ⚠️ 当期那一档常空 → 退年度同比 |
| 年度成效+增减 | t_governance_effectiveness | ✅ 15 行（县公司×年） |
| 停留/流转 | **t_power_work_order_status** | ✅ 34458 行，有状态+节点+时间 |
| 施工周期 | t_power_work_order_status（同状态流转） | ✅ 可算 |
| 高损/低电压台区 | t_power_area / t_power_company_budget_profile | ✅ |

## 六、坑（拆的时候必须知道）

1. **别停在"每月要花多少"**——那是中间量，不是答案。
2. **不要用均值**估单价，用中位数。
3. **"实际投入"在 t_power_work_cost 里**，不要因为工单表的 reality_total 空就说没有；但也要先测有值率，别拿零星几条当全部。
4. 同期那一档常空 → 走降级链（当期同比 → 年度同比 → 与全市横向）。
5. 分配额有多版本 → 只取 deleted_flag=0 的那一行。
