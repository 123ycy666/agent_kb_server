## 1 调试：一趟问答要能倒查到"哪一步判断错了"

现在答错时看不到原因：模型收到什么、调了哪只工具、SQL 是谁放行的，全在日志里翻不到。定稿 H15.2 原本就有「运行步骤可展开」，上一轮把它连同四件套一起撤了。

**问答页**：每轮答案下面一行摘要（依据 · 自检 · 数字来源 ▾），点开是本轮运行步骤。每一步一行，展开后必须给出四样：

| 步骤类型 | 必须能看到 |
|---|---|
| 分流 | 判成问数还是干活、命中哪条判据（判据原文 + 来自全局还是个人） |
| 检索 | 检索词、命中文档名、目录、相关度；个人池与通用池各命中几条 |
| 调工具 | 工具名、参数、返回原文、耗时 |
| 跑 SQL | SQL 原文、命中了哪张契约表、口径有没有管到它、返回行数、被哪道闸放行 |
| 自检 | 逐条结论 + 依据 |

「被哪道闸放行」是这一条的关键：现在 `run_sql` 不校验表名，`semantic.allowed_tables()` 又把整库并进白名单，所以模型查了口径外的表也没人拦。页面上要直接写「未经口径校验，由 ALLOWED_TABLES 放行」，让问题一眼可见，而不是等人去读代码。

**判据 D1**：任取一轮问答，三次点击内能指到出错的那一步，并看到该步的完整输入输出。

## 2 提示词页：一个页、两个页签、每行能改能试

页名「提示词」，页签「干活线 / 问数线」。页面回答的问题不是"我们一共有几段文本"，是"**这一项现在生效的是什么、谁给的、能不能改**"。

每行固定四列 + 一个动作：

| 列 | 内容 |
|---|---|
| 项 | 身份 / 口吻 / 红线 / 优先级 / 工具说明 / 数字纪律 / 口径材料 / 预处理规则 / 补全规则 / 说明书目录行 … |
| 生效值 | 当前真正在用的内容（不是库里存了什么，是**截断和兜底之后**的）；字数由系统算 |
| 来源 | `全局` / `个人（覆盖中）` / `代码·只读` |
| 在哪改 | 本页可改的直接给编辑；代码只读的给文件位置 |
| 动作 | `展开原文` · `试跑` |

- **只读项不删**：装配顺序、7 只工具的参数 schema、`KIND_HINT`、`DEFAULT_CHECK`、`spec.FOUR`、问数系统提示词、安全闸都在，折叠在「模型实际收到的原文」里，默认不展开。
- **说明书只出目录行**：模型每轮看到的是 5 行目录（名称·什么时候用·产物），正文是命中后才由工具读进来的，属于问答页的运行步骤。知识库资料同理不进这页。
- **字数只在一个地方有用**：被预算截断。所以不显示"6000 字上限"，只在某段真被截时标「已截掉 X%」。现在五段里四段是空，预算从未触发，这个配置项先不给人填。
- **试跑**：改完用同一条问句重跑，左旧右新并排。没这个动作，这页就只是文档站。

**判据 D2**：改一处库里的配置 → 下一轮该段生效值变化；同一句重跑能并排看到改前改后。
**判据 D3**：页面上列出的项，与代码里实际影响回答的项一一对得上，漏一项算不通过。

## 3 配置的作用域：全局一套，个人可覆盖

**不同的人配自己的问数。** 不做层级、不做角色，只有两级。

一张表：`作用域类型`（`global` / `user`）+ `作用域值`（用户 id，global 为空）+ `键` + `值` + `改的人` + `改的时间`。
生效规则：同一个键，有个人就取个人，没有就往上取全局。

首批开放的键：身份、口吻、红线、优先级、工具说明、数字纪律、口径材料、预处理规则、补全规则。

不动的：纠错词典 6 张表、指标口径、字典覆盖层、安全闸、可查表清单——这几样要么是大表，要么是安全约束，保持全局或代码。**要扩，是往 `作用域类型` 里加一个值，不改代码。**

页面上每行显示「来源：全局（被个人覆盖）」，并给「恢复继承」。

**判据 D4**：个人改「口吻」，只影响他自己；管理员改全局，没被覆盖的人下一轮跟着变。
**判据 D5**：作用域只出现在上表那 9 个键上，别的配置表没有作用域列。

## 4 库结构页：配置到底落没落库

一级页「库结构」，读 `information_schema`，不读配置文件。

- 左栏四组 `kb / cfg / qa / base`：表名 · 行数 · 有无页面入口（无入口标红）。
- 右栏点表：字段清单（名 / 类型 / 可空 / 默认 / 注释）+ 前 20 行真实数据，只读。
- **从提示词页每行点「看库里这行」跳过来**，定位到表、行、值。这是它和 DBeaver 的区别：入口是"我刚改的那一项存哪儿了"。

**判据 D6**：标红（无页面入口）的表数量为 0。定稿 H14.2 的兜底就靠这个数。
