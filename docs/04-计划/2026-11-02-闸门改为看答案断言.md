# 实施：核实闸改成「看答案断言」，工具不再由模式词表决定

日期：2026-11-02
来源：内网测试三个问题（`测试.txt`）——「全市 / 2025年全市情况 / 7月整体情况」全都没查库，
两个答「数据缺失」直接放行，一个写数字被拦成「未核实不予作答」。

## 目标

1. 判不出类型的问句按**查数**处理（给工具、给表目录），不再落 general 闭嘴。
2. 闸门只看**答案侧**：答案里有没有「没有工具结果支撑的具体断言」，不看问题里有没有业务词。
3. 触发提醒时**同时把工具补上**，杜绝「叫它查却没给工具」的死循环。

## 根因

**复现**：本地跑 `modes.judge()`

```
'全市情况怎么样'       -> general | 没命中规则 → 通用模式（自由作答）
'2025年全市情况怎么样' -> general | 没命中规则 → 通用模式（自由作答）
'2026年7月整体情况'    -> general | 没命中规则 → 通用模式（自由作答）
'两水供电所情况怎么样' -> data    | 含业务对象（没问数词也要查）→ 先查再答
```

**证据**：

- `agent_v2.use_tools('general')` = `mode != 'general'` → False → 整轮不传 `tools`，
  模型只能凭空写；它写的「快照表中均无记录」里的"快照表"是从注入的取数材料里抄的词。
- `agent.py:1371` 放行条件是 `not _CLAIM.search(answer)`；实测
  `_CLAIM("…数据缺失，无法作答。") = False` → 当通用问答放行（`unverified=false`）；
  `_CLAIM("全市共分配预算2536.73万元…") = True` → 要求核实 → 拦下。
  **同一句话，写不写数字决定结局**，与问题该不该查库无关。
- `modes.judge` 判"要不要查数"靠问题侧词表，而"全市/全县/全公司/啥情况/怎么样/好不好"
  这类说法是开集，实测 10 种同义问法 9 种落 general —— 补词表补不完。

**为什么**：把"能不能查库"和"要不要查库"都交给了问题侧词表。模式词表的职责是
**选哪套提示词材料**（有界、判错代价小）；现在它还管**有没有工具**（判错代价是闭嘴或编），
两件事混在一个开关上。

## 不改什么

- 不改 `preprocess`（补全/纠错的粗闸）——那是另一件事，它的失败代价是多补一次，不影响本修。
- 不改四份规则材料、不改 `prompt_text` / `prompt_material` 表结构。
- 不删 `_BIZ` 定义（`_apply_pack_lexicon` 还要覆盖它），只是不再拿它当闸门。
- 不动 `_final_answer` / `_swap_materials` / 步数预算。

## 验收判据（本地跑，不连内网）

1. `tests/agent/test_evidence_gate.py` 全绿，覆盖极端条件：
   空答案、纯空白、只有标点、超长答案、"0 条"、只有表名没有数字、
   "数据缺失/无记录/查无/暂无异常"、纯写作无断言、数字 + 单位各种写法、
   `mode` 三态 × `nudged` 两态 × `used_tool` 两态的笛卡尔积。
2. 判模式：`全市情况怎么样` / `全市整体情况` / `全市啥情况` / `说说全市` 必须落 `data`；
   `你好` / `谢谢` / `什么叫线损` / `帮我把这份材料写成汇报` / `做个PPT汇报` 保持不变。
3. 状态机模拟：把内网三条真实 trace 的形态喂进 `decide()`，输出必须是
   `nudge → (带工具) → 有工具结果 → pass`，不能出现「nudge 后仍无工具 → block」。
4. 老测试 `test_prompt_stack.py` 的判模式用例仍然通过（五条）。

### 循环级场景（假模型驱动 `agent.ask()`，不连库不连模型）

1. 内网第 2 条重放：先答「数据缺失」→ 必须 nudge → 查到数 → 正文出答案。
2. 判成 general 的问句写了数字 → nudge 且 **把 tools 补上**（第一次调用没工具、第二次有）。
3. 模型死活不查、两次都给断言 → 恰好 2 次模型调用后 block（不死循环）。
4. 纯问候 → 一次放行，不 nudge。
5. 空正文 → 不许把空白交给领导，另起一次要正文。
