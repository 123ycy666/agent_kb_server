# 实施计划 · 问数两段式 + 大屏问数页（2026-11-19）

## 1 目标

1. 让问数线重新查库：作答规则不再进工具循环，循环结束后单独一次模型调用产出正文。
2. 提示词页编辑抽屉删掉「现在注入的原文」块（与上面的编辑器重复）。
3. 新增一页「大屏问数」（侧栏第二位，路由 `/screen`）：三栏照对话页，只接 `POST /api/ask/data`，没有上传、没有文件、没有产物，用来单独测大屏那条只查数的链路。

## 2 根因

`agent_v2.system()` 把 `cfg.prompt_material` 的 fetch（查数口径）与 answer（作答规则）拼进同一个 system，
`prompt_material.block()` 按 slots 顺序拼，作答规则永远落在 system 末尾。作答规则开头是
「你的任务：基于已执行的 SQL 结果，或用户的通用提问，生成给前端展示的中文回答」，末尾是
「如果用户问题与业务无关，也可以直接用简短通用回复，不要拒答」——模型读到最后一段的**出答案声明**，
第一轮就不发 `tool_calls`，循环直接 break，给出编造的数值。

线上证据（2026-11-19 交接）：sandbox system 825 字时 44 轮有 41 轮带 SQL；装上作答规则后 system 1407 字，
07:10 / 07:11 / 07:22 四轮 SQL 全为 0。

## 3 改哪几个文件

| 文件 | 改什么 |
|---|---|
| `server/app/secretary/agent_v2.py` | `system()` 只装 fetch（`index_slots=('fetch','answer')` 保持清单不变）；新增 `answer_rules()` |
| `server/app/secretary/agent.py` | 循环结束加整理段：`system=作答规则`、`user=【本轮查到的结果】+循环正文`、`use_tools=False`、`think=False`，正文非空才替换；trace 记 `compose` 步 |
| `web/src/pages/Prompts.tsx` | 抽屉删「现在注入的原文」块（含 `body`/`tick` 状态与 `impactBody` 拉取） |
| `web/src/pages/ScreenAsk.tsx` | 新建：大屏问数页（会话列表 / 对话 / 运行步骤），只调 `/api/ask/data` + `/api/ask/progress` + `/api/sessions` + `/api/history` |
| `web/src/App.tsx` | 加 `path="screen"` |
| `web/src/layouts/MainLayout.tsx` | NAV 在 `/chat` 后面加 `/screen`「大屏问数」 |

整理段为什么只改写、不重读工具结果：实测让整理段自己从十几条 tool 结果里重读，
一次把「缺陷库项目（状态2、未完工）」读成「已完工」，另有若干次返回空正文（`reasoning_content` 有、`content` 空），
空正文时回落到循环草稿就成了 Markdown 表格，违反作答规则。改成「事实由循环给、只改口吻」后两种毛病都消失。

## 4 验收判据（每条可判真假）

1. `agent_v2.system()` 的返回值里不再出现「你的任务：基于已执行的SQL结果」；字数从 10309 降到 9727。
2. 问「2026年10月全市有多少个供电所」：`sql_query_count >= 1`，trace 的 kind 序列末尾有 `compose`，正文是纯文本且年份月份与 SQL 一致。
3. 问「两水供电所情况怎么样」：正文不含 `#`、`|`、`**` 表格符号，且「未完工 / 缺陷库项目」与 SQL 结果一致。
4. 作答规则为空时（随州配置）：不调整理段，行为与现在一致（`rules` 为空串直接跳过）。
   用户点了停止、或步数到顶走了 `_final_answer` 兜底时也不调整理段（判据：循环最后一步的 kind 是 `answer` 才调）。
5. `/prompts` 抽屉里搜不到「现在注入的原文」；`npm run build` 通过。
6. 侧栏第二项是「大屏问数」，点开是三栏；发一问能出正文且右栏有 `run_sql` 与 `compose` 两步；页面上没有任何上传入口。
