# 后台重构 · 需求定稿（2026-11-19）

> 这份是给下一个会话直接开工用的需求文档：需求已由 Fred 逐条确认，不再重新收集。
> 设计与调研放在最后「依据」一节，开工前读一遍就够，别重新发明。

## 1 目标

把现在这个不成套的后台，重做成一个标准的智能体后台：左侧九项菜单、页内标签页、三种页面模板；九页一期全做完，不留空壳。

现状问题（已实测）：能打开的只有八页；另有十一页写了没入口，其中预警规则、材料库这些是真在用的功能；技能没有管理界面；旧「干活线」页签还挂着；页面里塞满「用途说明」，观感像十年前的后台。

## 2 用户与权限

能进后台的都是干活的人：看运行逻辑、改配置、加技能，一律能做。**不设角色分级，不做权限配置页。**

## 3 信息架构（九项，一期全做）

```
概览  对话  智能体  技能  知识库  提示词  预警  任务  设置
```

「记录」并进「对话」：历史会话就在对话左侧翻，不再单开一页。

### 3.1 概览 `/home`

四个数字 + 一张最近会话表，不加图表。

- 数字：今日轮次、失败数、预警条数、待办事项。数据：`/api/stats`、`/api/alerts/daily`、`/api/workflows/items/overview`。
- 表：最近 10 个会话（标题、更新时间），点一行进对话。数据：`/api/agent/sessions`。

### 3.2 对话 `/chat`（现有页面，只调视觉）

- 三栏不动：左会话说、中消息、右运行步骤。
- 删掉顶部那句「一句话交代，它自己决定读什么、查什么、出什么」；模型名做成灰色小标签。
- 左栏加搜索框；原「记录」页的能力并进来——点会话即看历史，每轮的问答与工具轨迹在右栏看。

### 3.3 智能体 `/agent`

Tabs：身份与风格 │ 技能 │ 工具 │ 模型

| 块 | 内容 | 接口 |
|---|---|---|
| 身份 | 只读展示 + 「去提示词页改」链接 | `GET /api/agent/config` |
| 回答风格 | 多行输入，保存即生效 | `PUT /api/agent/config`（键 `agent_style`） |
| 技能 | 三选一（全开/只给指定/全关）+ 多选 + 「新建技能」入口 | `agent_skills`、`/api/v1/specs` |
| 工具 | 九行开关，每行显示中文名、真实工具名、「什么时候别用」（只读） | `agent_tools` |
| 模型 | 模型名、步数、上下文预算、压缩阈值（只读展示 + 跳设置） | `GET /api/agent/config`、`/api/models` |

### 3.4 技能 `/skills`（新页，技能管理）

列表页。列：名称、什么时候用、产物、状态（草稿/已发布/已退役）、更新时间、操作。

- 新建/编辑走右侧抽屉：名称、什么时候用、适用、产物、正文（大文本框）、检查项（多行）。
- 抽屉底部：`保存草稿`、`发布`；列表行操作：`编辑`、`退役`。
- 接口：`/api/v1/specs`（list / get / upload / classify / publish / retire）。

### 3.5 知识库 `/kb`

Tabs：文档 │ 库 │ 检索测试

- 文档：列表（文件名、类型、切片数、可见性、解析状态、更新时间），行操作「看切片」；上传接受 pdf/docx/xlsx/md/txt/csv。
- 库：五个库（名称、文档数、切片数、是否参与检索、创建时间），只读。
- 检索测试：输入框 + 检索；结果列（文档名、相似度、片段）。

### 3.6 提示词 `/prompts`

Tabs：问数线 │ 智能体。**删掉「干活线」页签。**

- 问数线：口径材料、作答规则、补问法、问题确定，四行，每行「编辑」开抽屉。数据：`/api/prompts/impact`、`prompt_material`、`prompt_text`。
- 智能体：一条跳转链接「身份与风格在智能体页改」。

### 3.7 预警 `/alerts`

Tabs：规则 │ 记录。**这期只做页面与列表，规则逻辑一行不改。**

- 规则：规则文档列表（名称、版本、最近改动、操作「编辑 / 试跑 / 导出」），编辑复用现有能力。接口：`/api/workflows/docs`（含 dry-run、export、import、versions）。
- 记录：`/api/workflows/notifications`、`/api/alerts/daily`。

### 3.8 任务 `/tasks`

- 事项列表：`/api/workflows/items`（含 `overview`、`close`、`chat`）。
- 运行记录：`/api/workflows/runs`、`/api/workflows/runs/{id}`。
- 调度：`/api/workflows/schedules`（只读展示）。

### 3.9 设置 `/settings`

Tabs：模型与端点 │ 员工源 │ 存储 │ 外观

- 模型：`/api/v1/models/config`、`/api/models`，连通测试 `/api/v1/models/test`。
- 员工源：MySQL 地址与表名、连通状态（只读）。
- 存储：上传目录、产物目录（只读）。
- 外观：侧栏深浅、字号（两三个选项）。

## 4 交互与版式规矩

- 左侧栏固定 220，九项铺开，不分组、不折叠。
- 页面标题行只有「标题 + 右侧主操作」，**全站不写用途说明段落**（现在那种「每一项都显示在哪、多大、能不能改」一律删）。
- 页内只一层 Tabs，不套二层；最多一层卡片。
- 标签页与筛选写进 URL（`?tab=skills`），刷新不丢。
- 危险操作（删除、退役）二次确认。
- 空态：一句「还没有技能」+ 一个「新建」按钮，不写解释。
- 按钮文案是动词（保存 / 发布 / 新建技能），不用「提交」；保存成功提示与按钮同名。

## 5 视觉令牌（一次配到 antd theme）

| 项 | 值 |
|---|---|
| 主色 | `#1677ff`（不另造品牌色） |
| 侧栏底色 / 选中 | `#001529` / `#1677ff` |
| 页面底 / 卡片底 | `#f5f7fa` / `#ffffff` |
| 圆角 | 卡片 8，按钮与输入 6，标签 4 |
| 间距 | 4 的倍数；区块间 16，区块内 12，表格行高 40 |
| 字号 | 页标题 20/600，区块标题 14/600，正文 13，辅助 12 |
| 表格 | 表头 `#fafafa`，关斑马纹，数字列 `tabular-nums` |

可用性硬要求（来自 Web Interface Guidelines）：图标按钮必须有 `aria-label`；表单控件必须有 label；交互元素必须有可见焦点环，不许 `outline: none`；长文本截断加悬停全文；加载态以 `…` 结尾。

## 7 硬边界

- 问数线代码一行不动。
- 预警与规则的**逻辑**不动，只做页面与列表。
- 技术栈不变：React 18 + antd 5 + `@ant-design/x`。
- 对话页的消息 part、SSE 事件契约、右栏观测树不动（那是刚做完的）。

## 8 验收判据（每条可判真假）

1. 九个菜单项都能点开，没有 404。
2. 登录后落在 `/chat`。
3. 全站搜不到「用途说明」类段落（标题行只有标题与主操作）。
4. 智能体页改回答风格 → 保存 → 下一轮回答形态变化。
5. 技能页新建一篇并发布 → 对话里说对应的活，它会 `read_skill` 并照做。
6. 技能页退役后，技能目录里不再出现。
7. 知识库「检索测试」输入「安全生产」有命中片段。
8. 提示词页只有两个页签，没有「干活线」。
9. 第 6 节的七页在代码里删掉，`grep` 无引用。
10. 任务页能列出事项与最近运行，不报错。
11. 预警页能列出规则文档，能进编辑（逻辑与现在一致）。
12. 抽查三个页面：图标按钮有 `aria-label`、焦点可见、危险操作二次确认。
