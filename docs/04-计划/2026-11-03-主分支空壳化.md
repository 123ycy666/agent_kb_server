# 主分支空壳化 + 规则测试分支（2026-11-03）

## 目标

主分支（`main`）做成**空壳**：部署后只有默认提示词、业务词表、纠错词典、时间地点规则（改过的）、数据库字段说明，**不预设任何业务规则**。
规则测试放 `online` 分支（线上专属），规则原样保留、可以随时恢复；测试要用的规则文档在那条分支上重来。

同时按 Fred 的要求改三处行为：

1. 时间地点规则：本轮没说时间、上一轮也没有 → 默认补**上一个月**（当前 11 月 → 补 10 月）。
2. 业务词表：命中的是「不查库就能答」的那几类词（寒暄 / 问概念 / 出文件 / 写作）→ 走正常聊天、处理文件，**不纠错、不补全**。
3. 业务相关的问题词表删除：**没命中上面那些词 → 一律算业务问题**，走补全 + 纠错流程。

加上删除清单（原文已备份，见下）：补全表、查数口径、判定标准、文档/作答规则、汇报口吻、自检清单。

## 边界

- 不动：业务词表**内容**（`keywords` 里除 `business_topics` 外的词条）、纠错词典（`t_nc_*`）、数据库字段说明（`semantic`）、页面可改词表那套未提交功能（Fred 确认保留）。
- 不动：`online` 分支上的规则内容 —— 本次只做代码侧开关与链路裁剪，规则原文一份不动。
- 不碰生产库数据（本地 PG 5433 未启动，只做代码层与文档层）。

## 验收判据

1. `prompt_tree.tree()` 里节点 4 无补全表、节点 7 无查数口径、节点 9 无判定标准、节点 10 无作答规则与汇报口吻、节点 11 无自检清单（改前 → 改后对比贴输出）。
2. 装配出来的 system 里没有「S4 作答格式」「规则材料」两段（改前有 → 改后无）。
3. `time_scope.resolve('情况怎么样', today=2026-11-05)` → `2026年10月` / `202610`。
4. `preprocess.gate('两水')` → True（当业务问题）；`gate('你好')` / `gate('帮我写个通知')` / `gate('做个PPT')` → False。
5. `modes.judge('台区线损情况')['mode']` → data；`business_topics` 不再参与判定（grep 不到读取点）。
6. `docs/08-历史归档/2026-11-03-删除的提示词规则/` 下 5 份原文 + README 齐全，能按 README 恢复。
7. `git branch` 里同时有 `main`（空壳）和 `online`（规则原样），两个分支都已推送，`git log --oneline` 能看到分叉点。

## 根因

不是"规则写得不对"，是**规则和部署形态混在一条分支里**：同一套代码既当线上（带 60 条判据）又当测试环境（要空壳），
于是删规则只能靠"记得别跑导入脚本"，下次部署又回来了。改成"代码里有开关 + 规则内容走分支"，空壳才是可复现的。
另外业务问题的识别原来是**开集词表**（`_BIZ` 29 个词），补不完；反过来用闭集（直通词）判，漏判就落到"业务"，代价是对多补一句。
