## 1 引言

### 1.1 目的

规定"一套骨架服务多个现场"这一改造要达成的行为、接口与数据要求，并给出可判定通过与否的验收方法。

### 1.2 范围

本产品交付一个骨架。**一个现场 = 一个 PostgreSQL 库**：现场的业务规则、口径、知识库、工作流、词典、示例问题全部存在该库中。代码里不含任何现场业务内容。新现场接入 = 建库 → 在「现场配置」页填连接 → 登录 → 配置业务内容。

不含：部署与域名（另一份规格）；宜昌/第三个现场的具体业务内容；大屏问数与干活线的新功能。

### 1.3 读者与用途

开发按第 3 节实现；测试按第 4 节判 pass/fail；验收方按第 5 节追溯。

### 1.5 术语

| 术语 | 定义 |
|---|---|
| 骨架 | 所有现场共用的代码与前端产物，彼此完全一致 |
| 现场 | 一个客户单位的一个部署实例，由它连的 PG 库唯一确定 |
| 引导配置 | 服务启动前必须可读的本地文件，含当前现场的 PG 连接与初始管理员 |
| 系统账号 | 供外部系统调用接口的令牌身份，不经页面登录 |
| 业务配置 | 可在后台页面修改、且每个现场不同的内容，一律存在该现场的 PG 库里 |

## 2 总体描述

### 2.1 产品前景

现状是单现场产品：随州一套代码、一个库，现场名、身份、示例问题还散落在代码常量里。改造后代码与现场解耦，同一份产物可服务任意多个现场。

### 2.2 产品功能概览

对话、问数（SQL 工具循环）、大屏问数、干活线、知识库、提示词管理、工作流文档、词典、指标口径、系统管理。

### 2.3 用户特征

- **实施人员**：新现场接入时在「现场配置」页填三条连接。
- **业务管理员**：在后台页面维护提示词、口径、词典、知识库、示例问题。
- **终端用户**：登录后使用对话与问数。
- **外部系统**：凭系统账号调用预警等接口，无页面。

### 2.4 运行环境

Python 服务 + PostgreSQL（本产品库）+ 业务 MySQL（问数数据源）+ 模型网关。前端为浏览器单页应用。

### 2.5 约束

- C-01 服务启动前必须先能连上 PG 库；连不上则该实例不可用，只提供「现场配置」页。
- C-02 一个实例同一时刻只服务一个现场。
- C-03 现有对外接口路径与请求格式不变。

### 2.6 假设与依赖

- A-01 每个现场有独立可写的 PG 库。
- A-02 各现场的业务库（MySQL）可被该实例访问。
- A-03 模型网关可达。

## 3 具体需求

每条需求含：编号、陈述、验证方法（检验/分析/演示/测试）、验收判据。验收判据见第 4 节。

### 3.1 功能需求（FR）

| 编号 | 需求陈述 | 验证方法 |
|---|---|---|
| FR-BOOT-001 | 服务启动时从引导配置读取当前现场的 PG 连接与初始管理员。读取不到或连接失败时，本实例只对外提供「现场配置」页，其余页面与业务接口返回不可用状态。 | 测试 |
| FR-CFG-001 | 「现场配置」页可填写 PG 连接（主机、端口、库名、用户、口令）与初始管理员（账号、口令），并提供连通性测试。该页在未配置或连接失败时不要求登录。 | 测试 |
| FR-CFG-002 | 保存配置后立即重连新库；初始管理员在该库不存在时创建，已存在时跳过，不覆盖已有口令。 | 测试 |
| FR-CFG-003 | 「现场配置」页可填写业务库（MySQL）连接与模型通道（网关地址、API Key、模型名），二者均提供连通性测试。连接信息存当前 PG 库。 | 测试 |
| FR-LOGIN-001 | 页面登录的账号与口令取自当前 PG 库的 `base` 片；JWT 签发密钥随当前现场，切换现场后旧 token 全部失效并要求重新登录。 | 测试 |
| FR-SYS-001 | 系统账号：请求头 `X-Internal-Token` 校验令牌值；令牌挂在服务上（全局一个），不参与页面登录，切换现场后仍然有效。覆盖 `/api/alerts/*`、`/api/internal/*` 及给 sga 换取 token 的入口。 | 测试 |
| FR-EMPTY-001 | 空库（无任何业务配置）启动后：可登录、后台各菜单页可打开、业务内容为空；问数不返回具体数字，明确提示该现场尚未配置。 | 测试 |
| FR-MIGR-001 | 按附录 B「移库」清单把业务内容迁入当前 PG 库；读不到时返回空，不回落源现场内容。重复副本（默认身份两份、示例问题两份）合并为一份。 | 检验 |
| FR-MIGR-002 | 纠错词表（单位类型、台区类型、业务停用词、`strip_head`、业务分类映射）由当前 PG 库的词典表驱动；匹配算法留在代码，不得内置业务词。 | 检验 |
| FR-PACK-001 | 现场的业务配置全部来自当前 PG 库的 `cfg` 与 `kb` 两片；新现场起步 = 把源现场的 `cfg.*` 与 `kb.*` 灌入目标库。 | 演示 |

### 3.2 界面需求（UI，前端变化）

| 编号 | 需求陈述 |
|---|---|
| UI-001 | 新增页面「现场配置」，含三条连接的表单、连通性测试按钮、保存并重连。 |
| UI-002 | 未配置或连接失败时，前端只呈现「现场配置」页；登录页与业务页不出现。 |
| UI-003 | 除「现场配置」外，现有页面布局与交互不变；数据源随当前现场切换。 |
| UI-004 | 业务配置为空的页面显示统一空状态文案「该现场尚未配置」，不显示随州内容。 |
| UI-005 | 登录页不提供现场选择；现场由该实例连的库决定。 |

### 3.3 接口需求（IF）

| 编号 | 需求陈述 |
|---|---|
| IF-DB-001 | 产品库为 PostgreSQL。连接信息存于引导配置；它是现场的唯一标识。 |
| IF-DB-002 | 业务库为 MySQL，供问数探查与查询。连接信息存产品库，可在页面修改。 |
| IF-MODEL-001 | 模型通道由网关地址、API Key、模型名组成，存产品库，可在页面修改。 |
| IF-SYS-001 | 系统账号以请求头 `X-Internal-Token` 传递，令牌为 64 位十六进制，存服务配置（不进库），可轮换。 |
| IF-API-001 | 现有对外接口的路径、请求体、响应体保持不变。 |

### 3.4 数据需求（DR）

| 编号 | 需求陈述 |
|---|---|
| DR-001 | 一个现场 = 一个 PG 库，按用途分四片：`cfg`（页面可改的配置）、`kb`（知识库、做法库、词典）、`qa`（会话、消息、轨迹）、`base`（用户、偏好、审计）。 |
| DR-002 | 各页面的取数来源固定如下表，不得跨库拼读。 |
| DR-003 | 切换现场 = 换 PG 库；四片一并切换。 |
| DR-004 | 现场迁移只含 `cfg.*` 与 `kb.*`；`qa.*` 的会话历史与 `base.*` 的账号不随现场走。 |

**DR-002 页面取数来源**

| 页面 | 数据来源 |
|---|---|
| 提示词管理 | `cfg.prompt_material`、`cfg.prompt_text` |
| 指标口径 | `cfg.caliber_metric`、`cfg.caliber_base` |
| 分流判据 | `cfg.route_rule` |
| 补全表 | `cfg.complete_rule` |
| 词典 | `cfg.t_nc_*` |
| 知识库 / 做法库 | `kb.document`、`kb.spec` |
| 对话与历史 | `qa.t_chat_session`、`qa.t_chat_message` |
| 账号与偏好 | `base.t_user`、`base.t_user_pref` |
| 现场配置 | 引导配置（PG）与 `cfg.runtime`（业务库、模型通道） |

### 3.5 非功能需求（NFR）

| 编号 | 需求陈述 |
|---|---|
| NFR-001 | 现场切换只影响本实例，不影响其它现场运行中的实例。 |
| NFR-002 | 空库不得导致页面报错或接口 500。 |
| NFR-003 | 本次改造不得使随州现有功能退化。 |
| NFR-004 | 运行时路径不得出现具体现场名与单位名：随州、国网随州供电公司、随县、曾都、广水、高新、环潭、两水、厉山、淅河、万和、淮河、白鹤、龚家棚。驱动运行时行为的词表（单位类型、台区类型、业务停用词、`strip_head`、示例问题、业务分类映射）必须存库。API 文档示例与评测样例可用行业通用词，但不得出现上述单位名。 |

### 3.6 分类判据

页面上能改的，必须在库；页面上改不了、每个现场又一样的，是代码。

| 在库 | 在代码 |
|---|---|
| 查数口径、作答规则、身份与追问/确认提示词 | 工具循环、SQL 执行与守卫、提示词装配 |
| 分流判据、补全表、指标口径、纠错词典 | 工具说明、分流兜底词表、`skills/office` 脚本 |
| 知识库、做法库、示例问题、现场名 | 鉴权、会话、消息、后台页面框架 |
