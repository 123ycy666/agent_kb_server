# 实施：提示词材料增删改查的极限条件测试与修复

日期：2026-11-02
来源：Fred「之前做的这个文档 增删改查 各种极限条件 也都测测」。

## 目标

用**真 PostgreSQL**（`pgserver` 内嵌 16.2，本机起临时实例）把 `prompt_material` /
`prompt_text` / `complete_rule` 的增删改查打到极限，把"会丢数据"的地方堵死。

## 根因（已用真库实测，不是猜）

本机没有 PG 也没有 docker，但装了 `pgserver`（自带 Windows 版 PG 16.2 二进制）：
起临时实例 → 灌 DDL → 跑 43 项断言，**4 项不符合预期**：

### ① `pgdb` 的 INSERT 兼容层把 `prompt_text` 写死（页面保存永远失败）

```
[prompt_text] 保存失败：UndefinedColumn: column "id" does not exist
LINE 1: ...updated_at = now() RETURNING id
```

`pgdb._Cursor.execute` 对任何 `INSERT` 都自动追加 `RETURNING id`（为兼容 pymysql 的
`lastrowid`）。而 `prompt_text` 的主键是 `k`，**没有 id 列** → 每条 INSERT 都报错。
线上 `prompt_text` 至今 0 行、全用代码默认值，就是这条造成的 —— 页面上「身份 / 汇报口吻 /
模式做法 / 词表」四个覆盖项，点保存一直是失败的。

### ② `replace_slot` 没有事务 —— 整份覆盖中途失败会把原内容删掉一半

```
res={'error': '...NUL (0x00)...'} 行数=3 现存=['一', '二']     # 原「甲、乙」已没了
res={'error': "invalid literal for int(): '不是数字'"} 现存=['一']
```

`DELETE slot` 先执行、再逐行 INSERT，autocommit=True。第三行写不进去（正文含 NUL、
或 `sort_no` 传了非数字）时，**原内容已经删了、新内容只写了一半**。页面上一次保存就能
把一份规则材料变成残缺状态，而且提示只是"写入失败"。

### ③ `complete_rules.save` 同一个病 —— priority 传字符串就把整张补全表清空

同上：先 `DELETE FROM complete_rule` 再插入。`int('不是数字')` 抛异常时 DELETE 已提交。
更糟的是**缓存把破坏藏住了**：失败路径不调 `clear_cache`，`rows()` 继续返回旧缓存，
刷新页面看着"还是那些行"，实际库里已经空了。

### ④ `delete_section` 删不存在的 id 也报成功

`DELETE ... WHERE id=%s` 影响 0 行，代码不看 `rowcount`，直接返回 `{'ok': True}`。
页面删一条已被别人删掉的节，会显示"已删除"，实际什么也没发生。

## 不改什么

- 不动 `prompt_material` 的 `MARK` / `strip_block` 语义（正文里恰好含标记会被截断，是已知边界，
  测试里钉死现状，不在这里改）。
- 不动 API 路由路径与返回结构（前端 `Prompts.tsx` 已按现在的形状写）。
- 不动四份材料的业务内容。

## 验收判据

`server/tests/agent/test_prompt_crud.py`（起内嵌 PG，不需要外部数据库）全绿，覆盖：

| 组 | 极限条件 |
|---|---|
| 查 | 未知 slot / 大小写 / 必带与全部 / 清单 / 标记截断 / 空块 / summary |
| 增 | 空标题 / 未知 slot / 300 字标题截 160 / 100 万字符正文 / NUL 字符 / 重名 |
| 改 | 版本 +1 / 缓存立刻失效 / 不存在 id / 覆盖 / 全空正文被拒且原数据在 / **中途失败整体回滚** |
| 删 | 删一行 / 立刻生效 / **删不存在的 id 要报错** / 删光后 block 为空 |
| 文本 | 未知 key / 坏 JSON / **合法 JSON 真能存进 PG** / 空白等于没覆盖 / reset |
| 补全 | 空表提示 / 保存读回 / 空行丢弃 / **priority 非法整体回滚** |
