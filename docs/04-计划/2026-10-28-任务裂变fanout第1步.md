## 第六轮（Fred 2026-10-28 截图「这咋什么都问不出了」）：线上问答两处根因

**复现**（线上 47.121.183.81，SSO 换 JWT 后直接调 `/api/ask`）：

| 问法 | 结果 |
|---|---|
| `2025年两水所整体情况` | `answer=…未查得…没有记录`，`db_query_count=0 sql_query_count=0`、工具 0 次 |
| `2026年1-10月两水所工单有多少单` | 归一成 `2026年1-10**亮台区水**所工单…`，SQL 查的是 `power_area_name LIKE '月亮%'` → 答"月亮台区缺陷工单 2 单"（问的却是两水所） |

**根因 1（问题被改坏）**：`name_corrector._resolve_spans` 的裸地名滑窗会从「10月」的中间起头，
切出 `月两`，前缀/同音撞上台区「月亮台区」→「地名层归一」把整段改成「月亮台区水所」。
时间词没有任何保护，凡是「…月两水所…」这类说法都会被改坏（本地可复现，与部署无关）。
修法：`DATE_SPAN`（`\d+\s*[年月日号]`）标记时间词区间，滑窗起点落在里面就跳过。

**根因 2（业务问题根本不查库）**：`modes.judge` 只有命中「问数词」或「要写材料+业务词」才判 data，
`整体情况 / 怎么样 / 情况如何` 这类**只提业务对象、没有问数词**的问法落到 `general`；
`general` 模式 `use_tools=False` → 一个工具都不给 → 模型只能凭提示词编，L3「查到 0 行就是答案」
把它们写成"库里没有记录"。修法：命中业务对象词就走 data（先查再答）；另加 `explain` 词表，
问概念/定义（"解释一下什么叫线损"）仍走 general。

## 根因（本步改 dispatch_service.py 的依据）

裂变没做成的原因不是"缺个循环"，而是**每个目标要有自己那条预警**：
父任务 `verify_rule` 是全市 47 个所，直接复制给子任务 → 所长被要求对全市负责，
数据永远不达标。所以子任务的 `alert_id / verify_rule / scope_* / biz_*` 必须
**按目标自己的范围反查预警**，查不到就退 `manual`，不许继承父的核销范围。
第二个根因：时限必须夹在父的窗口内，否则会出现"父已逾期升级、子还早"的荒唐状态。
