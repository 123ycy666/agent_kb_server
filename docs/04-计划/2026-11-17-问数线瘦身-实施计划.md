# 问数线瘦身 实施计划

- 日期：2026-11-17
- 基线：`a4ad514`（两线影响面页已完成，可回滚）
- 需求来源：`docs/04-计划/2026-11-17-需求记录.md`（R1–R8 与「本轮决定」）
- 目标一句话：**问数线只剩「问题 → 按口径写 SQL → 拿数据 → 按作答规则回答」**；业务规则全部在页面上可改，代码里只留框架。

## 根因（为什么不是改表面）

1. **复现**：问一个简单问题（「上个月全市欠费多少」），trace 里跑十几步，正文可能被"对账重写"改一次；
   页面上一项输入要翻三层配置才能定位。
2. **证据**：`agent.py` 1916 行里，业务规则（安全闸、指标校验、证据对账、输出清洗、打转判据、进度提醒）
   和框架（模型调用、工具执行、落库）混在一个文件；口径、作答、纪律三处重复。
3. **为什么**：每答错一次，就在代码里加一层校验拦一次 —— 校验层越加越多，业务规则被固化进代码，
   改口径要发版、页面改了不生效。**根本原因是"业务规则放在代码里"，不是某个校验写错了。**
   所以改法是搬家：规则全进 PG + 页面可改，代码只留框架；搬走之后不再补任何一层校验。

## 架构（改完长什么样）

```
入口：ask_db（默认） / office（要文件、带文件、指文件）——不动
入线：纠错 → 补问法 → 补全表 → 问题确定
system：身份（2–3 句） + 查数口径（PG，可改） + 作答规则（PG，可改） + run_sql（唯一工具，写死）
user  ：定稿问题 + 【今天】
循环  ：run_sql → 结果回填 → 再查 / 作答；无回显、无进度、无打转判断、无证据包、无对账、无清洗
出线  ：正文 → 落库（qa_log / 摘要，会话层，不影响回答）
```

## 全局约束

1. **`agent.execute()` 的函数实现层不删**。干活线（`loop.py`）在调 `A.execute('kb_search' / 'make_file' / 'metric_query' / 'run_sql' / 'describe_table' / 'list_tables' / 'find_column')`，删实现会连锁打断干活线。本轮只删**问数线的工具表（模型看到的 schema）**和**问数线循环**里的用法。
2. 模块层保留给干活线与后台页：`tools_db.py`、`semantic.py`、`caliber.py`、`tools_result.py`、`report.py`、`doc_files.py`。
3. 一处规则只留一处：口径只进口径正文，纪律只进作答规则。
4. 不写防御代码：不预检、不校验、不拦截、不兜底、不"再验一遍"。
5. 每阶段结束跑一次相关测试 + 一次 `/api/ask` 冒烟，出红先修红再进下一阶段。

## 实施任务

### T1 删 intent（预处理无条件走）

**改**：`preprocess.route()` 与 `gate()` 整块删除；`agent.ask` 里 `_route = _pre.route(...)` 换成写死
`{'use_db': True, 'use_file': False, 'make_file': False}`；删除 `cfg.prompt_text` 的 `intent` 键；
`allow_refine` 恒为 `True`；trace 里 `kind='intent'` 这一步删掉。

**验**：`pytest server/tests/test_prompt_crud.py server/tests/test_rule_stack.py -q`；
跑一句问数，trace 里没有 `intent` 这一步，且纠错/补全/确定三步都在。

### T2 装配只留身份 + 材料，内容改写

**改**：`prompt_stack.build()` 只接受 `identity / materials`；`agent_v2.system()` 只拼这两段 + 工具说明（工具说明已删，不拼）；
`agent.ask` 删 `priority / redlines / answer_format / personal_rules / persona / prefs / tool_guide` 的取值与传参；
`IDENTITY` 改成「你是{单位}{名称}的办公智能助手，服务…」两到三句；
把原来身份里的三条（汇报口吻 / 数字有出处 / 本地叫法）**并入作答规则正文**（PG `cfg.prompt_material` slot=answer）。

**验**：`GET /api/v1/prompts/preview` 只回两层；身份正文里没有"必须/不许"；
`pytest server/tests/test_prompt_stack.py -q`（按新结构改断言）。

### T3 问数线工具只留 run_sql，schema 重写

**改**：`agent.TOOLS` = 一只 `run_sql`：

```
name: run_sql
description: 对业务库执行一条只读查询并返回结果。查数、核对、明细与汇总都用它。
parameters:
  sql: string, "要执行的 SQL，单条只读语句"
required: [sql]
```

删 `finish / kb_search / kb_read / read_file / make_file / run_code / read_howto / get_rule /
list_metrics / metric_query / read_result / describe_table / find_column / list_tables` 的 **schema**；
`execute()` 的实现全部保留（干活线在用）。
循环里 `tools = agent.TOOLS` 固定，删 `_want` 子集逻辑。

**验**：`GET /api/v1/prompts/tools` 只返回 1 只；description 无示例句、有参数说明；
`pytest server/tests/test_rule_stack.py server/tests/test_ask_data_lane.py -q`。

### T4 循环瘦身

## 风险

| 风险 | 处置 |
|---|---|
| 删了证据包与对账，正文数字可能编 | 作答规则里写明"数字只来自本次查询结果；查不到就写没查到"，其余靠模型 |
| 删 `safe_select` 后 `run_sql` 能写库 | 部署层用只读账号；连接只给 SELECT 权限 |
| 无自动 LIMIT，大结果集把上下文撑爆 | 结果行数上限保留为运行参数（框架参数，页面可改） |
| 干活线共用 `execute()`，误删会连坐 | 全局约束 1：只删 schema 与问数线循环调用 |
| 现有 50 个测试大量依赖被删功能 | T9 逐条处理，删功能就删对应用例并记录 |
