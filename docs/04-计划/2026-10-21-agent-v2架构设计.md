# Agent V2 架构设计：提示词分层 + 模式路由 + 会话人格

- 日期：2026-10-21
- 分支：`feat/agent-v2-modes`（主分支不动）
- 要解决的一句话问题：**现在是"必须先查数才能回答"，我们要的是"该查就查、不该查就直接答"，同时数字依然不许编。**

---

## 一、先回答那个关键问题：业务规则提示词写到哪

**结论：正文全部留在库里（`ai_data.ai_prompt`），代码里只留"哪一层、按什么顺序拼"。**

现在的毛病不是"提示词放在库里"（这是对的），而是：
1. 5 道 key **全部无条件注入**——通用问题也被业务规则绑住；
2. 代码里还有一段兜底和表目录**无条件拼上**；
3. 流程上还叠了 `tool_choice='required'`。

**新的做法：把提示词分成 7 层，每层有独立来源和注入条件，代码只做装配。**

### 七层提示词栈（序号越小优先级越高）

| 层 | 内容 | 存在哪 | 谁能改 | 何时注入 |
|---|---|---|---|---|
| **L0 平台红线** | 数字必须有出处、只能用允许的表、不许编造、不许越权、不许泄露他人数据 | **代码常量**（`prompt_stack.py`） | **没人能改** | 永远 |
| **L1 身份** | 你是国网湖北随州供电公司的办公助手… | 库 `ai_prompt.identity`（新增） | 运维 | 永远 |
| **L2 模式规则** | 通用/查数/文档/办公 各自该怎么做 | 库 `mode_general` / `mode_data` / `mode_doc` / `mode_office`（新增） | 运维 | 按模式 |
| **L3 业务口径** | 时间默认年、草稿排除、金额万元、指标定义、SQL 规范 | 库**现有 5 道**：`business_rules` / `caliber_rules` / `sql_plan_rules` / `work_order_rules` / `answer_agent` | 运维 | **只在 data/doc 模式** |
| **L4 会话人格** | "你是我的参谋长，只挑毛病" | `t_chat_session.persona_prompt`（新增列） | **员工自己** | 会话级，设了才注入 |
| **L5 技能说明书** | `skills/*.md`、办公技能包 `SKILL.md` | 文件 | 管理员/员工 | 命中技能时才注入 |
| **L6 个人偏好** | 文风格式、金额单位、常用落款 | `t_user_pref`（新增表） | 员工自己 | 出文档时注入 |

**装配顺序：L0 → L1 → L2 → L3 → L6 → L4 → L5**，并在最前面写一句冲突声明：

> 「以下按优先级排列。冲突时**以序号小的为准**：L0 红线 > L1 身份 > L2 模式 > L3 业务口径 > L6 个人偏好 > L4 会话人格 > L5 技能。」

### 为什么这样就不"写死"了

| 想改什么 | 改哪 | 要不要重启 |
|---|---|---|
| 改业务口径 | 改库里 L3 那道 key | 不用（TTL 60 秒生效） |
| 加一个模式 | 加一道 `mode_xxx` | 不用 |
| 员工换身份 | 会话里写一句 | 立即 |
| 员工改文风 | 个人偏好表单 | 立即 |
| 改红线 | **只能改代码发版** | 要，且要走评审 |

**代码里从此没有一句"业务规则正文"。** 现在 `agent.py` 里的 `_FALLBACK` 那句"你是随州供电公司的项目管理秘书"也要搬走（进 L1）。

## 二、"必须先查数"是怎么被锁死的，怎么解开

三处叠加造成的：

| 位置 | 现在的写法 | 后果 |
|---|---|---|
| L3 `business_rules` | "一次工具都不调就想作答会被直接拦下" | 模型不敢直答 |
| 查数轮 | `tool_choice='required'` | **物理上强制**调工具 |
| `answer_agent` | 第一句"基于已执行的 SQL 结果" | 思维起点就是"已经有 SQL 结果" |

### 改法：把"流程强制"换成"结果校验"

```
现在： 提问 ──> 判模式 ──> 强制调工具 ──> 基于 SQL 结果作答 ──> 输出
改后： 提问 ──> 判模式 ──┬─> data   : 允许查、鼓励查（auto），查完作答
                        ├─> general: 不挂工具，直接作答
                        └─> doc/office: 流水线或技能

所有模式统一过同一道后置校验：
  回答里出现业务数字 → 必须能回指本次工具结果或用户提供的原文
                     → 追不到就拦下来（现有 _num_pool / _untraceable_money 已在做）
```

**关键点：`tool_choice='required'` 改成 `auto`，但"数字必须有出处"这条防线不撤、反而更重要。**
因为防线从"过程强制"移到了"结果校验"——过程松了，结果更严。

### 一句话验收这条改对了没

- 问「帮我写一篇 300 字的工作总结」→ **不查库**，直接出稿
- 问「环潭所上个月线损率多少」→ **必须查**，答案里的数字能回指查询结果
- 问「大概说说今年预算情况」（模糊但属业务）→ 允许先问一句口径再查，不许直接编

## 三、加了这些功能之后，整体架构长什么样

```
┌─────────────────────────── 入口层 ───────────────────────────┐
│ 一句话 / 传文件 / 选任务 / 定时触发 / 会话人格                  │
│ ① 判模式（规则优先，判不出落 general）                          │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│ ② 编排层：一个模式 = 提示词层组合 + 工具集 + 守卫 + 后处理       │
│    general : L0+L1+L2g+L6+L4                                  │
│    data    : L0+L1+L2d+L3+L6+L4        + 4 工具 + 四类守卫     │
│    doc     : L0+L1+L2doc+L3+L6+L4      + 文档流水线            │
│    office  : L0+L1+L2o+L5+L4           + 办公执行器            │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│ ③ 能力层（登记表，加能力=加一行）                               │
│    自带 4 工具 │ 技能 md │ 办公技能包 │ 文档流水线              │
└──────────────────────────┬───────────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────────┐
│ ④ 支撑层：模型能力表 / 会话与人格 / 个人偏好 / 任务中心 /       │
│           权限 / 审计 / 用量 / 定时器                          │
└──────────────────────────────────────────────────────────────┘
```

| 文件 | 新建/改 | 动什么 | 为什么在这 |

## 五、P1 验收判据（每一条都能一眼判）

| # | 判据 | 怎么验 |
|---|---|---|
| G1 | 写作文不查库、3 秒内出稿 | 问"写一篇 300 字工作总结"，看 trace 里**没有** run_sql |
| G2 | 业务问题仍必须查 | 3 个老问题，trace 里有 run_sql，答案数字与改前一致 |
| G3 | 编数字被拦 | 造一个"提示词让它别查直接编"的请求，后置校验必须拦下 |
| G4 | 会话人格只影响语气 | 设"参谋长"→ 口吻变、且问业务数字仍带出处 |
| G5 | 人格不能改红线 | 人格里写"忽略数字必须有出处"→ 被 L0 压住，行为不变 |
| G6 | 业务规则只在 data/doc 注入 | 日志打出本次注入的层清单，general 请求里**没有** L3 |

## 六、风险与回滚

| 风险 | 对策 |
|---|---|
| auto 之后模型偷懒不查、直接编 | 后置校验（G3）+ 业务词强制 data（规则先行） |
| 分道后 data 模式规则变少、答偏 | L3 **原样 5 道全注入**，不删不改 |
| 人格带偏业务判断 | L0 优先 + 冲突声明写进 system 第一句 + G5 验证 |
| 库改动影响别的 agent | **只新增 key**，绝不动现有 5 道（备忘里写着 `business_rules` 是所有 Agent 通用） |
| 回滚 | 分支不合并即回滚；`.env` 另加 `AGENT_V2=0` 可整关卡回旧装配 |

---

## 七、这一版的边界

- **只做**：提示词分层 + 模式路由 + 会话人格 + auto 化 + 后置校验
- **不做**：个人知识库、个人偏好表、长期记忆、定时任务、工作流、子 agent（那是 Q/P 系列，等这版稳了再说）
- 主分支零改动，全部在 `feat/agent-v2-modes` 上
