# 纠错词典：页面上自己导入（2026-11-21）

## 目标

纠错词表过去是「框架之前配好的」——随州那套库里有数据，换一套实例就没有，页面又只能一条一条点。
本次把**页面能力**补上：在「提示词 → 问数线 → ② 名称与错字纠错」里

1. 讲清拼音怎么参与纠错（为什么拼音列不用填、为什么同音能改对）；
2. 能按类别批量导入（CSV / XLSX），名称库的拼音码由服务端现算；
3. 导入后能立刻看到生效证据（立即重载 + 试一句）。

**不替任何现场灌数据**：不写宜昌的业务库，不预置任何现场地名。

## 根因

页面缺一条「批量写入 + 算拼音码 + 触发重载」的路径：

- 现有接口只有单条 CRUD（`POST/PUT/DELETE /prompts/lexicon/{key}[/{id}]`），2 万条名称库点不动；
- 名称库 `t_nc_catalog` 的 `py_full` 是离线编译产物，正手敲等于让这条名字永远匹配不上，页面必须替人算；
- 纠错引擎按 `MAX(update_time)` 指纹热更新，任何批量写都必须动这一列，否则导入完不生效且不报错；
- 空表会让 `Corrector.__init__` 直接抛 `FileNotFoundError`，整套纠错降级 —— 从零配置的现场先导一张表就等于没导。

## 验收判据

| # | 判据 | 怎么判 |
|---|---|---|
| 1 | 名称库导入不填拼音列也能纠错 | 导入 → `reload_now()` → `fix('环谭供电所的现损')` 输出 `环潭供电所的线损` |
| 2 | 拼音码与引擎同口径 | 导入后库里 `py_full=huantangondianso`、`py_strict=huantangongdiansuo`、`initials=htgds` |
| 3 | 重复导入不重复插 | 同一文件导两次：第二次 inserted=0、skipped=n |
| 4 | 替换模式不物理删 | 旧行 `deleted_flag=1`，列表只剩新行 |
| 5 | 坏文件不写半截 | 表头缺列 / 必填为空 / 坏 JSON 返回可读原因，失败明细带行号 |
| 6 | 导出能再导回来 | 导出 CSV 再用替换模式导入，行数与拼音码一致 |
| 7 | 空词典不整体降级 | 六张表全空时 `reload_now()` 成功、`fix()` 原样返回，页面体检点名缺哪张 |
| 8 | 页面能点到 | `web` 构建通过，`/prompts` 抽屉里能看到原理说明、导入、立即生效、试一句 |

## 步骤 → verify

1. 写 `lex_import.py`：五类规格（名称库 / 错别字 / 标准词 / 拼音表 / 单位规则）+ 模板 + 导出 → verify：`template_csv('catalog')` 首行是中文表头。
2. 拼音码现算：读一次 `t_nc_pinyin`，用 `name_corrector._encode_with` 同一套模糊音规则 → verify：判据 2 的三列值。
3. 导入写库：追加跳过 / 替换软删 / 词表 upsert，全在一笔事务里 → verify：判据 3-5。
4. 空表容错：`lex_source.MysqlSource.read` 返回空列表，`name_fix.status()` 对「六张表全空」点名 → verify：判据 7。
5. 接口 + 前端：胶囊按类别调 `/lexicon/import`，结果展示 inserted/skipped/failed → verify：`npm run build` 通过。
6. 端到端：起临时后端（非 8200）→ 导入 → 试一句 → 关掉 → verify：判据 1、8。
7. 出使用说明，写清拼音原理与导入顺序 → verify：判据表逐条命中。
