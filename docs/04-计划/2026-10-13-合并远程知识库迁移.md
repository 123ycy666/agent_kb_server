# 合并远程《知识库迁移》Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:executing-plans 逐步执行。步骤用 `- [ ]` 跟踪。
> 开场扫描：命中 ②③④⑤⑥ → 已调 brainstorming(判定) / writing-plans / resolving-merge-conflicts / test-evidence / verification-before-completion；写码轮再调 ponytail(full)。

**Goal:** 把远程 `origin/main` 最新的 3 个提交（含《知识库迁移：阿里云百炼 → 自建本地知识库》）合进本地 main，解决全部冲突并保持两条线的意图都在；产出可运行代码 + 安装包 + 含密钥的使用文档。

**Architecture:** 两边是同一条线的两个后继：
- **远程**（`20c2d60`，2026-10-13 15:16）= 知识库**检索面**切到自建系统（新增 `secretary/kb_client.py`）+ 把服务器较新代码同步回仓库 + **删掉整条管理面**（`/api/kb/**`、6 个文件、2 份交付文档）。
- **本地**（`4d4bc91` + 未提交工作区，2026-10-12~13 12:28）= 同一迁移的**另一套实现**（`tools_kb.py` 双后端开关，默认仍走百炼）+ agent 质量提升（finish 收尾工具 / 输出清洗 / 题型分流 / 超时重试）+ MODEL 默认值修复。

**合并方向：远程的架构 + 本地的增量。** 依据：远程是仓库最新、已在服务上跑过实测（/health kb:true、/api/ask 命中新库）；本地 7 处待拍板问题里 S7「切默认」本就写着「等 Fred 指令」，现在指令=合并远程。

**Tech Stack:** Python 3.12 标准库 + pymysql；自建知识库 `POST /api/v1/auth/login` + `POST /api/v1/search`。

## Global Constraints

- **不回退远程的管理面移除**：百炼 SDK / AK-SK / `/api/kb/**` / `/kb` 页面全部保持删除状态。
- **不发明新行为**：冲突处只做「保住两边意图」的取舍，取舍理由逐条写进提交信息。
- **一次一个变量**：合并期间不改提示词、不换模型、不调阈值。
- **判据动手前定死**，事后不许改（见 §4）。
- 证据落盘 `output/test_results/2026-10-13-合并验收/`（`00-index.md` + 逐项 `EV-NNNN-*.md`）。
- 凭据只在 `.env` 与交付文档里，**不新增到任何入库文件**（`.env` 已被 .gitignore）。

## 5. 风险

- **网络**：GitHub 直连/代理都不通；本仓库走 `ghfast.top` 镜像且必须 `http.sslBackend=openssl`（schannel 在本机 sandbox 下取不到凭据）。`.git/config` 里的 `http.sslBackend` 是本地配置，不入库。
- **删掉百炼回滚分支**是本次最大的取舍：回滚从「一行 env」变成「回滚这个合并提交」。若 Fred 要求保留，单独开一轮加回来。
- **12 题回归耗时长**（单题 6–20s，含分析页面更久）：判据先定，跑完只对判据。
- `.env` 会进安装包 → 安装包**不能进仓库**（放 `output/`，已被 .gitignore）。
