## 1. 红线（Fred 反复纠正过的，别再犯）

1. **不许写死**：阈值、时限、文案、角色词、部门名一律来自配置/查询。
   `server/app/dispatch_rules.py` 的 `ROLE_ADVICE` / `ADVICE_WINDOWS` / `ADVICE_BANNED` 是建议规则真源；
   改口径只改这里，不许在代码里再写一份。
2. **身份卡只管「系统自动给的默认建议」**，不限制自由问答。`advice_check()` 只在 `brief()` 里调用，
   问答/任务流转路径不许经过它。用户在对话里问什么，任何身份都要照实答。
3. **层级**：层–层转派是对的（Fred 确认）。派活只能给直接下一级、上报只能给直接上一级，
   同级只能抄送；同部门同岗位可换人；协办可相邻上下；抄送不限层级。
4. **一件事一张单**：一条预警 = 一个事项 = 一个 `case_id`，整棵树共用；第二个人再建 → `CASE_EXISTS`，
   只能改方案 / 补充要求 / 写说明。
5. **上级闭环要两个条件**（Fred 定）：子任务全闭环 **且** 自己那级数据达标。缺一不可。
6. **协同模式（一条任务多个所一起干）暂不设计**，只记在清单里。
7. **不做推送**（SSE / WebSocket / 企业微信都与本项目无关）：落库 + 前端自己取。
8. **每日扫描耗时不优化**（上班前后台跑）；要保的是**交互接口快速响应**。
9. **时间一律说人话**：对外显示 `10月30日 18:00`；接口保留 ISO，另给 `*_text`。
