### 0.1 四件套的正确位置（第 1 条落地口径）

- **问答页**：每轮答案下方一行，例：`依据《公文处理办法》v2 · 自检 3/3 · 2 个数字来源 ▾`。点开是**可展开区**（不是半屏常驻面板），内容为四件套 + 本轮运行步骤（每步工具名、参数、是否命中）。
- **运行日志（记录页）**：全量结构化落库，按 `qa_id` / 会话 / 时间可查，含每步 SQL、注入构成、自检逐条。
- **两者都要**：页面给当场看，日志给事后查。上一轮的错误是**删掉页面那一半**，不是"位置放错"。

### 0.2 提示词页必须列全（第 2 条落地口径）

干活线 14 条、问数线 8 条的清单沿用交接文档 4.2，实施时逐条对代码核一遍（下表的"字数"以运行时的**生效字数**为准，不是库里存的值）。

- 工具定义行必须能点开看**原文**：7 只工具的 `name` / `description` / `parameters` schema，就是模型收到的那份。
- 每行来源标三种：`库·可改` / `代码·只读` / `词表·可改`（定稿 H10.3）。
- 修掉现存自相矛盾：表格显示「工具说明 0 字」而预览显示「621 字」——两处都改成**生效字数 + 来源**（`库` 或 `代码兜底 DEFAULT_TOOLS_GUIDE`）。
- 表尾一句：**没列在表里的东西不影响回答。**

### 0.3 库结构页（第 3 条落地口径）

左栏四组 `kb / cfg / qa / base`，每张表一行：表名 · 行数 · 有无页面入口（无入口标红）。右栏：字段清单（名/类型/可空/默认/注释）+ 前 20 行真实数据，只读。这页是定稿 H14.2「每张表必须有页面入口」的兜底检查口，标红数必须为 0。

## 1 现状：缺的不是"能存"，是"能找、能管"

| 现在有 | 现在没有 |
|---|---|
| 空间表 `kb.knowledge_base`、文档表 `kb.document`、切片表 `kb.document_chunk`（向量 + tsvector + 标签数组）、标签表 `kb.tag`、说明书表 `kb.spec` | 目录树（一篇文档只认 `kb_id`，同一库下 19 篇平铺） |
| 混合召回（向量 + 关键词 RRF）+ 精排（rerank）已在 `services/retrieval/search.py` | 元数据：发文单位、文号、成文日期、生效/失效日期、文种、密级，一个字段都没有 |
| 版本链（`root_id` / `version_no` / `superseded_by`）与冲突检测 | 时效状态（现行 / 征求意见 / 已废止）与归档动作，只靠"新版取代旧版"隐式表达 |
| 标签是自由字符串数组 + `kb.tag` 只做词条统计 | 受控词表：没有维度、没有同义词、没有合并废弃，谁都能打新词 |
| 资料库页签读 `kb.spec where space='material'`（0 行） | 真正的 19 篇资料在 `kb.document`，一张页面都没有（定稿 H14.2 已违反） |

**一句话**：现在只有"库→文档→切片"三跳，缺中间那层"目录 + 元数据 + 状态"。所以人找不到东西，智能体也只能靠向量硬撞。

## 2 信息架构：四层，不许多

```
空间 (2 个固定)   说明书库 spec      资料库 material
                     │                  │
目录 (2 层封顶)   按"活"分类 3–4 个    一级 = 业务条线 / 二级 = 事项域
                     │                  │
文档 (1 主目录)   一篇文档只有一个主目录（= 归属，也是权限边界）
                     │
切片 (继承)       catalog_path / 状态 / 密级 / 生效日 冗余下沉，检索单表过滤
```

**为什么不建三层目录**：全库现有文档几十篇量级，三级目录会让 1.5 篇/目录变成 0.3 篇/目录，导航价值归零，人会退回搜索。同一主题多版本靠**版本链**区分，不靠新建子目录。

**为什么一级按业务条线而不是按使用场景**：目录同时是权限边界（H8.4「目录按身份过滤」），而权限跟着**专业条线**走，不跟着任务走。按场景建，同一条制度必然被重复放进"写公文""做台账"多个目录，归属唯一性立刻就破，接着只能拿标签补——那就成了两层都不清。（另一个选项的比较见第 10 节。）

## 3 存什么

### 3.1 目录树 `kb.catalog`（新增）

| 字段 | 说明 |
|---|---|
| `id` / `parent_id` | 两级；`parent_id` 为空即一级 |
| `space` | `spec` / `material`，两棵树分开 |
| `name` / `path` | `path` 形如 `/营销/电费回收`，检索按前缀裁子树 |
| `owner_id` | 目录负责人：为空 = 全局（管理员维护），否则本人私有 |
| `sort` / `enabled` | 排序、停用（停用不出现在上传选项，已有文档保留可见） |

一级 5 条（资料库）：**综合 / 安监 / 运检 / 营销 / 财务**。

### 3.2 文档元数据（`kb.document` 加列）

| 字段 | 必填 | 取值 |
|---|---|---|
| `catalog_id` | 是 | 主目录，一篇一个 |
| `title` | 是 | 题目（与文件名可不同） |
| `doc_kind` | 是 | 文种，取词表 |
| `issuer` | 是 | 发文单位 |
| `doc_no` | 是 | 文号，如 `国网办〔2024〕12号`；无文号的记录类填 `—` |
| `signed_on` | 是 | 成文日期 |
| `effective_from` / `effective_to` | 是 / 否 | 生效、失效日期 |
| `status` | 是 | `draft` 待发布 / `active` 现行 / `superseded` 被取代 / `archived` 已归档 |
| `secrecy` | 是 | `public` 公开 / `internal` 内部（默认）/ `sensitive` 敏感 |
| `tags` | 是 | 受控词表里的词，见 3.3 |

密级可见性：`public` 所有人；`internal` 登录用户；`sensitive` 仅上传者与管理员。裁剪发生在检索与展示，不改变已有下载链接的有效性。

### 3.3 受控词表 `kb.tag_term`（替换裸标签表）

只有两个维度，因为时效和密级已经做成字段，再套标签就是同一信息两处维护：

| 维度 | 取值（示例） | 约束 |
|---|---|---|
| 文种 | 制度、办法、细则、规定、规范、通知、通报、请示、报告、批复、函、纪要、模板、台账、流程、方案（16 个） | 每篇必选 1 个 |
| 主题 | 公文格式、保密、财务报销、安全生产、考核、信访、督查、值班、接待 | 选填 0–2 个，只放**跨目录**的词 |

- 词条字段：`dimension` / `term` / `synonyms[]` / `status`（启用·合并·废弃）/ `usage_count`。
- **不许自由输入新词**：要新词先在词表页登记（管理员），否则上传时选不到。这是防止标签泛滥的唯一硬手段。
- 同义词归并到标准词（如"安规"→"安全生产"），检索时一并展开。

### 3.4 切片冗余（`kb.document_chunk` 加列）

`catalog_path`、`status`、`secrecy`、`effective_from` 四个字段下沉到切片，检索时单表过滤，不 JOIN 文档表。这与现有"标签下沉"同一个思路，也是现有实现的延续。

### 3.5 说明书与文档的统一（修 3.2 那个空页签的根因）

**一切文件都进 `kb.document`**；说明书 = 文档 + `kb.spec` 属性（什么时候用 / 适用 / 产物 / 归属 / 检查项），用现有 `kb.spec.doc_id` 外键挂上。

- 删掉 `kb.spec.space` 里 `material` 这条分支——它现在是空的，却让资料库页签读了个空表。
- 说明书库 = 有 `kb.spec` 记录的文档；资料库 = 其余文档。两个页签查同一张表、不同条件，不会再显示同一份 5 篇。
- 说明书仍**不参与向量检索**（`is_retrievable=false`，保持 V17），只走目录行。

## 4 上传结构（固定六步，顺序不许换）

| 步 | 动作 | 校验（不过就 400，并说明缺哪项） |
|---|---|---|
| 1 | 选空间（说明书库 / 资料库） | 必选；说明书库还要选角色 |
| 2 | 选目录 | 必选；只能选 `enabled` 的目录；没合适目录 → 提「新建目录」申请，管理员批 |
| 3 | 填元数据 | 3.2 表里"必填"的 6 项（说明书另有四项：什么时候用 / 适用 / 产物 / 归属） |
| 4 | 打标签 | 文种 1 个、主题 0–2 个，**只能从词表选** |
| 5 | 上传文件 + 预览 | 支持 md / docx / pdf / txt；预览显示：切片条数、前 3 条切片、目录行（说明书） |
| 6 | 提交 → 待发布 | 状态进 `draft`，**检索不到**；目录负责人或管理员点「发布」→ `active`，60 秒内生效 |

- 同名同目录再上传 = **新版本**，旧版自动 `superseded`，回滚入口在版本抽屉。
- 存量 19 篇资料走「待补办」清单补元数据，补完才可检索；不补的一律算 `draft`。

## 5 管理结构（谁在哪儿改什么）

| 要做的事 | 在哪 | 谁能做 | 生效 |
|---|---|---|---|
| 建/改名/停用/合并目录 | 知识库 → 目录管理 | 管理员；本人私有目录本人可管 | 立即 |
| 新增词条、合并同义词、废弃 | 知识库 → 词表管理 | 管理员 | 立即，检索即展开 |
| 审待发布文档 | 知识库 → 待办（待审） | 目录负责人 / 管理员 | 发布后 60 秒 |
| 补元数据 | 知识库 → 待办（待补） | 上传人 | 补全即进待审 |
| 到期/被取代处理 | 知识库 → 待办（归档） | 目录负责人 | 归档后默认不检索 |
| 改密级 | 文档详情 | 上传人 / 管理员 | 立即 |

目录变更、密级变更、发布、归档都要写审计（定稿 H9.3）。

## 6 检索规则（六条，按顺序执行）

1. **先裁范围**：空间 + 目录子树（`path` 前缀，全局目录所有人可见、本人私有目录仅本人与管理员）+ 密级不高于用户 + 状态 = `active` + `effective_from <= 今天`。已废止/归档默认不在范围内。
2. **再召回**：向量取 20 + 关键词（tsvector）取 20，RRF 融合（`k=60`，沿用现有实现）。
3. **再精排**：rerank 取前 5；rerank 不可用时降级用融合分，并在结果里标明降级。
4. **每条带出处**：文档名 + 目录路径 + 文号 + 生效日期 + 时效。缺一样就不许出现在答案里（定稿 H6.3、H13）。
5. **说明书不走向量**：按目录行 + 关键词命中，读正文靠 `kb.spec.body`（保持 V17）。
6. **命中为 0 不许猜**：明确说「知识库里没有这类文件」，并给出两条退路（换词 / 放开"含已废止"重新查）。

补充两条口径：

- 用户明确要"历史版本/已废止"时，放开第 1 条的状态条件，结果逐条标「已废止（替代版本：X）」。
- 跨目录检索由**主题标签**承担，目录不再重复表达同一信息（ONES 的"标签与目录不重叠"）。

## 9 验收判据（每条都能跑出 pass / fail）

| 编号 | 判据 |
|---|---|
| K1 | 20 篇假文档每篇恰有 1 个主目录；从知识库首页点到任意一篇 ≤ 3 次点击 |
| K2 | 缺任一必填项提交 → 400 且指出缺哪项；手打词表外的标签 → 拒绝 |
| K3 | `draft` 文档检索不到；发布后 60 秒内可检索到 |

## 10 假设与岔口（Fred 只需看这一节的意见）

**目录一级按业务条线（A）**，已写进第 2 节。理由：目录=权限边界，权限按条线给；按场景（B：写公文 / 做台账 / 查数 / 办事）会让同一制度多目录重复，归属唯一性直接破。

B 只有在一种情况下才对：找文档的人**不按专业、只按任务**找，且同一份文件允许一个主归属之外再挂多个"使用场景"。那我们得加第 3 个标签维度（使用场景）兜住跨目录，目录仍按 A 建。**如果 Fred 认为日常就是按任务找，说一句，我改成 A 目录 + 使用场景标签，目录不动。**
