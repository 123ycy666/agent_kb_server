# 整个 agent 的重构方案（整理稿）

- 日期：2026-10-21
- 结论：**现在的 agent 不是"功能少"，是几处结构性锁死**。要加能力，先解开锁；解开之后，加什么都只是"挂上去"。
- 本文件只做方案，**不动代码**。

---

## 一、现状体检：六个锁死点

| # | 锁死点 | 事实（有出处） | 后果 |
|---|---|---|---|
| L1 | **单一人格** | 只注入 5 道提示词 key：`answer_agent / business_rules / sql_plan_rules / work_order_rules / caliber_rules`（`config.py:_PROMPTS` 默认值） | 所有输入都被当业务问题 |
| L2 | **提示词第一句就限定输入** | `answer_agent` 原文：「基于已执行的 **SQL 结果**，生成……分析回答」 | 写作文 / 翻译 / 常识问答 → 被拽去查库 → 查不到就说"未查得" |
| L3 | **提示词里塞了业务上下文** | `_system()` 同时拼「业务字典表目录」+「规则优先级」+「今天日期」 | 通用问题也被业务表结构污染 |
| L4 | **工具集固定 4 个** | `agent.py:TOOLS = kb_search / find_column / run_sql / finish` | 没有文件、写作、检索以外的任何工具 |
| L5 | **查数轮强制调工具** | 研究记录：查数轮 `tool_choice='required'`（`agent.py:212-215`） | 不想查库也必须调一次，纯生成类请求被破坏 |
| L6 | **能力无登记处** | 技能在 `skills/*.md` + `技能触发配置.json`；文档在 `doc_jobs` 三个 task；办公技能包刚搬进来但没人调 | 加能力 = 改代码 / 加 if；技能包接进来也用不上 |

**六处里，L1/L2/L3/L5 全在"提示词装配"这一处；L4/L6 在"工具与能力注册"。** 这就是重构的两个靶心。

## 二、目标结构：四层，职责单一

```
用户输入（问一句 / 传文件 / 选任务 / 定时触发）
        │
   ┌────▼─────────────────────────────┐
   │ ① 入口层：判模式（4 种）           │  规则优先；判不出落"通用"
   │   general / data / doc / office   │  判错只影响"给哪些工具"，不影响"能不能"
   └────┬─────────────────────────────┘
        │
   ┌────▼─────────────────────────────┐
   │ ② 编排层：一个模式 = 四件套        │
   │   提示词段 + 工具集 + 守卫 + 后处理 │
   └────┬─────────────────────────────┘
        │
   ┌────▼─────────────────────────────┐
   │ ③ 能力层：注册表                   │  工具/技能/流水线各登记一行
   │   自带 4 工具 · 技能包 · 文档流水线 │  别人的用别人的，业务的自己写
   └────┬─────────────────────────────┘
        │
   ┌────▼─────────────────────────────┐
   │ ④ 支撑层：模型能力表 / 任务中心 /   │
   │   权限 / 审计 / 用量 / 定时器       │
   └──────────────────────────────────┘
```

### 4 个模式各是什么

| 模式 | 提示词 | 工具 | 守卫（数字必须有出处等） | 典型请求 |
|---|---|---|---|---|
| **general**（新） | 新增一道 key `general_agent`：内网办公助手，问什么答什么 | 不挂查数工具 | **不生效** | 写作文、翻译、润色、解释概念、算个数、写邮件 |
| **data**（现有，一行不改） | 现有 5 道 key | 现有 4 个 | **全部生效** | 问数、问制度、问口径 |
| **doc**（现有） | 现有 pipeline 提示 | 不挂（流水线自己调模型） | 文档类守卫 | 速读、审校、查表、转 PPT |
| **office**（新） | 技能包 `SKILL.md` 原文 | 办公执行器工具 | 部分（禁止越界写盘） | 做 PPT、写公文、Excel 批处理 |

**关键约定：** 模式只决定"加载哪些提示词、给哪些工具"，**不决定"能不能做"**。判错最坏是多给几个工具、慢一点；用户说"不对，我是要…"就切。

## 三、分期（每期都能单独回滚）

| 期 | 内容 | 改动面 | 验收判据 | 回滚 |
|---|---|---|---|---|
| **P0 解锁**（核心） | 入口层判模式；`_system()` 按模式选提示词段；新增 `general_agent` 提示词（库插一行）；general 模式不挂工具、不强制调工具 | `agent.py` 两处 + 库一行 + `.env` 一个开关 | ① "写一篇 300 字的工作总结" 3 秒内出稿、不查库 ② 3 个老问数问题答案与改前一字不差 | 开关关掉 = 回到今天 |
| **P1 通用能力补齐** | 写作模板（总结/通知/报告/演讲稿）、翻译、润色、解释、算账、写邮件 | 只加提示词与技能文档 | 每类各 3 个真实请求，人工判"能用" | 删提示词行 |
| **P2 办公技能接线** | 技能包（已入库）接进 office 模式：执行器 + 自检闸门（`inspect_deck` 不通过不许下载） | `office_runner.py`（已有）+ `doc_jobs` 一个 task + 前端一项 | 真材料出 PPT，自检"通过"，3 页抽看合格 | 停 task，不影响其它 |
| **P3 定时任务** | APScheduler（MIT，进程内）替代外挂定时；页面可配"每天几点 → 跑哪套 → 发给谁" | 新模块 + 一张配置表 + 页面 | 配一条"每天 8:00 出指标日报"，连跑 3 天不重不漏 | 关开关，退回外部定时 |
| **P4 工作流/子 agent** | LangGraph（MIT）做多步编排；CrewAI/smolagents 做可选子 agent | 新模块 | 一条真实多步活（读文件→查数→出稿）一次跑通 | 不启用即可 |
| **P5 前端统一** | 现在有两套入口（legacy `index.html` + React SPA），合并成一个 | 前端 | 员工只看到一个入口 | 保留旧页 |

## 六、风险

| 风险 | 后果 | 对策 |
|---|---|---|
| 模式判错 | 用户觉得"刚才还能干的活现在干不了" | 模式只决定工具，不决定能力；且提供"改用…"一键切换 |
| 通用模式太松 | 开始胡编数字 | general 模式**不接业务问题**：一旦识别到业务词，强制切 data |
| 提示词外溢 | 改 `business_rules` 会污染别的 agent | 新 key 独立，绝不动现有 5 道 |
| 技能包脚本执行 | 代码执行风险 | 已有执行器：白名单 import、禁网络、超时、只收 `out/` |
| 工作流/子 agent 过度设计 | 复杂度爆炸 | P4 只在 P0–P3 都稳定后才考虑；默认不启用 |

## 七、要 Fred 拍板的三件事

1. **P0 就是"解锁"**：新增一道 `general_agent` 提示词 + 按模式选提示词段。**这一条你点头我就做**，做完拿"写工作总结"+3 个老问数问题给你对比。
2. **通用模式遇到业务问题怎么办**：我建议**强制切回查数模式**（宁可慢，不许它拿通用口吻回答业务数据）。
3. **P3 定时任务**：是先做"指标日报"这一条真实用例，还是先把"可配置"做出来？
