# 个人化能力：让每个员工有自己的助手（整理稿）

- 日期：2026-10-21
- 起因：Fred 提的方向不是"再加几个办公功能"，而是**让员工自定义自己的助手**——个人知识库、个人文风格式、自定义身份人格、长期记忆、自定义小任务、自定义提示词。
- 本文件只做方案，**不动代码**。

---

## 一、一句话判断

**我们缺的不是"更多功能"，是"每个人自己的那一份"。**

现在系统里所有东西都是公司级的：一个业务库、一个知识库、一套提示词、一套口径。
但真正让人天天用的助手，必须有"**我的**"：我的模板、我的文风、我的角色、我的任务。

**六件事，按"风险低→风险高"排序，也按这个顺序做。**

---

## 二、六件个人化能力（每件说清：谁存、怎么用、风险）

| # | 能力 | 员工视角 | 存哪 | 怎么用 | 风险 |
|---|---|---|---|---|---|
| A | **个人知识库** | "我自己的文件、我的模板、我常引用的材料" | **复用现有知识库**（已有"公开/私有"可见性），加 `owner=本人` 过滤 | 问问题时先检索我的库，再检索公司库，**分开召回、分别标出处** | 低（权限过滤已有） |
| B | **个人文风格式** | "写 Word 就用我这个格式：三号仿宋、28 磅行距、首行缩进 2 字" | 新表 `t_user_pref`（JSON） | 生成文档时读他的偏好，覆盖默认值 | 低 |
| C | **自定义身份人格** | "以后你就当我的参谋长，专门挑毛病" | 新表 `t_user_skill`（个人版 `skills/*.md`） | 追加在系统提示词**尾部**，只对自己生效 | 中（可能撞红线，见 §五） |
| D | **长期记忆** | "上次我们定的口径别再问我了" | 新表 `t_user_memory`，**按 user_id 命名空间隔离** | 抽取事实 → 存 → 下次按需召回 | **高**（投毒/串号/合规） |
| E | **自定义小任务 / 定时** | "每天早上 8 点，把我这个所的指标变化发给我" | 新表 `t_user_task` | APScheduler + 页面配置 | 中（跑飞了要能停） |
| F | **自定义提示词技能** | "帮我写年度总结"这类常用活，自己攒一套 | 同 C | 触发词命中即加载 | 低 |

**A 和 B 是"立刻有感、零模型风险"的两件**，建议先做。
**D（记忆）是最诱人、也最容易出事的一件**，放最后，且先做小范围。

---

## 三、为什么 A、B 该先做

1. **A 几乎不用新造**：现有知识库已经有"公开 / 私有"可见性、切片级权限、检索编排。个人库 = `owner=本人` + 上传入口 + 检索时区分"我的/公司的"两路召回。
2. **B 是员工最直接的痛点**：公文格式每次都调一遍字体行距，写一次记下来，以后自动套。
3. 两件都**不改变模型行为**，不会影响查数，也不会带来幻觉风险。

### B 具体怎么存（示例，不写代码）

```json
{
  "docx": {"正文": "仿宋_GB2312", "正文字号": 16, "行距磅": 28,
           "首行缩进字": 2, "标题": "方正小标宋简体", "标题字号": 22,
           "页边距_cm": {"上": 3.7, "下": 3.5, "左": 2.8, "右": 2.6}},
  "pptx": {"字体": "微软雅黑", "标题pt": 32, "正文pt": 18, "每页要点上限": 5},
  "习惯": {"金额单位": "万元", "日期格式": "YYYY-MM-DD", "常用落款": "XX供电所"}
}
```

生成文档时，**默认值 → 个人偏好 → 本次请求** 三级覆盖，谁具体听谁。

## 四、开源件：能接什么，不能接什么

| 用途 | 开源件 | 许可 | 内网 | 我的判断 |
|---|---|---|---|---|
| 长期记忆 | **Mem0** | Apache-2.0（待核） | ✅ 可换 pgvector | 外挂式，改造最小 |
| 长期记忆 | **Letta（原 MemGPT）** | Apache-2.0（待核） | ✅ PG+pgvector | 要"重构运行时"，太重 |
| 长期记忆 | **Zep / Graphiti** | Apache-2.0（待核） | ⚠️ 要 Neo4j | 时序事实强，但我们用不上 |
| 长期记忆 | **LangMem** | 待核 | ✅ | 和 LangGraph 绑定 |
| 长期记忆 | **MemOS**（国产） | 待核 | ✅ | 关注显存/KV，我们用不上 |
| 定时任务 | **APScheduler** | MIT | ✅ 纯 Python | **就用它** |
| 人格/角色 | SillyTavern | AGPL-3.0 | — | ❌ 不接，只学"角色卡"的产品形态 |
| 个人知识库 | AnythingLLM / Khoj / SiYuan | MIT / AGPL / AGPL | — | ❌ 我们已有知识库，不必再引一套 |

**结论**：记忆类可以"借鉴架构、必要时接 Mem0"，但**不建议第一版就引外部记忆服务** —— 我们已经有 `session_summary`（会话摘要）和 pgvector，先自己写 200–300 行的"事实抽取 + 存储 + 召回"就够，免得为记忆再造一套运维。

## 五、红线（这是我最担心的部分）

| 红线 | 为什么 |
|---|---|
| **个人提示词只能"追加"，不能"覆盖"** | 否则有人写"不要数字守卫"就能让 agent 编数字，整系统的可信度就没了 |
| **个人库绝不进共享检索** | 一旦污染，别人的答案里会冒出你的文件 |
| **记忆按 user_id 存储级隔离**（不是检索时过滤） | 已有公开数据：跨用户污染是这类系统最常见的漏洞 |
| **记忆要能看、能删、能导出** | 内网合规：员工对话属于敏感数据 |
| **自定义定时任务要有额度和开关** | 一个员工配 100 个任务会拖垮单进程 |
| **所有个人化改动进审计** | 谁改了什么提示词，要能追 |

## 六、分期（每期都能单独回滚）

| 期 | 内容 | 验收判据 | 回滚 |
|---|---|---|---|
| **Q1** | 个人知识库（复用现有库 + owner 过滤 + 我的文件入口） | 传一份自己的模板，问"按我的模板写"，召回的是我的文件、出处标"个人库" | 关开关，退回公司库 |
| **Q2** | 个人文风格式（`t_user_pref` + 写文档时套用） | 配一次格式 → 生成的 Word 逐项对得上（字体/字号/行距/缩进/页边距） | 删偏好，回默认 |
| **Q3** | 自定义身份 + 个人技能（`t_user_skill`，追加式） | 配"参谋长"人格，回答口吻变、但数字守卫仍在（用业务问题验证不被绕过） | 停用该人格 |
| **Q4** | 长期记忆（观察期，只记"我的偏好/我的项目"两类） | 隔一天再问同一件事，不用重复交代；且**看不到别人的记忆** | 一键清空 |
| **Q5** | 自定义定时任务（APScheduler + 页面） | 配一条"每天 8:00 出我所指标变化"，连跑 3 天 | 关开关 |

---

## 七、和"整个 agent 重构"的关系

`docs/04-计划/2026-10-21-agent重构总体方案.md` 里的 P0（解锁模式）是**地基**：
- 个人人格/技能 = 追加到某个模式的提示词尾部 → 没有"模式"，就无处可追加
- 个人库 = 在检索编排里加一路 → 依赖入口层知道"这是问数还是通用"

**所以顺序是：先 P0 解锁 → 再 Q1/Q2 个人化。** 反过来做会把个人化硬塞进单一人格里，越做越乱。

## 八、要 Fred 拍板

1. **顺序**：先 P0（解锁模式）再做个人化，还是先做 Q2（个人文风格式，最直观）？
2. **个人库**：复用现有知识库加 owner（推荐），还是新建一套"我的文件"目录？
3. **记忆**：第一版只记"偏好 + 我负责的项目"两类，可以吗？（全量记对话风险和合规都太大）
