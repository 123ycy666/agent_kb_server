# 秘书智能体 —— 需求定稿 v4（办公/问数 harness）

- 日期：2026-11-12
- 状态：待 Fred 确认后定稿；本文件只写需求，不写实现
- 前版：v1（用户故事与验收雏形）、v2（信息归属与 PG 信息架构）、v3（知识库四类角色与页面地图）

## 一、这个东西是什么

一个偏办公和问数的**完整智能体**，跟豆包办公、跟 DSH 一样用：

1. **说人话就能用**：一句话交代意图，它自己决定查什么数、写什么、出什么文件，多轮接着聊、接着改。
2. **专业知识在知识库里，不在代码里**：一类活一篇说明书（步骤 / 口径 / 格式 / 样板），它自己找、照着做、自己检查，配文档即加能力。
3. **两条执行线**：问数走成熟链路（不动）；其余走通用循环（新）。入口只分一次线。
4. **不是**：不是表单、不是固定流程、不是只有几个预设任务、不是把每一步写死在代码里的自动化。

## 二、体验标尺（与常见产品对齐，可验收）

| # | 体验 | 判法 |
|---|---|---|
| E1 | 说一句就出成品（不需要先选模板/填表） | "写个通知，明早九点开会" → 直接出 Word |
| E2 | 接着改，不重写 | 下一句"第三段语气正式点" → 改同一份产物 |
| E3 | 接得住指代 | "这个文件""刚才那个数""再出一版" 都能对上 |
| E4 | 不重复问已答过的事 | 同一会话内不追问已给过的信息 |
| E5 | 没说明书也能干 | 没有说明书的活直接做，不硬套模板、不瞎读说明 |
| E6 | 能澄清，但少打扰 | 缺关键信息且不能猜时问一句，其余自己决定 |
| E7 | 可中断 | 能停止生成，停止后不留半成品文件 |
| E8 | 出错说人话 | 失败给一句原因 + 重试，不甩服务器路径与堆栈 |
| E9 | 有据可查 | 每个数字可点开看查询；每个成品能看用了哪篇说明、自检过没过 |
| E10 | 记住人 | 语言、口吻、常用格式跨轮一致；偏好可存 |

## 三、能力需求

### H1 会话与多轮
H1.1 一场会话有连续记忆：最近若干轮原样带入，更早的压缩成摘要带入，不重复、不丢关键决定。
H1.2 会话内上传的文件，下一轮用"这个文件"能读到。
H1.3 会话可列表、可搜索、可删除（软删），历史里的每一步可展开看。
H1.4 支持中断与续跑；中断不产生半成品交付物。

### H2 每轮上下文装配（这是 harness 的核心）
H2.1 每轮由系统装配：身份与纪律 + 说明书目录 + 会话摘要 + 前几轮 + 会话文件清单 + 本轮已读说明正文 + 工具说明。
H2.2 常驻部分有字数上限（默认 6000 字），超限按"先压历史、再压目录"处理，且可查本轮注入了什么、各占多少。
H2.3 正文按需取：说明书正文、资料原文、上传文件正文都不常驻。
H2.4 说明书正文不参与向量检索。

### H3 工具面（少而准）
H3.1 干活线工具：检索资料、读文档全文、读会话文件、查数、出文件、自检、收尾。
H3.2 查数工具内部自动套错字纠正与口径读取，模型感知不到流程。
H3.3 工具错误必须能自纠：错误信息要写清"该怎么改"，不是错误码。
H3.4 出文件支持 docx / xlsx / pptx；版式由格式说明决定，模型只给内容。

### H4 说明书层（配文档即加能力）
H4.1 说明书写清：什么时候用、怎么一步步做（可点名其他说明书）、交付前检查哪几条。
H4.2 目录一行一篇（名称 · 什么时候用 · 产物），超 30 篇折叠。
H4.3 引用：正文里《书名号》自动成引用，读完一篇能顺着去读它点名的口径/格式。
H4.4 命中优先级：用户点名 > 说明书点名 > 本人 > 全局 > 管理员默认 > 最新版。
H4.5 未命中：按模型自己的通用能力做，并在回答里说明"没有对应说明"。

### H5 自检闭环
H5.1 命中说明书且其有检查项时，交付前逐条报"结论 + 依据"。
H5.2 有不过项 → 不出文件，整改后重报。
H5.3 未命中或说明无检查项 → 用三条默认项（结构、篇幅、出处），不强制拦。

### H6 交付与证据（四件套）
H6.1 每轮返回：答案、数字来源、用了哪篇说明、自检结果。
H6.2 产物可下载、可再改、可在会话里被再次引用。
H6.3 数字只来自查询；查不到写"需另行核实"。

### H7 知识库与上传
H7.1 两个空间：说明书库（进目录）、资料库（只检索）；个人资料库是入口不是新系统。
H7.2 上传必须选空间；说明书必须选角色 + 填四项（什么时候用、适用、产物、归属）。
H7.3 上传后进"待发布"，预览切片与目录行后确认发布；发布 60 秒内生效。
H7.4 聊天附件与知识库文档分开；附件不入库，聊完提示"要不要存进知识库"。
H7.5 支持 md / docx / pdf / txt；图片以原文件可下载查看。

### H8 权限与归属
H8.1 两级：全局 / 本人（部门预留不做）。
H8.2 全局只有管理员能设。
H8.3 口径类只能管理员改；个人只能提交补充建议。
H8.4 隔离在查询时执行：目录按身份过滤、取正文二次校验、检索按权限范围。
H8.5 权限变更 60 秒内生效，进行中的会话不追溯。

### H9 版本、冲突、退役、审计
H9.1 同名上传 = 新版本，旧版退役可回滚；历史正文不可改。
H9.2 退役不删；删除只给管理员，被引用时先列出引用方。
H9.3 每条配置可查谁改的、第几版、何时生效。
H9.4 冲突集中待办，可裁决。

### H10 注入与问数配置
H10.1 注入文本独立成页：身份、红线、优先级、工具说明、数字纪律。
H10.2 原"提示词"页 = 问数链路的说明书，页头写明只影响问数线。
H10.3 每一项标来源：代码 / 库 / 词表；能改的给改，不能改的给看（三态）。
H10.4 词典、补全表是数据，单独入口。

### H11 共享边界
H11.1 事实共享：口径、词典可给主智能体查数用（内部自动套）。
H11.2 流程不共享：问数流水线的判据只属于问数线。

### H12 任务与预警
H12.1 预警规则与记录集中一页；不写进提示词。
H12.2 问答与任务只有一个接缝：对话里"建任务" → 拟办草稿 → 人确认才建。
H12.3 任务流转与工作流只读展示，问答页不参与流转。

### H13 记录与评测
H13.1 记录：会话、消息、每轮口径与质量、每步执行、缺口、审计、反馈。
H13.2 新增记录项：四件套（说明/自检/数字来源）结构化落库、说话人名称、评测记录。
H13.3 保留期：轨迹 90 天，问答正文长期。
H13.4 评测：题集、跑分、改造前后对比，结果落盘成可回看的证据。

### H14 可配置边界（三态与扩展规则）
H14.1 页面上每一项标三态：可改 / 只读·库 / 只读·代码。
H14.2 每张表必须有页面入口；没有入口的配置不许存在。
H14.3 加新东西先答四问：哪张表、哪个页面、谁能改、多久生效；答不全视为没设计完。
H14.4 只有能力、页面、流程需要改代码；一类活、一条口径、一句话都不许改代码。

### H15 界面
H15.1 一级页：首页 / 智能问答 / 知识库 / 问数 / 提示词与注入 / 任务与预警 / 记录 / 评测 / 系统。
H15.2 问答页：流式、可停止、运行步骤可展开、四件套可见、产物可直接下载/再改。
H15.3 管理页统一版式：卡片分组 + 每项显字数/来源/最近修改/生效方式 + 右侧抽屉看全文与版本。

## 四、数据归属（谁能改的边界）

| 分组 | 放什么 | 页面 |
|---|---|---|
| kb | 空间、文档、切片向量、说明卡、引用、角色、版本、标签、冲突 | 知识库 |
| cfg | 注入文本、注入预算、问数链路、词典、补全表、口径、字典覆盖 | 提示词与注入 / 问数 / 系统 |
| qa | 会话、消息、每轮口径、每步执行、缺口、审计、评测 | 记录 / 评测 |
| base | 用户、角色、偏好、人设、模型、任务、预警 | 系统 / 任务与预警 |
| public | 只放兼容视图（过渡用） | 无 |

## 六、明确不做 / 已知例外

1. 问数链路口径材料每轮 1.8 万字常驻：本次不改，登记例外，单独立项。
2. 部门归属、按账号的提示词与分流判据：后置。
3. 工作流 9 张表：不动。
4. 说明书多人协同编辑、审批流：不做（只有草稿→发布）。
5. 自动判断文档角色：不做（人选或默认资料）。
6. 多单位/多租户：不做。
