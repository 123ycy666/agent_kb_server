# 2026-11-23 工作流框架重做 · 实施计划

## 目标

预警工作流从「模型读散文文档、自己写 SQL」改成「人填五段固定模板 → 框架编译成 SQL → 执行 → 回填到文档指定的表与字段」。定时器独立成触发器页面。产品基线里不出现任何业务词。

## 根因

旧框架的正文是给模型看的散文（取数六节 / 发送七节），执行器是 LLM 加一组工具，同一份文档两次跑出来的 SQL 不一样，没法复现也没法校验。产出目标写在正文里，框架读不出来，所以「回填业务表」那节写了也没有工具能执行。于是「新增一个文档就能加一条预警」根本不成立：要写两份文档、要模型猜、回填落不了地。

## 验收判据

1. 新建一份文档只填五段，保存即编译，能预览 SELECT 与 UPDATE 原文。
2. 试跑不写库，返回取到几行、命中几行、前 20 行结果。
3. 正式跑按文档回填指定表的指定列，同一事务完成，失败整轮回滚。
4. 定时任务可填多个时间点、可挂多个工作流，列表显示下次触发与上次结果。
5. 运行记录能看到编译出的 SQL 原文、影响行数、报错。
6. 框架代码里搜不到业务词：预算 / 结算 / 项目 / 台区 / 审批 / 工单。
