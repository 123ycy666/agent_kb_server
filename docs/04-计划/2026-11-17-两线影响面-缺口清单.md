## 0 结论

页面上标出来的只是**提示词那一段**，不是「一次回答的全部输入」。

- 问数线：`impact.py` 10 段 16 项，覆盖的是 system 里的材料与流程判据；
  **同一份 system 里的身份 / 模式做法 / 红线 / 优先级 / 工具说明五段一个字没列**，
  user 消息里的【今天】【数据时间】【提问人身份与数据范围】【本轮带来的文件】也没列。
- 干活线：`InjectPanels` 的 8 段来自 `inject.build()`，只覆盖「注入了多少字的上下文」；
  **决定这份活按哪份说明书做（命中判据）、给不给文件（自检门）、版式从哪来（做法库/偏好/默认）、给哪 7 只工具**，一条都没有。
- 还有一个坑：身份 / 红线 / 优先级 / 工具说明**存了两份**（`cfg.inject_text` 与 `cfg.prompt_text`），
  页面上只有干活线那一份能改；问数线读的是另一份，改错地方不生效。

## 4 两条线共用的两个坑

1. **同名两份数据**：`cfg.inject_text`（identity / redlines / priority / tools_guide / number_discipline）
   给干活线；`cfg.prompt_text`（identity / redlines / priority / tools / modes / intent / askfill / confirm）
   给问数线。名字一样、内容不共享 —— 在「提示词 → 干活线」改身份，问数线的身份一点没动。
2. **入口分流不在这一页**：`cfg.route_rule` 在「系统」页，判成哪条线决定了上面两张表哪一张起作用；
   判错时两张表都白配。`impact.py` 已指出，但页面还没有把它接到链路上。

## 5 页面要能回答的问题（要求级，不定实现）

每一行必须同时给：**它是什么 · 存在哪 · 多大（字数/条数）· 能不能改 · 改完多久生效 · 这一轮到底生效没有**。

最后一项现在只能看 trace，页面没有：

- system 装配：`chars`、`has_caliber`（`agent.py:1561`）
- 工具子集：`tools` 名字列表（`agent.py:1578`）
- 材料：本轮注入了哪几份（`_swap_materials` 前后各一次）
- 干活线：`spec_used`（说明书名+版本+检查项）、`self_check` 结论、`injection.parts`（`loop.py:379-394`）
- 数字：`evidence` 字数、`verify` 的 ok/重写标记（`agent.py:685,650`）

## 6 要 Fred 定的一件事

没标出来的这些，是**全部搬上页面**（页面会更长，但答错能一路指到输入），
还是**只搬能改的**（身份/红线/优先级/工具说明/材料 4 份/检查项），
只读的（判据优先级、工具子集规则、对账、运行参数）留在「代码位置 + 一句说明」？

倾向：按「能改的搬上页面 + 只读的给一行指针」——和 `impact.py` 现在的做法一致，
但要把第 2 节 1–8 条和第 3 节 1–5 条补齐，否则页面上改的东西和真实生效的东西永远对不上。
