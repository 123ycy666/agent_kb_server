# 入口分线改回默认问数

- 日期：2026-11-13
- 状态：完成

## 根因

**复现**：问答页问「凉水情况」（一句业务问话，没提任何要做的文件），回车。

**证据**（本机 PG `t_chat_session` = `s_6dca0597f8f5445a89c039f32ba50694`）：

- `t_chat_trace_step` 第 1 步 `step_kind=route`：`{"lane": "office", "product": "docx", "howto": "公文格式", "why": "不查数"}` —— 入口把它判成不查数，送进办公线。
- 同轮后 44 步：`kb_search` 1 次、`list_tables` 1 次、`run_sql` 36 次（第 20–46 步是同一条 SQL 反复发），`answer` = 「本轮没有给出内容。」，`db_query_count=36`，`qa_log` 里这一轮没有任何正文。

**为什么**：

1. 判据反向。`router._DEFAULT_ROUTE_RULE` 写的是「拿不准一律回『不查数』」，`_ask_lane` 只认字面上带「查数」的回答，其余一律落办公线。默认线选错了：办公线没有 2–6 步预处理兜住「凉水情况」这种半句话。
2. 判据太窄。规则把「查数」限定成金额 / 工单 / 预算 / 进度 / 指标 / 排名，问「某所的情况」不在这几类里，模型照规则答「不查数」。
3. 入口判出的 `product` 没有被使用。`agent.ask` 走办公线时写死传 `{'lane': 'office'}`，`agent_office` 拿到的 product 为空，交付契约也就不注入。

## 目标

默认走问数线（2–6 步预处理 + 证据包，一行不动）；只有两种情况去办公线：

1. 明确要一份能拿走的文件：说清产物（docx / xlsx / pptx）+ 说了让我做出来。
2. 本轮带了文件，或这句话在指会话里的文件（问数线没有 `read_file`）。

闲聊不单独判：走问数线，由它的第 1 步 `intent` 判「不查库」，不查任何库直接答。
