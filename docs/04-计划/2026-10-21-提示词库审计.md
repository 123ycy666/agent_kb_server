## 二、怎么"绕过"（不是删）

三道保险，按顺序：

1. **代码不引用 = 不会加载**。站点包 `site.yml` 里显式声明要注入哪几道（P0 已落），
   没声明的 key 在数据库里躺着也不会进提示词。
2. **导出脚本只认映射表**（`server/scripts/export_prompts.py` 的 `KEYS`），
   没进映射表的 key 不会被带进站点包。
3. **站点包 strict 装载**会在缺件/占位时报错，反向保证"只用了声明过的东西"。

**不删库的理由**：那 8 道可能是别的 agent（或别人维护的流程）在用，我们看不到；
而且删了不可逆。**不用即绕过**，比删安全。

## 三、代码里写死的地方（本轮要改）

| 位置 | 写死了什么 | 改成 |
|---|---|---|
| `config.py:276` | `PROMPTS` 默认名单硬编码 5 个 key | 从站点包 `site.yml` 的 `prompts.db` 读；`.env SECRETARY_PROMPTS` 仍可覆盖 |
| `prompt_stack.py` | `BUSINESS_KEYS` 写死 L3 的 5 段及顺序 | 从 `site.yml` 的 `prompts.l3` 读顺序；标题缺失时退回 key 名 |
| `site_pack.py` | — | 暴露 `l3_order()` / `db_prompt_keys()` 两个读取函数 |

改完的判据：**把 `site.yml` 里 `prompts.l3` 减少一项，注入的 L3 就少一段**，代码一行不动。

## 根因：为什么这几处必须改（不是补丁，是根因）

**现象**：换一个单位（仙桃）时，提示词 key 名单和 L3 口径顺序都得改代码。

**证据**：
- `config.py:276` —— `PROMPTS` 默认值是硬编码字符串 `'answer_agent,business_rules,sql_plan_rules,work_order_rules,caliber_rules'`；
- `prompt_stack.py` —— `BUSINESS_KEYS` 是写死的五元组，决定注入哪些 L3、按什么顺序；
- `site_pack.py` —— 只读到了包里的正文，**没有把"注入哪些/顺序如何"暴露出来**，所以装配层只能自己写死。

**为什么这是根因而不是表象**：站点包本来已经是规则真源，但"用哪几道、什么顺序"这层决策
仍留在代码里 —— 等于换站点还是要动代码，前面把正文搬进包的效果被这一层抵掉了。

**改法**（一次改到位，不逐处打补丁）：
1. `site.yml` 增加 `prompts.l3`（顺序）与 `prompts.db`（旧链路 key），站点自己声明；
2. `site_pack.load()` 把它们读出来并返回 `l3_order` / `db_prompt_keys`（缺声明时用现有顺序兜底）；
3. `prompt_stack.build()` 按 `l3_order` 遍历，标题缺失就用 key 名；
4. `config.PROMPTS` 改为读站点包（`.env SECRETARY_PROMPTS` 仍可覆盖）。

**验证**：把 `site.yml` 的 `prompts.l3` 删掉一项 → 注入的 L3 少一段，**代码零改动**。
