## 根因（为什么动这些文件）

**现象**：线上没有提示词入口，规则只能靠发版改；规则和资料混在一张 `document` 表里，靠文件名猜类型。

**证据**：

- `agent.ask()` 里纠错和补时间是无条件执行的（`agent.py:1040`、`agent.py:1103`），判题型在其后（`agent.py:1218`）。
- `rule_doc` 只认 `document.doc_type='rule'`，而 `pipeline._doc_type_of()` 用五个词猜类型 → 员工传《XX工作要求》会被判成规则。
- S6 目录 `MAX_TOPICS=40`，规则文档 60 个主题，第 41 位起静默截断（本轮实测 `unique topics = 60`）。
- 前端没有 `/prompts` 路由，`MainLayout` 菜单里也没有入口。

**为什么这么改**：规则按「份」存表、按阶段注入；页面直接读同一批数据。新页面必须有路由与菜单注册，否则 URL 直达不了——这是唯一入口，没有别的改法。

## M1 改动清单

### 1. 建表（`server/app/db_init.py` 追加 DDL）

```sql
CREATE TABLE IF NOT EXISTS prompt_material (
  id         bigserial PRIMARY KEY,
  slot       varchar(16)  NOT NULL,          -- fetch | judge | answer | check
  section    varchar(160) NOT NULL,          -- 小节名，如「八、审批停留」
  body       text         NOT NULL,
  sort_no    int          NOT NULL DEFAULT 0,
  enabled    boolean      NOT NULL DEFAULT true,
  version_no int          NOT NULL DEFAULT 1,
  updated_by varchar(64)  NOT NULL DEFAULT '',
  updated_at timestamptz  NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_material_slot ON prompt_material (slot, enabled, sort_no);

CREATE TABLE IF NOT EXISTS complete_rule (
  id         bigserial PRIMARY KEY,
  kind       varchar(16)  NOT NULL DEFAULT 'norm',   -- fill 补缺 / norm 归一
  match_text varchar(200) NOT NULL,
  fill_text  varchar(300) NOT NULL,
  priority   int          NOT NULL DEFAULT 100,
  enabled    boolean      NOT NULL DEFAULT true,
  updated_at timestamptz  NOT NULL DEFAULT now()
);
```

### 2. 新文件 `server/app/secretary/prompt_material.py`

对外函数（失败一律返回空，不许让问答崩）：

- `sections(slot)` → `[{id, section, body, sort_no, version_no}]`
- `text(slot)` → `'\n\n'.join(body)`（拼成给模型的段落）
- `chars(slot)` → 字数
- `save_section(id, body, user)` → 版本 +1
- `replace_slot(slot, rows, user)` → 整份覆盖（导入用）
- `all_slots()` → 五份的字数与节数

### 3. 规则导入 `tools/import_rules_to_materials.py`（新）

- 读 `server/app/secretary/skills/判据规则.md`（29113 字，60 主题）
- 按标题切分
- 按下面这张表分到四个 slot：

| slot | 装哪些章节 |
|---|---|
| `fetch` | 一、二、三、四、十三、十七（阈值） |
| `judge` | 五、六、七、八、九、十、十一、十二 |
| `answer` | 十五、十八、十九、二十（含 20.0~20.12）、二十一、二十二 |
| `check` | 十四、0.9（禁止的反模式）、22.5 |

- 零节（0.1~0.8）→ `fetch`（分流与拆解方法，查数时要用）
- `--dry-run` 打印分配结果，`--apply` 写库

### 4. 接口 `server/app/api/v1/prompts.py`（新）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/prompts/tree` | 主流程 14 节点 + 每节点挂的材料（静态定义） |
| GET | `/api/prompts/material/{slot}` | 某一份：字数、节列表、每节正文 |
| PUT | `/api/prompts/material/{slot}` | 整份保存（`[{id?, section, body}]`） |
| GET | `/api/prompts/preview` | 当前实际 system（调 `prompt_stack.build()`，分层返回） |
| GET | `/api/prompts/complete` | 补全表 |
| PUT | `/api/prompts/complete` | 补全表保存 |

写接口要管理员；只读材料（s0_redlines 等）不在 `prompt_material` 里，天然改不了。

### 5. 静态树定义 `server/app/secretary/prompt_tree.py`（新）

固定 14 个节点，每个节点带 `materials` 列表，元素形如：

```python
{'key': 'modes.text', 'name': '模式做法', 'editable': True, 'source': 'code:prompts_data.MODE_TEXTS'}
{'key': 'mat.fetch',  'name': '查数口径', 'editable': True, 'source': 'table:prompt_material'}
{'key': 'nc.typo',    'name': '纠错词典', 'editable': False, 'source': 'table:t_nc_typo'}
```

页面直接用这个结构渲染，不写死在 React 里。

### 6. 前端 `web/src/pages/Prompts.tsx`（新）

- 路由 `/prompts`，菜单「提示词」
- 左侧：14 个节点竖排卡片；每个节点右边挂它的材料按钮（可改=实线按钮，只读=灰）。
- 点材料 → 右侧抽屉：标题、字数、状态、正文编辑器（`textarea` 或按节折叠）。
- 可改的有「保存」，保存后提示"60 秒内生效"。
- 顶部一个「当前模型收到的提示词」按钮 → 调 `/api/prompts/preview` 显示全文。

### 7. 只读的材料在哪看

红线 / 优先级 / 身份 / 模式做法 / 汇报口吻来自代码常量，页面**只读展示**：
接口 `/api/prompts/preview` 已经把它们按层返回，页面直接展示每层正文。
