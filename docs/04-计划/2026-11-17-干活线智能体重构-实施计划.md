## 根因记录（P0 冒烟，2026-11-17）

### 现象 1：9 只工具全部返回 "An error occurred while running the tool."

- 复现：直接调 `runtime.run_stream`，「写个通知」→ 模型依次调 `read_skill`/`list_skills`/`make_file`，全部报错，最后模型改用正文兜底。
- 证据：`function_tool` 的默认失败处理把异常吞成一句通用文案；工具内部 `ctx.context` 取到 `None`，`c.user_id` 抛 `AttributeError`。
- 原因：`Runner.run_streamed(...)` 没传 `context=ctx`，`RunContextWrapper.context` 为空。
- 改法：调用时补 `context=ctx`；同时给每只工具挂 `failure_error_function`，把真实异常回给模型（不然下次还是只有一句通用文案）。

### 现象 2：`import app.agent.runtime` 报 `NameError: name '_err' is not defined`（tools.py:36）

- 复现：`python -c "from app.agent import runtime"` → 导入期即失败。
- 证据：装饰器 `@function_tool(failure_error_function=_err)` 在模块加载时求值，而 `_err` 定义在它下面（插在 make_file 之前）。
- 原因：补失败回显时把函数定义插到了第一只工具之后，Python 装饰器按从上到下求值。
- 改法：`_err` 上移到 `_file_ctx` 之后、第一只工具之前，一处定义、9 只共用。
- 判据：导入通过；工具报错时模型能读到 `工具执行失败：<异常>` 并自行改参数。
