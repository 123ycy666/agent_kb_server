## 1 引言

### 1.1 目的

规定随州、宜昌两套线上服务在部署、域名、登录态和发版上的要求，使二者完全独立、互不牵连。

### 1.2 范围

同一台服务器上的两个实例：随州（8200）与宜昌（8210），各自一个容器、一个库、一个主机名。不含产品功能改造。

### 1.3 读者与用途

运维按第 3 节实施；验收按第 4 节判定。

### 1.4 引用

- 本产品需求规格：`docs/04-计划/2026-11-19-骨架与业务库-需求规格说明书.md`
- 交接（含改法细节）：`C:\Users\Fred\.dsh\docs\2026-11-19-登录互挤与沙箱域名-交接.md`

### 1.5 术语

| 术语 | 定义 |
|---|---|
| 实例 | 一个容器，监听一个端口，连一个库 |
| origin | 协议 + 主机 + 端口三元组，决定浏览器 localStorage 的隔离边界 |
| 剥前缀 | nginx 把 `/sandbox/xxx` 转成 `/xxx` 后转发给后端 |

## 2 总体描述

### 2.1 现状

- 47.121.183.81 上 8200（随州，容器 `kb-merged`）与 8210（宜昌，容器 `kb-backend-sandbox`，现被叫沙箱）。
- 两个库都在同一个 `kb-postgres` 容器内。
- nginx 三个配置：`kb.conf`（`47.121.183.81`）、`sandbox.conf`（`sandbox.xibuyj.cn`，域名无 A 记录，从未生效）、`xibuyj.cn.conf`（静态站）。
- 前端两份产物：随州 `dist`、宜昌 `dist-sandbox`（`/sandbox/` 写死在包内）。
- `deploy.sh` 的 `CONTAINER / PORT / IMAGE / APP_DIR / DB` 为环境变量，nginx 段写死 `kb.conf`。

### 2.2 问题

1. 两个站同协议、同主机、同端口，浏览器视为同一 origin，共用 `kb_token / kb_user / kb_id`，而两边 JWT 密钥不同 → 后登的覆盖前一个，另一边 401 跳登录。
2. `sandbox.xibuyj.cn` 无 A 记录；且 `proxy_pass` 结尾不带斜杠、不剥前缀，`/sandbox/assets/*.js` 被后端当未知路由回 `index.html`，页面白屏。
3. 前端两份产物，发版要打两次。
4. `deploy.sh` 只认 `kb.conf`，推第二套会改到随州入口。

### 2.3 约束

- C-01 8210 外网不可达（安全组只放 80），不做端口方案。
- C-02 磁盘余量约 2.2G，禁止拉取新基础镜像。
- C-03 不得 `docker compose down` 整个 `kb-prod`（会停掉数据库容器）。
- C-04 两个库可同处一个 PostgreSQL 容器，但库名必须不同。

## 3 具体需求

### 3.1 功能需求（FR）

| 编号 | 需求陈述 | 验证方法 |
|---|---|---|
| FR-REL-001 | 两个实例各自独立部署：同一份产物，各自一个容器、一个库、一次发布动作。 | 演示 |
| FR-REL-002 | 只发布其中一个实例时，另一个实例不得被停止、换镜像或重启，登录态与会话不受影响。 | 测试 |
| FR-FE-001 | 前端只产出一份包，接口走相对路径；站点前缀由 nginx 剥离，不写死在包内。 | 检验 |
| FR-SCRIPT-001 | 发布脚本的 nginx 配置路径参数化，推第二套时不修改第一套的入口。 | 检验 |
| FR-DB-001 | 两个实例连接不同的库，库名不同，互不读写。 | 检验 |

### 3.2 接口需求（IF）

| 编号 | 需求陈述 |
|---|---|
| IF-DNS-001 | 每个实例一个独立主机名，从而成为不同 origin；禁止两个实例共用同一主机名与端口。 |
| IF-NGINX-001 | 带前缀的站点必须由 nginx 剥前缀后再转发，`proxy_pass` 结尾带斜杠，location 使用 `^~` 以避免被静态资源正则抢走。 |
| IF-NGINX-002 | 前端静态资源与接口均在同一前缀下可达，后端返回的未知路由不得替代静态资源。 |

### 3.3 非功能需求（NFR）

| 编号 | 需求陈述 |
|---|---|
| NFR-001 | 两个实例各自可登录，互不踢下线。 |
| NFR-002 | 发布失败可回滚到上一镜像，另一个实例不受影响。 |

## 4 验证与验收

| 验收编号 | 判据 | 方法 |
|---|---|---|
| AC-01 | 两个地址各登录一次，双方刷新后仍在登录态。 | 测试 |
| AC-02 | 两份前端主资源返回 `application/javascript`，不是 `text/html`。 | 测试 |
| AC-03 | 带前缀站点健康检查返回 `{"status":"ok"}`。 | 测试 |
| AC-04 | 同一份产物分别发布到两个实例，两个容器均正常，各自连接各自的库。 | 演示 |
| AC-05 | 只发布随州，宜昌的登录会话仍有效。 | 测试 |
