# 实施：删掉「认不出地点就静默沿用上一轮」

日期：2026-11-02
设计：`docs/03-设计/2026-11-02-地点解析三态.md`（上一版"加词表 + 别名跳跃"作废，
Fred 一句「又在加补丁？」否掉；这份按"删掉猜实体"重写）。

## 目标

1. 本轮问题提到单位名而系统没认出时，**不许**把它当成"没说地点"去套上一轮的范围。
2. 认不出就把"范围未定"写进口径，让模型按原话 + 业务库维表确认。
3. 删掉两处指向不存在模块（`object_index`）的死代码。

## 根因（服务器实测，确定性复现）

`time_scope.py:605-614` 里，`place_of()` 返回空串时静默 `place = prev['place']`：

```
prev=两水供电所
曾都供电所 / 曾都供电所情况怎么样 / 曾都所 / 曾都所呢 / 曾都那边 / 曾都的情况
    → 全部「两水供电所」（沿用）
曾都 / 曾都区 / 曾都区供电公司 → 正确认出「国网曾都区供电公司」
```

名录 51 条来自纠错词典 `t_nc_typo`，里面**没有「曾都供电所」**，只有「国网曾都区供电公司」
和简称「曾都区」—— 差一个「区」字整条落空。所以"偶然"是假象。

**为什么加提示没用**：`time_scope.py:634-635` 早就写了「如果本轮问题里其实提到了别的地点，
以问题里说的为准」，仍然错 —— 因为代码把「地点：两水供电所」钉死在【统计范围】里，
一句提示附注压不过一个钉死的范围。所以要**去掉钉死**，而不是再加判据。

## 不改什么

- 不加任何地点词表、不加 `曾都→曾都区` 这类别名跳跃（上一版就是死在这里）。
- 不改名录来源（纠错词典 vs 单位维表是**数据质量**问题，另开）。
- 不动时间解析、不动补全表、不动四份规则材料。
- 多轮沿用的机器字段保留（落库连续性靠它），只是**不再写进口径当既定范围**。

## 改法

`describe()` 的空地点分支：

| 情况 | 机器字段 `place` | 口径文本 | `place_confirm` |
|---|---|---|---|
| 上游强制 | 强制值 | 「强制按此范围取数」 | False |
| 认出地点 | 认出的地点 | 「地点：X」 | False |
| 明说全市 | 全市 | 「地点：全市」 | False |
| **认不出** | 沿用上一轮（或全市） | 「本轮范围未定」+ 条件指引 + 维表表名 | **True** |

口径文本（认不出时）：

```
地点：**本轮范围未定** —— 系统没从原话里认出单位名，这一轮不替你定范围。
      · 原话里没有单位名（纯追问，如「那售电量呢」）→ 沿用上一轮：两水供电所；
      · 原话里提到了单位（如「曾都供电所」）→ **不许用上一轮的范围**，
        先用 run_sql 查 t_power_supply_company / t_power_company 确认标准名再取数，
        查不到就反问一句是哪个单位，不要猜。
```

## 验收判据

`server/tests/agent/test_place_scope.py`（不连库，注入替身）全绿：

1. 认不出 + `prev=两水供电所`：「曾都供电所情况怎么样」「那售电量呢」→ `place_confirm=True`，
   口径含「本轮范围未定」和两个维表名，**不含**「地点：两水供电所」。
2. 明说全市：「全市情况怎么样」→ `place_confirm=False`、`place=全市`、口径含「地点：全市」。
3. 认出：「国网曾都区供电公司」→ 钉死、`inherited=False`。
4. 无上一轮 + 认不出：「曾都供电所」→ `place_confirm=True`，`place=全市`（机器默认）但口径仍是未定。
5. 上游强制 → 口径含「强制按此范围」。
6. 防回潮：`describe()` 的 `object` 恒为 None；源码里不再出现 `object_index`。

线上核对：连问「两水供电所情况怎么样」→「曾都供电所情况怎么样」，
第二轮 trace 的 `place_confirm=true` 且答案不再是两水的数。
