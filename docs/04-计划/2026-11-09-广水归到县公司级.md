# 裸地名「广水」归到县公司级（2026-11-09）

> 目标：用户只说地名、不带「公司 / 所」时，若这个地名既是县公司名的开头、又是该县某个所的全名，归到**县公司**那一级。
> 现状：`广水线损` → `广水供电所线损`（错一级）；应为 `国网广水市供电公司线损`。

## 口径

- 纠错词典 6 张表**没有优先级列**，`t_nc_catalog` 只有 `kind`（供电公司 / 供电所 / 供电服务站 / 台区）和 `owner`。
  选哪个名字由 `name_corrector._best_name_uncached.rank()` 决定，改表不生效；`t_nc_ambiguous.action` 也没接线（`self.ambiguous` 只建索引，无人读）。
- 因此改代码，判据只用库里已有的名字（不写死县名）：
  **候选里存在公司级单位，其核心地名以用户说的地名为前缀且更长（广水 ⊂ 广水市）** → 公司级优先。
- 影响面：51 个单位里只有「国网广水市供电公司（核心 广水市）← 广水供电所（核心 广水）」这一对满足，
  厉山 / 环潭 / 凉水 / 随县 / 高新 等裸地名不动。

## 根因（三层，缺一层就只改一半）

1. **级别不是排序键**。`rank()` 的键是「单位名优先 → 后缀同型 → 编号 → 汉字重合 → 覆盖度 → 名字长度 → 字典序」。
   单位名在 `area_core_str` 里没有核心串，汉字重合恒为 0 —— 于是单位之间实际只剩覆盖度和长度，
   两个都奖励更短的名字：广水供电所（核心 广水）覆盖 100%、5 个字；国网广水市供电公司（核心 广水市）
   覆盖约 75%、10 个字 → 所次次赢。
2. **同音栅栏会把它再丢一次**。`_is_glued_homophone` 拿候选**全名**去和用户片段比汉字重合，
   「广水」对「国网广水市供电公司」一个字都不重合 → 后面跟着「的」这类功能字时判为噪声，整段不改。
   所以只改 rank 会出现「广水线损」对了、「广水的线损」反而一点没改（实测）。
3. **候选表本身有重复**。`unit_spans` 按「核心地名的每个前缀」各存一份，广水市的前缀「广水」「广水市」
   都能命中 → 同一公司进候选两次，`alts` 里报给用户「其他候选」重名，`候选数` 也虚高。
4. **「广水所的线损」本来就是错的（与本次改动无关的旧 bug）**，改前输出「广水供电所**所**的线损」。
   `_TAIL_BLOCK_NEXT`（「所」后面跟这些字就不吸收后缀）里塞了 的/了/是/都/也/还/把/将/会/均 这些**纯功能字**，
   于是「所」+「的」时 `_asked_unit_kind` 返 None（认不出用户说的是所）、`_absorb_tail` 也不吸收，
   原地那个「所」没人吃 —— 补成「广水供电所」+「所」。
   这个名单本意是拦「广水**所有**台区」，只需留 有/以/在/属/述/需/及/对/长/谓/上/下/内/外 这类真能与「所」成词的字。
   **不修它，第 1 条会让「广水所的线损」跳到公司级**（用户明明写了所），所以它是补丁的必要一环。

## 步骤

1. 在临时副本上试补丁（项目文件不动），跑 `db/lexicon.sql` 离线数据源对照改前 / 改后 → verify：新用例翻转、旧用例不动。
2. `name_corrector.py` ①单位名收集处加去重（`unit_spans` 按前缀存多份，同一公司会进候选 2~3 次，`alts` 里重名）→ verify：`广水` 候选数 3 → 2。
3. `rank()` 加「级别优先」键，排在「后缀同型」之后、「编号 / 汉字重合 / 覆盖度」之前 → verify：`广水线损` 出公司级。
4. 回归用例补进 `server/tests/test_name_level.py` → verify：12 条旧用例 + 2 条新用例全绿。
