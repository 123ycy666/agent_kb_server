## 0. 三句话结论

1. **两个仓库没有任何共同提交**（`git rev-list` 交集 = 0），但内容上有共同祖先 `20c2d60`（2026-10-13 那次「知识库迁移 + 服务器代码同步」）。所以这不是「拉个新版本」，而是**两条并行线要合流**：新仓库是 server 那条线的延续，本地 main 是秘书那条线的延续。

## 7. 风险（按严重度）

1. **本地 671 行未提交改动会被覆盖** —— S0 不先提交，守卫层与名称归一修复就只在工作区里，一次 checkout 就没了。
2. **本机没有 PostgreSQL**（F14）—— 不装 PG + pgvector，合并后的平台根本起不来；`docker compose` 也用不了（无 docker）。
3. **线上磁盘 95%（剩 2.4 G）、py3.9.6**（F15）—— 将来切线上时，PG 数据 + node 构建产物 + Python 3.12 都挤不进去，得先清盘或换机（**本轮不动**）。
4. **包路径漏改会静默失效** —— 10-16 那个 `SKILL_DIR` bug 就是「路径算错 → 技能台整片空白，没有任何报错」。S3 的验收判据专门盯这个。
5. **两套部署方式并存** —— `deploy_update.py`（rsync+systemd）与新仓库的 docker/start 脚本互斥，切换期只能留一套。
