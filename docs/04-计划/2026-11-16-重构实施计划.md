# 秘书智能体重构 实施计划（可勾选）

> **给执行者**：本计划由 `writing-plans` 生成，配套技能 `test-driven-development` / `executing-plans` / `test-evidence` / `verification-before-completion`。步骤用 `- [ ]` 跟踪，勾完即完成。
>
> 唯一依据：`docs/04-计划/2026-11-12-秘书智能体-需求定稿.md`（需求）+ `docs/04-计划/2026-11-12-重构实施流程.md`（流程与判据）。需求不再讨论。

**Goal：** 把现有秘书智能体改成"偏办公和问数的完整智能体"——说明书驱动的干活循环 + 原封不动的问数链路 + kb/cfg/qa/base 四分组 PG + 9 个一级页前端，按 V1–V18、E1–E10 验收。

**Architecture：**
- **两条线，入口分一次**：`router.route()` 仍判 ask_db / office；ask_db 线（`preprocess` / `evidence*` / `_write_answer` / `tools_db` 安全闸）**一行不改**，只把口径材料的读取来源换成新表。
- **干活线新循环**：`loop.py` 给模型 7 只工具（检索资料 / 读文档全文 / 读会话文件 / 查数 / 出文件 / 自检 / 收尾），命中说明书→读正文→执行→自检→交付；四件套结构化落库。
- **说明书层 = 能力来源**：`kb.spec` 一族，上传即分类（待发布→预览→发布），配文档即加能力，不重启不发版。
- **PG 四分组 + public 兼容视图**：28 张表按 kb/cfg/qa/base 归位，`public` 只留同名简单视图（PostgreSQL 简单视图自动可写），旧代码零改动继续跑。

**Tech Stack：** Python 3.12 / FastAPI / psycopg3 / PostgreSQL 16（扩展 vector）/ MySQL 8 只读 / React 18 + antd + Vite / python-docx, openpyxl, python-pptx。

## Global Constraints（禁区，逐条硬约束）

1. 问数链路 `preprocess`（纠错/补全/补问法/问题确定）、`evidence*`（证据包）、对账与 `_write_answer`、`tools_db` 的 SQL 安全闸 **一行不改**；只允许换口径材料的读取来源，注入方式与顺序不变。
2. 入口分流保留（问数 / 干活两级），**不许合成一条线**。
3. 业务库 MySQL **只读**，不许写。
4. 工作流 9 张表与 `ad_wf` 库 **不动**。
5. **不许**新增"只有代码认识、页面看不见"的配置。
6. 每阶段先写能跑出 pass/fail 的检查，再写实现。
7. 每阶段结束跑判据 + 证据落 `output/test_results/<日期>-<阶段>/00-index.md` + 提交（提交信息写清改了什么/为什么/判据编号）。
8. 前端改动必须留改造前后截图。
9. 同一问题改到第 3 次说不清根因 → 停，换根因分析，不打补丁。
