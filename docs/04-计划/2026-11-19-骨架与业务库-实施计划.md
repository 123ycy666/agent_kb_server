# 骨架与业务库 实施计划（2026-11-19）

> 每步的「跑测试」都是可执行脚本（本仓库不装 pytest）：`python server/tests/xxx.py`，退出码即结论。
> **For agentic workers:** 按 T0→T8 顺序执行。每步先有能判 pass/fail 的检查，再写实现。步骤用 `- [ ]` 跟踪。
> 设计依据：`docs/03-设计/specs/2026-11-19-骨架与业务库-design.md`（下称 DESIGN）
> 需求：`docs/04-计划/2026-11-19-骨架与业务库-需求规格说明书.md`（SRS-01）、`docs/04-计划/2026-11-19-两套线上服务-需求规格说明书.md`（SRS-02）

**目标**：一个现场 = 一个 PG 库。同一份代码/前端产物服务任意现场；未配置或连不上时只剩「现场配置」页；业务内容全部来自当前库；切现场旧 token 失效、系统账号仍有效。

**技术栈**：FastAPI + SQLAlchemy 2 + psycopg3（PG16 / pgvector）、React 18 + Vite + antd、nginx + docker、bash 部署脚本。

## Global Constraints

- 随州不许退化（NFR-003）：本地 `ad_new` 的 `cfg.*` / `kb.*` 验收后内容不变（行数 + 关键正文逐项比对）。

- 仓库 hook：计划必须新鲜（<24h）且点名要新建的文件；同一文件改到第 7 次要有「根因」段。
- `docgen.py`、`office_runner.py`、`workflow/*.py` 带 BOM，读写按 `utf-8-sig`；中文文件写入用 Python `Path.write_text(encoding='utf-8')`，不要用 PowerShell 管道重定向。
