## 根因（有证据，2026-10-29 线上 47.121.183.81）

### ① 个人知识库「没生效」是**两层都没走到**，不是配置丢了

**第一层：文档根本没进「我的资料库」。**

| 库 | created_by | 文档 | 切片 |
|---|---|---|---|
| 1 系统知识库 | 1 | **6** | **251** |
| 2 我的资料库 | 1（Fred） | **0** | **0** |
| 3 我的资料库 | 6 | **0** | **0** |

- 全部 6 份文档都在 kb=1。今天 09:17 传的「台区项目情况查询规则.md」
  （doc id=8，owner=1，private，20 切片）也是 kb=**1**。
- 线上 `async_task` 里**只有一条** `doc_ingest`：kb_id=**1**、created_by=1、09:17:30 `done`。
  → 没有任何一次上传是冲着 kb=2/3 去的。也就是说"配到个人库"这个动作实际上没发生
  （问答页的「📎 文件」走 `/api/files` → `data/doc_files`，是**一次性临时文件**，不进知识库；
  要进个人库只能走 `POST /api/v1/kb/{kb_id}/documents`）。
- 另外线上有**两个同名「我的资料库」**（kb2 属用户1、kb3 属用户6），前端列表不区分，
  用户根本认不出哪个是自己的 —— 传错的概率很高。

**第二层：就算进了可见范围，模型也不会去查它。**

- trace 125（09:20:24，上传后 3 分钟问「龚家棚村4#台区项目情况」）：
  `kb_query_count=0 / db_query_count=1 / steps=4` → 只走了 `run_sql` + 规则检索，**一次 kb_search 都没调**。
- 全量 117 轮问答里只有 **8 轮**（6.8%）调过 `kb_search`，命中全在 kb1 的旧文档上。
- 规则通道 `rule_slices()` 只认 `config.RULE_DOC='判据规则'` 这一篇（`SECRETARY_RULE_DOC`），
  传到库里的其它文档（如「台区项目情况查询规则.md」）**进不了规则通道**，
  只能靠模型自己想起调 `kb_search` —— 而它没有。
- 结论：**用户自建文档的生效路径只有一条"模型主动 kb_search"，而这条路径 93% 的情况下不会走。**

### ② 「每步运行日志」：有数据，但传出去的不是日志

- `/api/ask` 响应里有 `trace`（每步：kind / tool / args / result / ms），线上每轮 4~7 步；
  落库 `t_chat_trace_step` 也正常（**562 行**）。所以"没有每一步"不成立。
- 真正缺的三块：
  1. **只有技术 JSON，没有一句人话**（前端"处理过程"就是把这坨 JSON 展开给用户看）；
  2. **历史接口把内容裁掉了**：`qa_log.get_history(with_steps=True)` 只 select
     `step_no/step_kind/round_no/tool_name/sql_text/result_rows/cost_ms/model_ms/status/error_msg`，
     **不含 `input_text` / `output_text`**（DB 里明明有）→ 历史页只能看到"第几步、什么工具、多少毫秒"；
  3. **没有"这次检索了哪些库 / 命中多少"的记录**：响应里无 `kb_scope` 字段，
     `trace` 里也没有"检索范围"这一条（这正是判断"个人库到底有没有生效"最需要的日志）。
- 另外 `AskResponse` 契约里只声明了 `trace`（注释写"仅调试用"），外部集成方按契约也拿不到日志。

## 方案

### A 档：最小改动（不动问答主链路，约半天）

| # | 改动 | 动哪里 | 怎么验 |
|---|---|---|---|
| A1 | 知识库列表只给「系统库 + 本人库」，并加 `is_mine` / `is_system` 字段；问答页勾选框显示「我的资料库（本人）」 | `services/knowledge_base.list_knowledge_bases` + `schemas/kb.py` + 问答页 `loadKbs()` | 两个账号登录，各自只看到一条自己的「我的资料库」 |
| A2 | 个人库上传入口 + 上传后回显（解析状态/切片数）；`📎` 上传提示"临时文件，只对本轮有效" | 知识库页/问答页 + `static/index.html` | 传一份 → `/api/me/personal-kb` 里 `files=1, chunks>0` |
| A3 | **`/api/ask` 响应新增 3 个字段**：`kb_scope`（实际检索的库 id+名）、`kb_hits`（kb_search 命中条数）、`steps_log`（每步一行中文） | `agent.ask()` 返回 + `schemas/agent.py` | 同题连问两次：配前 `kb_hits=0`、配后 `>0`，一眼可判 |
| A4 | `get_history(with_steps=True)` 补 `input_text/output_text`（DB 已有，只是没 select） | `qa_log.get_history` + `web/src/api/index.ts` 的 `TraceStep` | 历史页每步能展开看到输入/输出原文 |
| A5 | 个人库 `qa_enabled` 默认改 false（别的用户的个人库不再被前端自动勾进检索范围） | `personal_kb.ensure` | 问答页默认勾选里不再出现别人的库 |

### B 档：让它真的"生效"（改设计，1~2 天）

| # | 改动 | 为什么 |
|---|---|---|
| B1 | **个人库预检索**：命中制度/流程/规则/模板/口径类问法，或用户勾了个人库时，循环前先做一次 `kb_search`，把命中切片按"事实来源"注入（和 `doc_context` 同一条注入通道） | 模型 93% 不主动查库，靠提示词催不动（已试过硬提示，见 trace 里 nudge 记录） |
| B2 | **规则通道支持多篇**：`RULE_DOC` 从单篇改成列表（站点配置 + 个人库里的"规则/口径"文档），一起进 `rule_slices()` | 现在只认《判据规则》一篇，用户自建的规则文档天生无效 |
| B3 | `steps_log` 落库（`t_chat_trace_step` 加 `log_text`）+ 接口文档升 v1.5 | 外部集成/历史页/排障都用得上 |

### 不做

- 不改 `run_sql` 的必用约束（会拉长所有问数题的耗时）。
- 不做"人人一套向量空间"（个人库已复用公司库底座，够用）。

## 补全字段实测（2026-10-30 线上抓的真实响应）

Fred 问「线上接口到底有没有补全的内容」。实测（`output/test_results/2026-10-29-个人库与步骤日志/ask-response-full.json`，
问句「环谭供电所上个季度的工单有多少单」，user_id=1，10 KB / **35 个字段**）：

| 字段 | 实测值 | 说明 |
|---|---|---|
| `input_question` | 环谭供电所上个季度的工单有多少单 | 用户原话 |
| `fixed_question` | 环潭供电所上个**未确定**的工单有多少单 | 纠错+时间替换后 |
| `completed_question` | 同上（与 fixed_question **完全相同**） | `completion_used=false`：问题改写已取消 |
| `scope` | `{time:未确定, period_type:month, period_key:202610, place:环潭供电所}` | 时间/地点口径 |
| `name_fix_used` | true | 环谭→环潭 命中 |

→ **补全内容确实返回了**（前端 F12 能看到的 `completed_question` 就是它）。
→ 但**补的是什么，取决于 time_scope 认不认得**：本例把「上个季度」替换成了「未确定」，见下条 bug。

## 新发现 bug B0：「上个季度」被改写成「上个未确定」（2026-10-30 线上实测）

- 证据：`fixed_question = 环潭供电所上个未确定的工单有多少单`；
  trace seq=2 `{"matched":"季度","time":"未确定","period_key":"202610","hint":"问题里的「季度」没能对上可用的口径…"}`；
  模型回答开头也照抄了病句「您提到的"上个未确定"时间口径不明确」。
- 根因（两处叠加）：
  1. `time_scope.resolve` ⑥ 的季度正则只认 `[1-4一二三四]季度 | 本季度 | 这个季度`，
     **「上个季度 / 上季度 / 上一季度 / 下个季度」全部漏掉**（`time_scope.py:398`）；
  2. 落到 ⑥′「有时间的字眼但没对上口径」时 `_mk(_hint, '未确定', ...)`，
     而 `_mk → _rewrite(q, '季度', '未确定')` **把原文里的词替换成了「未确定」**（`time_scope.py:420-426`、`222-226`）。
  3. `period_key` 还是 `202610`（系统当月），与「未确定」自相矛盾；本轮靠模型自己反问才没算错数。
- 影响：病句进三处 —— 前端"补全参考"、模型输入、规则检索 query（trace seq=3 的 query 也是病句）。
- 修法（两行级）：① ⑥ 补相对季度词（上个/上/上一个/下个/下一个/上上季度），能算出具体区间；
  ② 兜底分支**不许改写问题文本**：`time_text='未确定'` 时 `_rewrite` 返回原句（保留「季度」原词）。

## 身份链实测（2026-10-30，线上只读）

「个人库要不要并入」只看**登录 JWT 的 user.id**，不认请求里的 `uid`。线上实测：

```
with_personal([1], user_id=1) = [1, 2]     # user1 → 并 kb2
with_personal([1], user_id=6) = [1, 3]     # user6 → 并 kb3
stats(user=1) = {'files': 0, 'chunks': 0}  # 库是空的
```

→ **id 没漏**；那次 `/api/ask` 用的是 JWT sub=1，个人库 kb2 **确实并进了检索范围**，
只是 0 切片，所以"等于没查"。

**四种会"漏"的情形（现在都是静默的，必须改成显式）：**

| # | 情形 | 现状 |
|---|---|---|
| L1 | `actor.user_id` 为空（无登录身份/服务账号） | `with_personal` 抛错被吞，只 print 一行；问答照常，用户看不出 |
| L2 | 上游传 `uid=xxx` 想指定"以谁的身份检索" | `uid` 只做记录（`AskRequest.uid` 注释"记录用"），**不参与检索身份** |
| L3 | sga/大屏用固定账号换 token 代所有人提问 | 个人库永远是那个固定账号的，其他人的个人库永不生效 |
| L4 | 上传人 ≠ 提问人（管理员代传 / 📎 临时文件） | `document.owner_id` = 上传人，提问人看不到 |

## 规则设计（让个人库"按设计生效"，Fred 拍板后落地）

| 规则 | 内容 | 落在哪 |
|---|---|---|
| **R1 身份** | 检索身份 = JWT 的 `user.id`，**唯一来源**，禁止用 `uid`/参数覆盖；`user_id` 为空时**不猜**，在响应里写 `personal_kb.enabled=false` + 原因（不许静默） | `agent.py` 的 `/ask`、`personal_kb.with_personal` |
| **R2 归属** | 个人库 = `knowledge_base.created_by = user.id 且 name='我的资料库'`；文档归属 = `document.owner_id = user.id`；代传只允许管理员且要写进目标的库 | `personal_kb.ensure`、`documents.upload` |
| **R3 范围** | 一次问答的检索范围 = 公司库（`qa_enabled`）+ **本人**个人库；**别人的个人库永不进 scope**；前端只显示「系统库 + 我的资料库」 | `_resolve_kb_scope`、`list_knowledge_bases`、问答页 `loadKbs()` |
| **R4 触发** | ① 命中"我的/我们的模板/我的口径/我上传的"→**必查**个人库；② 命中制度/流程/模板/格式类词 → 先查（公司库+个人库）；③ 纯问数（多少/排名/趋势）→ 业务库为主，个人库只作口径补充；④ 用户手动勾了个人库 → 必查 | `modes.judge` + `agent.ask` 预检索 |
| **R5 优先级** | 数字与事实：业务库 > 公司库 > 个人库；**格式/模板/文风**：个人库 > 公司库；**判据/阈值**：公司《判据规则》 > 个人库（个人库只能补充口径，不能改阈值） | 提示词 + `rule_slices` |
| **R6 可观测** | 响应新增 `kb_scope`（库 id+名+是否个人库）、`kb_hits`（每库命中数）、`personal_kb`（是否并入/文件数/切片数）；个人库为空或解析失败要在回答里明说 | `agent.ask` 返回、`schemas/agent.py` |

## 验收判据（可机器判真假，不用"感觉生效了"）

1. **暗号测试**：往「我的资料库」传一份含唯一暗号（如「环潭所对外话术是：先讲安全再讲进度」）的文档
   → 问「环潭所对外话术怎么写」→ 答案必须出现暗号，且响应 `kb_hits.personal > 0`。
2. **隔离测试**：换另一个账号问同样问题 → 答案**不得**出现暗号，`kb_scope` 里不得有对方库 id。
3. **静默测试**：个人库为空时提问 → 响应 `personal_kb.enabled=true, files=0`，回答里提示"资料库为空"。
4. **代问测试**：用固定账号换 token 代员工提问 → 明确返回 `personal_kb.enabled=false, reason=fixed_account`。

## 系统提示词构成体检（2026-10-30 线上实测，`_scratch/probe_prompt_online.py`）

线上**走 V2 七层装配**（system 含 `【装配说明】`），实测数据：

| 模式 | system 字符数 | 分层 | 说明 |
|---|---|---|---|
| data | **31,295** | L0 224 + L1 299 + L2 633 + L3 6,469 | 其余约 **2.4 万字符是「码表 + 表目录」**（`semantic.codes_menu()` / `table_menu()`） |
| general | 1,165 | L0 + L1 + L2 | 不给工具、无 L3、无码表 |

**五个问题（都可验证）：**

| # | 问题 | 证据 |
|---|---|---|
| **P1** | **legacy 的《规则优先级》段在 V2 下丢了** —— "user 段【统计范围】 vs system【时间处理】谁赢"没有裁判 | 线上 `含规则优先级段 = False`；而 L3 `business_rules` 里仍有【时间处理】"未指定年份默认当前年份"，与 user 段"不要自行推算日期"直接冲突 |
| **P2** | **没有「个人口径/规则」这一层** | L3 六段全部来自站点包（公司）；L6 只装格式偏好(prefs)；`modes.judge('按我的口径怎么写')` → **general**（没有 L3、没有工具） |
| **P3** | **体量失衡**：data 模式 3.1 万字符里，公司口径仅 6.5k，码表+表目录 2.4 万 → 个人规则即便注入 500 字也只占 1.6%，等于被淹没；且一轮循环 4~8 次，每次都重发 | 分层字符数见上表 |
| **P4** | **文案写死单篇规则**："标准只认《判据规则》，里面没写的不许自己编" —— 即使注入了个人规则，提示词也在明令否定它 | `agent.py:621-622`、`agent.py:1173-1183` |
| **P5** | **静默降级不可见**：站点包缺失→回落 legacy 或一句 `_FALLBACK`；`/health` 不报装配结果 | `agent_v2.system` 的 except 分支只 print |

**目标结构（建议）：**

```
system: S0 红线 → S1 事实与口径优先级（补回）→ S2 身份 → S3 模式做法
        → S4 公司业务口径(L3) → S5 我的口径与规则(新增,任何模式都注入,限量)
        → S6 个人偏好 → S7 会话人设 → S8 技能 → 日期
        → 码表/表目录（按需：仅本轮要查数时给，且收缩）
user  : 本轮问题(已纠错补全) + 统计范围 + 公司规则切片
```

**构成合规检查（可机器判）**：① system 必含 S1 优先级段；② 有个人规则时必含 S5 且字数达标；
③ general 模式也有 S5；④ 文案不出现硬编码单篇规则名；⑤ `/health` 返回
`prompt: {mode, layers, chars, has_priority, personal_rules}`。
