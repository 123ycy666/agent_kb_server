# 实施计划：工具化（分流三布尔 + 四只手 + 回答四份规则）

- 日期：2026-11-05 ｜ 分支：`feat/tools-routing`（原分支 `main` @ 37fd9b1）
- 设计：`docs/03-设计/2026-11-05-智能体架构-分流与工具.md`

## 目标

第 1 步判三个是/否（查库 / 读文件 / 出文件），第 7 步按判定给工具子集，第 8 步按动作拼回答规则；主循环仍只有一份，问数链路不动。

## 验收

1. 「你好」→ 0 次工具调用，system 不带查数口径。
2. 「今年预算执行得怎么样」→ 给查数 5 只，跑 `run_sql`，回答与现在同构。
3. 上传 20+ 页 docx 说速读 → 给 `read_file`，按页读，出清单带出处。
4. 说「做成 PPT」→ 走 `make_file`，产物过 `inspect_deck`，给下载链接。
5. 上传 xlsx 说审查 → 给 `read_file`，出问题清单。

## 根因（改前先记）

- 主循环每轮把 6 只查数工具全给、查数口径无差别注入 → 聊天也背表结构；
- 文件正文靠 `doc_context` 一次性注入，长文只给 8 段 → 速读看不见第 9 页以后；
- 模型没有读文件 / 出文件的手 → 只能描述，给不出文件。
