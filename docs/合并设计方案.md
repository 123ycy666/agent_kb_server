## 二、总体架构：一个仓库、两个服务、一个门户、两个数据库

```
合并系统+统一用户表/
├── server/            # 服务 A：知识库后端（FastAPI，:8000）
│   └── app/           #   内容存 PostgreSQL（docker 5433，pgvector）
├── agent/             # 服务 B：问数智能体（:8200，原 secretary 整体迁入）
│   └── 数据走 MySQL：dlj_data(只读) / ai_data(只读) / agent_data(读写)
├── web/               # 统一前端门户（React + AntD，:5173）
├── data/              # 上传文件与种子文档
├── docker-compose.yml # PostgreSQL+pgvector / Redis
└── .env               # 唯一配置文件：模型双通道 + 双数据库 + 内部令牌
```

**为什么保留两个服务进程而不是揉成一个**：agent 是标准库 http.server 实现（602 行 server.py + 810 行 agent.py），
长期稳定运行；强行改写进 FastAPI 收益低、风险高。两个服务通过本地 HTTP + 内部服务令牌协作，
对使用者仍是「一个系统、一个账号、一个入口」。

## 三、统一用户表设计（核心）

### 3.1 数据源角色

| 表 | 位置 | 角色 |
|---|---|---|
| `dlj_data.t_employee` | MySQL | **用户唯一权威源**（只读）：login_name / login_pwd(argon2id) / actual_name / administrator_flag / disabled_flag / deleted_flag |
| PG `app_user` | PostgreSQL | **本地投影表**（保留）：external_id=employee_id，username=login_name，display_name=actual_name，password_hash 置空 |
| PG `role / permission / user_role` | PostgreSQL | RBAC 权限体系**原样保留**（admin/user 两种角色） |

### 3.2 登录流程（auth.py 改造）

```
POST /auth/login {username, password}
  → ① MySQL 查 t_employee（login_name，deleted_flag=0 且 disabled_flag=0）
  → ② argon2id 校验 login_pwd（新增 argon2-cffi 依赖，security.py 增加 verify_argon2id）
  → ③ upsert PG app_user 投影行（username 对齐则复用旧行 ⇒ 存量文档 owner_id 不变）
  → ④ 角色同步：administrator_flag=1 → admin 角色；否则 → user 角色
  → ⑤ 签发 JWT（sub = app_user.id），后续权限判定全部走原 RBAC，零改动
```

### 3.3 影响面（改动清单）

| 文件 | 改动 |
|---|---|
| `server/app/core/security.py` | 增加 argon2id 校验函数（bcrypt 保留兼容旧哈希） |
| `server/app/core/database.py` | 新增 MySQL 引擎/Session（pymysql），仅用于员工认证 |
| `server/app/services/employee.py` | **新增**：MySQL 员工认证 + 投影同步的唯一出口 |
| `server/app/api/v1/auth.py` | login 改为 t_employee 认证；change-password 改为禁用（密码归 HR 系统管） |
| `server/app/api/v1/roles.py` | 用户管理 API 改为「员工列表（同步展示）+ 角色分配」 |
| `web/src/pages/Login.tsx` | 文案改为员工账号 |
| `web/src/pages`（用户管理页） | 员工列表 + 角色分配，去掉本地建用户 |
| `web/src/App.tsx:76` | 顺手修 P0 缺陷：`perm="role:read"` → `"user:manage"` |

### 3.4 账号停用/删除的语义

t_employee.disabled_flag=1 → 投影行 status=disabled，登录拒绝（403）；
deleted_flag=1 → 登录拒绝。历史数据（文档、审计）保留，不级联删除。

## 四、大模型 / 向量模型：本地 + 线上双通道

统一配置节（根 `.env`），一个总开关 `MODEL_CHANNEL`：

| 通道 | 用途 | 默认端点 |
|---|---|---|
| `mock` | 零依赖演示/自测（伪向量，不可评估检索质量） | 本地确定性实现 |
| `local` | 公司内网自建（vLLM / Xinference / Ollama，OpenAI 兼容） | bge-m3 / bge-rerank-m3 / deepseek-chat |
| `online` | 线上 API（阿里云百炼 compatible-mode） | text-embedding-v4 / gte-rerank-v2 / qwen3.8-max |

```bash
MODEL_CHANNEL=mock                 # 总开关：mock | local | online
# ── 本地通道 ──
LOCAL_LLM_BASE_URL=http://127.0.0.1:8000/v1
LOCAL_LLM_MODEL=deepseek-chat
LOCAL_EMBEDDING_URL=http://127.0.0.1:9997/v1/embeddings
LOCAL_EMBEDDING_MODEL=bge-m3
LOCAL_RERANK_URL=http://127.0.0.1:9997/v1/rerank
LOCAL_RERANK_MODEL=bge-rerank-m3
# ── 线上通道 ──
ONLINE_LLM_BASE_URL=https://llm-xxxx.maas.aliyuncs.com/compatible-mode/v1
ONLINE_LLM_API_KEY=sk-...
ONLINE_LLM_MODEL=qwen3.8-max
ONLINE_EMBEDDING_BASE_URL=...      # 百炼 text-embedding-v4（1024 维，与 bge-m3 同维）
ONLINE_RERANK_MODEL=gte-rerank-v2
```

- 知识库 `providers/factory.py` 改为按 `MODEL_CHANNEL` 装载 mock/local/online 三实现
  （online 实现从 `_backup_online_providers` 恢复适配，原项目 10-13 删档，本次按双通道要求恢复）
- agent 的 `config.py`：LLM_BASE/LLM_KEY/MODEL 从统一通道派生，不再单独读百炼 key
- ⚠️ 向量空间不兼容：切换 embedding 通道后必须重建索引（沿用原项目的 `embedding_model` 记录 + 重建提示）

## 五、agent ↔ 知识库协作方式

- `agent/kb_client.py` 的 `KB_BASE` 改为本地 `http://127.0.0.1:8000/api/v1`（不再绕公网 47.121.183.81）
- 知识库 `deps.py` 增加**内部服务令牌**通道：请求头 `X-Internal-Service-Token` 与 `.env` 中
  `INTERNAL_SERVICE_TOKEN` 相符且来源为 localhost 时，以系统身份放行（仅 /search 等只读检索接口）
- 这样不需要知道任何员工密码即可完成服务间调用；对外接口仍必须 JWT

## 六、前端统一入口

- React 门户导航增加「智能问答」入口 → 跳转 `http://127.0.0.1:8200/`（地址写在 .env，前端可配）
- agent 的三个静态页（问答页 / 语音页 / 技能台）继续由 agent 服务提供，不改写
- 模型配置页改造为双通道端点表单 + 通道切换（复用原 persist_provider_mode 思路）

## 八、启动方式（合并后）

```bash
# 0. 配置
copy .env.example .env      # 填 MySQL 密码、模型通道、内部令牌

# 1. 基础设施
docker compose up -d        # PG 5433 + Redis 6380

# 2. 知识库后端（含员工投影初始化）
cd server && python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3. 问数 agent
cd agent && python server.py            # 默认 127.0.0.1:8200

# 4. 前端
cd web && npm install && npm run dev    # 5173
```

## 九、验收标准

1. 用 t_employee 真实员工账号登录知识库前端成功，JWT 与权限正常
2. 管理员（admin）可见用户管理/审计；普通员工不可见
3. 上传文档 → 检索 → 问答全链路通（按所选模型通道）
4. agent 问答页提问 → 内部令牌调知识库检索 → 模型作答 → agent_data 留痕
5. `server/tests/selfcheck.py` 与 `agent/tests/test_semantic.py` 通过
