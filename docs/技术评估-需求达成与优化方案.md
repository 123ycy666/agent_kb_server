## 二、没完成 / 不足的（技术层面，按严重度）

### A. 与"企业级可用"直接相关的硬缺口
1. **本地模型没真正接**：当前 `.env` 是 `online` 档（阿里云+DeepSeek）。你已部署 bge-m3/bge-rerank-m3，但 `local` 档只是代码就绪、未启用、未配 `LOCAL_*` 地址。这是原始需求的核心，"壳子"要变"能用"必做这一项。
2. **异步任务没上 Celery**：`app/tasks/` 是空目录，`requirements.txt` 声明了 `celery+redis` 但零引用。上传/向量化走 `BackgroundTasks`（进程内）→ **重启丢任务、无重试、无死信**。好消息：接口契约已是 `202+task_id` 异步形态，将来换 Celery 不用改调用方。
3. **无 RAG 问答前端**：后端 `/chat`（RAG）已实现，但 `web/src` 里**没有对话页**（只有 `SearchTest` 检索测试页）。"连接本地大模型"通常期望能问答。
4. **OCR 缺失**：扫描件 PDF 无法解析（图片型 PDF 进库是空切片）。
5. **存储一致性巡检缺失**：`data/uploads/` 曾被清空、DB 记录完好，DB 与磁盘漂移无巡检脚本（已知待办）。

### B. 工程化 / 可靠性 / 安全
6. **测试工程化缺失**：`pyproject.toml` 配了 pytest+ruff，但 `tests/` 全是手写 `__main__` 脚本；**无 CI**（无 `.github`）、无 pre-commit。
7. **迁移体系没走正路**：`alembic/versions` 为空，靠 `db_init.py` 幂等 `ALTER TABLE`。小项目可接受，演进规模大后失控。
8. **安全**：`jwt_secret`/`bootstrap_admin_password` 硬编码 dev 默认值、`debug=True` 默认；**token 无撤销**（登出后 12h 有效）；限流只覆盖 API 应用层，**JWT 用户完全不限流**；无登录失败锁定。
9. **可靠性**：模型调用**只有 timeout、无重试/退避/熔断**；后台任务无重试/死信；无优雅关闭。
10. **可观测性**：无 metrics / 链路追踪 / 告警；日志仅 `basicConfig`，非结构化。
11. **数据治理**：删除即硬删（无回收站）；无备份/恢复策略；审计日志无保留策略。
12. **成本**：embedding 批量无并发/限流控制；冲突检测每个候选一次 LLM 调用（已有 `conflict_max_llm_calls=12` 上限兜底）。

### C. 检索质量（有 RRF+rerank，但还能更准）
13. 无 **parent-child**（小块检索+父块返回）→ 长文档召回完整度有限。
14. 无 **query 改写**（HyDE / 多查询）→ 口语化提问召回弱。
15. **无检索评估集** → 无法量化 recall@k / MRR，优化只能"凭感觉"。

## 三、优化方向与方案（按 ROI 排序）

### 优先级 P0 — 把"壳子"变成"能用"
- **① 真正接通本地模型**：`.env` 改 `PROVIDER_MODE=local` + 填 `LOCAL_EMBEDDING_URL/LOCAL_EMBEDDING_MODEL=bge-m3/LOCAL_RERANK_URL/LOCAL_RERANK_MODEL=bge-rerank-m3/LOCAL_LLM_BASE_URL`；新建 KB 时 embedding 选 bge-m3（**1024 维**，需新建或重建索引）。风险：bge-m3 与现 online 档向量空间不同，存量向量必须重建，否则静默失效。
- **② 补 RAG 问答页**：后端 `/chat` 已具备，前端加 `Chat.tsx` + 路由即可，是"连接大模型"最直观的验收入口。

### 优先级 P1 — 检索质量可量化
- **③ 建检索评估集 + 指标**：准备 20~50 条 (问题, 期望文档) 黄金集，跑 recall@k / MRR。先量化再调，避免盲改。
- **④ parent-child 检索**：切分保留"父块 id"，检索用小切片召回、返回父块上下文，提升长文档完整性。
- **⑤ query 改写**：检索前用 LLM 生成 1~3 个改写 query 或一个 Hypothetical Document（HyDE），扩大召回。

### 优先级 P2 — 工程化与可靠性
- **⑥ Celery 化**：接口契约现成（202+task_id），把 `BackgroundTasks` 换成 Celery+Redis worker，加重试/死信队列。
- **⑦ 安全加固**：启动校验密钥非空、生产 `debug=False`、JWT 短期+黑名单（Redis）、登录失败锁定、对 JWT 用户也限流。
- **⑧ 可观测三件套**：structlog 结构化日志 + Prometheus metrics（QPS/延迟/模型调用数）+ OTel 链路追踪。
- **⑨ 数据治理**：删除改软删（回收站 30 天）+ 定时备份脚本 + 存储一致性巡检（有记录无文件 / 有文件无记录）。

### 优先级 P3 — 测试与扩展
- **⑩ 测试工程化**：把 `tests/` 手写脚本改写成 `test_*.py` pytest 用例，接 GitHub Actions CI + pre-commit（ruff/black/mypy）。
- **⑪ OCR**：图片型 PDF 接入 PaddleOCR / 调本地多模态模型，先转文本再切分。
- **⑫ 迁移正规化**：把 `db_init.py` 的幂等 DDL 迁移到 alembic，便于团队协作与回滚。

## 四、一句话总结
**你最初要的"壳子 + 5 个功能"已经 100% 落地，且工程质量在企业级骨架里算扎实。** 真正还没做完的是"从骨架到生产可用"的最后一公里：本地模型实际接通、Celery 异步、RAG 问答前端、安全/可观测/测试工程化。其中**第①项（接通你已部署的 bge-m3/bge-rerank-m3）是离你原始意图最近、ROI 最高的一步**。
