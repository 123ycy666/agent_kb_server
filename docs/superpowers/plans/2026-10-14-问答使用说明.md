# 问答使用说明 · 实施计划（2026-10-14）

**目标**：产出《供电所精益预算数智问答 · 使用说明》—— 一份带目录的问答对（交甲方）；过程中把回答暴露的规则缺失补进 `skills/判据规则.md`。

**技术栈**：本地 `secretary/server.py`（8200）；`POST /api/ask`（多轮同 session_id）；证据落 `output/test_results/`。

## Global Constraints

- 使用说明是**给甲方看的**：不写规则迭代、不写内部过程话术、不写测试标记。
- 维度三个：预算分配 / 项目全过程 / 穿透式复盘（**考评不问**）。
- 题目一律用**残缺原话**问；文档每道题三行：**原话 → 补全后 → 回答**。
- 对象用真实数据（47 个供电所、4 个县公司、真实线路与台区名）。
- 问过的不重问；改规则与写文档都从结果库取。
- 一次只改一条根因，禁止加特例词、加分叉凑过。

## 任务

### Task 1 环境与基线
- 起服务（8200），`/health` 期望 200 且 kb=true；不打 8299 旧进程。
- 抽 1 个场景（场景 1）跑通链路，确认返回里有补全后的问题与回答。
- 验收：场景 1 的 6 轮全部落盘（原话 / 补全后 / 回答 / 用时）。

### Task 2 场景组一：预算分配（20 场景）
- 按 `docs/题目清单.md` 场景 1–20 逐条问；同场景同 session_id；不重问。
- 每条按 `docs/测试方案与判据.md` 的 A/B/C/D 逐项判。
- 验收：20 个场景全部落盘并逐项判完，失败项列出。

### Task 3 场景组二：项目全过程（28 场景）
- 同上（场景 21–48）。

### Task 4 场景组三：穿透式复盘（24 场景）
- 同上（场景 49–72）。

### Task 5 独立问题（6 条）
- 只测单次效果，重点看补全与口径。

### Task 6 按失败改规则
- 一条失败 → 归因（规则缺失 / 没说清 / 模型没照做 / 数据没有）→ 只改前两类，改在对应节。
- 改完换**同场景新问法**复验，不重问原句。
- 输出：规则改动清单（哪条规则、因为哪个问答、改前改后）。

### Task 7 成文
- 按上面的结构把跑通的问答对填进 `docs/使用说明.md`；答案只从结果库取。
- 验收：每个场景都能查到对应记录；抽查 5 条与原话/回答完全一致。

### Task 8 收口
- 证据索引 + 逐条 EV；更新 `待办总账.md`。
