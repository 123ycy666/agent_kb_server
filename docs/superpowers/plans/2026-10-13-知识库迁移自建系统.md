# 计划：规则检索从百炼迁移到自建知识库（47.121.183.81）

> 开场扫描：命中 ②③④⑤⑥ → 已调 brainstorming / writing-plans / test-driven-development / test-evidence / verification-before-completion；写码轮再调 ponytail(full)。

**Goal:** 问答链路的**规则检索面**从阿里云百炼索引 `r57xtq9ypm` 换成自建库 KB 5「秘书问答规则」，检索准确度不低于百炼，且能一行回滚。

**Architecture:** 只改 `secretary/tools_kb.py` 的检索实现，加后端开关；对 `agent.py` 保持原返回结构 `{nodes:[{score,doc_name,title,content}]}` 不变。分数刻度随源一起对齐（否则「分析/查数」分流判据失效）。

**Tech Stack:** Python 3.12 / urllib（与现有一致，不引入新依赖）；自建库 FastAPI + pgvector，`POST /api/v1/auth/login` + `POST /api/v1/search`。

## Global Constraints（每步都适用）

- **一次只动一个变量**：模型（deepseek-v4.1-flash）、system 提示词、`docs/分析问答-要点清单.json`、`MAX_STEPS`、`top_k`、`RULE_TOP_K`、`rerank` 全部冻结。本轮唯一变量 = 检索源（+ 它自带的分数刻度）。
- **判据动手前定死，事后不许改**；一次不达标就拆更小的台阶，不改判据。
- **不写死**：代码里不出现任何规则节名/关键词；不新增「由代码替模型判断哪些规则适用」的逻辑；给模型的是可读、带定位、完整的切片，不是被裁剪过的残片。
- **回滚一行**：`SECRETARY_KB_BACKEND=bailian`。
- 自建库侧**只读**（本轮不新增上传/删除）；不动「公司知识库」(id=3)；不动百炼管理面 `/api/kb/**`。
- 证据落盘到 `output/test_results/kb_migration/`（`00-index.md` + 逐项 `EV-NNNN-*.md`）。

## 2. 做什么 / 不做什么（含与别的做法的差别、对后续的影响）

| 决定 | 备选做法与差别 | 对后续的影响 |
|---|---|---|
| **① 换检索源 + 保留开关**（默认仍是 bailian，验收通过后才把 local 变默认） | 双路并行（两套都查）= 两套系统都要维护、延迟翻倍、结果要融合；直接替换删掉百炼分支 = 出事没法回滚 | 只维护一套；回滚一条 env；百炼侧仍可作对照基线 |
| **② 用已有的 KB 5 专用库** | 塞进「公司知识库」(id=3) = 规则文档和制度文档混排、互相挤占召回名额，且将来重建/授权耦合 | 分库 → `kb_ids=[5]` 天然隔离；将来换 embedding/分块只影响这一个库 |
| **③ 不重构规则文档、不调 chunk_size** | 把 194 行表格拆成小标题条目 / chunk_size 512→2048 = 动规则原文语义 + 触发百炼侧 md5 同步 + 同时改两个变量 | 现在不动；只有 S2 召回不达标才另开一步做，且会单独量。实测断表只有 7 处，先付不起这个代价 |
| **④ top_k 不变** | 加大到 6–8 = 提示词变长、无关切片进上下文，且与百炼基线不可比 | 先换源，跑完 S2/S4 再用数字决定要不要加 |
| **⑤ 分数刻度随源一起换**（改用 `SECRETARY_ANALYSIS_SCORE` 的实测值） | 不改 = 见 F7；用代码把新库分数"归一化"到百炼刻度 = 凭空造一个映射，没人能验证它单调、也没人知道它哪天失效 | 刻度是源的属性，不是第二个变量；依据是两套后端 `rule_best` 的实测分布（S3 落盘） |
| **⑥ 不做「代码侧挑规则」** | 曾把"拿问题检索判据"扩到多文档，结果把相邻技能的标准套到本题（见 `agent.py:348` 注释） | 保持"只认《判据规则》一篇"不变；选题靠模型自己 `kb_search` |

## 3. 怎么保证检索准确度（4 层，每层都能机械判定）

| 层 | 做法 | 判据（先定死） |
|---|---|---|
| **A 切片可读性** | 不改文档；把命中切片的**完整原文**（含自带 `【标题路径】` 前缀，最长 577 字）交给模型，`title` 用 `heading_path`，不做 450 字截断 | 抽查 12 题命中的每一片：单独读不出现"这行属于哪张表"的悬空（F6 那 7 处若进 top-3 必须记录在案并说明影响） |
| **B 位置信息** | `title=heading_path`，content 保留 `【路径】` 前缀；信息只搬不丢（前缀从 content 里移到 title 也可，**不许两者都丢**） | 返回节点里 `title` 非空且能定位到节 |
| **C 召回命中率** | `output/kb_recall_cases.json`：12 题逐题写"必须召回的节"（**从规则文档自己的标题里挑**，不看检索结果挑，避免自证）；`output/kb_recall_check.py` 对**两套后端各跑一遍**，脚本判 hit@3 / hit@8，不用模型判 | ① 12 题里 ≥11 题在 top-8 命中至少一个必须节；② 新库 ≥ 百炼同口径命中率；③ 逐题落盘，退化题要能点名 |
| **D 端到端回归** | 冻结其它一切，`TEST_TAG=kbmig` 跑 12 题 → `judge_points.py`；再跑一轮连续追问（换问法） | ① 12 题业务要点 **≥ 41/54**（v4.1 基线），第 4 / 5 / 9 题不退化；② 连续追问 **≥ 66/80**（conv4 基线）且继承不退化；③ 逐题对照表落盘 |

- 做成什么样：`kb_search('预算执行率 口径')` 在两种后端下返回**同构**结果；`agent.py` / 提示词 **0 行改动**。

  1. 先写会失败的测试 `output/test_kb_backend.py`：断言 local 分支返回 `nodes` 非空、每节点有非空 `title`+`content`+`doc_name`、结构键与 bailian 分支一致 → **亲眼看到它在改之前失败**；
