# 分析问题拆解 · 04「哪个所花得最慢？慢在哪？」

## 一、谁问、问谁
- 角色：市公司财务部 / 市领导；对象：全市各所
- 原话：「哪个所花得最慢」「谁进度最差」「慢在哪」

## 二、想要什么答案
**排名 + 归因**：是哪几个所、慢在同一个原因还是各有各的原因、该让谁动。
**不是给一张执行率排行榜就完事。**

## 三、思维链

**第 1 步 · 算各所执行率**（口径同 03；分配取所级有效行，已审批取状态 3/6/7）

**第 2 步 · 排序并**分类**，不能只按数字排**
- **A 类 真 0%**：当年连草稿都没有 → 储备为零
- **B 类 有项目没批**：有状态 1/2 的工单 → 卡在审批
- **C 类 批了没动**：有状态 3/6 停留久 → 卡在施工
- 三类混在一起排名是没有意义的（原因完全不同）

**第 3 步 · 逐类查依据**
- A：`t_power_work_order` 当年该所条数（含草稿）
- B：`t_power_work_order_status` 定位卡在哪个 **node_type**、停留多少天（用当前日期 − 进入该节点的时间）
- C：同上，看施工阶段停留

**第 4 步 · 找共性**
- 是普遍卡在同一个节点（如都卡在县公司财务部）→ 那是**流程瓶颈**，不是某个所的问题
- 还是各所各有各的（一个没项目、一个卡审批）→ 分别给动作

**第 5 步 · 该谁动**
- 卡在哪个节点 → 对应角色（所长 / 营销部 / 财务部 / 运检部 / 领导）

## 四、回答要出现什么
1. **结论**：最慢的是哪几个所（+ 一共多少个所没启动）
2. **分类**：A/B/C 各几个，分别是谁
3. **依据**：每类的判定数据（条数 / 卡在哪个节点 / 停留几天）
4. **共性**：是流程瓶颈还是各所自身
5. **建议**：谁先动、动什么

## 五、数据可得性 / 坑
- 停留天数用 **t_power_work_order_status**（不是工单表的 create_time）—— 用创建时间会把"刚转来的件"算成卡了很久
- 同一节点可能有多次流转（驳回重提）→ 取**最后一次进入**当前节点的时间
- 所名为空的记录要排除或单列
