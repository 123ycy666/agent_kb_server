| 项目 | 说明 |
|---|---|

## 1 概述

### 1.1 它是什么

一个用自然语言提问、由系统自动查数并给出**分析结论**的业务助手。它面向预算分配、项目全过程管理、穿透式复盘三类工作，替代「自己翻系统、自己拉表、自己算」的过程。

### 1.2 一句话能问什么

**凡是答案在业务库里的问题，都可以问**：分了多少、花了多少、执行率多少、哪些项目卡住、卡在谁那里、哪些所指标差、某个台区/线路什么情况、往年怎么投的、明年该怎么调。

### 1.3 一次提问背后发生的五件事

1. **字面纠错与名称归一**：错别字、简称、口语写法会被纠正为系统里的标准名称（不改动原意）。
2. **时间与范围补全**：问句里的「这个月 / 上月 / 今年」会换成具体期间；没说的按统计范围或上一轮续用，并在回答里写明口径。
3. **查数与对账**：系统自己去查业务库，多张表交叉核对；每个数字都要有出处，查不到就写「未查得」，合计取库里的统计值而不是自己加。
4. **给结论**：按「结论 → 依据 → 原因 → 建议 → 预计效果」组织（见第 7 章）。
5. **（可选）出页面**：本部署**已关闭页面生成**（见 7.3），回答只返回文字。

### 1.4 不能用它做什么（先说清）

- 不预测未来：能推算「按当前速度会怎样」，不会替上级定盘子（明年盘子未下达时会直接说明）。
- 不代替决策：给建议和依据，最终调不调、调多少由人定。
- 不编数据：查不到就写未查得；系统没采集的字段（实际投入、合同付款、项目级成效等）会明确说明「无数据源、无法判定」。
- 不做审批操作：只读，不批单、不改数据。

## 2 业务场景总览

### 2.1 三个维度

| 维度 | 覆盖的问题 | 典型角色 |
|---|---|---|
| 一、预算分配 | 分多少、为什么这么分、公不公平、该怎么调 | 所长、县财务、市财务、市县领导 |
| 二、项目全过程 | 项目从申报到完工的每个环节：储备、审批、施工、验收、金额合规 | 所长、县运检、县财务、市财务 |
| 三、穿透式复盘 | 从全市到县、到所、到台区逐级下钻；投入与成效对账 | 市县领导、县运检、市财务 |

### 2.2 提问人身份与角色

同一个问题，不同身份看到的范围和重点不同（县里只看本县，所里只看本所）。上游把范围传给系统后，回答里会写明它按什么范围、什么期间作答。

| 角色 | 关注点 | 建议问法 |
|---|---|---|
| 供电所所长 | 本所分了多少、钱花到哪、还差什么 | 「我们所今年分了多少、花到哪了、还剩多少」 |
| 县公司财务 | 本县分配结构、执行进度、在途资金 | 「我们县各所分了多少、哪个所最慢」 |
| 县公司运检 | 项目储备够不够、审批积压、施工进度 | 「我们县手上报了多少、够花完吗、缺多少」 |
| 县公司领导 | 本县横向对比、短板在哪、先抓什么 | 「我们县哪个所问题最重、先治哪几个」 |
| 市公司财务 | 全市总盘、超支与偏差、调剂空间 | 「全市分了多少钱、花了多少、有没有所批超了」 |
| 市公司领导 | 公平性、错配、趋势与目标 | 「各所分到的钱跟问题严重程度搭吗」 |
| 其他（营销、审计等） | 单笔工单合规性、流程停留 | 「这单金额合不合理、现在卡在哪」 |

## 3 维度一 · 预算分配（经典示例）

**可以问**：分了多少 / 为什么这么分 / 谁分得少 / 公不公平 / 明年怎么调 / 有没有批超 / 钱够不够用。

**提问要点**：说清**对象**（哪个所、哪个县、全市）和**期间**（今年、本月、1-9 月）。说不清也没关系：系统会按上游给的范围与上一轮续用，并在回答里写明口径。

## 6 提问方式

### 6.1 不用问全：残缺、口语都能问

用平时跟同事说话的方式问即可，不需要按系统字段组织语言，也不需要自己限定时间与范围。发现口径不对，直接纠正再问。

| 问法 | 说明 |
|---|---|
| 「今年分了多少钱、花了多少？」 | 一句话两个问题，会分点回答 |
| 「我们所今年分了多少」 | 对象从提问人身份带入 |
| 「1-9 月全市预算执行情况」 | 自己限定期间与范围，回答按此口径 |

### 6.2 补全效果对照

系统会把口语纠正成标准名称，把相对时间换成具体期间。下面是实测对照（左：原话；右：系统补全后实际使用的问题）：

| 原话 | 系统补全后实际使用的问题 |
|---|---|
| 唐镇今年分了多少、花了多少、还剩多少？ | 唐镇供电所2026年1-9月，分了多少、花了多少、还剩多少？ |
| 环潭这次分了多少？ | 环潭供电所这次分了多少？ |
| 今年一共做了多少项目、花了多少钱？ | 2026年1-9月一共做了多少项目、花了多少钱？ |
| 跟去年口径一样吗？ | 跟2025年口径一样吗？ |
| 环潭今年分了多少还剩多少？ | 环潭供电所2026年1-9月，分了多少还剩多少？ |
| 均川今年分多少、排第几？ | 均川供电所2026年1-9月，分多少、排第几？ |
| 厉山基础条件咋样？ | 厉山供电所基础条件咋样？ |
| 今年各公司总预算怎么配的？ | 2026年1-9月各公司总预算怎么配的？ |

### 6.3 追问：同一场会话里接着问

同一场会话中，没说的对象与期间会**沿用上一轮**，可以直接用「这单 / 这个所 / 那这些单」「跟上月比」「那明年呢」这类省略说法。换对象或期间时说出来即可，以本轮说的为准。若指代词在本场会话里找不到对象（既没提过名称、也没有上一轮），系统会**先问清是哪一张 / 哪一条**，不会自己挑一个凑答。

### 6.4 好的问法与容易跑偏的问法

| 想要的结果 | 好的问法 | 说明 |
|---|---|---|
| 要判断 | 「够不够花」「合不合理」「该先办哪个」 | 给结论 + 判定依据 |
| 要清单 | 「哪些所没动」「卡在哪几个节点」 | 给条数与对象，按金额或停留时间排序 |
| 要对比 | 「跟去年比怎么样」「各县横向比比」 | 写明对比口径；无基期的会说明「暂缺可比基期」 |
| 容易跑偏 | 「明年能分多少」（盘子未下达） | 只能给按现有规则的推算，并说明依据 |
| 容易跑偏 | 「实际花了多少」（未采集实际投入） | 会说明只能用预算金额口径 |

## 7 回答的构成

### 7.1 回答怎么组织

一句话：**你问哪一层，就答哪一层，答完就停。**

| 你怎么问 | 回答长什么样 |
|---|---|
| 问一个数 / 一份名单 / 排第几 / 差多少 | 数 + 口径，1–3 行，不加建议、不带成效 |
| 问情况 / 做判断（怎么样、够不够、哪个多） | 第一句给结果（多/少、快/慢、够/不够、谁最多），再用 1–3 个关键数支撑 |
| 问原因（为什么、差在哪） | 讲成因与证据，**不给对策** |
| 问办法（怎么办、先干哪个、钱往哪投） | 给动作：谁、做什么、多少、什么时候 |
| 问预测（能达标吗、年底到多少） | 给区间和参照，标注「推算」 |
| 不是业务问题（问候、常识、写作、解释概念） | 直接正常回答，不查库、不套业务话术 |

问得不清楚时（如只说「预算情况」），才按这一方面的常规项答全，并给一句结论；
问得明确（如「还剩多少」）只答那一项。

### 7.2 各类问题的标准项（只用于「问得不清楚」的情况）

| 问题类型 | 回答里一定会有 |
|---|---|
| 预算执行类 | 分了多少、花了多少、执行率、单项目规模与月均项目数、结论与卡点 |
| 预算分配类 | 分配额、排名或分位、决定它的几项得分与权重、与相邻对象的差距 |
| 审批与流程类 | 各节点待办条数与金额、停留时长分档、责任岗位 |
| 项目与金额类 | 同类比较基准（中位/最高）、偏离倍数、结构异常点、核实建议 |
| 成效与趋势类 | 指标现值、对比基期与变化量、目标差距、支撑判断的明细 |
| 复盘与下钻类 | 逐级数值 + 每级差距来源 + 下一步动作 |

### 7.3 分析页面（本部署已关闭）

本部署**不生成分析页面**：分析类问题同样只返回文字回答（结论、依据、建议齐全）。页面生成能力在代码里保留（配置项 SECRETARY_PAGE 打开即可），需要时可随时启用。

### 7.4 口径标注

回答里会写明三件事：**期间**（如「2026 年 1-9 月」）、**范围**（如「洪山供电所」）、**状态口径**（如「已审批」按哪几个状态计）。凡涉及跨年、含往年、系统未采集的，都会另行说明；也不会把内部系数说成「XX% 基准线」。

## 8 边界与限制

### 8.1 数据边界（系统里就没有的）

| 情况 | 系统会怎么答 |
|---|---|
| 实际投入 / 决算金额 | 系统未采集实际投入数据，只能用预算（申报）金额 |
| 合同金额、实际付款 | 无数据源，无法与项目进度比对（会直接说明「无法判定」） |
| 项目级成效（单个项目解决什么、效益多少） | 成效字段未采集，无法逐项排名 |
| 往年评分明细 | 只有当年有明细，往年只能看成效与排名 |
| 完工日期、计划工期等字段为空 | 改用同类项目的中位/分位相对口径，不硬判「逾期」 |
| 同比基期缺失 | 明确写「暂缺可比基期」，不拿别的期间顶 |
| 分线路跳闸、台区低电压标识 | 未按该粒度采集时直接说明，不给编的数 |

### 8.2 能力边界

- 只读：不批单、不改数、不发起流程。
- 不预测政策与盘子：上级未下达的额度只能按现有规则推算，并写明依据。
- 不编数：查不到写「未查得」；同一回答里同一个数只有一个值；金额对不上会先自己核一遍再说。

### 8.3 使用建议

- 一次问一件事，比一句话塞十个问题答得更细；一句话问了多件事时会逐件回答。
- 多轮追问比重复问更省事：上一轮的对象与期间会自动续用。
- 分析类单题约需数十秒（含页面生成），查数类通常十几秒；批量调接口时建议同一账号串行提问。

## 附录 C 术语与口径速查

| 术语 | 含义 |
|---|---|
| 分配额 | 该对象当年分到的预算（所级看分配结果表，公司级看公司预算配置） |
| 已审批 | 工单状态为「审核通过待施工 / 施工中 / 施工完成待验收」的合计；**审核中不算**，因为单据还在审批流里 |
| 未审批 | 尚未走完审批的单据；系统按「草稿、提交审核、驳回已修改」计（**审核中**会单独说明），回答里会写明含哪几类 |
| 执行率 | 已审批金额 ÷ 分配金额 |
| 在办 | 处于审批、待施工、施工中、待验收的项目；已驳回、已取消不计入 |
| 待办 / 待审批 | 停在某个审批节点、状态为「待处理」的任务（不等于全库「审核中」） |
| 停留天数 | 系统当天 − 进入该节点的时间 |
| 六项指标 | 售电量、线损率、用户平均停电时长、故障报修工单、故障跳闸次数、意见工单 |
| 口径 | 一个数字是「按什么期间、什么范围、什么状态」算出来的；回答里都会写明 |

工单状态取值：0 草稿、1 提交审核、2 审核中、3 审核通过待施工、4 已驳回、5 已取消、6 施工中、7 施工完成待验收、9 驳回已修改。
