# 计划硬门（PreToolUse）落地记录

> 2026-10-19 · 依赖 `dsh-hooks-plugin` 0.2.15（社区插件，装进 desktop profile 的 bundles）

## 它在干什么

改代码文件之前，要求 `docs/04-计划/` 里有一份 **24 小时内更新过** 的计划；没有就 deny，并告诉模型先写计划。

- 脚本：`D:\秘书智能体\hooks\plan-guard.ps1`
- 配置：`D:\秘书智能体\.dsh\hooks.json`（项目层，热重载）
- 策略参数：`.dsh\plan-guard.json`（`planDir` / `maxPlanAgeHours` / `gateGlobs` / `exemptGlobs` / `planGlobs`）

## 判定顺序

1. 只处理 `PreToolUse` 且 `tool_name ∈ {write, edit}`
2. 取目标路径（`file_path` / `path` / `filePath` / `target_file` 任一）
3. 归一化：相对路径按 `cwd` 展开、反斜杠统一成正斜杠
4. 命中 `exemptGlobs`（`docs/* output/* hooks/* .dsh/* *.md`）→ 放行
5. 不命中 `gateGlobs`（`*.py *.ts *.tsx *.js *.mjs *.vue *.sql *.ps1 *.sh *.bat *.yml *.yaml *.json`）→ 放行
6. 计划目录里有 `maxPlanAgeHours` 小时内的 `*.md` → 放行，否则 deny

## 踩到的坑（重要）

- **执行策略会 fail-open**：插件用 `& 脚本.ps1` 调用，系统默认执行策略禁止运行脚本 → 退出码 1、无决策输出 → **静默放行**。
  修法：命令写成 `& powershell.exe -NoProfile -ExecutionPolicy Bypass -File '...plan-guard.ps1'`，不依赖本机策略设置。
- **stdin 按控制台编码读会炸（最阴的一个）**：`[Console]::In.ReadToEnd()` 用 GBK 解 UTF-8 字节，**路径里有中文时 `ConvertFrom-Json` 直接抛异常 → catch → 静默放行**。ASCII 路径测不出来，只在真实工作区暴露。
  修法：按字节读再显式 UTF-8 解码。
  ```powershell
  $stdin = [Console]::OpenStandardInput()
  $ms = New-Object System.IO.MemoryStream
  $stdin.CopyTo($ms)
  $raw = [System.Text.Encoding]::UTF8.GetString($ms.ToArray())
  ```
- **脚本必须存成 UTF-8 with BOM**：Windows PowerShell 5.1 按 ANSI 读无 BOM 的 `.ps1`，中文会破坏语法。
- 退出码不 gate，决策只能靠 stdout JSON；`hookEventName` 从输入原样回填。

## 已知边界

- 只管 `write` / `edit` 两个工具；MCP 的文件写入工具不在此列（需要时在 matcher 里加 `mcp__.*` 并扩展脚本）。
- 计划"够新"用文件 mtime 判断，不用文件名里的日期 —— 名字怎么起都不影响。
- 这是**硬门但不是唯一防线**：脚本出错即放行（fail-open），所以监控 hook 的退出码是必要条件。
