> 2026-10-19 · 对象：`~/.dsh/AGENTS.md`（现 4,273 字）+ `~/.dsh/skills/*`（38 个技能）+ 宿主机制
> 本文只做盘点与方案，**不改任何规则文件**。判据：每条结论都要能指到"读过哪个文件/哪行文档"。

## 三、宿主的三个"能强制"的口子（实测读源码/文档）

### 1. plan mode（`/plan`）
- 机制：`/plan` 进入 → 探索设计 → 调 `exit_plan_mode` 把**完整计划**提交给你 → 你批准才往下走。
- **重要限制**（官方 README 原话）：它「**不限制 agent：每个工具仍可调用**，因此需要强制限制时请使用沙箱模式与审批提示」。
- 结论：plan mode 是**流程引导**，不是硬门。

### 2. hooks（`@deepseek-ai/dsh-hooks-claude-code`，Claude Code 兼容）
实测支持的事件与能力（`lib/index.js` + README）：

| 事件 | 能做什么 |
|---|---|
| `SessionStart` | 挂上下文进会话 |
| `UserPromptSubmit` | **拦下这条 prompt**，或附加上下文 |
| `PreToolUse` | **拦下这个工具调用**，或改成"要审批" |
| `PostToolUse` | 工具跑完后追加/校验 |
| `Stop` | 强制再跑一轮 |

- 现状：`~/.dsh/profiles/desktop/cordis.patch.yml` 里只挂了 ponytail 与 memory 两个 MCP，**没有挂 hooks**；`~/.claude/settings.json` 里也没有 `hooks` 键。
- 也就是说：**"改代码前必须先有计划"这类硬门，本机现在根本没装**，过去一直靠 AGENTS.md 里的散文提醒 —— 这就是"写进规则也不生效"的物理原因。

### 3. goal（`dsh-goal`）
- 机制：每会话一个持久完成目标，跨轮 / 跨重启存活，有 round 上限与 blocked 状态；`/goal` 命令；我也有 `create_goal`/`update_goal` 工具。
- 官方定位：「需要跨自动 Goal Round 持续的长目标时用；**常规单轮工作不要用**」。
- 这就是 P5（长对话忘目标）的原生解：目标写在会话状态里，不靠上下文记忆。

## 四、我的初步判断（等你拍板，不含外部研究结论）

1. **P1/P2 的正解不是"再写一条要写计划的规则"**，而是二选一：
   - 轻：用 `todo_write` + 一段计划的短格式（每步一行 `→ verify:`），不落文件；
   - 重：`/plan`，或 PreToolUse hook 硬拦"没计划文件不许改代码"。
2. **P5 的正解是 `/goal`**，不是提醒我"别忘"。
3. **P3/P6/P7 要靠技能 + 一条极短判据**（技能里已有细则），规则里只留"什么时候必须调哪个"。
4. **P8 的正解是"少写规则、多装机制"**：散文规则超过某个长度后，遵从率下降而维护成本上升。
5. **P7 那条"穷举 = 求救信号"应当恢复**（我删错了）。

## 五、外部研究结论（全文见 `2026-10-19-AGENTS规则失效与替代机制.md`，278 行，逐条带链接与证据等级）

| 结论 | 证据 | 对本文的意义 |
|---|---|---|
| 指令越密、单条遵从越低（500 条满密度下最强模型 68%），且偏向靠前 | [论文] arXiv 2507.11538（IFScale）；位置效应 arXiv 2307.03172 | 规则表放最前是对的；继续往 §1–§5 加条目收益递减 |
| 上下文文件**平均不提升成功率**、约 +20% 推理成本；失败在实现能力而非缺知识 | [论文] arXiv 2602.11988、2607.27250 | "再加一条规则"的期望收益常常是 0 或负 |
| 提示词是建议，hook 才是强制 | [官方] Claude Code best practices：`advisory` vs `deterministic` | 与 §三 一致：本机 hook 没挂，硬门不存在 |
| 漂移是"有界均衡"，提醒有效；机制侧用 PLANS.md（AGENTS.md 只留一句指针 + Progress/Decision Log） | [论文] arXiv 2510.07777；[官方] Codex PLANS.md | P4/P5 的正解是"进度写在磁盘、压缩后重读 Progress" |
| 能静态判定的别用散文（魔法数 → lint 规则） | [一手] Fowler CodeSmell / Replace Magic Number；ESLint `no-magic-numbers` | P7 应从规则里搬进 lint/脚本 |
| 规则副作用有官方直认：矛盾时"随便挑一条"、强调太多"没有一条突出"、文件臃肿"忽略真正的指令" | [官方] code.claude.com/docs/en/best-practices | P8 有据可依 |

**证据缺口**（不装懂）："为满足规则而产出无关文档"没有找到直接实证，只有间接材料（规则饱和 + 指令密度），标 [推断]。

**钩子可用性的矛盾已澄清**：研究代理在宿主 `app.asar` 里搜不到 `PreToolUse`/`SessionStart` 是**对的**（桥接是独立 npm 包，不打包进宿主）；但 `@deepseek-ai/dsh-hooks-claude-code` 确实存在于 profile 依赖树（`profiles\desktop\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-hooks-claude-code`），只是**没有挂载**（`dsh-base` 的 `cordis.patch.yml` 里没有任何 `hook` 字样）。能不能挂上＝一次 patch + 重启的实测，**尚未验证**。
