# 骨架与业务库 设计（2026-11-19）

> 对应需求：`docs/04-计划/2026-11-19-骨架与业务库-需求规格说明书.md`（下称 SRS-01）
> 部署侧：`docs/04-计划/2026-11-19-两套线上服务-需求规格说明书.md`（下称 SRS-02）
> 本文只解决「怎么实现」，不改 SRS 的任何意图；SRS 里没写死、需要取保守方案的分叉都记在第 8 节。

## 1 结论

一个现场 = 一个 PG 库。服务启动时读本地引导配置 `config/site.json` 得到「当前现场」：

```
                     ┌─────────────────────────────────────────┐
  启动 → 读 config/site.json ── 有? ──连得上 PG? ── 建/补管理员 ──→ 正常工作
                     │                     │
                     └─ 没有 ──────────────┴──→ 降级：只有「现场配置」页
```

降级时后端对**一切业务接口**返回 503 `SITE_NOT_CONFIGURED`，前端只渲染「现场配置」页（登录页也不出现）。

## 2 现场标识与「切现场就失效」

| 项 | 取值 | 理由 |
|---|---|---|
| 现场标识 `site_id` | `host:port/dbname` | 一个字段就能定位一个库；不含口令，可展示 |
| JWT 密钥 | `hmac_sha256(服务密钥, "site:" + site_id)` | 密钥随现场派生；切现场后旧 token 的签名**必然**验不过 |
| token 载荷 | 追加 `sid=site_id` | 双保险：即便服务密钥不变，sid 不符也判失效 |
| 服务密钥 | `.env` 的 `JWT_SECRET` | 挂在服务上、全局一份，不进库（IF-SYS-001 对系统令牌的要求同理） |
| 系统令牌 | `.env` 的 `INTERNAL_SERVICE_TOKEN` | 全局一份；切现场**不重建**，故切完照样能用（AC-06） |

登录口径（FR-LOGIN-001）：账号行一律落在当前库 `base.app_user`。
口令校验顺序：① 该行的 `password_hash`（bcrypt，骨架/新现场用）→ ② 业务库 `t_employee`（随州现网用）→ 都不过则 401。
`LOCAL_LOGIN_ENABLED` 不再作为开关：**哈希非空就允许本地口令**，否则回落到 HR。这样随州零退化、新现场一建库就能登。

## 3 数据层：怎么把连接换成新库

三处连接必须同时切，否则会出现「一半读新库、一半读旧库」：

```
core/database.py    engine / SessionLocal（SQLAlchemy：知识库、RBAC、审计、工作流）
secretary/pgdb.py   DSN（psycopg 直连：词典、提示词、问数记录、智能体表）
业务库/模型通道      cfg.runtime（MySQL 连接、模型网关）——本来就在库里
```

实现要点：

1. `SessionLocal` 是 sessionmaker 实例，用 `configure(bind=new_engine)` 原地改绑 —— 其它模块 `from app.core.database import SessionLocal` 拿到的旧引用**照样生效**，不用改 20 处调用方。
2. `engine` 无法原地改 URL，改为「重建对象 + 调用方读模块属性」：把 3 处 `from ... import engine` 改成 `from app.core import database` + `database.engine`。
3. `pgdb.DSN` 是模块级字符串，`connect()` 每次读它 —— 直接重新赋值即可，`agent/db.py`、`prompt_text`、`runtime_cfg` 全部自动跟随。
4. 切完必须清缓存，否则读到旧库数据：`prompt_text` / `prompt_material` / `runtime_cfg` / `inject_store` / `caliber` / `complete_rules` / `route_rule` / `spec` / `meta_admin` / `semantic` / `kb_adapter` 的默认库缓存 + 纠错引擎 + 模型 provider 缓存。统一收在 `core/site.py:reset_caches()`。
5. 工作流库（`ad_wf`）默认沿用 `.env` 派生值（随州零退化）；引导配置里写了 `wf_database` 才跟着切。

## 4 新库从零可用（FR-CFG-002 / AC-02）

连上一个空库后按顺序补齐，全部幂等：

```mermaid
flowchart LR
  A[建 schema cfg/kb/qa/base] --> B[SQLAlchemy create_all 到 public]
  B --> C[public 实体表搬进各自 schema]
  C --> D[public 建同名可写视图]
  D --> E[各模块 ensure 建 cfg./qa. 私有表]
  E --> F[初始管理员：不存在则建，已存在且已有口令则跳过]
```

`public` 视图是必须的：ORM 模型名不带 schema，`search_path=public`，视图让旧代码一行不改（沿用 `db/migrate_v5.py` 已验证的做法）。`表 → schema` 的映射只留一份（`core/pg_schema.py`），`db/migrate_v5.py` 改为引用它。

**初始管理员的精确规则**（FR-CFG-002 的保守读法）：
- `base.app_user` 无该行 → 新建，`role=admin`、`status=active`；
- 有该行且 `password_hash` 非空 → **跳过**，一个字节都不改；
- 有该行但 `password_hash` 为空 → 只补口令（没有「已有口令」可覆盖），角色/状态不动。

后端接口（新增 `server/app/api/v1/site.py`）：

| 方法 路径 | 鉴权 | 作用 |
|---|---|---|
| `GET /api/v1/site/status` | 公开 | `{configured, ok, error, site{host,port,dbname,user}, business_empty, model{channel,base_url,model}, system_token_configured}` |
| `GET /api/v1/site/config` | 降级时公开；正常时需 admin | 当前引导配置（口令脱敏）+ 业务库/模型通道（来自 `cfg.runtime`） |
| `PUT /api/v1/site/config` | 同上 | `{pg, admin, mysql?, model?}`：先试连 → 写文件 → 立即重连 → 建/补管理员 → 落业务库/模型配置 |
| `POST /api/v1/site/test` | 同上 | `{target: pg\|mysql\|model, ...}` 三条连通性测试，只测不存 |

`business_empty` 判定：`cfg.prompt_material` + `kb.document` + `cfg.caliber_metric` 三张表行数全为 0。（AC-03）

## 6 业务内容移库（附录 B.1）

| 内容 | 新家 | 代码里留什么 |
|---|---|---|
| 身份默认值（两份合并） | `cfg.prompt_text` key=`identity` | 默认空串 |
| 现场名/全称/地市标签/县公司清单/默认所 | `cfg.site_info`（k/v） | 读库函数 + 读不到返回空 |
| 示例问题（两份合并） | `cfg.preset_question` | 读库，空则空列表 |
| 单位类型/台区类型/停用词/`strip_head`/单位前后缀/单字尾词 | `cfg.t_nc_word`（kind + word + extra） | 匹配算法（保持原逻辑） |
| 业务分类映射（目录树） | `kb.catalog`（已有表） | 默认空树 |
| 评测题与文档名 | `kb.eval_question`（已有表） | 默认空集 |
| 落款示例 | `cfg.t_nc_word` kind=`signoff_sample` | 通用示例 |
| `skills/*.md`、`howto_docs/*.md` | 移出 `server/app` → `docs/08-历史归档/2026-11-19-移出-server-app 的入库源稿/` | 不读 |

纠错词表的注入方式：`name_corrector` 的模块级常量改为**空默认 + `configure(words)` 注入**；`name_fix` 在构造 `Corrector` 前从 `cfg.t_nc_word` 读词表注入。读不到词表 = 行为退化但不误改（空词表下没有简称匹配、没有停用词护栏 → 所以随州库必须灌满，见 AC-08 抓的回归）。

## 8 分叉与取舍（SRS 未写死处的保守选择）

| # | 分叉 | 选择 | 依据 |
|---|---|---|---|
| 1 | `/api/internal/*` 无现存路由 | 新建最小命名空间：`GET /api/internal/status`（现场/库/模型连通状态，不含密钥）；sga 换 token 沿用 `/api/v1/auth/sso/login`，额外接受 `X-Internal-Token` | FR-SYS-001 点名要覆盖这三处；不新造业务能力 |
| 2 | `/api/alerts/daily` 依赖的 `secretary/alerts.py` 已在 d8d8a1e 删除（当前调用即 500） | 重建最小实现：从工作流库按账号取未读通知/待办；工作流库不可达就返回 `status=unknown` 而不是 500 | AC-06 要它可用；不复活旧预警引擎 |
| 3 | 降级页要不要登录 | 未配置/连不上：三个接口全公开（不登录也没法登录）。已配置正常：需 admin JWT | 否则任何人可改现场连接 = 直接换库 |
| 4 | 系统令牌为空时 | 保持现行为：不校验（本地开发），`/health` 与降级页显示「未配置令牌」；线上 `.env.production` 必须配 64 hex | 与 `SSO_LOGIN_KEY` 现有口径一致；不擅自把本地开发锁死 |
| 5 | 现场名等「现场信息」存哪 | `cfg.site_info`（随 cfg 片，跟现场走） | DR-002 把「现场配置」归引导配置 + `cfg.runtime`；现场名属于业务配置 |
| 6 | 空库启动时要不要种演示数据 | 不种。空就是空，问数明确回「该现场尚未配置」 | FR-EMPTY-001 / UI-004 |
