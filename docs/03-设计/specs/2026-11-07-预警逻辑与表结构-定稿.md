## 一 逻辑只有三层

```mermaid
flowchart LR
  B["业务数据<br/>MySQL 已有表"] -->|"取数文档：怎么算、多少算异常"| R["预警结果<br/>wf_item"]
  R -->|"发送文档：按人组织成一句话"| N["每人版本<br/>wf_notify"]
  N --> F["前端：预警列表 / 我的通知"]
```

- **判据**（取数文档）回答"怎么判断"。
- **结果**（`wf_item`）回答"判断出来是什么"——客观事实，不知道发给谁。
- **版本**（`wf_notify`）回答"这件事对某个人怎么说"——同一批结果，所长一句本所、县财务一句本县、市领导一句全市。

**存结果，不存过程。** 每轮每对象算出来的值（含没命中的）不建表：排错看运行日志（SQL 原文 + 工具返回），
「这轮没出现就关闭」靠本轮写过的对象键集合，「还在不在」靠结果表的状态与最近命中日期。

## 三 表结构

### 3.1 `wf_item` 预警结果（21 列）

去重键 `(doc_id, object_key)`：同一判据下同一对象只有一行，命中就更新，本轮没出现就置 `closed`。

| 列 | 类型 | 含义 |
|---|---|---|
| `id` | bigserial | 主键，通知和前端都靠它指结果 |
| `doc_id` / `doc_name` | bigint / varchar(120) | 哪条判据算出来的（名字冗余，列表不 join） |
| `alert_type` | varchar(16) | 类（取数文档的分类字段带过来，代码不校验枚举） |
| `object_key` / `object_name` | varchar(160) / varchar(200) | 对象键（所 id / 工单 id / 台区 id）与对象名 |
| `unit_name` | varchar(120) | 归属供电所（工单、台区也填） |
| `county_name` | varchar(120) | 归属县公司 |
| `value` / `value_unit` | numeric(16,4) / varchar(16) | 当前值与单位（`%` / `元` / `天`） |
| `threshold` / `tier` | numeric(16,4) / varchar(8) | 阈值、档位 high / mid（low 只是显示用） |
| `reliable` | smallint | 0 = 数据不全，不发 |
| `status` / `close_reason` | varchar(16) / varchar(32) | open / closed；数据恢复 或 人工关闭 |
| `first_seen` / `last_seen` | timestamptz | 首次命中、最近命中（发送判"今天"用它） |
| `detail` / `evidence` | jsonb | 明细几项、依据几项（键名由取数文档第六节定） |
| `sent_at` | timestamptz | 最近一次被通知；空 = 还没通知过 |
| `task_id` | bigint | 留给任务流转 |

索引：`UNIQUE (doc_id, object_key)`、`(status, alert_type, tier)`、`(county_name, status)`、`(unit_name, status)`、`(last_seen)`。

### 3.2 `wf_notify` 每人版本（14 列）

| 列 | 类型 | 含义 |
|---|---|---|
| `id` | bigserial | 主键 |
| `level` | varchar(16) | 层面（取值由发送文档第四节定） |
| `alert_type` | varchar(16) | 预算 / 指标 / 审批 |
| `scope_name` | varchar(120) | 这句话说的是谁的范围：厉山供电所 / 随县 / 全市 |
| `recipient_login` | varchar(64) | 收件人 = `t_employee.login_name` |
| `recipient_name` / `role_code` | varchar(64) / varchar(32) | 姓名、岗位（`find_user` 返回） |
| `message` | varchar(200) | 那一句话（字数和禁词按运行参数校验，不在代码、不在表） |
| `alert_ids` | bigint[] | 这句覆盖哪几条结果；**第一个是最差那条**；GIN 索引 |
| `doc_id` | bigint | 哪份发送文档 |
| `sent_at` / `read_at` | timestamptz | 发出时间；`read_at` 空 = 未读 |
| `reason` | text | 为什么发给他（排查用） |
| `channel` | varchar(16) | 本期只有 station |

覆盖条数 = `array_length(alert_ids,1)`，最差点开 = `alert_ids[1]`；不为这两个再开列，也不建关系表。

## 四 取数与发送一一对应

`wf_doc.pair_doc_id`：发送文档指回它的取数文档；`UNIQUE (pair_doc_id)` 保证一份取数只挂一份发送。

| # | 类 | 取数文档（六节） | 发送文档（七节） | 对象 |
|---|---|---|---|---|
| 1 | 预算 | 预算花不完 | 预算花不完 · 发送 | 所 |
| 2 | 预算 | 单笔工单预算异常 | 单笔工单预算异常 · 发送 | 工单 |
| 3 | 预算 | 工单金额缺失 | 工单金额缺失 · 发送 | 工单 |
| 4 | 指标 | 台区线损超线 | 台区线损超线 · 发送 | 台区 |
| 5 | 指标 | 台区售电量骤降 | 台区售电量骤降 · 发送 | 台区 |
| 6 | 指标 | 指标同比恶化 | 指标同比恶化 · 发送 | 所 |
| 7 | 审批 | 已批未开工 | 已批未开工 · 发送 | 工单 |
| 8 | 审批 | 工单长期未结束 | 工单长期未结束 · 发送 | 工单 |
| 9 | 审批 | 审批长期未通过 | 审批长期未通过 · 发送 | 工单 |

命名规则：取数文档 = 判据名；发送文档 = `<判据名> · 发送`。类只三类，决定找哪个岗位、句子里用哪个词。

## 五 文档结构（每份第一节都是目的）

**取数六节**

| 节 | 写什么 |
|---|---|
| 一 目的 | 查出什么、算到哪个对象、结果表里落成什么、跑完是什么样子 |
| 二 管什么 | 这条判据盯哪件事、算到哪一层 |
| 三 看哪些数据 | 表、列、关联键、过滤、坑（单位、排序规则、缺数据） |
| 四 怎么算 | 时间口径、分组、一个对象一条 |
| 五 多少算异常 | 比较方式、阈值、分档、多少以上不报 |
| 六 存什么数据 | 对象、归属所、归属县、当前值与单位、阈值、档位、明细几项、依据几项、可靠性 |

**发送七节**

| 节 | 写什么 |
|---|---|
| 一 目的 | 把哪份取数文档的结果、按哪几层、变成一句什么话、发给谁、产出在哪 |
| 二 读哪些数据 | `doc_name` 过滤、取列、时间口径、排序与条数、明细用哪些键 |
| 三 字段是什么意思 | 每列含义、`value_unit` 怎么读、`detail` 有哪几个键 |
| 四 怎么判断该不该发 | 状态 / 可靠性 / 档位 / 今天命中；按 `unit_name`、`county_name` 归三层 |
| 五 发给谁 | 层面 → 岗位 → `find_user` 参数；多账号取哪个；查不到怎么办 |
| 六 一句话怎么写 | ≤30 字、一个数字、三层句式、禁止项、正反例 |
| 七 怎么存 | `send` 每个参数取什么、返回怎么判、`finish` 交什么 |

不写进文档：什么时候跑（定时方案）、发几次（`no_repeat_days`）、框架怎么实现。

## 六 一句话标准

| 层面 | 句式 | 例 |
|---|---|---|
| 所级 | `{单位}{事由}{一个数}` | 厉山供电所今年预算到年底结余 69 万 |
| 县级 | `本县 {n} 所{事由}` | 本县 4 所预算到年底花不完 |
| 市级 | `全市 {n} 所{事由}` | 全市 38 所预算到年底花不完 |

硬约束落在库里和工具里：字数 ≤30、只一个数字、不含 `high/mid/low`、顿号不超过一个。

## 七 谁能改什么

| 要改的东西 | 改哪里 | 动不动代码 |
|---|---|---|
| 判据（阈值、口径、看哪张表） | 取数文档正文 | 不动 |
| 一句话说法、发给谁 | 发送文档五、六节 | 不动 |
| 什么时候跑 | 定时方案 | 不动 |
| 同人同层面几天内不重发 | 运行参数 `no_repeat_days` | 不动 |
| 一句话多长、禁哪些词、几个数字 | 运行参数 `msg_max_chars` / `msg_banned_words` / `msg_max_separators` / `msg_max_numbers` | 不动 |
| 怎么按单位+岗位找账号 | 运行参数 `user_query_sql` / `user_filter_unit` / `user_filter_role` | 不动 |
| 表结构 | 不动 | 要改就是新版本 |
