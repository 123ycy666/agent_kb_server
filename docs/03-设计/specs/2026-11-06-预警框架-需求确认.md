# 预警框架 · 需求确认（2026-11-06）

- 状态：需求已与 Fred 逐条对完，设计未出、未动代码。
- 一句话：**预警不是另一套系统，是"按规则文档跑一遍"的框架**。代码里零业务规则，规则文档存在库里、在页面上写；取数和发送是两个独立工作流，靠"存下来的结果"串起来。

---

## 一、定位

问数是**人触发**的流水线，预警是**定时触发**的流水线，骨架是同一副：配置 → 装配 → 执行 → 落对象 → 对话里读懂 → 有动作。

预警的具体形态：**定时器到点 → 按某份规则文档跑一轮 → 结果落库 → 另一个工作流把结果发出去 → 对话里能看、能问、能接着办**。

## 二、已定决策

| # | 决定 | 边界 |
|---|---|---|
| D1 | 代码里零业务口径：判据、阈值、表名、SQL、类型、文案、时间，一个字都不进 .py | 代码只做机制：读文档、提供工具、存取、调度 |
| D2 | 触发器 = **调度方案**（独立一张表，一个方案一个 cron），规则文档挂方案，不是规则自带 cron | 加时间点、改时间、停文档都在页面里，不重启 |

| D4 | 一份规则文档 = 一条判据；加一条预警 = 加一份文档 | 同类多条 = 多份文档挂同一个方案 |
| D5 | 执行由模型按文档干活：自己写 SQL、自己跑、自己判、自己交结构化结果 | 不给它固定步骤方块 |

| D9 | 金额下限 / 一次最多几条 / 多久内不重复 —— 属**存取与运行规则**，归框架（运行参数表），不进文档 | 现在散在 3 个环境变量里 |

## 三、本期范围

**做**：框架的五张表、配置页（文档 + 调度方案 + 运行参数）、调度器（库驱动、可热重载）、取数执行器、工具集（run_sql / 查单位账号角色 / 写事项 / 写结果）、发送工作流、对话接入（点事项进对话、现跑工作流、接着问）。

**不做**：建任务、下发、流转、核销、级联升级；外部通道（邮件/短信/微信）只预留接口。

**交付物**：框架 + 一份**空的八节模板**（教人怎么填），不含任何业务内容。装好之后系统里零预警，因为一份文档都没写。

## 四、框架的五个部件

1. **规则文档页 + 库**（`rule_doc`）
2. **调度方案页 + 库**（`schedule`）
3. **调度器**：到点 → 取出挂在该方案下的文档 → 起一轮
4. **执行器 + 工具**：模型按八节干活，产出结构化结果
5. **存储与查询**：批次 / 结果流水 / 事项；对话、列表、发送都读这里

## 五、规则文档的八节（取数工作流）

| 节 | 必填内容 |
|---|---|
| 一 基本信息 | 文档名、预警类型（自由文本）、启用 + 关闭原因、算到哪一层（所/县/市）、挂哪个调度方案（存在 `schedule_id` 列，不进正文） |
| 二 看什么数据 | 数据源（业务库 / 本系统库，可多个）、表或视图、关键字段含义、排除哪些行、**字段缺失时退用什么、怎么标注不可靠** |
| 三 怎么算 | 算哪个数、时间口径（今天 / 年初至今 / 年初到上月 / 最新期 / 滚动 N 月）、跟什么比、是否外推或取最值 |
| 四 判断标准 | 比较方式（>、<、区间、取前 N）、阈值、**分档（可引用明细字段）**、多条件与/或、计数型条件（≥N 项） |
| 五 一条怎么算 | 分组键（所 / 单 / 节点 / 指标 / 层级）、**一个对象一条还是多个并一条**、同一对象去重口径 |
| 六 输出什么 | 对象（名 + 键）、当前值、阈值、档位、明细、依据（表.字段 + 口径 + 数据截止日）、可靠性标记 |
| 七 标题怎么写 | 标题模板（字数上限）、正文模板；数字只能引第六节 |
| 八 不算什么 | 不报的情况（花得完不报、字段全空属治理不属预警、表内汇总行不能算） |

## 六、数据模型（9 张表 + 三层含义）

字段级清单见设计稿 §三；这里只定"应该存哪几样东西、各自一行是什么"。

| 表 | 一行是什么 | 存什么 | 属哪层 |
|---|---|---|---|
| `wf_doc` | 一份规则文档 | 文档名、工种、启用、八节正文、版本、挂哪个方案 | 配置 |
| `wf_doc_version` | 文档的一次历史版本 | 第几版、谁存的、当时正文 | 配置（历史） |
| `wf_schedule` | 一个定时方案 | 名称、cron、时区、启用 | 配置 |
| `wf_run` | 一份文档跑一次 | 谁触发、起止时间、数据截止日、查了几个、命中/新增/关闭/发送几个、错误 | **过程** |
| `wf_run_log` | 这一轮的每一步 | 读了哪几节、SQL 原文、行数、工具入参出参、错在哪 | **过程**（细） |
| `wf_result` | **每个对象每轮一行** | 对象、值、阈值、比较方式、档位、是否命中、明细、依据、可靠性 | **流水** |
| `wf_item` | **一个在办的问题** | 对象、最新值/阈值/档位、明细、依据、标题、状态、首见/最近/命中次数、已发时间、预留任务号 | **结果** |
| `wf_notify` | 一条发送 | 发给谁、通道、依据、时间、成败 | 结果（发送） |
| `wf_param` | 一条运行参数 | 步数上限、单轮条数上限、不重发天数、流水保留月数、默认通道 | 框架（不进业务文档） |

三条硬规则：

- **没命中也要有行**：整轮没命中 → `wf_run` 一行 `hit_n=0` ＋ `wf_result` 全 `hit=false`。
- **命中才进事项**：`wf_item` 按 `(文档, 对象键)` 唯一，重复命中只更新，数据恢复置 `closed`。
- **原始过程留一份**：模型写的 SQL 和原始输出整段存进 `wf_run_log`，不看汇总数字。

## 七、存取与运行规则（框架管，文档不写）

- 幂等：`run_key` 唯一，同一轮重复触发只算一次。
- 去重：事项按文档 + 对象键唯一。
- 关闭：本轮该对象未命中 → 事项 `closed`，原因写"数据恢复"；**只有本轮结果写全了才关**（少写了就记一条 error，不关）。
- 保留：`wf_result` 默认 12 个月（可配）；`wf_item` 永久。
- 运行参数（`wf_param`）：步数上限、单轮最多写几条、同一事项多久内不重复报。**不在页面上编辑**，技术侧直接改库。
- 结果不完整（文档第六节给不全）→ 当场标失败，不许静默丢。
- 停用文档不许挂定时方案；停用会自动从方案上解挂。

## 八、文档与表的分界

文档只交第六节那五项；`status`、`first_seen/last_seen/seen_times`、`dedupe_key`、`run_id`、关闭判定、收件人 —— **全部由框架填，文档管不着**。

## 九、对话怎么接

- 点一条事项 → 这一行进对话（带明细、来自哪份文档、哪一版、数据截止日）。
- 问「为什么触发」→ 现跑取数工作流，摊开同一份结构化结果（不查缓存、不另算）。
- 问「会发给谁」→ 现跑发送工作流，只算不发。
- 接下去问明细、问别的对象，都在同一个会话里。
