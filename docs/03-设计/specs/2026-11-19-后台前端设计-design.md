# 后台前端设计（2026-11-19）

> 依据：Fred 的要求——标准智能体后台、照开源抄布局、标签页就够、不写用途说明、不过分设计。
> 参考：Dify 工作室（应用→左侧配置→顶部标签）、LibreChat Agents 侧栏分区、Langfuse 会话→trace；规则来自 Web Interface Guidelines（Vercel）里适用的条目。
> 技术栈不变：React 18 + antd 5；只换版式与结构。

## 1 全局壳

```
┌──────────┬────────────────────────────────────────────────────┐
│ 侧栏 220 │ 页面标题                          [主操作按钮]      │
│          ├────────────────────────────────────────────────────┤
│ 概览     │ 标签页：文档 │ 库 │ 检索测试                        │
│          │ ┌────────────────────────────────────────────────┐ │
│ 对话     │ │ 工具栏：搜索框  筛选   [新建]                   │ │
│ 智能体   │ ├────────────────────────────────────────────────┤ │
│ 技能     │ │                                                │ │
│ 知识库   │ │  表格 / 表单 / 内容区                          │ │
│ 提示词   │ │                                                │ │
│ 预警     │ └────────────────────────────────────────────────┘ │
│ 任务     │                                                    │
│ 记录     │                                                    │
│ 设置     │                                                    │
└──────────┴────────────────────────────────────────────────────┘
```

规矩：

- 侧栏固定 220，深色底（`#001529` 系）；一级项图标＋两字，不再分组折叠，10 项以内不分组。
- 页面标题行只有「标题 + 右侧主操作」，**不写用途说明**。原来的「每一项都显示在哪、多大、能不能改」这类段落全删。
- 页面内部只用一个 Tabs，不套二层 Tabs；页面里最多一层卡片。
- 对话页沿用现有三栏布局（左会话、中消息、右运行步骤），只调视觉。

## 2 三种页面模板

### 2.1 列表页（技能、知识库文档、记录、任务）

```
[搜索……]  [筛选▾]                         [+ 新建]
┌──────────────────────────────────────────────────────┐
│ 名称            状态    更新        │ 操作           │
│ 公文格式        已发布  11-16 10:20 │ 编辑 · 退役    │
│ 查数口径        已发布  11-12 09:31 │ 编辑 · 退役    │
└──────────────────────────────────────────────────────┘
                                            共 5 条
```

- 行高 40，悬停有底色；操作放行尾，最多三个，多出来的进 `···`。
- 空态：一句「还没有技能」+ 一个「新建」按钮，不写解释。

### 2.2 设置页（智能体配置、提示词、设置）

```
标签页：身份与风格 │ 技能 │ 工具 │ 模型
┌──────────────────────────────────────────────────────┐
│ 身份            [多行输入                              ]│
│                 字数 86/2000                          │
│                                                       │
│ 回答风格        [多行输入                              ]│
│                 留空 = 中性                            │
│                                                       │
│                           [重置] [保存]               │
└──────────────────────────────────────────────────────┘
```

- 标签左、内容右在同一行；标签宽度 120，右对齐。
- 保存按钮固定在区块底部右侧；保存后右上角 `message.success`，文案与按钮同名（「已保存」）。
- 输入框下面最多一行小字（字数、留空行为），不写「这个字段用来干什么」。

### 2.3 对话页（沿用，视觉收敛）

现有结构不动：左 240 会话、中间消息流、右 320 运行步骤。改的是：去掉顶部那句「一句话交代，它自己决定读什么、查什么、出什么」；模型名做成灰色小标签放标题右侧。

## 3 九个页面

### 概览

```
今日 128 轮    失败 3     预警 2 条     待处理任务 1
今日会话列表（8 行）
```

四个数字 + 一张最近会话表，不加图表。

### 智能体（`/agent`）

Tabs：身份与风格 │ 技能 │ 工具 │ 模型

- 身份与风格：两段多行输入（身份只读链接去提示词页，风格可改）。
- 技能：范围三选一（全开 / 只给指定 / 全关）+ 多选列表 + 「上传技能」。
- 工具：九行，每行开关 + 一行「什么时候别用」（来自工具描述，只读）。
- 模型：模型名、步数上限、上下文预算、压缩阈值。

### 技能库（`/skills`）

列表页。列：名称、什么时候用、产物、状态、更新时间、操作。
编辑走右侧抽屉：名称 / 什么时候用 / 适用 / 产物 / 正文（大文本框）/ 检查项（多行）；抽屉底部「保存草稿」「发布」。

### 知识库（`/kb`）

Tabs：文档 │ 库 │ 检索测试

- 文档：列表（文件名、类型、切片数、可见性、状态、更新时间）；行尾「查看切片」。
- 库：五张库的列表，列：名称、文档数、切片数、是否参与检索、创建时间。
- 检索测试：一个输入框 + 「检索」，下面是命中片段列表（文档名、相似度、片段）。

### 提示词（`/prompts`）

Tabs：问数线 │ 智能体。**删掉旧的「干活线」页签。**

- 问数线：口径材料、作答规则、补问法、问题确定，四行，每行右侧「编辑」打开抽屉。
- 智能体：只有一条跳转链接「身份与风格在智能体页改」。

### 预警（`/alerts`）空壳

Tabs：规则 │ 记录。规则页给一张空表 + 「新建规则」按钮（点击提示「后面单独设计」）；记录页给现有预警列表。不动后端逻辑。

### 任务（`/tasks`）沿用

现有任务中心，换成列表页模板：列 任务名、状态、最近运行、耗时、操作。

### 记录（`/records`）沿用

问答记录列表 → 点开右侧抽屉看这一轮的问答、口径、工具轨迹。

### 设置（`/settings`）

Tabs：模型与端点 │ 员工源 │ 存储 │ 外观

- 模型与端点：base_url、模型名、密钥（掩码，只能替换不能回显）。
- 员工源：MySQL 地址、表名、连通性状态（只读）。
- 存储：上传目录、产物目录（只读）。
- 外观：侧栏深浅、字号（两三个选项）。

## 5 照抄的规则（只列适用的）

- 图标按钮必须有 `aria-label`；表单控件必须有 label。
- 交互元素要有 `focus-visible` 焦点环，不许 `outline: none`。
- 危险操作（删除、退役）二次确认。
- 空态给一句 + 一个动作；错误信息写「怎么改」。
- 按钮文案是动词：「保存」「发布」「新建技能」，不用「提交」。
- 数字列用等宽数字；长文本 `truncate` + 悬停显示全文。
- 加载态以 `…` 结尾：「保存中…」。
- 标签页、筛选写进 URL（`?tab=skills`），刷新不丢。

## 6 不做（防止过分设计）

- 不写用途说明段落、不写引导语、不放插画。
- 不加图表、不加仪表盘组件、不做深色主题（除侧栏）。
- 不搞双层导航、不做面包屑（只有一级）。
- 不动技术栈，不引入 Tailwind/shadcn。
- 首屏不做动效；只有抽屉、弹窗的默认过渡。

## 7 待办（Fred 2026-11-19 提的，后面再做）

**对话式建技能**：跟智能体把自己的想法讲一遍，它整理成一篇技能的正文（步骤、口径、检查项），你确认后一键入库并发布，不用自己去写文件、也不用填四项。

现在这条路要几步：上传 md/txt/docx → 填「什么时候用/适用/产物/归属」→ 预览 → 发布。上传本身不挑格式（词表里 pdf/docx/xlsx/md/txt/csv 都能进知识库，技能只吃 md/txt/docx），但「标准」那一份是 SKILL.md：头部 `name` + `description`，正文写做法，附件打包在一起。

现成的参照：

| 来源 | 做法 |
|---|---|
| Anthropic Agent Skills 规范 | 一个目录 + `SKILL.md`（frontmatter 里 name/description，正文写步骤与检查项） |
| Dify Skills | `.zip` / `.skill` 包（内含 `SKILL.md`，≤50MB），工作区级资产，一改全应用生效 |
| LibreChat | 后台有「新建技能」对话框，直接写正文，不必先有文件 |

所以更省事的做法是：**智能体产出 SKILL.md 文本 → 你在抽屉里看一眼 → 发布**，比「先有文件再上传」少两步。这条留下一版做。
