# 干活线：智能体完整设计（2026-11-17）

- 范围：只动干活线。问数线一行不改，入口分流保留。
- 目的一：加能力 = 加一篇技能，不改代码。
- 目的二：一个智能体该有的东西一次想全——上下文、记忆、工具、技能、会话、产物、流式、观测、评测、权限、配置。
- 选型：OpenAI Agents SDK 做运行时；其余在本仓库实现完整，不做半截。

## 一、验收判据（能跑出 pass/fail）

1. 删光技能，活还能干（不因为代码找不到技能而崩）。
2. 加一篇技能，不改代码，下一轮就能被用上。
3. 任意一轮的 trace 里，工具调用是模型选的，没有代码预设的步骤。
4. 关掉页面再回来，模型知道上一轮出过哪个文件、查过什么数。
5. 会话超过 6 万 token 后还能接着干，压缩而不是截断。
6. 同一句「写个通知」在没有任何说明书的情况下也能出 docx。

## 二、现状：问题不在"步骤多"，在于代码替模型做了决定

| 现状 | 它在替模型决定什么 | 位置 |
|---|---|---|
| 8 段注入 + 6000 字预算 + 压缩顺序 | 这轮看到什么 | `inject.py` |
| `spec.pick` 按适用词挑一篇说明书 | 这活归哪篇知识 | `spec.py:122` |
| `Gate` + 把检查项抄进 user 消息 | 交付合不合格、给不给文件 | `loop.py:480` |
| `finish` 工具、按有无文件切工具 | 什么时候算完、能做什么 | `loop.py:98/286` |
| `_system` 追加三段 | 这轮必须交什么格式 | `loop.py:151` |
| `pipeline_*` 六条（速读/校对/表格/汇报/公文/比对） | 功能是一个个代码流程 | `doc_jobs.py:181` |
| `qa_log` 只存问答 + trace | 历史会话里没有工具调用与结果 | `qa_log.py` |

三个直接后果：

- 加一类活要写一条新路径（六条 pipeline 就是六条路径），不是写一篇技能。
- 会话续不上：下一轮只看到「上一轮问/答」两行字，看不到它读过哪个文件、跑过什么 SQL。
- 知识和判断散在代码、说明书、页面三处，改一处不知道另一处会不会跟着变。

## 三、选型

| 候选 | 结论 | 理由 |
|---|---|---|
| **OpenAI Agents SDK**（MIT，Python，0.24.0） | 选 | 循环、工具、session、tracing、guardrails、human-in-the-loop、MCP 都有；用 `OpenAIChatCompletionsModel` 接非 OpenAI 端点，已在你们的 DeepSeek MaaS 上跑通（见验证） |
| Claude Agent SDK | 不选 | 绑 Claude 模型，你们用 DeepSeek |
| Pydantic AI | 备选 | 类型与评测好，session 与记忆要自己写；没有先发优势 |
| LangGraph | 不选 | 图/状态机就是工作流形状，和这次方向相反 |
| Dify / FastGPT / RAGFlow | 不选 | 平台，换掉现有前端与数据层 |
| DB-GPT / WrenAI | 只抄语义层结构 | 整平台接进来要换前端；问数线也不动 |

验证记录：`%TEMP%\agent-poc`，一个文件、3 只工具、2 篇技能、没有代码路径，模型自己完成「读技能 → 查数 → 出文件」，并在我给的假数据自相矛盾时主动拒答。日志 `run.log`。

## 四、结构

```
/api/agent/run (SSE)          web /chat 三栏
        │                          ▲ 事件
        ▼                          │
  runtime.py  ── Agent + Runner ───┘
        │
        ├── instructions：身份 + 作业规则 + 技能目录 + 关于我 + 今天
        ├── tools/      9 只，包现有实现（不重写生成器）
        ├── skills.py   kb.spec → 目录 / 正文
        ├── session.py  PGSession（SDK Session 协议）
        ├── memory.py   偏好 / 事实 / 笔记
        └── trace.py    run / span 落库
```

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `runtime.py` | 建 Agent、跑 Runner、事件转 SSE、停止 | 不挑技能、不拼上下文之外的判断 |
| `tools/` | 执行能力、校验参数、返回摘要 | 不替模型决定用不用 |
| `skills.py` | 目录、正文、发布状态 | 不按关键词替模型挑 |
| `session.py` | 会话项读写、压缩 | 不做摘要以外的加工 |
| `memory.py` | 长期记忆读写 | 不自动注入全部记忆 |
| `trace.py` | 每一步落库 | 不影响回答 |

## 五、一轮的完整流程

1. `POST /api/agent/run`：`session_id?`、`text`、`file_ids[]`。
2. 无 `session_id` 建会话（标题取首句前 20 字）。
3. 装 instructions：身份（2–3 句）+ 作业规则（≤10 行）+ 技能目录（≤30 行）+ 关于我（≤5 行）+ 今天。
4. 装输入：用户原话 + 附件 `file_id` 清单（只给 id 与文件名，正文按需读）。
5. 拉会话项：`agent_item` 里未归档的项（受预算约束）。
6. 循环：模型 → 工具调用 → 执行 → 结果回填 → 再决策；每步落 `agent_span` 并推 SSE。
7. 模型不再发工具调用 = 终答。
8. 压缩检查：超阈值就压（见七）。
9. 新项写 `agent_item`。
10. 写 `agent_run`（模型、token、耗时、状态）。
11. SSE 结束事件（含本轮产物列表）。
12. 返回。

什么情况会提前结束：用户点停止、步数到上限、模型连续报错、工具越权。

## 六、上下文（每轮装什么）

| 层 | 内容 | 上限 | 谁决定 |
|---|---|---|---|
| 常驻 | 身份、作业规则、技能目录、关于我、今天 | 约 1.5k 字 | 代码装，内容在库 |
| 会话 | 未归档 item（含工具调用与结果） | `context_budget` | 代码裁剪，模型消费 |
| 按需 | 技能正文、文件正文、知识库切片、表结构、记忆 | 单次结果上限 | 模型调用 |

规则：

- 不在代码里挑知识，不写「这轮必须用哪篇」。
- 工具结果超过 `tool_result_cap`（默认 8000 字）时落文件、回摘要 + `ref`，模型要细节再读。
- 上下文预算 `context_budget`（默认 60k token，按字符/2 估中文）、`compact_at`（0.6）、`keep_recent`（12 项），都在 `/runtime` 改。

## 七、记忆

| 层 | 存什么 | 存哪 | 谁能读 |
|---|---|---|---|
| 会话记忆 | 用户/助手/工具调用/工具结果/产物/错误 | `qa.agent_item` | 本轮与续跑 |
| 工作笔记 | 长任务的进度、清单、中间结论 | `qa.agent_note` | 本会话，按 key |
| 长期记忆 | 偏好、单位/人名/文风等事实、产出记录 | `qa.agent_memory` | 本人跨会话 |
| 压缩摘要 | 老会话项的浓缩 | `agent_item(type=summary)` | 本会话 |

压缩顺序（只在超阈值时动）：

1. 清老工具结果：保留调用名与一行摘要，正文标「已清理」。
2. 最老的 60% 项交给模型压成一条 `summary`（保留决定、未完成事项、产物引用）。
3. 保留最近 `keep_recent` 项与全部产物引用。
4. 原文不删（`archived=true`），trace 页还能查。

长期记忆怎么用：

- `remember(kind, text)` 写；`recall(query)` 读；不自动全量注入。
- 「关于我」只放 top5 偏好（文风、单位全称、常用格式），每行一句，超过 5 行的存着不注入。
- 产物记录也进长期记忆：文件名、时间、技能、`file_id`；「上次那个通知」靠 `recall` 找回。

## 八、工具（9 只）

| 工具 | 做什么 | 主要参数 | 返回 |
|---|---|---|---|
| `read_file` | 读会话文件正文 | `file_id`、`offset`、`limit` | 文本块 + `next_offset` |
| `make_file` | 出 docx / xlsx / pptx | `kind`、`spec` | `file_id`、`url`、`name`、`bytes` |
| `read_skill` | 读一篇技能正文 | `name` | 正文 + 检查项 + 关联技能 |
| `list_skills` | 全部技能目录 | — | 一行一篇（目录超 30 篇时才需要） |
| `search_kb` | 检索制度/资料切片 | `query`、`top_k` | 切片 + 出处 |
| `query_data` | 查业务库 | `sql` | 列、行、`row_count`（只读账号） |
| `db_schema` | 看表结构 / 按词找字段 | `table` 或 `keyword` | 字段清单 |
| `remember` / `recall` | 长期记忆 | `kind`+`text` / `query` | ok / 命中项 |

工具书写规则（照 Anthropic 的 ACI 建议）：

- 一只工具一个动作，动词开头，`snake_case`。
- description ≤3 句：做什么、什么时候用、返回什么。示例放技能里，不放 description。
- 每个参数有 description，可选值用 `enum`，默认值写在参数说明里。
- 出错要写「怎么改」，不是错误码。
- 返回给摘要和引用，别把整张表塞进上下文。

## 九、技能（加能力的唯一入口）

一篇技能 = `kb.spec` 的一行 + 正文：

| 字段 | 用途 |
|---|---|
| `name` | 目录里的名字，也是 `read_skill` 的入参 |
| `description` / `when_to_use` | 一行「什么时候用」，模型靠它判断 |
| `applies` | 适用词（只给检索/提示用，不再由代码挑） |
| `product` | 产物类型 |
| `fmt` | 版式 |
| `check_items` | 交付前自检项（模型照做，代码不拦） |
| `body` | 正文：步骤、口径、样板、检查项 |
| 归属、版本、状态 | 本人/全局、草稿/发布、可回滚 |

规则：

- 目录一行一篇：`名称 · 什么时候用 · 产物`；正文按需读。
- 正文里《书名号》= 关联技能，模型顺着读。
- 同名 = 新版本；发布 60 秒内生效。
- 加能力流程：写一篇 md → 上传 → 选角色/填什么时候用 → 发布 → 下一轮可用。全程不改代码。

六条 pipeline 的处理：

| 现在 | 现在是什么 | 重构后 |
|---|---|---|
| 速读 `digest` | `pipeline_digest` 一条代码流程 | 技能《文件速读》+ `read_file` / `make_file` |
| 校对 `proofread` | `pipeline_proofread` | 技能《校对》+ `read_file` / `make_file` |
| 表格审查 `table_audit` | `pipeline_table` | 技能《表格处理》+ 工具（表格抽取保留代码） |
| 汇报 `deck` | `pipeline_deck` | 技能《汇报材料》+ `make_file` |
| 公文 `doc_write` | `pipeline_doc_write` | 技能《公文写作》+ `make_file` |
| 比对 `compare` | `pipeline_compare` | 技能《文本比对》+ 工具 `diff_text`（差异计算保留代码） |

判定标准：确定性、无需判断的算工具；要读、要写、要取舍的算技能。

## 十、会话

表（`qa` schema，新表，不动 `t_chat_*`）：

```sql
create table qa.agent_session (
  id uuid primary key, user_id bigint not null, title text default '',
  status text default 'active', created_at timestamptz default now(),
  updated_at timestamptz default now(), deleted_flag smallint default 0);

create table qa.agent_item (
  id bigserial primary key,
  session_id uuid not null references qa.agent_session(id) on delete cascade,
  seq int not null, type text not null, payload jsonb not null,
  tokens int default 0, archived boolean default false,
  created_at timestamptz default now());
create index on qa.agent_item (session_id, seq);

create table qa.agent_note (
  id bigserial primary key, session_id uuid, key text, body text,
  updated_at timestamptz default now());

create table qa.agent_memory (
  id bigserial primary key, user_id bigint, kind text, text text,
  created_at timestamptz default now());

create table qa.agent_run (
  id uuid primary key, session_id uuid, user_id bigint, model text,
  status text, error text, tokens_in int, tokens_out int, ms int,
  created_at timestamptz default now());

create table qa.agent_span (
  id bigserial primary key, run_id uuid, seq int, kind text, name text,
  payload jsonb, ms int, created_at timestamptz default now());
```

`agent_item.type`：`user` / `assistant` / `tool_call` / `tool_result` / `summary` / `artifact` / `error`。
`payload` 直接存 SDK 的 item，续跑时原样喂回去。

为什么现在的历史会话不对：`t_chat_message` 只有问答两条，工具调用只在 trace JSON 里，下一轮模型看不到「它自己上一轮查过什么、生成过哪个文件」；只能靠 `session_files` 把文件塞进清单。新表把工具调用与结果当一等公民。

跨会话：「上次那个通知」→ `recall("通知")` 命中产物记录 + 会话列表；找不到就直说没有。

## 十一、产物

- `make_file` 落会话沙箱，登记 `file_id` / `url` / `bytes`，同时在会话里写一条 `artifact` item。
- 再改：`read_file` 读回 → 重新 `make_file`，同名新版本，回答里给最新版。
- 下载、预览沿用现有文件接口。
- 中断：已生成的文件保留，没完成的工具调用丢弃，不留半份。

## 十二、流式与页面

SSE 事件：`run_started` / `assistant_delta` / `tool_started` / `tool_finished` / `artifact` / `run_finished` / `error`。

`/chat` 三栏：会话列表、对话、右侧运行步骤（读 `agent_span`，逐步展开：模型输入摘要、工具名、参数、结果摘要、耗时）。
停止：写 `agent_run.status='stopped'`，循环在下一步边界退出。

## 十三、观测

- 每次运行一条 `agent_run`，每次模型调用与工具调用各一条 `agent_span`。
- 记 token、耗时、错误；页面按会话看总成本。
- trace 只记摘要与引用，原始大结果落文件。

## 十四、评测

| 套件 | 内容 | 判据 |
|---|---|---|
| 问数 12 题 | 走问数线，不改 | 数字逐字一致 |
| 文件 8 题 | 通知/纪要/汇报/表格/速读/校对/比对/公文 | 产物存在、结构命中技能、无占位 |
| 多轮 5 题 | 接着改、指代「这个文件」、换格式 | 改的是同一份，不重写 |
| 无技能 3 题 | 停用全部技能 | 仍能出文件 |

每条记：是否完成、工具调用次数、耗时、token、是否编造数字。
结果落 `output/test_results/<日期>-干活线智能体/`，每次改动对比上一版。

## 十五、权限与沙箱

- 工具内校验归属：文件按 user_id，知识库按可见范围，SQL 用只读账号。
- 文件沙箱沿用 `office_runner` 的目录边界。
- 代码不做业务判断（不拦交付、不预检口径）。
- 破坏性动作（删除、覆盖）在工具里要求显式参数，页面二次确认。

## 十六、运行配置（`/runtime`）

模型、`base_url`、`api_key`、`max_turns`（默认 30）、`context_budget`、`compact_at`、`keep_recent`、`tool_result_cap`、`memory_topk`。
改完 5 秒内生效。

## 十七、删与留

删（P1–P3 分批）：

- `loop.py` 的固定骨架、`inject.py`、`_system` 三段、`Gate`、`self_check` 工具、`finish`。
- `spec.pick` 的自动挑选（保留按名字取，供 `read_skill` 用）。
- `agent_office.py`（已无调用方）。
- `doc_jobs` 的六条 `pipeline_*`（P3 换成技能后删）。
- `impact_office.py` 的 37 项（按新流程重做，不保留旧口径）。

留：

- `agent.execute` 的实现层（`run_sql`、`metric_query`、`describe_table` 等）。
- `tools_file` 的读文件、生成器、自检。
- `docgen` / `howto_build` / `pipeline_deck._BUILD_CODE` 的版式与生成能力。
- 知识库、说明书表、版式三层、文件存储。
- `qa_log` 与旧聊天表（历史展示用，不再进新会话）。

## 十八、迁移

| 阶段 | 做什么 | 判据 |
|---|---|---|
| P0 影子 | 新建 `server/app/agent/`，8 只工具包现有实现，`/api/agent/run` 只在测试环境开 | 20 条任务跑通；trace 里工具调用全是模型发的 |

## 十九、不做

- 不动问数线（入口、预处理、system、单工具）。
- 不做多智能体群；只在长任务需要独立探索时用子代理（返回一段摘要，不入主上下文）。
- 暂不接 MCP；工具签名已按可转 MCP 的形状写。
- 不做多租户、部门权限（沿用现有两级）。
