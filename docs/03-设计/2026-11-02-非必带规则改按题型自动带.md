# 设计：非必带规则改成「按题型自动带」

日期：2026-11-02
触发：Fred「你测试下这个不是必带的字段，他是不是会自己去读全规则然后回答，还是直接忽略，
不然这个机制就是有问题的」。

## 实测结论（已钉死，服务器上跑的）

**机制在实战里等于忽略**，两个独立的坑：

1. **时机错位**：循环阶段 system 里只有 `fetch+judge` 的 6 条非必带清单，工具可用；
   收尾前 `_swap_materials(('answer','check'))` 把 19 条 answer 非必带的清单换进来，
   **紧跟着 `_final_answer()` 是 `use_tools=False`** —— 清单给了，`get_rule` 已经调不了。
   那 19 条「每类题怎么答」的规则，**从来没有被读过一次**。
2. **定位不准**：三题共 5 次 `get_rule`，命中该用的那条 **0 次**。模型不抄清单里 40 字的长标题，
   凭印象编短名（「预算执行达标判据」「十七、资金合理性」），编错就报"没有这条规则"。

静态链路本身是好的（24 条非必带全部可取、正文没漏进注入块、清单条数对得上）——
所以问题不在数据，在**"让模型按需取"这个机制设计**。

## 为什么"按需取"必须撤掉

它要求模型同时做对三件事：**知道该取**（时机）、**记得住名字**（定位）、**愿意取**（自觉）。
实测三件全不成立。而且它把"规则该不该用"这个判断推给了一个只会概括、不抄 ID 的模型。

但**不能改回全量注入**：24 条非必带 9,877 字，加上常驻 4,248 + 必带 9,706 ≈ 24K 字/轮，
而且历史上"规则灌太多 → 问什么都扩成小报告"已经吃过一次亏。

## 关键发现：触发语本来就在标题里

```
20.2 审批待办 / 审批积压类（「我这儿多少待审批」「哪些卡住了」「先办哪几张」「有没有遗漏」）
20.6 金额合理性（离群）类（「哪些申请金额明显不合理」「这单金额合理吗」）
20.11 预测 / 外推类（「投完指标能到啥样」「年底能到多少」「明年能多分多少」「能不能达标」）
```

**括号里的「」就是规则作者写的典型问法。** 所以路由不需要新建词表、不需要改表结构、
不需要加页面字段 —— 从标题里解析即可。改标题 = 改路由，规则作者自己就能维护。

没有「」的（`19.1 三条缺省约定…`、`22.2 回答的骨架…`）不是题型路由，永不自动注入 —— 正确。

## 方案

### ① 代码按题型挑，收尾前注入正文（取代"让模型取"）

新增 `prompt_material.route_answer_rules(question)`：

- 取 `answer` + `check` 的非必带节，从标题解析 `「…」` 触发语；
- 与问句算 **Dice 字二元组重合率**，≥0.34 视为命中，取 top2，总字数 ≤1500；
- 返回 `[{section, score, matched, body}]`。

`agent` 在 `_swap_materials(('answer','check'))` 之后把命中的正文拼进 system，
trace 记一条 `rule_route`（命中哪几条、分数、各多少字）—— 线上能直接看出"这题带了哪条做法"。

阈值宁缺勿滥：打不到就不注入，退化成本轮只有必带规则，**不会比现在更差**。

### ② `get_rule` 退化成兜底，不再要求抄长标题

- `topic` 允许直接传**问题原话**；
- 匹配顺序：精确/子串 → 触发语 Dice → 都没有就返回 5 条候选（`20.2 ｜ 审批待办/积压` 这种短名）；
- 清单文本里给短代号，不再让模型面对 40 字长标题。

### ③ 循环阶段的清单不动

`fetch`/`judge` 那 6 条（0.6 先拆题、0.7 领导视角、19.1 缺省约定…）仍走清单 + `get_rule`：
它们不是题型路由，而且循环阶段工具确实可用，模型取得到（实测能取到）。

## 不改什么

- 不改"必带"的语义：作者勾了就是每轮都带，优先级最高。
- 不改四份规则的正文内容，不改表的字段。
- 不动时间/地点解析、不动核实闸。

## 验收判据（都是确定性的，能写成断言）

1. `route_answer_rules('哪些申请金额明显不合理')` → 命中 `20.6`。
2. `route_answer_rules('今年预算能达标吗')` → 命中 `20.11`。
3. `route_answer_rules('哪些工单卡在审批里，先办哪几张')` → 命中 `20.2`。
4. `route_answer_rules('全市情况怎么样')` → **不命中任何 20.x**。
5. `route_answer_rules('哪些卡住了，年底前能清完吗')` → 同时命中 `20.2` 和 `20.11`。
6. 注入后收尾阶段注入块增幅 ≤1500 字，且必带内容一字不少。
7. 线上三题重跑：trace 里出现 `rule_route` 并命中对应条；答案体现该条要求
   （20.11 的"按当前速度外推 + 缺口量化"、20.6 的离群判定口径）。
8. `get_rule('能不能达标')`（原话）→ 能取到 20.11；`get_rule('瞎编的名字')` → 明确"没有这条"+5 条候选短名。

## 风险 / 回退

- **打错题型** → 注入不相干的"怎么答"，比打不到更糟。对策：阈值 0.34 + top2 + 字数上限；
  线上看 trace 的 `rule_route`；调法是**改规则标题里的「」触发语**（作者侧，不用改代码）；
  实在不行把那条改成必带。
- **新加题型忘记写「」** → 永不命中，静默退化成现状。对策：验收第 4 条之外的兜底用例
  里加一条"answer 非必带里没有「」的节，路由必须跳过且不报错"。
