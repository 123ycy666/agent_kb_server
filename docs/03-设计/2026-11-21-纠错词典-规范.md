# 纠错词典规范（表结构 / 拼音码 / CSV 文件 / 接口）

> 代码：`server/app/secretary/lex_import.py`（导入导出）、`lex_admin.py`（行级读写）、`lex_source.py`（读取）、
> `libs/name_correction_lib/name_corrector.py`（拼音编码与匹配）。
> 示例文件：`deploy/lexicon_samples/`（随部署包发出，五个 CSV + 说明）。

## 1 存储

词典存在当前现场库（`config/site.json` 指定的 PG）的 `cfg` schema。`public` 下同名视图是
`create or replace view public.X as select * from cfg.X`，代码与页面都不带 schema 前缀，
`search_path=public` 落到视图，写入穿透到 `cfg`。唯一例外：`cfg.t_nc_word` 没有视图，代码显式带 `cfg.`。

公共列（六张 `t_nc_*`）：`id bigserial`、`deleted_flag smallint`（1 = 软删，列表与引擎都不读）、
`create_time`、`update_time`。`t_nc_word` 用 `enabled boolean`、`updated_at timestamptz`。

`update_time` 是热更新指纹：引擎每 60 秒取六张表的 `MAX(update_time)` 拼接比对，变了整体重建。
物理 DELETE 不改这一列，所以页面删除一律软删，导入一律写 `now()`。

## 2 表规范

### 2.1 `t_nc_typo` 错别字纠正

| 列 | 类型 | 必填 | 取值 | 说明 |
|---|---|---|---|---|
| `wrong` | varchar(64) | 是 | 用户错写的字面 | 与输入做精确子串比对 |
| `right_word` | varchar(64) | 是 | 正确写法 | 替换结果 |
| `org` | varchar(64) | 否 | 适用组织 | 与 `wrong` 组成唯一键，不参与匹配 |
| `freq_level` | varchar(32) | 否 | 高频 / 中频 / 低频 | 只进纠错明细 |
| `reason` | varchar(64) | 否 | 同音 / 形近 / 简称 | 只进纠错明细 |
| `sample` | varchar(200) | 否 | 纠正示例 | 只给人看 |

唯一索引 `(wrong, org)`。匹配 `_fix_words`：不走拼音，长词优先；
片段前是「今/去/明/上/下/本/当/同/每/这/那」且 `wrong` 以「年/月」开头，或片段后接「了/着/过」时判跨词，不改。

### 2.2 `t_nc_term` 术语与别名

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `term` | varchar(64) | 是 | 术语，唯一 |
| `definition` | varchar(400) | 否 | 定义 |
| `alias` | varchar(200) | 否 | 常见表达 |
| `org` | varchar(64) | 否 | 适用组织 |

作用：术语 ≥3 字时受保护，不被错字表替换。唯一索引 `(term)`。

### 2.3 `t_nc_ambiguous` 歧义确认

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `py_code` | varchar(64) | 否 | 拼音码 |
| `name_a` / `name_b` | varchar(64) | 是 | 两个同名候选 |
| `kind_a` / `kind_b` | varchar(32) | 否 | 各自类别 |
| `action` | varchar(64) | 否 | 处理方式 |

唯一索引：无。**当前版本建了索引但无读取点**，填了不改变纠错结果。

### 2.4 `t_nc_wordlist` 标准词表

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `word` | varchar(64) | 是 | 标准词，唯一 |
| `domain` | varchar(32) | 否 | 领域 |
| `src` | varchar(64) | 否 | 来源 |
| `py_full` | varchar(100) | 否 | 运行时不读，留空 |
| `initials` | varchar(40) | 否 | 留空时按拼音表补 |

匹配 `_fix_vocab`：用 `encode_light` 现算拼音码，整句滑窗，只改唯一候选。唯一索引 `(word)`。

### 2.5 `t_nc_catalog` 名称库

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | varchar(200) | 是 | 标准名称，唯一 |
| `kind` | varchar(32) | 否 | `供电公司` / `供电所` / `供电服务站` / `台区` |
| `owner` | varchar(200) | 否 | 上级单位名 |
| `py_full` | varchar(200) | **自动** | 模糊音码，建 `by_code` 索引，运行时读 |
| `py_strict` | varchar(200) | **自动** | 严格音码，当前版本不读 |
| `initials` | varchar(80) | **自动** | 声母串，当前版本不读 |
| `core_code` | varchar(80) | 否 | 台区核心码，只有台区填 |
| `source_id` | varchar(64) | 否 | 来源库主键，仅追溯 |

唯一索引 `(name)`。名称库是名称归一与同音改名的主体：没有它，系统认不出用户说的是哪个单位。
`kind` 必须落在 `cfg.t_nc_word` 的 `unit_kind` 取值里，否则这条名字不参与单位简称匹配。

### 2.6 `t_nc_pinyin` 拼音表

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `hanzi` | varchar(4) | 是 | 单个汉字，唯一 |
| `initial` | varchar(4) | 是 | 声母，零声母留空 |
| `final` | varchar(8) | 是 | 韵母，`ü` 写作 `v` |

唯一索引 `(hanzi)`。读音按库内业务名称语境定音，多音字与 `catalog.py_full` 同口径。

### 2.7 `cfg.t_nc_word` 单位规则

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `kind` | varchar(24) | 是 | 见下表 |
| `word` | varchar(80) | 是 | 词面 |
| `extra` | jsonb | 否 | 结构见下表，默认 `{}` |
| `sort_no` | int | 否 | 排序 |
| `enabled` | boolean | 否 | false = 停用 |

唯一索引 `(kind, word)`。

| kind | 用途 | `extra` |
|---|---|---|
| `unit_kind` | 单位类型词 | — |
| `unit_level` | 类型词级别，数字小=级别高 | `{"level": 0}` |
| `suffix_hint` | 片段含这些词才去名称库按完整名匹配 | — |
| `unit_prefix` / `unit_suffix` | 归一时先剥的前缀 / 吸收的后缀 | — |
| `area_suffix` | 台区类型后缀 | — |
| `generic_word` | 组织通用词，拼音不许触发简称匹配 | — |
| `common_word` | 禁入常用词，同音也不许改成地名 | — |
| `asked_unit_suffix` | 用户口语级别词 | `{"kinds": ["供电所"]}` |
| `ask_tail` | 单字级别尾词 | `{"single": "所", "block_next": "有以在"}` |

`unit_kind` 与 `suffix_hint` 都为空 = 名称归一关闭，只做错别字层。

## 3 拼音码规则

### 3.1 读音表

`t_nc_pinyin` 一汉字一行，拆成（声母, 韵母）。库内现值：**22 个声母、37 个韵母**。

声母（全量，含零声母）：

```
（空） b p m f d t n l g k h j q x zh ch sh r z c s
```

韵母（全量，`v` 表示 `ü`）：

```
（空） a o e i u v ai ei ao ou an en ang eng ong er
ia ie iao iou ian in iang ing iong
ua uo uai uei uan uen uang ueng
ve van vn
```

两条写法约定，与库内 2 万字表一致：

1. `ü` 一律写 `v`（`云` = 零声母 + `vn`，`区` = `q` + `v`）。
2. `y` / `w` 开头的音节按零声母记（`云` 的声母为空，不是 `y`）。

### 3.2 合成规则

一个字的码 = 声母 + 韵母；整串按字顺序直接拼接，不加分隔符。

| 场合 | 声母 | 韵母 |
|---|---|---|
| `py_full`（模糊） | 过模糊表 | 过模糊表 |
| `py_strict`（严格） | 原样 | 原样 |
| `initials`（首字母） | 原样 | 不取 |
| `encode_light`（标准词表用） | 只并 z/c/s 与 zh/ch/sh，尖团音不并 | 过模糊表 |

模糊音表（`name_corrector.INITIAL_FUZZY` / `FINAL_FUZZY`）：

| 类别 | 合并 |
|---|---|
| 声母 | zh→z、ch→c、sh→s、n→l、r→l、f→h、j→z、q→c、x→s |
| 韵母 | ang→an、eng→en、ing→in、ong→on、iong→ion、ueng→uen、iang→ian、uang→uan、uo→o、ie→e、ve→ue |

表里没有的字（字母、数字、生僻字）原样保留，**不转小写**：

| 名称 | `py_full` | `py_strict` | `initials` |
|---|---|---|---|
| 环潭供电所 | `huantangondianso` | `huantangongdiansuo` | `htgds` |
| 青云供电所 | `cinvngondianso` | `qingvngongdiansuo` | `qgds` |
| 夷陵区供电公司 | `ilincvgondiangonsi` | `ilingqvgongdiangonsi` | `lqgdgs` |
| 白鹤2组台区 | `baihe2zutaicv` | `baihe2zutaiqv` | `bh2ztq` |
| 10kV线路 | `10kVsianlu` | `10kVxianlu` | `10kVxl` |

### 3.3 逐字演算（青云供电所）

| 字 | 声母 | 韵母 | 模糊后 | `py_full` 累计 | `initials` 累计 |
|---|---|---|---|---|---|
| 青 | q | ing | c + in = `cin` | `cin` | `q` |
| 云 | （空） | vn | `vn` | `cinvn` | `q` |
| 供 | g | ong | `gon` | `cinvngon` | `qg` |
| 电 | d | ian | `dian` | `cinvngondian` | `qgd` |
| 所 | s | uo | `so` | `cinvngondianso` | `qgds` |

零声母的字对 `initials` 贡献空串（上表「云」），所以 `initials` 比字数短是正常现象。

### 3.4 查字与补字

```sql
-- 查这几个字的读音
SELECT hanzi, initial, final FROM cfg.t_nc_pinyin WHERE hanzi = ANY('{青,云,供,电,所}');

-- 补一个音（名称库出现了表里没有的字，同音匹配就会漏这个字）
INSERT INTO cfg.t_nc_pinyin (hanzi, initial, final) VALUES ('芸', '', 'vn')
  ON CONFLICT (hanzi) DO UPDATE SET initial = excluded.initial, final = excluded.final;
```

名称库导入时，`py_full` 用当时库里的拼音表算。拼音表缺字 = 该字原样进码，
正确写法的名字仍能匹配上（两边用同一个字），但同音不同字对不上。
补音后重新「导出现有 → 导入」一次名称库，拼音码才按新表重算。

### 3.5 拼音码参与哪一层

| 层 | 方法 | 表 | 用哪个码 | 判据 |
|---|---|---|---|---|
| ① 错字 | `_fix_words` | `t_nc_typo` | 不用拼音 | 精确子串，长词优先，跨词边界不改 |
| ② 标准词 | `_fix_vocab` | `t_nc_wordlist` | `encode_light` | 整句滑窗，唯一候选才改；与地名同音只反问 |
| ③ 完整名 | `_fix_names` | `catalog.py_full` | 模糊音 | 片段含 `suffix_hint` 的词；码命中直接改，否则同长度桶内相似度 <88 不改；多候选只提示 |
| ④ 简称 | `_annotate_partial_names` | 名称库 | 严格音 | 裸地名只改字、不补后缀；纯同音且前后是虚词不改 |
| ⑤ 台区 | `_match_areas` | `catalog.core_code` | 核心码 | 已关闭（`NORMALIZE_AREAS=False`） |
| ⑥ 未知对象 | `_detect_unknown` | — | — | 只列最接近候选，不改正文 |

归一 `resolve` 在 ①-⑥ 的结果上补成库内标准名（`X` → `X供电所`），级别按 `unit_level`：公司 → 所 → 服务站。

### 3.6 三条不能做的事

1. **不要手敲 `py_full`**：与 `encode` 不同口径的码，这条名字永远匹配不上，且不报错。页面新增、修改、导入都现算。
2. **不要用 pypinyin 自己算**：多音字按通用读音算出来的码与库内读音表不一致（`曾` / `长` / `重` / `乐`）。
3. **不要只填名字不填 `kind`**：`kind` 不在 `unit_kind` 里的名字不参与单位简称匹配，只有完整名匹配能用。

## 4 CSV 文件规范

### 4.1 文件

| 项 | 要求 |
|---|---|
| 扩展名 | `.csv`、`.xlsx`、`.xlsm`（`.xls` 不支持） |
| 编码 | UTF-8（有无 BOM 均可）；GBK 自动识别 |
| 结构 | 首行表头，其后每行一条；全空行跳过 |
| 表头 | 中文列名或库列名都认，大小写与空格不敏感 |
| 规模 | 单次 ≤ 60000 行、≤ 100 MB |
| 去重 | 同一文件内同键重复，保留最后一行 |

### 4.2 五类字段

| 类别 `key` | 必填 | 可选 | 自动 |
|---|---|---|---|
| `pinyin` | 字、声母、韵母 | — | — |
| `word` | 类型、词 | 附加、排序 | — |
| `catalog` | 名称 | 类别、所属、核心码、来源ID | 拼音码、拼音码_严、首字母 |
| `typo` | 错误写法、正确写法 | 适用组织、频率等级、错因类型、纠正示例 | — |
| `wordlist` | 标准词 | 领域、来源 | 首字母 |

列名对照（中文表头 → 库列）：

| 中文 | 库列 | 中文 | 库列 |
|---|---|---|---|
| 字 | `hanzi` | 名称 | `name` |
| 声母 | `initial` | 类别 | `kind` |
| 韵母 | `final` | 所属 | `owner` |
| 类型 | `kind` | 核心码 | `core_code` |
| 词 | `word` | 来源ID | `source_id` |
| 附加 | `extra` | 错误写法 | `wrong` |
| 排序 | `sort_no` | 正确写法 | `right_word` |
| 标准词 | `word` | 适用组织 | `org` |
| 领域 | `domain` | 频率等级 | `freq_level` |
| 来源 | `src` | 错因类型 | `reason` |
| 首字母 | `initials` | 纠正示例 | `sample` |
| 拼音码 | `py_full` | 拼音码_严 | `py_strict` |

### 4.4 校验与失败

| 情况 | 结果 |
|---|---|
| 表头缺必填列 | 整份拒绝：`表头缺必填列：名称（模板里有的列请照抄）` |
| 必填单元格为空 | 该行进失败明细：`第 3 行：「正确写法」为空` |
| `附加` 不是 JSON | 该行进失败明细：`第 3 行：附加列不是 JSON` |
| `排序` 不是数字 | 该行进失败明细：`第 3 行：排序列不是数字` |
| 超过行数或大小 | 整份拒绝 |
| 写库异常 | 整批回滚，返回错误原文 |
| 同键已存在且为追加模式 | 跳过；软删过的同键行复活并更新 |

### 4.5 两种写入模式

| 模式 | 行为 |
|---|---|
| `append`（默认） | 同键跳过；软删行复活并更新 |
| `replace` | 该类先全部置软删（`deleted_flag=1` / `enabled=false`），再写入文件内容 |

替换模式不物理删，旧行留库可追溯。

## 5 接口规范

前缀 `/api/v1/prompts`，全部要求登录态（`Authorization: Bearer <token>`），未登录 401。

### 5.1 体检

`GET /lexicon/status`

```json
{"ok": true,
 "items": [{"key": "pinyin", "name": "拼音表（汉字 → 声母 / 韵母）", "rows": 20922,
            "why": "所有同音比较的读音来源。缺它，同音归一整体不可用。",
            "hint": ""}],
 "counts": {"pinyin": 20922}}
```

`items` 顺序固定：`pinyin`、`word`、`catalog`、`typo`、`wordlist`；`hint` 非空说明该类缺失会关掉哪层能力。

### 5.2 模板与导出

`GET /lexicon/template/{key}` → `text/csv; charset=utf-8`，中文表头 + 一行示例。
`GET /lexicon/export/{key}` → 当前库全量（`deleted_flag=0` / `enabled=true`），表头与模板一致，可原样再导入。
`key` 不在五类内 → 404 `{"error": "不支持的导入类型：x"}`。

### 5.3 导入

`POST /lexicon/import`，`multipart/form-data`

| 字段 | 必填 | 取值 |
|---|---|---|
| `file` | 是 | CSV / XLSX |
| `key` | 是 | `pinyin` / `word` / `catalog` / `typo` / `wordlist` |
| `mode` | 否 | `append`（默认）/ `replace` |

成功 200：

```json
{"ok": true, "key": "catalog", "mode": "append", "total": 3,
 "inserted": 3, "updated": 0, "skipped": 0, "ms": 420,
 "failed": [], "warning": "拼音表是空的，拼音码算不出来（导入的这列会留空，同音匹配不会生效）"}
```

失败 400：`{"error": "表头缺必填列：名称（模板里有的列请照抄）"}`。
`failed` 元素为 `{"row": 行号, "reason": "说明"}`，最多回 30 条。

### 5.4 立即生效

`POST /lexicon/reload` → `{"ok": true, "status": {"available": true, "reason": "", "source": "db:pg"}}`
失败 500：`{"ok": false, "error": "..."}`。

### 5.5 试一句


### 5.6 行级增删改查

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/lexicon` | 可编辑表概览：`{"ok":true,"tables":[{"key","name","note","rows","cols":[{"key","label"}]}]}` |
| GET | `/lexicon/{key}?q=&limit=&offset=` | 分页查询，`limit` 上限 200，返回 `total` 与 `rows` |
| POST | `/lexicon/{key}` | 新增一条，返回 `{"ok":true,"id":N}` |
| PUT | `/lexicon/{key}/{id}` | 整行覆盖保存 |
| DELETE | `/lexicon/{key}/{id}` | 软删 |

可编辑 `key`：`catalog`、`typo`、`term`、`ambiguous`、`wordlist`。
`catalog` 新增或改名时三个拼音列由服务端现算。
主键冲突 400：`{"error": "「名称」 已经有这一行；要改它请直接改那一行，不要重复新增"}`。
`pinyin` 与 `word` 不开放行级编辑，只走导入导出。

## 6 完整操作清单

### 6.1 一套新库从零配好

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 导 `pinyin.csv`（另一套已有全量表的实例用「导出现有」拿 20922 字） | 体检 `拼音表` > 20000 |
| 2 | 导 `word.csv`（`unit_kind` + `suffix_hint` + `common_word`） | 体检 `单位规则` > 0 |
| 3 | 导 `catalog.csv`（本现场机构名单，拼音列留空） | 体检 `名称库` = 名单条数 |
| 4 | 导 `typo.csv`（本地错字，可空） | 页面列表能看到行 |
| 5 | 点「立即生效」 | 返回 `ok=true`，`available=true` |
| 6 | 「试一句」打一句带错字的话 | 输出与预期一致 |

`t_nc_term`、`t_nc_ambiguous` 可留空：前者只做术语保护，后者当前不读。

沙箱实例（`sandbox.xibuyj.cn`）的拼音表 20922 字与单位规则 214 条已于 2026-11-21 预置，
现场只剩第 3 步：把他们的机构名单导进名称库。

### 6.2 加一个供电所

1. 名称库表 →「加一行」→ 名称 `青云供电所`、类别 `供电所`、所属 `青云市供电公司` → 存。
2. 名字里有拼音表没有的字，先按 3.4 补拼音行，再删掉这一行重加（重算拼音码）。
3. 立即生效 →「试一句」输入 `青芸供电所的线损率`，期望改成 `青云供电所的线损率`。

### 6.3 加一条错字

错别字表 →「加一行」→ 错误写法 `线笋率`、正确写法 `线损率` → 存 → 立即生效。
错字是字面替换，不补名字：用户只说「线笋」时不会变成「线损率」。

### 6.4 整套搬到另一套实例

源实例「导出现有」五类 → 目标实例按 6.1 的顺序导入；名称库用 `replace` 模式可清掉旧地名。
