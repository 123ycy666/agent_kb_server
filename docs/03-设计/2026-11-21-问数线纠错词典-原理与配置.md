# 问数线第②步：名称与错字纠错 —— 原理与配置

> 代码位置：`server/app/secretary/name_fix.py`（入口）、`server/app/secretary/libs/name_correction_lib/name_corrector.py`（算法）、
> `server/app/secretary/lex_source.py`（词典来源）、`server/app/secretary/lex_admin.py`（页面读写）、`server/app/secretary/lex_words.py`（词表）。
> 实测数据取自 2026-11-21 的三份库：随州 `ad_new`、宜昌 `ad_yc`、沙箱 `skeleton`。

## 1 环节定义

| 项 | 值 |
|---|---|
| 在问数链的位置 | ① 入口分流之后、③ 补问法之前（`agent.py` 的 `fix` 步） |
| 存储 | 本系统 PG 的 `cfg.t_nc_*` 六张表 + `cfg.t_nc_word` 词表；`public.t_nc_*` 是同名视图 |
| 生效方式 | 服务把六张表全量读进内存建索引，之后每次纠错零 SQL；每 60 秒比对 `MAX(update_time)`，变了整体重建 |
| 关闭开关 | `SECRETARY_NAMEFIX=0`；只读 CSV 不开库：`SECRETARY_LEXICON=file` |
| 失败行为 | 词表缺失/连不上 → 本步降级为原文，不影响提问链路 |

## 3 执行顺序

`name_fix.fix()` 先 `correct()` 走六层，再 `resolve()` 做名称归一：

| 步 | 方法 | 读哪张表 | 改正文 | 判据 |
|---|---|---|---|---|
| ① | `_fix_words` | `t_nc_typo` | 改 | 精确子串命中，长词优先；片段前是「今/去/明/上/下/本/当/同/每/这/那」+年/月，或后接「了/着/过」→ 判跨词，不改；命中术语内部 → 不改 |
| ② | `_fix_vocab` | `t_nc_wordlist` | 改 | 整句滑窗，用 `encode_light` 拼音码查词表；只有唯一候选才改；前/后一个字能组成已知词 → 判跨词不改；纯同音且贴合功能字 → 不改；与地名同音 → 只反问不改 |
| ③ | `_fix_names` | `t_nc_catalog` | 改 | 片段必须含类型后缀提示词（`SUFFIX_HINT`），按拼音码查名称库，相似度 ≥88 才改；多候选只提示不改 |
| ④ | `_annotate_partial_names` | `t_nc_catalog` | 只改字 | 裸地名/简称：「X错」→「X」，**不补后缀**；只认单位名核心前缀，严格音（不合并平翘舌）；纯同音且前后是虚词 → 不改；结果写进 `entities` 交下游 |
| ⑤ | `_match_areas` | `t_nc_catalog`（台区） | **已关闭** | 模块级 `NORMALIZE_AREAS=False`（2026-11-09 起），整段原样返回 |
| ⑥ | `_detect_unknown` | —— | 不改 | 只在 `unresolved` 里列「最接近」的候选，供人工看 |
| 归一 | `resolve` | 同上 | 改 | 在 `correct()` 结果上补成库内标准名：「X」→「X供电所」；已有标准名的区间不重复补；裸地名优先单位名，级别 公司 → 所 → 服务站；编号必须一致；库内无精确名时给「地名层合成名」并提示用前缀 LIKE |

实测（随州词典，宜昌问句）：

| 输入 | 输出 | 说明 |
|---|---|---|
| 西陵供电所的线损是多少 | 不变 | 名称库没有「西陵」，不归一 |
| 夷陵区供电公司上个月售电量 | 不变 | 同上 |
| 两河供电所的售电量 | 不变 | 名称库里只有随州的「两河…台区」，没有「两河供电所」，且台区归一已关 |
| 环谭供电所的现损 | 环潭供电所的**线损** | ①「现损→线损」；③把「环谭」按同音改成**随州**的「环潭供电所」 |
| 当阳玉阳供电所的线笋率 | …**线损**率 | ①同音错字 |
| 秭归县供电公司预蒜执行情况 | …**预算**执行情况 | ①同音错字 |
| 全市立了多少个工单 | 不变 | 纯同音 + 紧贴功能字，被判噪声 |

表中「环谭」那一行是配置前要知道的：名称库里是哪一家的地名，纠错就把别家的同音写法往哪一家改。

## 4 拼音码口径

编码规则（`name_corrector.encode`）：逐字取 `t_nc_pinyin` 的（声母, 韵母），声母按 `INITIAL_FUZZY` 合并、韵母按 `FINAL_FUZZY` 合并，直接拼接。

```
INITIAL_FUZZY: zh→z ch→c sh→s n→l r→l f→h j→z q→c x→s
FINAL_FUZZY:   ang→an eng→en ing→in ong→on uo→o ie→e ve→ue iang→ian uang→uan …
encode('环潭供电所', fuzzy=True)  = huantangondianso    # catalog.py_full
encode('环潭供电所', fuzzy=False) = huantangongdiansuo  # catalog.py_strict
initials                        = htgds                # 首字母
```

`t_nc_pinyin` 的读音不是通用拼音字典，而是**按库内业务名称语境投票定音**，所以多音字（曾/长/重/乐）与 catalog 预计算列口径一致。

各表拼音列的实际用途（`grep` 过 `name_corrector.py`，只有下面标「读」的进索引）：

| 表.列 | 谁生成 | 运行时是否读 | 说明 |
|---|---|---|---|
| `catalog.py_full` | 离线编译；`sync_lexicon.py` 用 `encode(name, True)` 现算 | **读**（建 `by_code` 索引） | 同音归一的唯一键；**留空 = 这条名字永远匹配不上** |
| `catalog.py_strict` | 同上，`encode(name, False)` | 不读 | 单位简称层用现算的严格音，不读这一列 |
| `catalog.initials` | 离线/`pypinyin` 首字母 | 不读 | 只为词典格式完整 |
| `catalog.core_code` | 离线编译 | 读（台区核心词索引，改名层已关） | 只有台区有值；单位名留空 |
| `pinyin.initial/final` | 离线一次性生成 | 读（所有现算编码的来源） | 改一行会影响全局新算的词 |
| `wordlist.py_full/initials` | 页面 `initials` 可自动补，`py_full` 不补 | 不读（词表层现算 `encode_light`） | 填错不报错，也不影响结果 |
| `ambiguous.py_code` | 手工/离线 | 不读（整表未使用） | 见 §7-② |

结论：**拼音码不是给业务看的字段，是纠错索引的键**。手工插 `catalog` 时真正必须填的是 `py_full`（有 `core_code` 的台区再填 `core_code`），且必须与 `encode` 同口径；`wordlist` 的拼音列随意。

## 5 加一条纠错的做法

### 5.1 只改字：`t_nc_typo`（页面可加，60 秒生效）

对「用户把字打错/写成同音字」，一条就够。它是精确子串替换，不做拼音、不补后缀。

```
错误写法：夷凌供电所      正确写法：夷陵供电所
错误写法：线笋            正确写法：线损
错误写法：预蒜            正确写法：预算
```

限制：用户只说「夷凌」时不会被改成「夷陵」，因为 typo 层只换整段出现的子串，补全由 `catalog` 那一层负责。

### 5.2 让系统认识这个名字：`t_nc_catalog`（页面无入口）

需要能做「只说地名 → 认出是哪个单位」「同音错字 → 归一到库内标准名」时，必须往名称库加行：

```sql
INSERT INTO cfg.t_nc_catalog
  (name, kind, owner, py_full, py_strict, initials, core_code, source_id, deleted_flag)
VALUES
  ('夷陵区供电公司', '供电公司', '', 'ilincvgondiangonsi', 'ilingqvgongdiangongsi', 'ylqgdgs', '', '1', 0);
```

- `kind` 用现有取值：`供电公司` / `供电所` / `供电服务站` / `台区`；`owner` 填上级单位名；
- 拼音码不要手敲——`encode` 依赖库里的拼音表，脱离服务进程算不出真值：

```bat
cd D:\秘书智能体
python -c "import sys; sys.path.insert(0,'server'); from dotenv import load_dotenv; load_dotenv('.env'); from app.secretary import name_fix; name_fix._corrector(); from app.secretary.libs.name_correction_lib import name_corrector as nc; print(nc.encode('夷陵区供电公司',True), nc.encode('夷陵区供电公司',False))"
:: 实测输出：ilincvgondiangonsi ilingqvgongdiangongsi
```

直接 `from name_correction_lib.name_corrector import encode` 得到的是汉字原文：那条路径没有挂数据库数据源，拼音表为空。

- `deleted_flag=0`、`update_time` 用 `now()`；缺了 `update_time` 不会触发 60 秒热重载。

### 5.3 批量灌名称库：`server/scripts/sync_lexicon.py`

从业务库 MySQL 的 `t_power_supply_company`（公司）、`t_power_company`（所）、`t_power_push_area`（台区）增量写进 `t_nc_catalog`，拼音码用同一套 `encode` 现算，**只增不删**。

宜昌业务库 `yc_dlj_data` 实测：13 家公司、88 个供电所、20275 个台区，字段与脚本要求一致。

```powershell
# .env 里 MYSQL_* 指向 47.121.183.81:3306；库名默认 dlj_data（随州），宜昌要显式指定
$env:MYSQL_DB_BUSINESS='yc_dlj_data'
python server/scripts/sync_lexicon.py            # dry-run，只打印待新增
python server/scripts/sync_lexicon.py --apply    # 真写库
```

前提与副作用：

| 项 | 说明 |
|---|---|
| 依赖 | 需要 `pypinyin`（本机当前未装，`pip install pypinyin`）、`pymysql`、`python-dotenv` |
| 目标库 | 脚本按 `PG_DSN` / `DATABASE_URL` 连 PG，跑前确认指向要改的那套系统库 |
| 不会删 | 目标库里已有的名称原样保留 → 宜昌库现在这 20183 条随州名会和宜昌名并存，归一可能出现两家候选 |
| 清旧数据 | 换现场前先把名称库清掉：`UPDATE cfg.t_nc_catalog SET deleted_flag=1, update_time=now()`（字典里注释要求软删，物理删除改不动版本指纹） |
| 台区数 | 20275 条台区会一并入库（台区改名层已关，只用于保护区与候选） |

### 5.4 单位规则词表：`t_nc_word`（无页面、无 API）

决定「什么算单位名、什么后缀能认、哪些常用词不许当地名」。`skeleton` 库**没有这张表**，那套实例的单位/简称归一整体关闭，只剩错字层。

```sql
INSERT INTO cfg.t_nc_word (kind, word, extra, sort_no) VALUES
  ('unit_kind', '供电所', '{}', 9),
  ('asked_unit_suffix', '供电所', '{"kinds":["供电所"]}', 9),
  ('common_word', '负荷', '{}', 0)
ON CONFLICT (kind, word) DO UPDATE
  SET extra = EXCLUDED.extra, sort_no = EXCLUDED.sort_no, enabled = true, updated_at = now();
```

**灌数据的现成脚本只有 `db/seed_b1.py`**（逐条调 `lex_words.save` 的 upsert）；服务启动时 `site._ensure_module_tables` 只会建空表。表中 `kind + word` 联合唯一，重复插入报 `duplicate key`。

`kind` 取值与含义见 `lex_words.py` 头部注释；`extra` 是 jsonb，`ask_tail` 需要 `{"single":"所","kinds":[...],"block_next":"有以在…"}`。

## 6 一条记录怎么填

### 6.1 错别字纠正（6 列，只有前 2 列影响纠错）

| 页面列 | 库列 | 必填 | 作用 |
|---|---|---|---|
| 错误写法 | `wrong` | 是 | 与用户输入做精确子串比对 |
| 正确写法 | `right_word` | 是 | 替换结果 |
| 适用组织 | `org` | 否 | 备注，不参与匹配 |
| 频率等级 | `freq_level` | 否 | 备注，写日志 |
| 错因类型 | `reason` | 否 | 备注，写日志 |
| 纠正示例 | `sample` | 否 | 备注 |

可直接照抄的三条默认案例（宜昌）：

| 错误写法 | 正确写法 | 适用组织 | 频率等级 | 错因类型 | 纠正示例 |
|---|---|---|---|---|---|
| 夷凌供电所 | 夷陵供电所 | 宜昌 | 高频 | 同音 | 夷凌供电所上个月线损 → 夷陵供电所上个月线损 |
| 渔阳关供电所 | 五峰渔洋关供电所 | 宜昌 | 高频 | 同音 | 渔阳关供电所这个月工单 → 五峰渔洋关供电所这个月工单 |
| 线笋 | 线损 | 电力局 | 高频 | 同音 | 线笋率多少 → 线损率多少 |

操作：下拉选「错别字纠正」→ 点「加一行」（插到第一行）→ 填前两列 → 点该行「新建」→ 保存后下拉计数 +1，60 秒内生效。

三条都只做字面替换。用户只说半截（「渔阳关」不带「供电所」）时，先加 `catalog` 行（§5.2），再让纠错层按拼音归一。

### 6.2 标准词表（4 列）

| 页面列 | 库列 | 作用 |
|---|---|---|
| 标准词 | `word` | 唯一有用列，词表层按它的拼音匹配同音错字 |
| 领域 | `domain` | 只写进结果里的「领域」字段 |
| 来源 | `src` | 备注 |
| 拼音码 / 首字母 | `py_full` / `initials` | 运行时不读；首字母留空会按拼音表自动补 |

### 6.3 歧义确认（6 列）与术语（4 列）

这两张表在当前版本里不改变纠错输出：`ambiguous` 建了索引无人读（§7-②），`term` 只保护 ≥3 字的术语不被错字表替换。填了不会有副作用，也不会有纠错效果。

## 7 页面与实现不一致的地方

① **超过 50 条看不到**：前端 `lexicon(key, q)` 不传分页参数（`web/src/api/index.ts:807`），后端 `limit` 默认 50（`server/app/api/v1/prompts.py:310`），前端表格分页 10 条/页。105 条错别字只有前 50 条可见，翻页也翻不到第 51 条；要看全只能用搜索框逐词查。

② **「歧义确认」加了不生效**：`name_corrector.py:817-822` 建了 `self.ambiguous`，全文再没有读取点（`grep self.ambiguous` 只有这两处）。页面上 81 条「歧义确认」对纠错零影响。

③ **写「六张纠错词典」，页面只有 4 张**：`server/app/secretary/impact.py:169` 名称是「六张纠错词典」，`lex_admin.TABLES` 只有 typo/term/ambiguous/wordlist 四张；`catalog`、`pinyin` 明确不给改（前端提示「名称库与拼音库是离线编译的」），`t_nc_word` 连入口都没有。

④ **删除是软删，页面没有恢复入口**：`lex_admin.delete` 只置 `deleted_flag=1`，列表按 `deleted_flag=0` 过滤（`lex_admin.py:247`）。误删只能在库里改回。

⑤ **截图的表名与线上接口对不上**：截图顶部写「存库：dct_t_nc.*」，而线上沙箱 `GET /api/v1/prompts/impact` 实测返回 `"where":"cfg.t_nc_*"`，仓库前端（`web/src/pages/Prompts.tsx:85`）也没有「存库」这段文案 —— 截图页面不是当前这版代码产出。配置前先用 §9 的 SQL 确认表在哪个 schema。

⑥ **新增行没有必填提示**：「加一行」插入空对象并放到首行（`ChainEditors.tsx:289`），行 key 用数组下标（`:251`）。填错只会在点「新建」时收到「「错误写法」不能为空」这类报错。

## 8 线上导入

### 8.1 页面只能一条一条

纠错词典接口只有单条 CRUD：`POST/PUT/DELETE /api/v1/prompts/lexicon/{key}[/{id}]`。没有 CSV 上传、没有批量新增、没有导入按钮。105 条错别字靠页面点 105 次；20183 条名称库根本点不了（页面也不给入口）。

### 8.2 批量路径

| 路径 | 命令 | 适用 | 注意 |
|---|---|---|---|
| 业务库 → 名称库 | `python server/scripts/sync_lexicon.py --apply` | 补齐公司/供电所/台区，拼音码自动 | 只增不删；需 `pypinyin`；先跑 dry-run |
| 整库搬词典 | `docker exec kb-postgres pg_dump -U kb -d ad_new -t 'cfg.t_nc_*' --data-only \| docker exec -i kb-pg-sandbox psql -U kb -d skeleton` | 把随州整套词典搬到另一套实例 | 跨容器走管道；目标库要先有这七张表的结构（`skeleton` 缺 `cfg.t_nc_word`，`COPY` 会报 relation does not exist）；不要带 `CREATE TABLE` |
| 空库初始化 | `psql -f db/lexicon.sql` | 全新实例一次装好六张表 + 41564 行 | 脚本建的是 `public.t_nc_*` **表**，目标库已有同名**视图**时 `DROP TABLE IF EXISTS` 报「is not a table」，先 `DROP VIEW IF EXISTS public.t_nc_typo, public.t_nc_term, public.t_nc_ambiguous, public.t_nc_wordlist, public.t_nc_catalog, public.t_nc_pinyin CASCADE;`；脚本里 `setval(..., 1, false)` 只把序列重置为 1，导入后必须 `SELECT setval('public.t_nc_typo_id_seq', (SELECT max(id) FROM public.t_nc_typo));`（六张表各一遍），否则页面新增撞主键 |
| 单条补错字 | 页面「加一行」 | 补几条，60 秒生效 | 见 §6.1 |

### 8.3 沙箱（宜昌）当前状态

`GET /api/v1/prompts/lexicon` 实测四张可编表全 0 行，六张词典表（含 `t_nc_catalog`、`t_nc_pinyin`）也是 0 行，`cfg.t_nc_word` 不存在 → 这套实例上「错别字纠正」层能用但没词，单位/简称归一整体关闭。要让宜昌问数认宜昌的供电所，按顺序做：① `t_nc_catalog` 灌宜昌机构（§5.3）→ ② `t_nc_word` 补单位后缀/禁入词（§5.4）→ ③ `t_nc_typo` 补本地错字（§6.1）。

## 9 校验

```bash
# 词典是否就绪（表在不在、行数、真跑一次纠错）
python server/scripts/check_lexicon.py

# 表在哪、多少行（本机 PG 5433）
psql "postgresql://kb:kb_dev_pwd@127.0.0.1:5433/ad_yc" -c "
  select 'typo' t, count(*) from cfg.t_nc_typo where deleted_flag=0
  union all select 'catalog', count(*) from cfg.t_nc_catalog where deleted_flag=0
  union all select 'word', count(*) from cfg.t_nc_word;"

# 名称库内容是否为本地地名
psql "postgresql://kb:kb_dev_pwd@127.0.0.1:5433/ad_yc" -c \
  "select name, kind from cfg.t_nc_catalog where kind='供电所' order by id limit 10;"

# 页面接口（改完 60 秒后生效）
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8200/api/v1/prompts/lexicon
```
