# 需求：规则出库 + 提示词可见（2026-11-01 定稿）

> 这份定死做什么、不做什么、怎么算完成。做的时候不许加需求。
> 配套：`2026-11-01-设计-规则分层与提示词页面.md`、`2026-11-01-问答主流程图.md`

## 一、一句话

规则从知识库里搬出来单独存；问答按流程阶段只带该阶段的规则；本地加一个页面，能看到模型此刻收到的全部提示词。

## 二、要做的事（四条，不多不少）

| # | 做什么 | 为什么 |
|---|---|---|
| R1 | **规则移出知识库**，单独一张表存（阶段、主题、正文、版本、启用）。知识库从此只放资料 | 规则和资料是两种东西：规则要精确取、要按阶段给、要能回滚；资料要按相似度找。混在一起，规则既拿不到向量，又会被 40 条上限截断 |
| R2 | **规则按阶段注入**。流程走到哪一步，只递这一步的规则包，一个包 ≤4000 字 | 规则会一直变多。全量注入撑不住，检索又不知道你在第几步 |
| R3 | **流程前段重排**：加粗闸（判要不要动原话），纠错挪到粗闸之后，补全独立成一步 | 现在什么都不管先纠错、先补时间；写通知、闲聊也被改。补全规则还埋在文档里，靠模型自己想起来查 |
| R4 | **新增页面「提示词」**：本地能看到 S0~S9 每层的字数与正文、六个规则包、补全表 | 现在改了规则不知道有没有生效，哪层在起作用也看不见。全靠猜 |

## 三、范围边界

**做**：上面四条 + 让它本地跑通。

**不做**：

- 不新建第二个知识库索引。
- 不改资料检索链路（`kb_search` / `run_sql` / `doc_context`）。
- 不改判模式四分类（general / data / doc / office）。
- 不做「一条问题一个规则条目」。
- 不动 S0 红线与 S1 优先级的内容。
- 页面只做「看 + 改规则」，不做上传（上传还在知识库页）。

## 四、验收判据（每条都能在本地验）

| # | 判据 | 怎么验 |
|---|---|---|
| A1 | 规则不再从 `document` 表读 | 把 `document` 里所有 `doc_type='rule'` 删掉，问答仍能拿到全部规则 |
| A2 | 知识库里只剩资料 | 知识库文档列表里不再出现规则文档 |
| A3 | 每个阶段的规则 ≤4000 字 | 页面上每个包显示字数，全部达标 |
| A4 | 一条规则只在一个包里 | 页面上六个包之间章节不重复 |
| A5 | 改规则下一轮生效 | 页面改一条，不重启，再问相关问题答的是新规则 |
| A6 | 写作类输入原话零改动 | 输入「帮我写个通知」，trace 里没有纠错动作 |
| A7 | 「两水」走完整新前段 | trace 依次出现：粗闸放行 → 纠错 → 补全 → 定口径 → 判题型 data |
| A8 | 页面能看到全部提示词 | 打开页面，S0/S1/L1/L2/S4/S6/L7… 每层都有标题、字数、正文 |
| A9 | 现有测试全绿 | `test_prompt_stack` / `test_rule_stack` / `test_kb_chain` / `test_scope_param` |
