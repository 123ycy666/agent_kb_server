# 大屏跳转对接说明（2026-10-21）

> 面向：大屏前端 / Java 侧同事
> 结论：**已实现**。你只需在 `/api/ask` 请求里加一个 `want_screen: true`，就能拿到
> `layer` / `method` / `mainId` / `data` 四个字段用于跳转；不传则完全走原来的问答。

---

## 一、你要做的两件事

### 1）后端配置（一次性）

在 `.env` 里加两行：

```ini
SCREEN_PREVIEW_URL=http://127.0.0.1:11999/api/ai/big-screen/preview
SCREEN_PREVIEW_TIMEOUT=5
```

- **不填 `SCREEN_PREVIEW_URL` = 整个功能关闭**（现有问答行为完全不变）。
- 超时按你确认的 **5 秒**。超过就当没识别，不影响问答。

### 2）前端调用带开关

```http
POST /api/ask
Authorization: Bearer <你的 token>
Content-Type: application/json

{
  "question": "2026年两水供电所线损率情况",
  "session_id": "s_xxx",
  "want_screen": true
}
```

**只有大屏这一路要带 `want_screen: true`**。知识库页、技能台、定时任务、预警这些调用方
**不要带** —— 带了就是每个问题都白等最多 5 秒。

---

## 二、我们返回什么

成功的响应（在原有字段基础上**平铺**多出四个）：

```jsonc
{
  "answer": "……",
  "session_id": "s_xxx",
  "qa_id": 2000,

  "layer": "lineLossAnalysis",
  "method": "stationBudgetInfo",
  "mainId": 123,
  "data": [{ "stationName": "两水供电所", "year": "2026" }]
}
```

字段含义与你方 `/preview` 接口一致：

| 字段 | 说明 |
|---|---|
| `layer` | 二级页面标识（你方白名单值） |
| `method` | 大屏动作；`unknownIntent` = 未识别 |
| `mainId` | 跳转用业务主键，可为 `null` |
| `data` | 意图参数列表，固定一个对象且含 `year` |

**传给 `/preview` 的问题文本**：用的是**补全后**的问题（已做地名/名称纠错、时间补全，
不做语义改写）。例如用户打「环谭供电所的现损」，传过去的是「环潭供电所的线损」。

---

## 三、四种情形，前端怎么判断

| 情形 | 响应表现 | 前端行为 |
|---|---|---|
| 没带 `want_screen` | **没有**这四个字段 | 不跳转（现状不变） |
| 带了，识别成功 | 四个字段都有 | 按 `method` 跳转 |
| 带了，返回 `unknownIntent` | `method = "unknownIntent"` | 不跳转，正常展示 `answer` |
| 带了，你方超时 / 服务不可用 | **没有**这四个字段 | 不跳转，正常展示 `answer` |

**判断规则很简单：`method` 存在且不等于 `unknownIntent` 才跳转，其它一律正常显示回答。**

第三条和第四条的区别只在于排查：我方后端日志会打一行
`[screen] preview 调用失败，已跳过：<原因>`，联调时看它就知道是对方没起还是超时。

## 四、自测命令（不依赖前端）

```bash
# 1. 登录拿 token
TOKEN=$(curl -s -X POST http://127.0.0.1:8200/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"<账号>","password":"<密码>"}' | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# 2. 带开关提问
curl -s -X POST http://127.0.0.1:8200/api/ask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"2026年两水供电所线损率情况","want_screen":true}' \
  | python -m json.tool | grep -E "layer|method|mainId|\"data\"|answer"
```

先确认你方 `/preview` 自己能通：

```bash
curl -s -X POST http://127.0.0.1:11999/api/ai/big-screen/preview \
  -H "Content-Type: application/json" \
  -d '{"message":"2026年两水供电所线损率情况"}'
```

**如果我方返回里没有那四个字段，先自己排查这一步能不能通**（大概率是 `SCREEN_PREVIEW_URL`
没配、或端口不通）。

## 六、三个注意点

1. **超时 5 秒会加到这一路问答的耗时上**：只有带 `want_screen` 的请求才付这个成本。
   如果你方识别经常接近 5 秒，建议优化或把超时降到 3 秒（改 `.env` 即可，不用改代码）。
2. **你方服务挂了不影响问答**：已实测（直接杀掉对方进程），问答照常返回、`qa_id` 正常落库。
3. **如果本服务跑在容器里**，`127.0.0.1:11999` 指向容器自己，要改成宿主机 IP。
   当前内网是 `start_backend.sh` 直接跑的，按上面的配置即可。

## 七、联调时可能问到的

| 问题 | 回答 |
|---|---|
| 「补全」具体做了什么？ | 只做地名/名称纠错 + 时间补全（如「今年」→具体年份），**不改写问法**、不做会话改写 |
| 会不会传历史会话？ | 不会。只传这一轮补全后的文本 |
| `mainId` 会不会是字符串？ | 你方返回什么我们透传什么；`int` / `string` / `null` 都原样给前端 |
| 枚举以后加了新值怎么办？ | 我们只透传不解释，**你方加值我们自动跟随**，不用改代码 |
| 需要鉴权吗？ | 现在不带。若后续要带固定 token，告诉我们，加一个请求头即可 |
