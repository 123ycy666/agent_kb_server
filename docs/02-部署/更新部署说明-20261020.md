```bash

cd /opt/kb && cp -a kb-delivery kb-delivery.bak.$(date +%F_%H%M)

# ③ ★ 建预警/任务流转的表（本次新增，10 张）
docker cp db/dispatch_tables.sql kb-postgres:/tmp/dispatch_tables.sql
docker exec kb-postgres psql -U kb -d ad_new -f /tmp/dispatch_tables.sql

# ④ 重启后端
./start_backend.sh          # 或 systemctl restart kb-backend

# ⑤ 自检
source .venv/bin/activate
python scripts/preflight_check.py
```

如果你上次**没建过对话记录表**（`db/chat_tables.sql`），这次一起补上：

```bash
docker cp db/chat_tables.sql kb-postgres:/tmp/ && \
docker exec kb-postgres psql -U kb -d ad_new -f /tmp/chat_tables.sql
```

三个 SQL 脚本（`lexicon` / `chat_tables` / `dispatch_tables`）**全是幂等**的，
重复执行只会打印 `NOTICE: ... already exists, skipping`，不会删数据。

## 四、⚠️ 一条安全提醒（请务必看）

本次新增了 **SSO 免密换 token 接口**（供 sga 前端直连），配置项：

```ini
SSO_LOGIN_ENABLED=true      # 默认就是 true
SSO_LOGIN_KEY=              # 默认空
```

**代码里的判断是「配了 key 才校验」**（`auth.py`：`if settings.sso_login_key and x_sso_key != key: 拒绝`）。
也就是说 **key 留空 = 知道用户名就能换到该用户的 token**。

- 纯内网、只给受信系统调用 → 现状可接受；
- 只要这个端口能被更多人访问 → **必须**设 `SSO_LOGIN_KEY`（一串随机值），或把 `SSO_LOGIN_ENABLED=false`。

同理，`INTERNAL_SERVICE_TOKEN` 为空时，`/api/alerts/*` 的系统接口和 `/api/internal/*` 也不校验。
