# 两套线上服务 实施说明（2026-11-19）

> 需求：`docs/04-计划/2026-11-19-两套线上服务-需求规格说明书.md`（SRS-02）
> 产品侧：`docs/03-设计/specs/2026-11-19-骨架与业务库-design.md`（第 7 节）
> 本文只写**服务器上怎么落地**；本次改动没连服务器、没有真发部署，落地时照本文执行。

## 1 两套实例的参数对照

| 项 | 随州（老服务） | 宜昌/沙箱（第二套） |
|---|---|---|
| 容器 | `kb-merged` | `kb-backend-sandbox` |
| 端口 | `127.0.0.1:8200` | `127.0.0.1:8210` |
| 产品库 | `ad_new` | 该实例自己的库（如 `skeleton`） |
| 镜像 | `kb-merged:latest` / `:prev` | 独立镜像名（如 `kb-sandbox:latest` / `:prev`） |
| 数据卷 | `kb_merged_uploads` | 独立卷（如 `kb_sandbox_uploads`） |
| nginx 配置 | `/etc/nginx/conf.d/kb.conf` | 另一份（如 `/etc/nginx/conf.d/sandbox.conf`） |
| 站点入口 | `/` | 路径前缀 `/sandbox/` 或独立主机名 |
| 引导配置 | `/root/agentkownlg/config/site.json` | 该实例自己的 `config/site.json` |

两套**共用的只有**：docker 引擎、nginx 进程、模型网关的 Key。库、镜像、容器、卷、配置、登录态各自独立。

## 2 发布一套不影响另一套（FR-REL-001/002、AC-04、AC-05）

`deploy.sh` 的每条动作都作用在「环境变量指定的那一个对象」上：

```bash
# 只发随州（不碰宜昌）
CONTAINER=kb-merged PORT=8200 DB=ad_new \
IMAGE=kb-merged:latest PREV_IMAGE=kb-merged:prev VOL_PREFIX=kb_merged \
NGINX_CONF=/etc/nginx/conf.d/kb.conf \
SITE_CONFIG=/root/agentkownlg/config/site.json \
bash /root/agentkownlg/merged/deploy/deploy.sh /root/agentkownlg/merged.tar.gz

# 只发宜昌（不碰随州）
CONTAINER=kb-backend-sandbox PORT=8210 DB=skeleton \
IMAGE=kb-sandbox:latest PREV_IMAGE=kb-sandbox:prev VOL_PREFIX=kb_sandbox \
NGINX_CONF=/etc/nginx/conf.d/sandbox.conf \
NGINX_TEMPLATE=/root/agentkownlg/sandbox/merged/deploy/nginx/prefix.conf \
SITE_PREFIX=sandbox HEALTH_PATH=/sandbox/health \
SITE_CONFIG=/root/agentkownlg/sandbox/config/site.json \
APP_DIR=/root/agentkownlg/sandbox \
bash /root/agentkownlg/sandbox/merged/deploy/deploy.sh /root/agentkownlg/sandbox/merged.tar.gz
```

判据（验收时逐条看）：

- `docker ps` 里另一套的 `STATUS` 运行时间**没有清零**（没被重启）；
- 另一套的镜像 ID 与 `:prev` 标签没变；
- 另一套的 `config/site.json` 没被覆盖。

## 3 带前缀站点的 nginx（IF-NGINX-001/002、AC-02、AC-03）

`deploy/nginx/prefix.conf` 是模板，`deploy.sh` 会替换 `__PREFIX__` / `__PORT__` 后追加到 `NGINX_CONF`：

```nginx
location ^~ /sandbox/ {
    proxy_pass http://127.0.0.1:8210/;   # ← 结尾斜杠 = 剥前缀
    ...
}
location = /sandbox { return 301 /sandbox/; }
```

三条必须同时成立，少一条就白屏或 404：

1. **`^~`**：否则被 `location ~* \.(js|css)$` 正则抢走，静态资源被后端 catch-all 兜成 `index.html`
   （`application/javascript` 变 `text/html`，浏览器按 JS 解析直接报错 —— 也就是老 `sandbox.conf` 的白屏根因）；
2. **`proxy_pass` 结尾带斜杠**：不带斜杠不会剥前缀，后端收到 `/sandbox/assets/…` 一律 404/兜底；
3. **静态资源与接口走同一个前缀**：模板是整块反代，满足。

前端只产出一份包（FR-FE-001）：`vite build` 的 `base` 是相对的 `./`，
`index.html` 里是 `./assets/index-xxx.js`，浏览器在 `/sandbox/` 下解析成 `/sandbox/assets/…`，
nginx 剥掉前缀后由后端 SPA 兜底返回真实文件（`content-type: application/javascript`）。
包内不出现任何前缀字符串，构建后可自查：

```bash
grep -c "/sandbox" web/dist/index.html web/dist/assets/*.js   # 期望 0
```

## 4 独立主机名（IF-DNS-001，仍在待定）

两个实例若共用「同一主机名 + 同一端口」，浏览器把它们当**同一 origin**，
`localStorage` 里的 `kb_token / kb_user / kb_id` 是同一份 —— 后登的覆盖先登的，
另一边 401 跳登录（SRS-02 §2.2 问题 1）。

要彻底互不影响，每个实例一个主机名。**这一步需要先加 DNS 记录，属于用户侧操作，本次没有代做**：

1. 在阿里云给第二套加一条 A 记录（如 `yc.example.cn` → `47.121.183.81`）；
2. 新建 `/etc/nginx/conf.d/<第二套>.conf`，`server_name` 填该域名，`location /` 整块反代到 8210
   （不用前缀模板；模板见 `deploy/nginx/kb.conf`，把 `server_name` 与端口换掉即可）；
3. `nginx -t && nginx -s reload`；
4. 该实例的 `config/site.json` 与第一套各一份，互不引用。

在没有独立域名之前，路径前缀（本文第 3 节）能保证**静态资源与接口不串**，
但**登录态仍共用一个 origin** —— 这是 SRS-02 §6 的待定项，不是代码能绕过的。

## 5 引导配置（产品侧新增，部署时必须放好）

每个实例启动时读本地文件 `config/site.json`（可用 `SITE_CONFIG_FILE` 改）：

```json
{
  "pg": {"host": "127.0.0.1", "port": 5433, "dbname": "<该实例的库>",
         "user": "kb", "password": "<口令>"},
  "admin": {"username": "admin", "password": "<初始管理员口令>"}
}
```

- 容器里挂到 `/app/config/site.json`（`deploy.sh` 的 `SITE_CONFIG` 负责，只读挂载）；
- 没有这个文件或连不上库时，容器照常启动，但**只提供「现场配置」页** —— 此时打开页面填三条连接即可，
  不用再改文件、不用重启；
- 该文件含明文口令：`chmod 600`，不要进代码仓库（`.gitignore` 已排除 `config/site.json`）。

## 6 回滚

- 应用：`deploy.sh` 自带的失败回滚（换回 `:prev` 镜像 + 旧代码目录）；
- 库：`gunzip -c _deploy_bak_*/<DB>.sql.gz | docker exec -i kb-postgres psql -U kb -d <DB>`；
- nginx：`deploy.sh` 备份在 `_deploy_bak_*/<配置文件名>`，把这一份拷回去再 `nginx -t && nginx -s reload`
  —— **只还原该实例那一份**，另一份不动。

## 7 本次没做的事

- 没有连服务器，没有真跑 `deploy.sh`（按需求「改动只落在 `deploy/` 与文档」）；
- 没有加 DNS A 记录（用户侧）；
- 没有动 `kb-postgres` 容器本身（SRS-02 §7 明确不在范围）。
