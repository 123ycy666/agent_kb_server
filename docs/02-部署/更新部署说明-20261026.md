# 更新部署说明（2026-10-26）

> 适用：已部署过（10-21 或更早）的环境。改动很小，**只有 2 件事要做**。

---

## 一、这次修了什么

| 问题 | 现象 | 现在 |
|---|---|---|
| **机构级别判错** | 「广水公司」被识别成「广水供电所」，查出来的数是**所级**不是公司级 | 已修，见第四节验证 |
| **词典不跟业务库同步** | 业务库新增的台区问不到；改名后的旧名还能命中 | 新增同步脚本 `scripts/sync_lexicon.py` |

另外把「所/公司/服务站」后缀残留（`广水供电所公司`、`广水供电所所`）和「公司」被改成「箱变」也一并修了。

---

## 二、对方要做的 2 步

```bash
# ① 覆盖代码 + 重启（名称归一的修复立刻生效）
cd /opt/kb && cp -a kb-delivery kb-delivery.bak.$(date +%F_%H%M)
unzip -o kb-delivery-linux.zip -d /opt/kb
./start_backend.sh            # 或 systemctl restart kb-backend

# ② 同步一次词典（补齐业务库里有、词典里缺的台区）
cd /opt/kb/kb-delivery && source .venv/bin/activate
python server/scripts/sync_lexicon.py            # 先看差异，不写库
python server/scripts/sync_lexicon.py --apply    # 确认无误再写
```

**不用** `pip install`、**不用**跑任何 SQL（`pypinyin` 本来就在依赖里）。

---

## 三、同步脚本要注意的三点

1. **默认只预览不写库**。先跑一次看「待新增」多少条、都是什么，再决定要不要 `--apply`。
2. **只增不删、不改已有行**。词典里人工补过的标注不会被覆盖；业务库没推全也不会误删。
   （我们这边实测：业务库 20326 条、词典 20183 条，差 39 条，剥掉「国网」前缀后是 35 条真台区。）
3. **它会自动修 id 序列**。`db/lexicon.sql` 是 COPY 带 id 导入的，序列不会前进，
   不修的话任何 INSERT 都会撞主键——脚本每次运行前都会对齐，不用你操心。

> 建议做成每周一次：`python server/scripts/sync_lexicon.py --apply`。
> 词典变更后服务端 60 秒内自动重载，**不用重启**。

| # | 问法 | 期望 |
