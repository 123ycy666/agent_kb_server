## 二 配置（都可不配，默认能跑）

| 变量 | 默认 | 作用 |
|---|---|---|
| `DISPATCH_ON` | `1` | 总开关；`0` 时新接口返回 503（回滚用） |
| `DISPATCH_AI_ON` | `1` | `0` 时只用规则建议，不调模型 |
| `DISPATCH_TICK_MINUTES` | `10` | 内部催办/升级/自动核销循环间隔；`0` = 关闭，改由外部 cron 调 `/api/dispatch/tick` |
| `DISPATCH_FILES_DIR` | `<server>/data/dispatch` | 附件与报告落盘目录 |
| `DISPATCH_SCAN_ACCOUNTS` | 空 | 逗号分隔；只扫这些账号（调试用），空 = 全部有效账号 |

> `INTERNAL_SERVICE_TOKEN` 沿用现有 `.env`，不新增。

## 三 升级步骤

```bash
# 0) 备份（可选但建议）
pg_dump -h 127.0.0.1 -p 5433 -U kb -d ad_new -Fc -f ad_new_before_dispatch.dump

# 1) 建表（幂等；空库/老库都跑这一条）
psql -h 127.0.0.1 -p 5433 -U kb -d ad_new -v ON_ERROR_STOP=1 -f db/dispatch_tables.sql

# 2) 升级依赖（无新依赖；确认 docx 可用）
python -c "import docx; print('docx ok')"

# 3) 重启服务（启动时会 create_all + 增量迁移，幂等）
#    Windows: 启动全部.bat    Linux: systemctl restart secretary

# 4) 冒烟（见第四节）
```

**为什么还要跑 SQL**：`create_all` 只建"不存在的表"，但 DDL 文件里还带索引与 CHECK；
先跑 SQL 可以保证索引/约束一定在。两步都幂等，谁先谁后都行。

## 五 定时任务

| 频率 | 调用 | 说明 |
|---|---|---|
| 每天 8:00 | `POST /api/alerts/scan {"cadence":"daily"}` | 预算 + 项目类 |
| 每周一 | `POST /api/alerts/scan {"cadence":"weekly"}` | 目前只有默认关的子判据，可不配 |
| 每月 5 日 | `POST /api/alerts/scan {"cadence":"monthly"}` | 指标类 + 完工未复盘 |
| 每年 1/7 月 | `POST /api/alerts/scan {"cadence":"yearly"}` | 复盘类 |
| 每 10 分钟 | 服务内部已自带（`DISPATCH_TICK_MINUTES`）；也可外部调 `POST /api/dispatch/tick` | 催办/升级/自动核销 |

**多进程/多实例**：内嵌 tick 会每个进程各跑一遍（幂等，但白耗 DB）。
多实例部署请设 `DISPATCH_TICK_MINUTES=0`，只让一个实例（或外部 cron）调 tick。

## 七 性能实测（2026-10-19，本机 → 远程 MySQL 3306）

| 动作 | 账号/范围 | 耗时 |
|---|---|---|
| 全量 daily 扫描 | 122 账号 / 63 个口径 | **31 秒** |
| 全量 monthly 扫描 | 同上 | **8.5 秒** |
| 全量 yearly 扫描 | 7 个口径 | **1 秒** |
| 单账号列表 `GET /api/alerts` | 1 | < 100ms |
| tick（< 100 个在办任务） | — | < 1 秒 |
| 附件/报告 docx | 1 | < 1 秒 |

瓶颈在**业务库网络往返**（每条 SQL 约 120ms），不在代码逻辑。
已做两个优化：批量解析（58s → 0.5s）、按 cadence 跳过不用的取数（月/年扫描 59s → 9s/1s）。

## 八 已知限制

| 项 | 现状 | 何时补 |
|---|---|---|
| 4 个子判据默认关 | `acceptance_overdue` / `amount_structure` / `no_effect` / `stale` | 业务补字段（状态流转时间、产出数据）后开 |
| 模型不可用 | AI 建议退回规则模板，接口仍 200（`ai_used=false`） | 不需补 |
| 任务追问 | 复用 `/api/ask` 的模型链路，模型挂时返回"模型暂不可用" | 不需补 |
| 附件 | 单文件 ≤20MB，落本机磁盘 | 要对象存储再改 `FILES_ROOT` |
| 通知 | 站内信；不写业务库 `t_message`（只读） | 要外部推送由上游拉接口 |
| 多实例 tick | 需关内嵌循环 + 外部统一调 | 部署时按第五节处理 |
