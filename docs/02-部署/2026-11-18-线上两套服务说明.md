## 5 共用什么、不共用什么

**共用（只有三样）**

1. 同一台服务器与 docker 引擎；
2. 同一个 nginx 进程：80 端口按路径分流 —— `/` 走老服务 8200，`/sandbox/` 走新服务 8210；
3. 同一套模型网关的 key（新服务的 `.env.sandbox` 里复用了 `ONLINE_*`）。

**不共用**

- 进程：两个容器，互不重启；
- 数据库：`ad_new` vs `skeleton`，各自独立的容器和数据卷；
- 配置文件：`.env.production` vs `.env.sandbox`；
- 账号：老系统人员库 vs 新服务本地测试账号；
- 业务库：老的那套 vs 对方的 `yc_dlj_data`；
- 规则/口径：老服务在用的一套 vs 新服务里的三节测试口径。

## 6 本次为开新服务动过什么

| 动作 | 影响老服务吗 |
|---|---|
| 新建目录 `/root/agentkownlg/sandbox`（代码 + 配置） | 不影响 |
| 新建容器 `kb-pg-sandbox`、`kb-backend-sandbox`、网络 `kb-sandbox-net` | 不影响 |
| 建 `ad_wf` 库（新服务的定时任务库，缺了容器起不来） | 建在新库容器里，不影响 `ad_new` |
| 在 `/etc/nginx/conf.d/kb.conf` 里加 14 行 `location /sandbox/` | 改前备份为 `kb.conf.bak_sub`；`nginx -t` 通过后平滑 reload，没有中断、没重启 |
| 另建了一个 `/etc/nginx/conf.d/sandbox.conf`（`sandbox.xibuyj.cn` 指向新服务） | 目前用不上（域名没解析），留着备用；不配 DNS 就不生效，也不影响任何现有站点 |
| 清理没有容器引用的悬空镜像 | 只删了未被引用的镜像层，老服务镜像没动；磁盘 1.2G → 2.2G 空闲 |

老服务的容器、数据库、配置、数据：**一个字没改**（容器仍是连续运行 2 天那个）。

## 7 日常操作

```bash
# 看两套状态
docker ps --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'

# 新服务日志
docker logs --tail 100 kb-backend-sandbox

# 只重启新服务（改代码后需要重启；改 env 必须重建，见下）
docker restart kb-backend-sandbox

# 新服务改了 .env.sandbox 之后：必须重建，不能只 restart
docker rm -f kb-backend-sandbox
# 再按原参数 docker run 一次（参数见 /root/agentkownlg/sandbox 下的启动记录）

# 老服务（非必要不要动）
docker restart kb-merged
```

## 8 怎么彻底撤掉新服务（如果不需要了）

```bash
# 1) 停并删容器（不动老服务）
docker rm -f kb-backend-sandbox kb-pg-sandbox
# 2) 删数据卷（新库的所有数据都会没）
docker volume rm kb_sandbox_pgdata kb_sandbox_uploads
# 3) 去掉 nginx 里那段 /sandbox/
cp /etc/nginx/conf.d/kb.conf.bak_sub /etc/nginx/conf.d/kb.conf && nginx -t && nginx -s reload
# 4) 可选：删目录
rm -rf /root/agentkownlg/sandbox
```

第 3 步的第 2 条命令会把 nginx 配置恢复成加新服务之前的原样。
