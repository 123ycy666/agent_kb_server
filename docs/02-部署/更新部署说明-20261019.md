## 一、结论：**重发整包，不要发增量**

本次不是小补丁：从 10-18 11:01 那一版到现在，共 **18 个提交、129 个文件**
（后端核心 `agent.py` +811 行，新增整套预警模块 4 个文件，技能文档改了 184 行）。

发增量需要你自己挑文件、漏一个就出怪问题；整包只有 **2.0 MB**，直接覆盖最省事。

| 文件 | 大小 | 说明 |
|---|---|---|
| `kb-delivery-linux.zip` | **2.0 MB** | 覆盖用（代码 + 文档 + 建表脚本 + 自检脚本） |
| `kb-delivery-wheels-linux-arm64.zip` | 56.4 MB | **不用重发**（依赖版本没变，见第三节） |

传完请核对校验和（走 U 盘/网盘时尤其要核，避免传坏一半）——
具体值见**发送时附带的《更新部署说明》**，或在传完后自己算一遍：

```bash
sha256sum kb-delivery-linux.zip
```

## 二、对方要做的 5 步

```bash
# ① 备份（只备份代码目录，不用备份数据库）
cd /opt/kb && cp -a kb-delivery kb-delivery.bak.$(date +%F_%H%M)

# ② 覆盖代码 —— ⚠️ 解压前先确认不会覆盖 .env 和 data/
unzip -o kb-delivery-linux.zip -d /opt/kb
#   注意：包内不含 .env，也不含 data/uploads，所以不会被覆盖
#   但如果你把 .env 放在 kb-delivery/ 里，解压前先把它挪出去

# ③ ★ 建对话记录表（本次新增，必须执行，见第四节）
docker cp db/chat_tables.sql kb-postgres:/tmp/chat_tables.sql
docker exec kb-postgres psql -U kb -d ad_new -f /tmp/chat_tables.sql

# ④ 重启后端
./start_backend.sh          # 或 systemctl restart kb-backend

# ⑤ 自检
source .venv/bin/activate
python scripts/preflight_check.py
```

**第 ③ 步是幂等的**（全是 `CREATE TABLE IF NOT EXISTS`），重复执行不会删数据、
不会报错，可以在已有数据的库上放心跑。

## 四、⚠️ 最关键的一步：为什么必须建表

这一条是本次更新里**最容易漏、后果最隐蔽**的：

> 10-15 把对话记录从 MySQL 迁到 PG 时，那 5 张表是**在服务器上手工建的**，
> 仓库里一直没有建表脚本。所以**全新库部署时，一问一答能正常返回，
> 但历史对话 / 会话统计 / 会话摘要全部不工作**（`/health` 里 `session_summary=false`）。

涉及的表（本次补上的 `db/chat_tables.sql`）：

| 表 | 用途 | 缺了会怎样 |
|---|---|---|
| `t_chat_session` | 会话列表 | 历史对话页永远空白 |
| `t_chat_message` | 每轮问答内容 | 点开会话看不到内容 |
| `t_chat_query_trace` | 查询口径主表 | 无法追溯这答案是怎么算出来的 |
| `t_chat_trace_step` | 工具执行步骤 | 详情里的执行过程缺失 |
| `t_user` | 用户投影 | 部分按用户统计失效 |

**判断你这边是否已经踩到这个坑**：登录后问一个问题，看返回里的 `qa_id`：

- `qa_id` 是**数字** → 落库正常，建表只是补保险
- `qa_id` 是 **null** → 就是这个问题，执行第 ③ 步即可修复

也可以在启动后看 `/health`，`session_summary` 为 `false` 就是没建表。

## 五、本次新增的功能（可选，不影响原有功能）

| 功能 | 需要额外做什么 |
|---|---|
| **预警模块**（工单/预算/指标对比的自动预警） | 无。读的是现有 MySQL 业务表（`t_power_work_order` 等），有数据就能用 |
| **免密换 token 接口**（供 sga 前端直连） | 可选：`.env` 里配 `INTERNAL_SERVICE_TOKEN`。**不配则该接口无鉴权**（内网可用，但不建议） |
| **页面开关** `SECRETARY_PAGE` | 可选，默认 `0`（关） |
| **一键部署脚本** `deploy/` | 可选，你们已经手工部署过，可以不用 |
| **模型默认值调整** | 内网走 `MODEL_CHANNEL=local`，跟 `LOCAL_LLM_MODEL` 走，不受影响 |

新增的 `.env` 配置项**全部有默认值**，不配也能启动。

## 七、出问题怎么回滚

```bash
# 停后端 → 把备份目录换回来 → 重启
cd /opt/kb
mv kb-delivery kb-delivery.failed.$(date +%F_%H%M)
mv kb-delivery.bak.20261019_xxxx kb-delivery
cd kb-delivery && ./start_backend.sh
```

**数据库不用回滚**：建表是 `IF NOT EXISTS`，只新增不修改，旧代码照常跑。
