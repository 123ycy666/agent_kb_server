# 对外接口文档（供其他项目前端对接）

> 版本：2026-10-19　适用服务：统一知识库与智能问数平台（合并版）
> 线上地址（**换服务器只改这一行**）：`http://47.121.183.81`　部署位置：`/root/agentkownlg/merged`
> 下文示例统一写作 `$BASE`；本文只覆盖**外部前端要用**的接口，完整 74 个接口见 `/docs`（Swagger）。

---

## 0. 通用约定

| 项 | 说明 |
|---|---|
| Base URL | `$BASE`（当前见文首那一行；**不要**带 `/api` 以外的路径前缀） |
| 编码 | 请求/响应均 UTF-8，`Content-Type: application/json`（上传除外） |
| 鉴权 | 登录后拿 `access_token`，之后每个请求加 `Authorization: Bearer <token>`，有效期 **12 小时** |
| 分页 | `page` 从 1 开始，`page_size` 默认 20 / 最大 100；返回 `{items,total,page,page_size}` |
| 时间 | ISO8601 带时区（如 `2026-10-19T03:42:10.769905Z`，UTC） |
| 错误 | 以 HTTP 状态码为准；`/api/v1/*` 错误体为 `{"detail":"原因"}`，`/api/*` 业务接口可能返回 `{"error":"原因"}` |

**状态码约定**：`200` 成功 / `202` 已受理（异步） / `400` 参数错 / `401` 未登录或令牌过期 /
`403` 无权限或所选知识库全不可用 / `404` 资源不存在 / `500` 服务内部错误。

### ⚠️ 跨域（对方前端必读）

服务端 CORS 目前为 `CORS_ORIGINS=*`（2026-10-19 为配合 sga 前端直连临时放开），
任意来源的浏览器请求都不会被拦。如需收紧，在 `.env.production` 改成具体域名（逗号分隔）并重启容器。

## 1. 认证

### 1.1 登录 `POST /api/v1/auth/login`

账号来自人力资源系统 `t_employee`（`login_name` + 密码），**不是本地账号**。

```json
{ "username": "zhangsan", "password": "******" }
```

响应：

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 43200,
  "user": { "id": 12, "username": "zhangsan", "display_name": "张三" },
  "roles": ["user"],
  "permissions": ["doc:read", "search:query", "kb:read"]
}
```

### 1.2 免密换 token `POST /api/v1/auth/sso/login`（第三方系统直连用）

```json
{ "username": "zhangsan" }
```

凭 HR 登录名（`t_employee.login_name`）直接换本平台 JWT，**不校验密码**；
员工必须存在且在职，否则 401。返回结构与 1.1 完全一致（`access_token` / `expires_in` / `user` / `roles` / `permissions`）。

> ⚠️ 等价于「知道用户名就能拿到该用户身份」，仅限内网/受信系统使用。
> 需要收紧时：`.env` 设 `SSO_LOGIN_ENABLED=false` 关闭，或配置 `SSO_LOGIN_KEY` 要求请求头 `X-SSO-Key`。

### 1.3 当前身份 `GET /api/v1/auth/me`

返回 `{id, username, display_name, actor_type, roles[], permissions[], app_id}`。
**前端按钮级权限建议直接用 `permissions`**，不要硬编码角色名。

常用权限码：`doc:read` `doc:upload` `doc:update` `doc:delete` `doc:tag`
`kb:read` `kb:create` `kb:update` `kb:delete` `search:query`
`conflict:read` `conflict:resolve` `audit:read` `user:read` `system:config`。

## 2. 快速开始（一条完整链路）

```bash
BASE=${AI_BASE:-http://47.121.183.81}     # 没设环境变量时用当前线上地址

# ① 登录
TOKEN=$(curl -s -X POST $BASE/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"zhangsan","password":"******"}' | jq -r .access_token)

# ② 看有哪些知识库
curl -s "$BASE/api/v1/kb?page=1&page_size=20" -H "Authorization: Bearer $TOKEN"

# ③ 上传一个文档（异步受理，拿 task_id）
curl -s -X POST "$BASE/api/v1/kb/1/documents" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@制度.pdf" -F "is_public=true" -F 'tags=["行政","制度"]'

# ④ 轮询任务直到 status=done
curl -s "$BASE/api/v1/tasks/<task_id>" -H "Authorization: Bearer $TOKEN"

# ⑤ 提问
curl -s -X POST $BASE/api/ask \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"凉水供电所今年线损情况","kb_ids":[1]}'
```

## 3. 智能问答（问数）

### 3.1 提问 `POST /api/ask`

请求体（`question` 之外全部可选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `question` | string | **必填**，用户原话，不需要预处理 |
| `session_id` | string | **继续对话时传上一轮返回的 `session_id`**；不传则新建会话 |
| `kb_ids` | int[] | 检索范围（知识库 id）。不传 = 用服务端「参与智能问答」标记的库。全部无权限 → `403` |
| `model` | string | 指定模型 id，不传用默认 `deepseek-v4.1-flash-1017`（清单见 3.3） |
| `uid` / `user_code` | string | 业务侧用户 ID（可选，默认取登录用户） |
| `user_name` | string | 展示名（可选） |
| `channel` | string | 来源渠道，默认 `web`（可用于区分端） |
| `history_turns` | int | 多轮上下文轮数，默认 5；传 `0` 关闭上下文 |
| `scope` | string | 业务口径（如 `随县供电公司`）；不传按“全市” |
| `today` | string | 业务日期 `YYYY-MM-DD`；不传按系统当天 |
| `max_steps` | int | 最大工具轮次（一般不要传，服务端有预算保护） |

> `want_page` / `page_mode` 已**下线**（分析页面功能关闭），传了也返回空，请忽略 `page_html`。

响应（关键字段）：

```json
{
  "qa_id": 128,                        // ★ 评价时要用；为 null 表示这次没落库
  "session_id": "s_f6ce0c2806e841e3...", // ★ 继续对话 / 查历史要用
  "answer": "两水供电所今年1-9月……",
  "model": "deepseek-v4.1-flash-1017",
  "input_question": "凉水情况",
  "fixed_question": "两水供电所情况",    // 纠错后的问法
  "scope": { "time": "2026年1-9月", "place": "两水供电所", "time_is_default": true },
  "steps": 22,                          // 工具轮次
  "db_query_count": 16,                 // 查库次数（可用于展示“查了 N 次”）
  "kb_query_count": 1,
  "elapsed_ms": 24500,
  "unverified": false,                  // true = 数据未核实，前端建议弱化展示
  "trace": [ /* 每步明细，调试用；默认不展示给用户 */ ],
  "page_html": "", "page_token": ""
}
```

**耗时预期**：简单问题 5~10s，复杂分析题 15~30s（多轮取数）。前端务必做 loading 与超时（建议 120s）。

### 3.2 继续对话

第二轮起，把上一轮的 `session_id` 带回来即可：

```json
{ "question": "那意见工单呢？", "session_id": "s_f6ce0c2806e841e3...", "kb_ids": [1] }
```

服务端会自动带上最近 5 轮上下文，并沿用上一轮的时间/地点口径（“那…呢”这类追问能接上）。

### 3.3 可选模型 `GET /api/models`

返回 `{default, models:[{id,label,group,note}]}`。前端做成下拉框时，
**把 `default` 作为初始值**；用户切换后把 `id` 作为 `ask` 的 `model` 传回。

### 3.4 评价 `POST /api/feedback`

```json
{ "qa_id": 128, "feedback": 1, "note": "口径对" }
```

`feedback`：`1` 赞 / `0` 踩；`note` 可选。`qa_id` 取 3.1 的返回值。

### 3.5 每日预警 `POST /api/alerts/daily`（给定时任务，不是给前端）

```bash
curl -X POST $BASE/api/alerts/daily \
  -H "X-Internal-Token: <INTERNAL_SERVICE_TOKEN>" \
  -H 'Content-Type: application/json' -d '{"account":"zhangsan"}'
```

⚠️ 走**内部令牌**而不是用户 JWT；令牌在服务器 `.env.production` 的 `INTERNAL_SERVICE_TOKEN`。
**该值为空时接口不校验身份**，务必确认线上已配置。

## 4. 对话历史

### 4.1 我的会话列表 `GET /api/sessions`

查询参数：`limit`（默认 50，最大 5000）、`offset`（默认 0）。
**只返回当前登录用户自己的会话**，其他用户看不到。

```json
{
  "total": 2, "returned": 2, "limit": 50, "offset": 0, "truncated": false,
  "sessions": [
    {
      "session_id": "s_f6ce0c2806e841e38182883b6ecbb510",
      "title": "凉水情况",
      "ai_model": "deepseek-v4.1-flash-1017",
      "channel": "web",
      "client_ip": "203.0.113.10",
      "msg_count": 2,
      "status": 1,
      "create_time": "2026-10-19 03:42:10.769905",
      "last_msg_at": "2026-10-19 03:42:10.773549",
      "ended_at": null
    }
  ]
}
```

> `title` 由服务端根据首句问题生成，可直接用于列表展示。

### 4.2 某场会话的明细 `GET /api/history`

查询参数：`session_id`（**必填**）、`limit`（默认全量）、`with_steps`（默认 `false`，为 `true` 时带每轮执行的 SQL/工具明细）。

```json
{
  "session": { "session_id": "s_f6ce...", "title": "凉水情况", "msg_count": 2, "...": "同 4.1" },
  "total": 2, "returned": 2, "limit": 2, "truncated": false,
  "messages": [
    {
      "id": 7, "seq_no": 1,
      "direction": 1,          // ★ 1=用户提问，2=AI 回答
      "sender_type": 1,        // 1=用户，2=AI
      "msg_type": 1,           // 1=文本
      "content": "凉水情况",
      "model": null,
      "latency_ms": null,
      "qa_id": null,           // AI 那条才有值，可配合 /api/feedback
      "create_time": "2026-10-19 03:48:13.043772",
      "fixed_question": null, "completed_question": null,
      "name_fix_used": null, "completion_used": null,
      "period_type": null, "period_key": null
    }
  ]
}
```

**渲染建议**：按 `seq_no` 升序排列，`direction==1` 放右侧气泡、`direction==2` 放左侧；
消息内容已是最终文本（Markdown 直接渲染即可）。

### 4.3 记录库概览 `GET /api/stats`

返回问答总量、知识缺口数、未核实数、纠错命中数，用于“数据看板”小卡片（可选）。

## 5. 知识库

### 5.1 列表 `GET /api/v1/kb`

`?page=1&page_size=20`

```json
{
  "items": [{
    "id": 1, "name": "系统知识库", "description": null,
    "embedding_model": "online/text-embedding-v4", "embedding_dim": 1024,

    "document_count": 0, "chunk_count": 0, "visible_document_count": 0
  }],
  "total": 1, "page": 1, "page_size": 20

```

> `qa_enabled=true` 表示该库**参与智能问答**（前端不传 `kb_ids` 时用它）。

### 5.2 详情 `GET /api/v1/kb/{kb_id}`　　`PATCH /api/v1/kb/{kb_id}`

`PATCH` 可改：`name` / `description` / `chunk_size` / `chunk_overlap` / `status` / `qa_enabled`（传哪个改哪个）。

```json
{ "name": "公司制度", "description": "可选", "chunk_size": 512, "chunk_overlap": 64 }
```

`embedding_model` 通常留空（跟随系统默认，1024 维）。返回同 5.2。

### 5.4 删除 `DELETE /api/v1/kb/{kb_id}`

⚠️ **级联删除该库下所有文档与切片，不可恢复**。前端务必二次确认。
返回 `{"ok":true,"message":"...","warnings":[]}`。

### 5.5 统计 `GET /api/v1/kb/{kb_id}/stats`

```json
{ "kb_id": 1, "document_count": 12, "visible_document_count": 10,
  "conflict_document_count": 1, "chunk_count": 2948,
  "document_status": { "ready": 11, "pending": 1 } }
```

### 5.6 切换向量模型 `POST /api/v1/kb/{kb_id}/embedding-model`

切换后**必须**调 `POST /api/v1/kb/{kb_id}/reindex` 重建索引，否则检索维度不匹配。一般不要给前端开放。

## 6. 文档

支持格式：`GET /api/v1/system/formats` →
`.pdf` `.docx` `.md` `.markdown` `.txt` `.csv` `.xls` `.xlsx` `.xlsm`。

### 6.1 上传 `POST /api/v1/kb/{kb_id}/documents`（multipart）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | 文件 | ✅ | 单个文件；多选用**多次请求**，一次一个 |
| `is_public` | bool | ✗ | 默认 `false`＝仅上传者可见可检索；`true`＝所有人可见 |
| `tags` | string | ✗ | **JSON 数组字符串**，如 `'["行政","制度"]'`，不是逗号分隔 |

```bash
curl -X POST "$BASE/api/v1/kb/1/documents" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@制度.pdf" -F "is_public=true" -F 'tags=["行政","制度"]'
```

响应 **202**（仅表示“已受理”，不代表入库完成）：

```json
{ "task_id": "8f00c38c-7503-4a21-9d01-19ffd9ae1ba7",
  "status": "accepted",
  "message": "已受理，正在后台解析与向量化；可轮询任务状态获取最终结果",
  "doc_id": null,            // 受理时还没有 doc_id，完成后在 task.result 里
  "conflict_count": 0,
  "conflict_docs": [],
  "warnings": [] }
```

### 6.2 轮询任务 `GET /api/v1/tasks/{task_id}`

```json
{
  "id": "8f00c38c-7503-4a21-9d01-19ffd9ae1ba7",
  "task_type": "doc_ingest", "kb_id": 1, "ref_id": null,
  "status": "done",           // pending | running | done | failed | conflict_pending
  "progress": 100, "stage": "ready",
  "error_msg": null,
  "result": {                 // done 后才有
    "doc_id": 1,              // ★ 最终文档 id
    "chunk_count": 3,
    "conflict_count": 0
  },
  "created_at": "...", "finished_at": "..."
}
```

**前端建议**：1~2 秒轮询一次，`status=done` 后从 `result` 取 `doc_id` 再刷新列表；
`failed` 展示 `error_msg`。大文件（几十 MB）可能 1~3 分钟。

### 6.3 文档列表 `GET /api/v1/kb/{kb_id}/documents`

查询参数：`page`、`page_size`、`parse_status`、`has_conflict`（bool）、`tags`（可重复传）。

```json
{
  "items": [{
    "id": 37, "kb_id": 1, "root_id": null, "version_no": 1, "is_active": true,
    "filename": "制度.pdf", "file_ext": ".pdf", "file_size": 182734,
    "parse_status": "ready",       // pending(排队/解析中) | ready(可用)
    "parse_error": null,
    "has_conflict": true, "conflict_count": 2,
    "chunk_count": 86,
    "visibility": "public",        // public | private
    "owner_id": 1, "uploaded_by_app": null,
    "created_at": "...", "updated_at": "...",
    "tags": ["行政","制度"]
  }],
  "total": 12, "page": 1, "page_size": 20
}
```

### 6.4 文档详情 `GET /api/v1/documents/{doc_id}`

同 6.3 的单个对象（额外有 `content_hash`、`storage_path`）。

### 6.5 下载 `GET /api/v1/documents/{doc_id}/download`

返回原文件流，带 `Content-Disposition: attachment`。前端 `<a href>` 直接下载即可（**需要带 token**，
所以建议用 `fetch` + `blob` 再触发下载，或在 URL 上做一次性签名——当前不支持 URL 内 token）。

> **关于“文档位置”**：列表/详情里的 `storage_path`（如 `/data/uploads/kb_1/20261019..._制度.pdf`）
> 是**服务器容器内的物理路径**，不是可访问 URL，前端**不要**拿它拼链接。
> 取文件只有两个正口：本节 `/download`（下载）与下节 `/content`（预览）。

### 6.6 浏览器内预览 `GET /api/v1/documents/{doc_id}/content`

`Content-Disposition: inline`，PDF/图片可直接在 `<iframe>` 里打开；Word/Excel 由浏览器决定（多半下载）。

### 6.7 切片预览 `GET /api/v1/documents/{doc_id}/chunks`

返回该文档的切片列表（调试/溯源用，一般后台页面才需要）。

### 6.8 删除 `DELETE /api/v1/documents/{doc_id}`

```json
{ "ok": true, "message": "已删除", "warnings": [] }
```

⚠️ 删除会同时移除切片与向量，**不可恢复**（版本历史仍可查）。前端务必二次确认。

### 6.9 可见性 `PATCH /api/v1/documents/{doc_id}/visibility`

```json
{ "visibility": "public" }   // public | private
```

### 6.10 标签

- 覆盖式设置：`POST /api/v1/documents/{doc_id}/tags`　`{"tags":["行政","预算"]}`
- 删除单个：`DELETE /api/v1/documents/{doc_id}/tags/{tag_name}`（`tag_name` 需 URL 编码）
- 词表：`GET /api/v1/tags`；筛选可选项：`GET /api/v1/tags/options`

### 6.11 版本

- 历史：`GET /api/v1/documents/{doc_id}/versions`
- 回滚：`POST /api/v1/documents/{历史版本的 doc_id}/restore`（**无请求体**，路径里的 id 是旧版本那一条）

### 6.12 重建索引 `POST /api/v1/documents/{doc_id}/reindex`

解析异常或换模型后使用；耗时较长，返回任务或直接同步完成（以响应为准）。

## 7. 冲突提醒

### 7.1 冲突列表 `GET /api/v1/conflicts`

查询参数：`kb_id`、`status`（`pending` / `resolved` / `ignored`）、`doc_id`、`page`、`page_size`。

```json
{
  "items": [{
    "id": 9, "kb_id": 1,
    "new_doc_id": 37, "old_doc_id": 21,
    "conflict_type": "数值冲突", "relation": "contradict",
    "similarity_score": 0.91, "rerank_score": 0.87,
    "reason": "同一指标口径不同……",
    "new_snippet": "台区线损率 2.24%",
    "old_snippet": "台区线损率 2.61%",
    "status": "pending",            // pending | resolved | ignored
    "resolution": null,             // overwrite | keep_old | coexist | cancel | ignore
    "new_doc_name": "制度.pdf", "old_doc_name": "旧制度.pdf", "old_doc_version": 1,
    "created_at": "..."
  }],
  "total": 1, "page": 1, "page_size": 20
}
```

### 7.2 统计 `GET /api/v1/conflicts/stats`

```json
{ "total": 0, "pending": 0, "resolved": 0, "ignored": 0, "by_type": {}, "by_relation": {} }
```

### 7.3 对单个文档重检 `POST /api/v1/conflicts/detect`

```json
{ "doc_id": 37 }
```

需要 `conflict:resolve` 权限。

### 7.4 全库扫描 `POST /api/v1/conflicts/scan`（管理员）

```json
{ "kb_id": 1, "only_unscanned": true }
```

### 7.5 处理冲突 `POST /api/v1/conflicts/{conflict_id}/resolve`

```json
{ "resolution": "keep_old", "note": "以旧版为准" }
```

`resolution` 取值：`overwrite`（用新版覆盖）/ `keep_old`（保留旧版）/ `coexist`（两者并存）/
`cancel`（取消新版）/ `ignore`（忽略，不再提醒）。

## 8. 检索（不算问答，只返回片段）

`POST /api/v1/search`

```json
{
  "query": "差旅报销标准",
  "kb_ids": [1],
  "tag_filters": ["行政"],
  "top_k": 5,
  "recall_k": 50,
  "rerank": true,
  "include_conflict": false
}
```

返回 `{query,total,results[],took_ms,recall_count,applied_filters,filter_notice,degraded,degraded_reason}`。
`degraded=true` 表示向量/精排降级（仍返回结果，但排序可能变差），前端可提示“结果可能不完整”。

## 10. 错误码与排查

| HTTP | 典型返回 | 原因 / 处理 |
|---|---|---|
| 400 | `{"detail":"..."}` / `{"error":"缺少 session_id"}` | 参数缺失或格式错 |
| 401 | `{"detail":"Not authenticated"}` | 没带 token / token 过期（12h）→ 重新登录 |
| 403 | `{"answer":"所选知识库不可用..."}` | `kb_ids` 全部无权限/已停用；或缺少对应权限码 |
| 404 | `{"error":"session 不存在"}` | session_id 错，或不属于当前用户 |
| 409 | `{"detail":"标签已存在"}` | 创建重名标签（仅 `/api/v1/tags`） |
| 429 | — | 上游模型限流由服务内部退避重试，**一般不会抛给前端** |
| 500 | `{"answer":"服务异常：..."}` | 服务端错误；把 `question`、时间点、`session_id` 反馈给我们 |

**问答接口的“软失败”**：模型网关不可用时仍返回 `200`，但 `answer` 是
`模型「xxx」在当前模型网关不可用...`，且 `qa_id=null`。前端应识别 `qa_id=null` 并提示重试/换模型。

## 11. 前端对接时序（建议）

```
登录 ──► 存 token（内存/ sessionStorage）
  │
  ├─ 知识库页：GET /api/v1/kb ──► 选库
  │      └─ 文档页：GET /api/v1/kb/{id}/documents
  │             ├─ 上传：POST .../documents ──► 得到 task_id ──► 轮询 /tasks/{id}
  │             ├─ 删除：DELETE /documents/{id}（二次确认）
  │             ├─ 下载/预览：/download · /content
  │             └─ 冲突：列表 has_conflict=true ──► GET /api/v1/conflicts?doc_id=
  │
  └─ 问答页：
        POST /api/ask {question, kb_ids}
          ├─ 首轮：不传 session_id ──► 存返回的 session_id
          ├─ 追问：带上 session_id（服务端自动续上下文）
          └─ 评价：POST /api/feedback {qa_id, feedback}
        历史页：
          GET /api/sessions ──► GET /api/history?session_id=
          └─ 点“继续对话” ──► 回到问答页，带上该 session_id
```

---

## 12. 对接注意事项（踩坑清单）

1. **`session_id` 是“继续对话”的唯一凭据**，必须由前端保存；丢了就是新会话。
2. **`kb_ids` 必须传**（或让服务端用默认库），且用户要有该库权限，否则 `403`。
3. **上传是异步的**：202 只代表受理，必须轮询 `/api/v1/tasks/{id}` 到 `done` 才算成功。
4. **`tags` 是 JSON 数组字符串**，不是逗号分隔；传错会被忽略。
5. **问答可能 15~30 秒**：前端超时至少 120s，并展示“正在查数（第 N 步）”类反馈。
6. **下载/预览需要带 token**，不能直接 `<a href>` 裸链；用 `fetch + blob`。
7. **跨域**：对方域名不在 `CORS_ORIGINS` 里浏览器会拦；见第 0 节。
8. **权限码以 `GET /api/v1/auth/me` 返回为准**，不要用角色名判断。
9. **历史只属于当前登录用户**；切换账号看不到别人的会话（这是设计，不是 bug）。
10. **删除不可逆**（文档/知识库），前端一律二次确认。
