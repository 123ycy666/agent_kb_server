## 技能文件格式

### 收哪些文件

唯一一条文件级校验是扩展名。扩展名不在白名单内 → `500`，响应里的支持列表原文：

```text
.csv, .docx, .markdown, .md, .pdf, .pptm, .pptx, .txt, .xls, .xlsm, .xlsx
```

实查原文：`raw/specs-upload-unsupported-ext.json`。

### 文件内容落到哪

服务端只把文件当成「一段正文文本」。frontmatter 不解析、不校验、不剥离。

| 文件里的内容 | 落到 `kb.spec.body` 的形态 | 实查原文 |
|---|---|---|
| YAML frontmatter 整块（`---` 到 `---`） | 原样保留，成为正文首段 | `body` 以 `---\nname: 文档实查-上传建技能\ndescription: …\nrole_code: sudu\n---` 开头 |
| `#` / `##` 标题行 | 独占一行，`#` 与层级被去掉 | `文档实查-上传建技能`、`什么时候用` |
| 标题下的段落 | 前面加 `[标题路径] `，路径用 ` > ` 连接 | `[文档实查-上传建技能 > 什么时候用] 用户说「文档实查」时用这篇。` |
| 列表项 `- x` / `1. x` | 去掉列表标记后同上一行处理 | `[文档实查-上传建技能 > 步骤] 读原文` |
| 空行 | 正文里的段落分隔，也是 `preview.slices` 的分片边界 | `slices` 出 5 片 |

实查原文：`raw/specs-upload-spec.json`、`raw/specs-edit-uploaded.json`。

### 元数据从哪来

技能的名称、角色、四项、检查项、结构、版式都不从文件读，只从 multipart 字段来。

| 字段 | 来源 | 实查 |
|---|---|---|
| 技能名 `name` | form `name`；不传则取文件名去扩展名，截前 120 字 | `name=文档实查-上传建技能` → 响应 `"name":"文档实查-上传建技能"` |
| 角色 `role_code` | form `role_code`；空串 → 落资料库 | 不传 → `"space":"material"` |
| 什么时候用 `when_to_use` | form `when_to_use` | 不传 → `""` |
| 适用 `applies` | form `applies` 字符串，按 `,` `，` `、` 三种分隔符切成数组 | `applies=甲，乙、丙` → `"applies":["甲","乙","丙"]` |
| 产物 `product` | form `product` | 不传 → `""` |
| 检查项 `check_items` / 结构 `outline` / 版式 `fmt` | 上传接口不收，落默认值 | `"check_items":[]`、`"outline":[]`、`"fmt":{}` |
| frontmatter 里的 `name` / `role_code` / `role` | 不读 | 坏 frontmatter 文件上传仍 `200`，`role_code` 仍是 form 里的 `sudu` |

实查原文：`raw/specs-upload-spec.json`、`raw/specs-upload-material.json`、`raw/specs-edit-applies-split.json`、`raw/specs-upload-bad-frontmatter.json`、`raw/specs-edit-bad-frontmatter.json`。

### 发布要求的四项（代码校验逻辑）

`publish()` 只校验四项非空：`role_code`、`when_to_use`、`applies`（非空数组）、`product`。缺任一项 → `400`，响应带 `missing` 数组。归属（`owner_id`）不在发布校验项内；正文不校验长度与结构。

## 二 `POST /api/v1/specs/upload` 上传即分类

**① 概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/v1/specs/upload` |
| 鉴权 | 需要 `Authorization: Bearer <access_token>` |
| Content-Type | 请求 `multipart/form-data`；响应 `application/json` |

**② 请求参数**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `file` | form | file | 是 | 上传文件。扩展名必须在白名单内，见「技能文件格式」；文件字节被解析成正文 |
| `role_code` | form | string | 否 | 角色码，取自 `GET /specs/roles`。非空且 `space` 不是 `material` → 落说明书库（`space=spec`、`status=pending`）；空 → 落资料库（`space=material`、`status=material`） |
| `space` | form | string | 否 | 传 `material` 时，即使给了 `role_code` 也强制落资料库 |
| `when_to_use` | form | string | 否 | 什么时候用，原样落库 |
| `applies` | form | string | 否 | 适用词字符串，服务端按 `,` `，` `、` 切数组 |
| `product` | form | string | 否 | 产物 |
| `name` | form | string | 否 | 技能名；空则取文件名去扩展名，截前 120 字 |
| `global_scope` | form | integer | 否 | 默认 `0`。传 `1` 且当前账号是管理员 → `owner_id` 为 `NULL`（全局）；否则 `owner_id` 为当前用户 |

**③ 响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `spec_id` | number | 新建的 `kb.spec` 行 id |
| `name` | string | 技能名 |
| `space` | string | `spec`（说明书库）/ `material`（资料库） |
| `status` | string | `pending`（说明书库待发布）/ `material`（资料库） |
| `version_no` | number | 版本号。同名同归属且 `enabled` 的行已存在时 +1，并把旧行置 `enabled=false`、`status='retired'` |
| `doc_id` | null | 固定 `null`：上传走的是问答文件底座 `data/doc_files/u<user_id>/<file_id>/`，不进 `kb.document` |
| `chars` | number | 解析出的正文长度（字符数） |
| `retrievable` | bool | 资料库 `true`，说明书库 `false` |
| `in_menu` | bool | 固定 `false`，发布后才进目录 |
| `preview` | object | 同「七 preview」结构 |
| `assumption` | string | 一句话说明。取值只看 `role_code` 是否为空 |

**④ 错误码**

| 状态码 | 响应体 | 触发条件 |
|---|---|---|
| 401 | `{"detail":{"code":"NOT_AUTHENTICATED","message":"缺少访问凭证","detail":null}}` | 没带 / 过期 token |
| 422 | `{"detail":{"code":"VALIDATION_ERROR","message":"请求参数校验失败","detail":[{"type":"missing","loc":["body","file"],"msg":"Field required","input":null}]}}` | multipart 里没有 `file` 字段 |
| 500 | `{"detail":{"code":"INTERNAL_ERROR","message":"DocFileError: 不支持的文件格式：.doc。支持：…","detail":null}}` | 扩展名不在白名单（实查用 `.doc`） |

## 三 `POST /api/v1/specs/{spec_id}/classify` 填四项

**① 概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/v1/specs/{spec_id}/classify` |
| 鉴权 | 需要 `Authorization: Bearer <access_token>` |
| Content-Type | 请求 `application/json`；响应 `application/json` |

**② 请求参数**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `spec_id` | path | integer | 是 | 技能 id |
| `role_code` | body | string | 否 | 空则保留原值 |
| `when_to_use` | body | string | 否 | 空串则保留原值 |
| `applies` | body | string[] | 否 | 空数组则保留原值 |
| `product` | body | string | 否 | 空串则保留原值 |
| `owner_scope` | body | string | 否 | `global` → `owner_id=NULL`；其余（含缺省 `own`）→ 当前用户 |
| `check_items` | body | string[] | 否 | 不传则保留原值 |
| `outline` | body | string[] | 否 | 不传则保留原值 |
| `fmt` | body | object | 否 | 不传则保留原值 |

**③ 响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 技能 id |
| `role_code` | string | 写入后的角色 |
| `when_to_use` | string | 写入后的什么时候用 |
| `applies` | string[] | 写入后的适用词 |
| `product` | string | 写入后的产物 |
| `owner_scope` | string | 写入后的归属口径：`global` / `own` |
| `check_items` | string[] | 写入后的检查项 |
| `ready` | bool | 角色、什么时候用、适用、产物四项是否都非空 |
| `missing` | string[] | 上述四项里还缺哪些（中文名） |
| `error` | string | 只在技能不存在时出现 |

**④ 错误码**

| 状态码 | 响应体 | 触发条件 |
|---|---|---|
| 401 | `{"detail":{"code":"NOT_AUTHENTICATED","message":"缺少访问凭证","detail":null}}` | 没带 / 过期 token |
| 200 | `{"error":"没有这篇说明书（id=999999）"}` | `spec_id` 不存在。本接口不把业务失败翻成 4xx，一律 200 |
