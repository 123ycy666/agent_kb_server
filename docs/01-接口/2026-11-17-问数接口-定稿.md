# 问数接口（定稿 2026-11-17）

> 适用版本：`03e8c4a` 之后（问数线瘦身：业务规则全部在页面上可改，代码只留框架）。
> 老的《2026-11-12-问答与文件接口》里与"分线 / 判据 / 证据包 / 对账 / 出文件"有关的段落已作废，以本文为准。

## 0 一句话

一次问数 = **问题 → 纠错 → 补问法 → 补全表 → 问题确定 → 模型按「查数口径」写 SQL → 按「作答规则」回答 → 落库**。
代码不校验、不拦截、不重写；口径与作答规则都在 PG 里，页面上改完下一轮生效。

## 1 认证与通用约定

| 项 | 说明 |
|---|---|
| 认证 | `Authorization: Bearer <token>`；token 由 `POST /api/v1/auth/login` 取得 |
| 编码 | 请求与响应都是 UTF-8；`Content-Type: application/json`（带文件可用 `multipart/form-data`） |
| 时间 | 服务端时区固定，`today` 不传就取系统当天 |
| 只读 | 业务库连接必须用**只读账号**；代码里没有 SQL 白名单/字面检查（设计如此） |

## 2 POST /api/ask — 提问（默认入口）

### 2.1 请求

```json
{
  "question": "上个月全市欠费多少？",
  "session_id": "s_abc123",
  "today": "2026-11-17",
  "model": "deepseek-v4.1-flash",
  "history_turns": 5
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 用户原话。错字、简称、漏时间地点都由服务端补，不需要上游预处理 |
| `session_id` | string | 否 | 不传由服务端生成并回在响应里；多轮对话原样回传 |
| `today` | string | 否 | 业务日期 `YYYY-MM-DD`；别名 `business_date` |
| `model` | string | 否 | 覆盖运行配置里的模型；不传用页面配置（再缺省用 `.env`） |
| `max_steps` | int | 否 | 覆盖步数上限（默认 100；只防死循环） |
| `history_turns` | int | 否 | 取最近几轮上下文（只用于「问题确定」），`0` = 不用上下文 |
| `uid` / `user_code` | string | 否 | 业务用户标识（落库用）；默认取登录人 |
| `user_name` | string | 否 | 显示名，默认取登录人显示名 |
| `channel` | string | 否 | 来源渠道（`web` / `api` …），落库用 |
| `file_ids` | string[] | 否 | 引用已上传文件（`/api/files` 返回的 `file_id`） |
| `kb_ids` | int[] | 否 | 检索范围；不传用「参与智能问答」标记的库 |
| `stream` | bool | 否 | `true` 时立刻返回 `task_id`，用 `/api/ask/progress` 看步骤、`/api/ask/stop` 停止 |
| `want_page` / `page_mode` | bool / string | 否 | **已下线**，收下忽略 |
| `profile` / `scope` | string | 否 | **已下线**，收下忽略（要限定范围就写进问题里） |
| `want_screen` | bool | 否 | 大屏跳转意图识别；只在配置了 `SCREEN_PREVIEW_URL` 时生效 |

`multipart/form-data` 时：文本字段同上；同名文件字段直接上传，服务端先落 `file_id` 再提问。
`question` 为空返回 `{"answer": "问题为空", "trace": []}`。

### 2.2 响应

```json
{
  "answer": "2026年10月全市累计售电量45.38亿千瓦时，同比下降9.54%。",
  "session_id": "s_abc123",
  "qa_id": 12345,
  "input_question": "上个月全市欠费多少？",
  "fixed_question": "2026年10月全市欠费多少？",
  "steps": 3,
  "sql_query_count": 3,
  "db_query_count": 3,
  "kb_query_count": 0,
  "no_db_query": false,
  "elapsed_ms": 18420,
  "model": "deepseek-v4.1-flash",
  "today": "2026-11-17",
  "trace": [
    {"seq": 1, "kind": "route", "tool": "router", "result": {"lane": "ask_db"}},
    {"seq": 2, "kind": "namefix", "tool": "name_fix", "result": {"used": false}},
    {"seq": 3, "kind": "confirm", "tool": "confirm", "result": {"used": true, "ask_time": "2026-11-17"}},
    {"seq": 4, "kind": "system", "tool": "system", "result": {"chars": 19360}},
    {"seq": 5, "kind": "tool", "tool": "run_sql", "ms": 511, "round": 1,
     "args": {"sql": "select sum(amount) ..."}, "result": {"columns": ["total"], "rows": [{"total": 712345678.9}], "row_count": 1}},
    {"seq": 8, "kind": "answer", "model_ms": 2380, "content": "2026年10月全市…"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `answer` | ★ 回答正文（纯文本，不含 Markdown） |
| `session_id` | ★ 会话 id，多轮必须回传 |
| `qa_id` | 本轮落库主键；查「四件套」/ 运行步骤用 `GET /api/v1/inject/report?qa_id=` |
| `input_question` / `fixed_question` | 原话 / 纠错后的问句 |
| `steps` | 模型循环轮数 |
| `sql_query_count` | 本轮执行了几条 SQL |
| `trace` | 过程轨迹（调试用）。**瘦身后只有 6 种 `kind`**：`route` / `namefix` / `complete`（补全表命中时才有）/ `confirm` / `system` / `tool` / `answer`；不会再出现 intent、progress、evidence、verify、page |
| `doc_warnings` | 只有带文件且文件有问题时才出现 |
| `layer` / `method` / `mainId` / `data` | 只有 `want_screen=true` 且识别出意图时才出现（字段名与对方大屏接口一致） |

模型不可用时，`answer` 是一句人话（如「模型这次没答上来…」），并照常落库、`trace` 为空。

### 2.3 流式（可选）

`POST /api/ask` body 加 `"stream": true` → 立刻返回：

```json
{"task_id": "t_7f3a", "stream": true, "session_id": "s_abc123"}
```

- `GET /api/ask/progress?task_id=t_7f3a` → `{done, steps:[...同 trace...], session_id, elapsed_ms}`；`done=true` 时多一个 `result`（完整的 2.2 响应）
- `POST /api/ask/stop?task_id=t_7f3a` → `{ok:true}`；模型下一轮开头收手，回了部分结果

## 3 POST /api/ask/data — 只问数

请求与响应同 `/api/ask`，差别只有三点：

1. 不进入口分线（固定走查数）；
2. 不收文件（带了会回一条 `doc_warnings` 说明被忽略）；
3. 不拟办任务（不会出现 `task_draft`）。

## 4 业务规则接口（页面「提示词 → 问数线」用的就是这些）

业务规则全部存在 PG，八个位置一一对应：

| 规则 | 读 | 写 |
|---|---|---|
| 入口分流判据 | `GET /api/v1/inject/route-rule` | `POST /api/v1/inject/route-rule`（整份 JSON） |
| 纠错词典（四张可编） | `GET /api/v1/prompts/lexicon`（概览）、`GET /api/v1/prompts/lexicon/{key}`（行） | `POST/PUT/DELETE /api/v1/prompts/lexicon/{key}[/{id}]` |
| 补问法 | `GET /api/v1/prompts/texts` | `PUT /api/v1/prompts/texts/askfill` |
| 补全表 | `GET /api/v1/prompts/complete` | `PUT /api/v1/prompts/complete`（整表覆盖） |
| 问题确定 | `GET /api/v1/prompts/texts` | `PUT /api/v1/prompts/texts/confirm` |
| 身份 | 同上 | `PUT /api/v1/prompts/texts/identity`；`DELETE` 恢复代码默认 |
| 查数口径 | `GET /api/v1/prompts/material/fetch` | `POST /api/v1/prompts/material/section/{sec_id}`（逐节保存） |
| 作答规则 | `GET /api/v1/prompts/material/answer` | 同上 |

辅助：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/prompts/impact` | 八项规则一览（存在哪 / 大小 / 能不能改 / 生效方式） |
| `GET /api/v1/prompts/impact/body?key=` | 某一项现在的原文（`key` 见上表左列） |
| `GET /api/v1/prompts/tools` | 问数线给模型的工具定义（现在只有 `run_sql`） |
| `GET /api/v1/prompts/meta` | 数据表字典（库结构页用；**不参与问数回答**） |

生效时间：词典 60 秒；其余下一轮生效（进程内缓存 60 秒，保存时主动清缓存）。

## 5 运行配置接口（页面「运行配置」）

| 接口 | 说明 |
|---|---|
| `GET /api/v1/runtime/config` | 当前覆盖值 + 代码默认值 + 可用模型清单 |
| `PUT /api/v1/runtime/config` | 保存；空串 = 恢复默认。可存：`model`、`max_steps`、`sql_timeout_ms`、`tool_result_chars`、`db_host`、`db_port`、`db_name`、`db_user`、`db_password` |
| `POST /api/v1/runtime/test` | 用当前（或传入的）连接试 `select 1`，只回能不能连 |

保存后 5 秒内生效；换库会自动重连，不需要重启服务。存储表 `cfg.runtime`。

## 7 错误与排查

| 现象 | 多半是 | 怎么查 |
|---|---|---|
| `answer` 是「模型这次没答上来…」 | 模型端点不可用 / 模型名不在网关 | `GET /api/v1/runtime/config` 看当前模型；`POST /api/runtime/test` 不测模型 |
| `answer` 是「按口径没查到」 | 口径里没有这张表/字段，或期间没数据 | 看 `trace` 里 `run_sql` 的 `args.sql` 与 `result.error` |
| 一直只有 `answer` 没有 `tool` | 模型认为不用查数 | 看 `system.chars`；口径正文是否为空（`GET /prompts/material/fetch`） |
| 判成干活线（`route.lane=office`） | 问句里带了产物词 + 做出来的说法 | 改「入口分流判据」，或换问法 |
| 401 | 没带 token / token 过期 | 重新登录 |
