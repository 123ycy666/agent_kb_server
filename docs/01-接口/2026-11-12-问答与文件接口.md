# 问答与文件接口（v6 · 2026-11-12）

> 给内网对接用。页面与接口同端口（容器 8200 / 对外 80）。页面：`/agent/`；接口前缀 `/api`。
> 认证：`Authorization: Bearer <JWT>`（统一员工账号签发）。除 `/api/health` 外都要令牌，未带 401。
> 本版对应：入口分线（办事 / 读件 / 闲聊 / 问数四条线）+ 做法库 + 交付契约 + 实时步骤 + 停止生成。

---

## 0. 本版变了什么（v6）

| 类别 | 变化 |
|---|---|
| 新增 | `POST /api/ask/data`：只问数的入口（不分线、不读文件、不出文件、不拟办）；`/api/ask` 保持智能体分支，能问数也能办事 |
| 新增 | 结果对象多四个字段：`lane` / `product` / `howto` / `plan` —— 前端据此渲染计划卡 |
| 新增 | 轨迹多两种步骤：`kind=route`（分到哪条线）、`kind=plan`（按哪份做法做什么产物） |
| 新增 | 办公线：办事题（要 docx / xlsx）走独立链路，自动套做法版式，必须交产物；可读本会话前几轮 |
| 变更 | `make_file` 的 `spec` 扩展（docx 支持 `sign_off`/`tables`；xlsx 支持 `header`/`formats`/`widths`/`total_row`/`freeze`），返回值多 `fmt_used` |
| 变更 | `describe_table` / `list_tables` 在业务字典为空时直读 `information_schema` |
| 变更 | 页面 `/agent/` 不再请求 `GET /api/presets`（区块隐藏，接口保留） |
| 不变 | 查数线（原 2–6 步预处理 + 证据包 + 写正文）行为、入参、字段全不动；`SECRETARY_ROUTER=0` 可整条回退到 v5 |

## 1. 提问

### `POST /api/ask`

| 入参（JSON） | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 用户原话。空 → 直接回 `{"answer":"问题为空"}`，不调模型 |
| `file_ids` | string[] | 否 | 先调 `POST /api/files` 上传得到 |
| `session_id` | string | 否 | 不传则服务端生成；同一场会话传同一个即可续问，办公线会读本会话前 5 轮 |
| `stream` | bool | 否 | `true` → 立刻返回 `task_id`，之后轮询 progress |
| `model` | string | 否 | 缺省用配置里的模型 |
| `profile` | string | 否 | 提问人身份/关注口径 |
| `history_turns` | int | 否 | 查数线读几轮上下文；0 = 不读 |
| `today` | string | 否 | 业务上的"今天"（`YYYY-MM-DD`）；不传取系统当天 |
| `scope` | string | 否 | 上游强制的数据范围，只记录 |
| `kb_ids` | int[] | 否 | 检索范围；不传用库里 `qa_enabled` 的库 |
| `want_page` / `page_mode` | bool / string | 非 stream 时用 | 生成分析页面（页面不依赖） |

流式返回：

```json
{"task_id": "t_cd09a7f53e68", "stream": true, "session_id": "s_fa96..."}
```

非流式返回是完整结果对象，字段见 §1.4。

### 分线规则（结果里的 `lane`）

| `lane` | 判据 | 走什么 |
|---|---|---|
| `office` | 原话同时有产出性动词（写 / 做 / 生成 / 导出 / 起草 / 发我 / 交上去…）与产物名（Word / Excel / 表格 / 报告 / 通知 / 公文 / PPT…），或本轮带了文件且要求改写 | 取做法 → 计划 → 工具循环 → 出文件 → 自检 → 产物卡 |
| `read` | 本轮带了文件、只要看法/提取/校对 | 分页读 → 清单 |
| `ask_db` | 其余，需要本单位业务数据 | 原查数链路（2–6 步预处理 + 证据包 + 写正文） |
| `chat` | 寒暄 / 与业务无关 | 0 工具，直接答 |

判不出时回 `ask_db`。路由是服务端行为，调用方无需传参。

### `POST /api/ask/data`（只问数）

入参与返回同 `POST /api/ask`（字段见 §1.4），`stream` / `GET /api/ask/progress` / `POST /api/ask/stop` 通用。
随附的 `file_ids` 或 multipart 文件会被忽略，并在 `doc_warnings` 里写明。

| 项 | `POST /api/ask` | `POST /api/ask/data` |
|---|---|---|
| 入口分线 | 判 office / read / ask_db / chat | 不分线，恒为 `ask_db` |
| 查库 / 读文件 / 出文件 | 按本轮原话判 | 固定 是 / 否 / 否 |
| 可用的工具 | 按判据给子集 | `kb_search` `list_metrics` `metric_query` `run_sql` `read_result` `finish` |
| 预处理 | 只在 `ask_db` 线上跑 | 照跑：纠错 → 补问法 → 问题确定 |
| 拟办 / 大屏跳转 | 有 | 拟办无；大屏跳转同左（带 `want_screen` 才转） |
| 轨迹首步 `route` | 判到的线 | `{"lane":"ask_db","forced":true}` |

### `GET /api/ask/progress?task_id=`

边跑边读，`steps` 就是执行轨迹；`done=true` 时把完整结果一起给出来。

```json
{
  "done": false,
  "elapsed_ms": 8256,
  "session_id": "s_fa96...",
  "steps": [
    {"seq": 1, "kind": "route", "tool": "router",
     "result": {"lane": "office", "product": "docx", "howto": "公文格式", "need": ["data", "file_write"], "why": "产出性动词 + docx"}},
    {"seq": 2, "kind": "plan", "tool": "plan",
     "result": {"做法": "公文格式", "产物": "docx", "步骤": ["取做法","查数/读文件","按做法成文","生成文件","自检","交付"]}},
    {"seq": 3, "kind": "tool", "tool": "make_file", "ms": 929,
     "result": {"name": "关于召开项目推进会的通知.docx", "bytes": 38429,
                "file_id": "f_dc6856dd1095", "url": "/api/files/f_dc6856dd1095/download",
                "fmt_used": {"body": {"font": "仿宋_GB2312", "pt": 16, "line": 28, "indent_chars": 2},
                             "page": {"top": 3.7, "bottom": 3.5, "left": 2.8, "right": 2.6}},
                "self_check": {"verdict": "通过"}}},
    {"seq": 4, "kind": "answer", "content": "已生成《关于召开项目推进会的通知》…"}
  ]
}
```

`steps[].kind`：

| kind | 出现在哪条线 | 含义 |
|---|---|---|
| `route` | 四条线都有 | 分到哪条线、产物、做法、理由 |
| `plan` | office / read | 按哪份做法做什么产物、几步 |
| `tool` | office / read / ask_db | 一次工具调用（`tool` / `args` / `ms` / `round` / `result`） |
| `intent` / `namefix` / `complete` / `confirm` / `rules` / `system` / `tools` / `progress` / `evidence` / `verify` / `final` | 仅 `ask_db` | 与 v5 完全一致 |
| `answer` | 四条线 | 最终正文 |

任务不存在或超过 30 分钟：`404 {"done":true,"steps":[],"error":"任务不存在或已过期"}`。

### `POST /api/ask/stop?task_id=`

把这一问标记为停止：模型循环下一轮开头收手，用已到手的材料回一句。

```json
{"ok": true, "task_id": "t_cd09a7f53e68"}
```

停止后 `answer` 为 `（已停止生成）`。任务不存在 → 404。

### 1.4 结果对象（`result`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `answer` | string | 最终回答正文。办公线是一句话（"已生成《…》，自检通过"），正文在文件里 |
| `lane` | string | **v6 新增**。`office` / `read` / `ask_db` / `chat` |
| `product` | string | **v6 新增**。`docx` / `xlsx` / `checklist` / `text` |
| `howto` | string | **v6 新增**。本轮用的做法名（没匹配到为空串） |
| `plan` | object | **v6 新增**。`{"做法","产物","步骤":[...]}`，计划卡直接渲染这个 |
| `artifacts` | array | 本轮产出的文件：`[{kind, name, bytes, file_id, url, self_check}]` |
| `trace` | array | 完整轨迹（同 progress 的 steps） |
| `session_id` / `qa_id` | string / int | 落库后的会话与本次问答主键 |
| `fixed_question` / `completed_question` | string | 查数线才有；办公线是原话 |
| `qtype` | string | 查数线 `查数`/`分析`；办公线 `办公`/`读件`/`闲聊` |
| `db_query_count` / `sql_query_count` / `kb_query_count` | int | 各类工具调用次数 |
| `no_db_query` | bool | 本轮有没有查业务库 |
| `elapsed_ms` | int | 总耗时 |
| `files` | array | 本轮带的文件（名字/字数/file_id） |
| `history_used` | int | 查数线读到的上下文轮数 |
| `page_html` / `page_token` | string | 分析页面（页面不用） |

## 2. 会话与历史

| 接口 | 说明 |
|---|---|
| `GET /api/sessions?limit=&offset=&all_users=` | 我的会话列表（管理员可 `all_users=1`）。返回 `{total, returned, sessions:[{session_id,title,create_time,last_msg_at,msg_count}], can_view_all, all_users}` |
| `GET /api/history?session_id=&with_steps=1` | 某场会话的全部消息。返回 `{session, total, returned, messages:[{direction, content, model, steps?...}]}`。`direction=1` 用户、`2` AI |
| `POST /api/sessions/{session_id}/delete` | 软删（仅本人）。成功 `{ok:true}`；不是自己的 → 404 |

`with_steps=1` 时每条 AI 消息带 `steps`（含 `step_no / step_kind / tool_name / input_text / output_text / cost_ms / status`）。
**产物就在 `output_text` 里**（`make_file` 那一步的 JSON 含 `name`/`bytes`/`url`/`self_check`），页面据此在历史里还原文件卡片。办公线的 `step_kind` 会多出 `route` 与 `plan` 两类。

## 3. 文件

| 接口 | 说明 |
|---|---|
| `POST /api/files` | multipart：`file`（必填）、`purpose=chat|task`。返回 `{file_id, name, ext, size, parsed:{ok,chars,blocks}}` |
| `GET /api/files?page=&page_size=` | 我的文件列表（上传的 + 产出的）。返回 `{items:[{file_id,name,ext,size,created_at,parsed}], total, page, page_size}` |
| `GET /api/files/{file_id}/download` | 下载原件（产物也走这里）。必须带 Authorization 头，裸链接 401 |
| `GET /api/files/{file_id}/blocks` | 解析结果（段落/表格，带章节与段号） |
| `DELETE /api/files/{file_id}` | 删除（含解析结果） |

存储位置（本地部署）：

```
server/data/doc_files/u<用户号>/<file_id>/orig.<ext>   ← 原件 / 产物
server/data/doc_files/u<用户号>/<file_id>/parsed.json ← 解析出来的块
server/data/doc_files/u<用户号>/<file_id>/meta.json   ← 名字/大小/sha256/解析状态
server/data/agent_out/<会话>/f<时间戳>/out/<文件名>    ← 生成时的任务目录（留档）
```

## 4. 工具（模型自己调，供排障与对接看）

| 工具 | 参数 | 返回要点 |
|---|---|---|
| `run_sql` | `sql`（字符串**或字符串数组**） | 单条 → `{rows, row_count}`；数组 → `{multi:true, count, results:[...]}`，最多 6 路并发 |
| `describe_table` | `table` | 字段清单。业务字典有这张表 → 字典口径；字典为空 → 直读 `information_schema`，返回多一个 `"source": "information_schema"` |
| `find_column` | `keyword` | 命中字段 |
| `list_tables` | `keyword` | 表清单。业务字典为空时改列库内实况（`note` 标"字典未登记"） |
| `list_metrics` / `metric_query` | — / `code`, `year`, `scope_id` | 指标代号与按口径取数（派生值由系统算） |
| `kb_search` | `query`, `top_k` | 切片（带文档名与分数） |
| `kb_read` | `doc_id` 或 `doc_name`, `offset`, `limit` | 文档全文分块，`next_offset` 为 `null` 表示读完 |
| `read_file` | `file_id`, `offset`, `limit` | 上传文件的分块（段落号/章节/正文）；`next_offset` 按实际给出的块数算，单次最多 6000 字 |
| `make_file` | `kind`（docx/pptx/xlsx）, `spec`, `self_check` | 见下 |
| `run_code` | `code`, `timeout` | 沙箱跑 python（白名单 import、独立子进程、超时即杀），产物从 `out/` 取 |

### `make_file` 的 `spec`（v6）

docx：

```json
{"title": "关于召开项目推进会的通知",
 "sections": [["一、会议时间", "2026 年 11 月 13 日上午 9:00。"],
              ["二、参会人员", "各项目责任单位负责人。"]],
 "sign_off": ["国网随州供电公司", "2026 年 11 月 12 日"],
 "tables": [{"header": ["单位", "金额"], "rows": [["随县", "8000000"]]}]}
```

xlsx：

```json
{"sheets": [{"name": "2026年工单",
             "title": "2026年各供电所工单数量",
             "header": ["序号", "单位", "工单数", "预算(元)", "占比"],
             "rows": [[1, "随县", 81, 3702022.55, 0.2555]],
             "formats": ["0", null, "0", "#,##0.00", "0.00%"],
             "widths": [6, 14, 10, 14, 10],
             "total_row": true,
             "freeze": "A3"}]}
```

返回值：`{kind, name, bytes, file_id, url, fmt_used:{body,page}, self_check:{verdict, tail}}`。
版式（字体/字号/行距/页边距/落款/页码/表头/数字格式）由服务端按本轮做法自动套，调用方与模型都不传格式；自检不过直接返回 `{"error":"自检不通过，已拦下交付"}`，不给文件。

## 6. 约定与错误码

| 情形 | 返回 |
|---|---|
| 未带 / 令牌无效 | `401` |
| 选了不可用的知识库 | `403 {"answer":"所选知识库不可用（不存在、已停用或没有权限）"}` |
| 问题为空 | `200 {"answer":"问题为空","trace":[]}` |
| 任务不存在 / 过期 | `404 {"error":"任务不存在或已过期"}` |
| 未知 `/api/*` | `404 {"error":"接口不存在","path":"/api/xxx"}` |
| 模型不可用 | `200`，`answer` 是人话说明（网关没这个模型 / 连不上），同时落库留痕 |

其它：返回里的时间都是 ISO 字符串；`Decimal` 统一转字符串（`default=str`）；页面 `/agent/` 响应头 `Cache-Control: no-store`，改完前端刷新即生效。
