## 1. 新增了什么

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 1 | POST | `/api/files` | 上传文件（上传即解析） |
| 2 | GET | `/api/files` | 我的文件列表 |
| 3 | GET | `/api/files/{file_id}` | 文件元信息 |
| 4 | GET | `/api/files/{file_id}/blocks` | 解析块（段落/表格，带章节路径与段号） |
| 5 | GET | `/api/files/{file_id}/text` | 整篇纯文本 |
| 6 | GET | `/api/files/{file_id}/download` | 下载原件 |
| 7 | DELETE | `/api/files/{file_id}` | 删除文件（含解析结果） |
| 8 | POST | `/api/ask` | **增量**：新增 `file_ids` 字段 与 `multipart` 形态（原有字段不变） |
| 9 | POST | `/api/docs/jobs` | 建文档任务（异步，202） |
| 10 | GET | `/api/docs/jobs` | 我的任务列表 |
| 11 | GET | `/api/docs/jobs/{job_id}` | 任务详情（进度 / 结果 / 成果文件） |
| 12 | GET | `/api/docs/jobs/{job_id}/download` | 下载成果文件 |
| 13 | POST | `/api/docs/jobs/{job_id}/cancel` | 取消任务 |

三条调用路径：

```
A 一次调用（外部系统 / curl）
  POST /api/ask  (multipart: question + files)

B 两段式（前端 / 多轮追问同一份文件）
  POST /api/files → file_id → POST /api/ask (JSON + file_ids)

C 长任务（20 页以上文件的抽取 / 审查）
  POST /api/files → POST /api/docs/jobs → 轮询 GET /api/docs/jobs/{id} → 下载 outputs[].url
```

支持的 `task`：

| task | 名称 | 产出 |
|---|---|---|
| `digest` | 长文速读 | Markdown + `速读_<文件名>.docx` + `待办清单_<文件名>.xlsx` |
| `proofread` | 公文审校 | Markdown + `纠错清单_<文件名>.docx`（传 `want_xlsx:true` 再加 xlsx） |
| `table_audit` | 表格审查 | Markdown + `表格审查_<文件名>.docx` + `.xlsx` |

## 2. 调用约定（只列与新增接口相关的）

### 2.1 鉴权

与已有接口完全一致：请求头带 `Authorization: Bearer <access_token>`。
token 由 `POST /api/v1/auth/login` 获取（细节见 `docs/01-接口/接口文档.md`）。

### 2.2 错误格式

沿用全局格式（`server/app/main.py` 的 `HTTPException` 处理器），未改：

```json
{ "detail": { "code": "UNSUPPORTED_FORMAT", "message": "不支持的文件格式：.exe…", "detail": null } }
```

**本次新增的错误码**

| code | HTTP | 含义 | 处理 |
|---|---|---|---|
| `UNSUPPORTED_FORMAT` | 400 | 文件格式不支持 | 按 `message` 里的清单换格式 |
| `FILE_TOO_LARGE` | 400 | 超过大小上限 | 压缩/拆分 |
| `EMPTY_FILE` | 400 | 文件为空 | 重选 |
| `BAD_CONTENT` | 400 | 内容非字节（服务端内部） | — |
| `BAD_JSON` | 400 | 请求体不是合法 JSON | 检查序列化 |
| `FILE_NOT_FOUND` | 404 | file_id 不存在 / 不属于当前用户 / 已过期 | 重新上传 |
| `UNSUPPORTED_TASK` | 400 | task 不在支持列表 | 见 §1 |
| `NO_FILE` | 400 | `file_ids` 为空 | 先上传 |
| `JOB_NOT_FOUND` | 404 | job_id 不存在 / 不属于当前用户 | 重建任务 |
| `JOB_BUSY` | 429 | 同账号并发任务达上限（3） | 等前一个完成 |
| `OUTPUT_NOT_FOUND` | 404 | 成果文件不存在 | 重跑任务 |

### 2.3 与新增接口相关的约定

| 项 | 约定 |
|---|---|
| 时间 | ISO8601 带时区，如 `2026-10-19T15:02:11+08:00` |
| 分页 | `page`（≥1，默认 1）、`page_size`（1–100，默认 20）；返回 `{items,total,page,page_size}` |
| 可见性 | 文件与任务**只属于上传者**；别人的 id 一律 404（不区分"不存在"与"无权限"） |
| 文件保留 | 默认 30 天，过期后接口返回 `FILE_NOT_FOUND` |
| 去重 | 同用户同内容（sha256 相同）→ 复用已有 `file_id` |
| 限额 | 单文件 `max_upload_mb`（默认 100MB）；单用户并发任务 3；每任务分析前 30 段（约 3.6 万字）；`/blocks` 的 `limit ≤ 500` |

### 2.4 下载必须带请求头（前端必读）

新增的下载接口（§5.6、§5.12）同样校验 `Authorization`，所以**不能把地址塞进 `<a href>`**（浏览器导航不带 header，必然 401）。正确做法：

```javascript
async function saveBlob(url, name) {
  const r = await fetch(url, { headers: { Authorization: `Bearer ${tk}` } });
  if (!r.ok) throw new Error('HTTP ' + r.status);
  const blob = await r.blob();
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob); a.download = name;
  document.body.appendChild(a); a.click();
  setTimeout(() => { URL.revokeObjectURL(a.href); a.remove(); }, 1000);
}
```

## 3. 数据结构

### 3.1 FileObject（文件对象）

| 字段 | 类型 | 说明 |
|---|---|---|
| `file_id` | string | 形如 `f_8f3c2a1b9d4e`，问答/任务引用它 |
| `name` | string | 原文件名（已清洗非法字符） |
| `ext` | string | 小写扩展名，**带点**，如 `.docx` |
| `size` | int | 字节数 |
| `sha256` | string | 内容摘要（去重与校验用） |
| `purpose` | string | `chat` / `task` |
| `created_at` | string | ISO8601 |
| `parsed` | object | 解析结果，见 3.2 |

### 3.2 parsed（解析结果）

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 是否解析出文字 |
| `chars` | int | 全文字数（`ok=false` 时无） |
| `blocks` | int | 块数（段落 + 标题 + 表格） |
| `headings` | int | 标题块数 |
| `tables` | int | 表格块数 |
| `preview` | string | 正文前 200 字 |
| `warnings` | string[] | 如"含 3 个图表，图表里的数字未解析" |
| `meta` | object | 解析器附加信息，**形态不稳定，勿依赖** |
| `error` | string | `ok=false` 时的原因 |

> ⚠️ **解析失败不阻断上传**：仍返回 `file_id`，`parsed.ok=false` + `error`（用户能"先问起来 + 知道为什么解析不了"）。

### 3.3 Block（解析块）

| 字段 | 类型 | 说明 |
|---|---|---|
| `para_no` | int | 段号，从 1 开始 |
| `text` | string | 文本（表格块是 `a \| b \| c` 行拼） |
| `heading_path` | string \| null | 章节路径，如 `二、时间安排`（PPT 为 `第3页 > 标题`） |
| `block_type` | string | `heading` / `paragraph` / `table` |
| `level` | int | 标题层级，正文为 0 |

### 3.4 JobObject（任务对象）

| 字段 | 类型 | 说明 |
|---|---|---|
| `job_id` | string | 形如 `j_2b7d1e9a4c55` |
| `task` | string | `digest` / `proofread` / `table_audit` |
| `status` | string | `queued` / `running` / `done` / `failed` / `cancelled` |
| `progress` | int | 0–100 |
| `stage` | string | 阶段文案，如 `抽取 5/12 段`（**可直接展示**） |
| `created_at` / `started_at` / `finished_at` | string \| null | ISO8601 |
| `outputs` | array | `[{name, url}]`，仅 `done` 后有值 |
| `error` | string \| null | `failed` 时的一句人话 |
| `result` | object \| null | 见 3.5 |

### 3.5 result（三种 task 各一型）

**`digest`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `answer_markdown` | string | 一页纸速读（结论 / 要点 / 待办清单 / 风险），可直接渲染 |
| `items` | array | 结构化待办，见下表 |
| `risks` | string[] | 罚则 / 一票否决 / 口径变化 |
| `evidence` | array | `[{claim, quote, section, para_no, verified}]` |
| `warnings` | string[] | 未核实条数、跳过段落等 |
| `stats` | object | `{chunks, items, unverified, elapsed_ms}` |
| `role` | string | 建任务时传的角色（仅回显） |

`items[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `matter` | string | 要做的事 |
| `unit` | string | 责任单位（原文没写则为空串，建议展示"未提及"） |
| `deadline` | string | 时限（原文写法） |
| `materials` | string[] | 需上报材料 |
| `quote` | string | 支撑这句的原文短句（**供人工核对**） |
| `verified` | bool | 该 `quote` 能否在原文找到；`false` = **需人工确认** |
| `section` | string | 出处章节（`verified=true` 时回填） |
| `para_no` | int | 出处段号 |

> `_section` / `_para` 是内部字段，**对接方可忽略**。

**`proofread`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `answer_markdown` | string | 问题清单（Markdown 表格 + 分类统计） |
| `issues` | array | 见下表 |
| `stats` | object | `{total, by_type, elapsed_ms}` |
| `warnings` | string[] | 模型审校失败的段落等 |

`issues[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | `错别字/用词`、`英文逗号`、`英文句点`、`多余空格`、`数字符号`、`单位混用`、`层次序号混用`、`标题过长`、`标题带句号`、`引号不配对`、`日期格式混用`、`病句`、`表述不清`、`前后矛盾`、`指代不明`、`语气` |
| `quote` | string | 原文片段（全文级问题为"（全文）"） |
| `suggestion` | string | 改成什么 |
| `reason` | string | 为什么 |
| `source` | string | `规则`（确定性）/ `模型` |
| `section` | string | 出处章节 |
| `para_no` | int | 出处段号 |
| `verified` | bool | 原文能否定位（规则类恒为 true） |

**`table_audit`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `answer_markdown` | string | 问题清单（含每张表的问题数） |
| `issues` | array | 见下表 |
| `stats` | object | `{total, by_type, sheets:[{sheet,rows,cols,issues}]}` |
| `warnings` | string[] | 目前为空 |

`issues[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `sheet` | string | 工作表名 |
| `cell` | string | 单元格坐标，如 `B7` |
| `type` | string | `空值` / `重复行` / `合计不平` / `单位混写` / `文本数字` / `日期格式混用` |
| `message` | string | 说清哪一列、差多少 |
| `suggestion` | string | 怎么改 |

## 4. 接口详单 · 文件

### 4.1 上传文件

`POST /api/files` · `multipart/form-data`

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `file` | file | 是 | — | 单个文件；多文件请多次调用 |
| `purpose` | string | 否 | `chat` | `chat` / `task` |

```bash
curl -X POST http://127.0.0.1:8200/api/files \
  -H "Authorization: Bearer $TOKEN" -F "file=@通知.docx"
```

```json
{
  "file_id": "f_dda867586b33",
  "name": "通知.docx",
  "ext": ".docx",
  "size": 36745,
  "sha256": "22a1257a822c38f07ff037843790e2dadb92e18ada7f7aa5dc5de161813ea36f",
  "purpose": "chat",
  "created_at": "2026-10-19T14:53:51+08:00",
  "parsed": {
    "ok": true, "chars": 21408, "blocks": 143, "headings": 26, "tables": 3,
    "preview": "关于开展2026年配网缺陷治理的通知\n公司各单位：…",
    "warnings": [],
    "meta": { "heading_count": 26, "table_count": 3, "paragraph_count": 143 }
  }
}
```

解析失败（仍 200，仍给 `file_id`）：

```json
{ "file_id": "f_1a2b…", "name": "扫描件.pdf", "ext": ".pdf", "size": 921034,
  "sha256": "…", "purpose": "chat", "created_at": "…",
  "parsed": { "ok": false, "error": "该 PDF 中未提取到任何文本（可能是扫描件）" } }
```

### 4.2 我的文件列表

`GET /api/files?page=1&page_size=20` → `{ items: FileObject[], total, page, page_size }`（按 `created_at` 倒序）。

### 4.3 文件元信息

`GET /api/files/{file_id}` → 单个 `FileObject`；失败 `404 FILE_NOT_FOUND`。

### 4.4 解析块

`GET /api/files/{file_id}/blocks?offset=0&limit=50`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `offset` | int | 否 | ≥0，默认 0 |
| `limit` | int | 否 | 1–500，默认 50 |

```json
{ "title": "通知",
  "blocks": [
    { "para_no": 1, "text": "通知", "heading_path": null, "block_type": "heading", "level": 1 },
    { "para_no": 2, "text": "请于2026年11月30日前将治理台账报送运检部。",
      "heading_path": "通知", "block_type": "paragraph", "level": 0 }
  ],
  "total": 3, "offset": 0, "limit": 2 }
```

用途：前端"跳到原文"、把任务结果里的 `section`/`para_no` 在正文里高亮。

### 4.5 整篇纯文本

`GET /api/files/{file_id}/text` → `{ "file_id": "f_…", "text": "[二、时间安排] 请于2026年11月30日前…" }`

### 4.6 下载原件

`GET /api/files/{file_id}/download` → 二进制流（`Content-Disposition: attachment`）。必须带 `Authorization`（见 §2.4）。

### 4.7 删除文件

`DELETE /api/files/{file_id}` → `{ "ok": true, "file_id": "f_…" }`

## 5. 接口详单 · 问答（只列新增部分）

`POST /api/ask` 是**原有接口**，本次只加了两样东西，其余字段/行为不变（见 `docs/01-接口/接口文档.md`）：

### 5.1 新增入参

| 字段 / 形态 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file_ids` | string[] | 否 | 本轮引用的文件；也接受 `"f_a,f_b"` 逗号串 |
| `multipart` 形态 | form | 否 | **同一个 URL**：`Content-Type: multipart/form-data` 时按表单解析，字段含 `question` + `files`（可多个） |

```bash
# 一步到位：文件 + 问题
curl -X POST http://127.0.0.1:8200/api/ask -H "Authorization: Bearer $TOKEN" \
  -F "question=这份文件要求什么时候上报？要报什么材料？" -F "files=@通知.docx"
```

```json
// 或两段式（已上传过的文件可多轮复用）
{ "question": "这份文件要求什么时候上报？", "file_ids": ["f_dda867586b33"], "session_id": "s_9f2c" }
```

### 5.2 新增出参

| 字段 | 类型 | 说明 |
|---|---|---|
| `files` | array | 本轮实际用到的文件 |
| `doc_warnings` | string[] | 文件侧告警（如"《扫描件.pdf》没能解析出文字"） |

`files[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `file_id` | string | 文件 id |
| `name` | string | 文件名 |
| `chars` | int | 全文总字数 |
| `used_chars` | int | 实际进入上下文的字数 |
| `truncated` | bool | 是否节选 |
| `mode` | string | `全文` / `节选 1/8 段` |
| `cited_sections` | string[] | 本轮可引用的章节（回答里的"出处"应在此范围） |
| `warnings` | string[] | 该文件的解析告警 |

### 5.3 上下文策略

| 情况 | 行为 |
|---|---|
| 全文 ≤ 6000 字 | 整篇进上下文 |
| 全文 > 6000 字 | 按问题召回**章节块**（最多 8 块）+ 附全文目录 |
| 多个文件 | 总预算 6000 字，平均分配（每文件至少 1500 字） |

回答纪律（服务端提示词已写死）：只依据文件内容回答；文件里没有的写"文件中未提及"；时限/金额/责任单位必须回指原文并标章节；节选时不得声称"全文只有这些"。

## 6. 接口详单 · 文档任务

### 6.1 建任务

`POST /api/docs/jobs` · JSON → **HTTP 202**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task` | string | 是 | `digest` / `proofread` / `table_audit` |
| `file_ids` | string[] | 是 | 目前**只取第一个**（多文件暂未支持） |
| `options` | object | 否 | 见下表 |

| `options` 字段 | 类型 | 适用 | 默认 | 说明 |
|---|---|---|---|---|
| `want_docx` | bool | 全部 | `true` | 是否产出 docx |
| `want_xlsx` | bool | `digest` / `table_audit` | `true` | 是否产出 xlsx |
| `want_xlsx` | bool | `proofread` | **`false`** | 审校默认只出 docx；要 xlsx 必须显式传 `true` |
| `role` | string | `digest` | `""` | 提问人角色（当前仅回显） |

```bash
curl -X POST http://127.0.0.1:8200/api/docs/jobs \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"task":"digest","file_ids":["f_dda867586b33"]}'
```

```json
{ "job_id": "j_d1117d94eb21", "task": "digest", "status": "queued", "progress": 0,
  "stage": "排队中", "created_at": "2026-10-19T15:10:02+08:00",
  "started_at": null, "finished_at": null, "outputs": [], "error": null, "result": null }
```

错误：`UNSUPPORTED_TASK`(400)、`NO_FILE`(400)、`JOB_BUSY`(429)、`BAD_JSON`(400)。

> 响应**立刻返回**，执行在后台线程；必须轮询 6.3。

### 6.2 我的任务列表

`GET /api/docs/jobs?page=1&page_size=20` → `{ items: JobObject[], total, page, page_size }`

```json
  "finished_at": null, "outputs": [], "error": null, "result": null }
```

```json
  "error": null,
  "result": {
    "task": "digest", "file_name": "通知.docx",

                "verified": true, "section": "二、时间安排", "para_no": 7 }],
    "risks": ["逾期未报将在月度考核中扣分并通报批评"],
    "evidence": [{ "claim": "报送治理台账", "quote": "请于2026年11月30日前…",
                   "section": "二、时间安排", "para_no": 7, "verified": true }],
    "warnings": [], "stats": { "chunks": 4, "items": 1, "unverified": 0, "elapsed_ms": 18432 },
    "outputs": ["速读_通知.docx", "待办清单_通知.xlsx"]
  } }
```

失败：

```json
{ "job_id": "j_x", "task": "digest", "status": "failed", "progress": 20, "stage": "失败",
  "outputs": [], "result": null, "error": "该 PDF 中未提取到任何文本（可能是扫描件）" }
```

轮询建议 1.5 秒一次；`stage` 可直接展示（"抽取 5/12 段"比"处理中"有用）。

### 6.4 下载成果

`GET /api/docs/jobs/{job_id}/download?name=速读_通知.docx`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | `outputs[].name` 原值，**不能带路径** |

只允许取本任务 `out/` 下的文件；`name=../job.json` 返回 `404`。必须带 `Authorization`（见 §2.4）。

### 6.5 取消任务

`POST /api/docs/jobs/{job_id}/cancel`

已结束的任务调用是**幂等**的；运行中则当前那一步跑完即停，状态置 `cancelled`。

## 7. 典型流程

### 7.1 带文件问答

```javascript
const fd = new FormData(); fd.append('file', fileObj);
const up = await fetch('/api/files', { method:'POST', headers:{Authorization:`Bearer ${tk}`}, body: fd }).then(r=>r.json());
if (!up.parsed?.ok) console.warn('解析失败：', up.parsed?.error);

const ans = await fetch('/api/ask', {
  method:'POST',
  headers:{ 'Content-Type':'application/json', Authorization:`Bearer ${tk}` },
  body: JSON.stringify({ question:'这份文件要求什么时候上报？', file_ids:[up.file_id], session_id })
}).then(r=>r.json());

console.log(ans.answer, ans.files?.[0]?.cited_sections);
```

### 7.2 长文速读 / 公文审校

```javascript
const job = await fetch('/api/docs/jobs', {
  method:'POST',
  headers:{ 'Content-Type':'application/json', Authorization:`Bearer ${tk}` },
  body: JSON.stringify({ task:'digest', file_ids:[up.file_id] })   // task 换成 proofread / table_audit 亦可
}).then(r=>r.json());

let s;
do {
  await new Promise(r => setTimeout(r, 1500));
  s = await fetch(`/api/docs/jobs/${job.job_id}`, { headers:{Authorization:`Bearer ${tk}`} }).then(r=>r.json());
  renderProgress(s.stage, s.progress);
} while (s.status === 'running' || s.status === 'queued');

if (s.status === 'done') { renderMarkdown(s.result.answer_markdown); s.outputs.forEach(o => addButton(o.url, o.name)); }
else { showError(s.error); }
```

## 8. 任务状态机

```
queued ──→ running ──→ done
   │           │
   │           ├──→ failed        (error 有值，result 为 null)
   │           └──→ cancelled
   └──→ cancelled
```

`progress` 只增不减；`stage` 给人看；**判完成只看 `status`**；`outputs`/`result` 只有 `done` 才有。

## 9. 未实现与边界

| 项 | 现状 |
|---|---|
| SSE 进度推送 | ❌ 未实现（用 1.5s 轮询） |
| `task=report` / `task=pptx` | ❌ 未实现（等模板） |
| 多文件任务（一次分析多份） | ❌ 未实现（`file_ids` 只取第一个） |
| `.doc` / `.wps` | ❌ 不支持（提示另存为 `.docx`） |
| 扫描件 PDF / 图片 | ❌ 不支持（无离线 OCR） |
| PPT 里的图表数字 | ❌ 取不到（写进 `parsed.warnings`） |
| 修订痕迹 / 干净修订版 | ❌ 有意不做（产出是"问题清单"） |

## 10. 联调清单

- [ ] `POST /api/files` 上传 `.docx` → `file_id` 且 `parsed.ok=true`
- [ ] 上传 `.exe` → `400 UNSUPPORTED_FORMAT`（不是 500）
- [ ] 用别人的 `file_id` → `404 FILE_NOT_FOUND`
- [ ] `POST /api/ask` 带 `file_ids` → 回答里有文件中的具体日期/单位；`files[0].truncated` 符合预期
- [ ] 长文（>6000 字）→ `files[0].mode` 为 `节选 x/y 段`，回答带章节出处
- [ ] `POST /api/ask` multipart 形态 → 同上
- [ ] `POST /api/docs/jobs` → `202`；轮询能看到 `stage` 变化
- [ ] `done` 后下载 `.docx` 能打开、里面有待办清单表
- [ ] 运行中 `cancel` → `cancelled`
- [ ] 别人的 `job_id` → `404`；`name=../job.json` → `404`
- [ ] 下载走 `fetch` + blob（不是裸 `<a href>`）
