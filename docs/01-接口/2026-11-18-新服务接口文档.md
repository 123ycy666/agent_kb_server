## 0 通用约定

| 项 | 说明 |
|---|---|
| Base URL | `$BASE` = `http://47.121.183.81/sandbox`（所有接口都在这个前缀下） |
| 编码 | 请求/响应均 UTF-8；`Content-Type: application/json`（上传除外） |
| 鉴权 | 登录后拿 `access_token`，之后每个请求加 `Authorization: Bearer <token>`，有效期 **12 小时** |
| 分页 | `page` 从 1 开始，`page_size` 默认 20 / 最大 100；返回 `{items,total,page,page_size}` |
| 时间 | 对话历史返回本地时间字符串 `YYYY-MM-DD HH:mm:ss`（直接展示，不要再转）；`/api/v1/*` 返回 ISO8601 带时区 |
| 两套前缀 | 管理面 `/api/v1/*`；问数 `/api/*`（**不带 v1**，别加错） |

**状态码约定**：`200` 成功 / `202` 已受理（异步） / `400` 参数错 / `401` 未登录或令牌过期 /
`403` 无权限 / `404` 资源不存在 / `422` 参数校验失败 / `500` 服务内部错误。

错误体形状：

```json
// /api/v1/*
{"detail": {"code": "BAD_CREDENTIALS", "message": "用户名或密码错误"}}
// /api/*（问数侧）
{"error": "原因"}
```

**跨域**：服务端 `CORS_ORIGINS=*`，浏览器可直接跨域调。要收紧改 `.env` 后重启。

## 1 认证与人员库

### 1.1 现状：只有一个测试账号

| 项 | 值 |
|---|---|
| 账号 | `admin` |
| 密码 | `skeleton2026` |
| 角色 | `admin`（管理员） |

**本服务不连接任何外部账号表**（不读别的系统的人员库）。要加人，用 1.5 的本地账号脚本；
以后要改成你们自己的员工库，按 1.9 做。

### 1.1.1 后续接你们自己的员工库时要做的四步（现在不用做）

1. **建表**：在你们的 MySQL 里建 `t_employee`，列名按 1.4 那张表（`employee_id` / `employee_uid` / `login_name` / `actual_name` / `administrator_flag` / `disabled_flag` / `deleted_flag` / `login_pwd`）；
2. **生成密码**：`login_pwd` 按 1.4 的规则算 argon2id（`密码_UID大写_UID小写`），不是裸密码；
3. **改配置**：服务端 `.env.sandbox` 填 4 项 ——
   ```
   MYSQL_HOST=你们MySQL地址
   MYSQL_PORT=3306
   MYSQL_USER=只读账号
   MYSQL_PASSWORD=密码
   MYSQL_DB_BUSINESS=员工表所在库名
   ```
4. **重建容器**（⚠️ 是重建，不是重启 —— 重启不会重新读 env 文件）：
   ```bash
   docker rm -f kb-backend-sandbox
   # 再按原来的 docker run 命令起一次（参数见运维记录），或用 compose 重新 up
   ```

验证接好了：`GET $BASE/health` 里 `employee_source.ok` 变成 `true`，并显示有效员工人数。
在那之前它是 `false`（当前就是这样，说明只认本地账号）。

接好之后，账号仍以本地账号优先还是员工库优先：先查员工表，查不到再校验本地账号。
员工表里的人加 / 停用，都在你们自己的库里改 `administrator_flag` / `disabled_flag` / `deleted_flag`，本服务不用动。

### 1.2 登录 `POST /api/v1/auth/login`

```json

```

```json

  "access_token": "eyJhbGciOiJIUzI1NiIs...",
```

| 情况 | 返回 |
|---|---|

### 1.3 免密换 token `POST /api/v1/auth/sso/login`

凭员工登录名直接换 JWT，**不校验密码**（服务与服务之间用，内网）。

```json
{ "username": "zhangsan" }
```

返回结构与 1.2 一致。员工不存在或已停用 → `401`。若服务端配了 `SSO_LOGIN_KEY`，请求头必须带 `X-SSO-Key`。

### 1.4 员工表结构（接你们账号时按这个建）

表名 `t_employee`，放你们的 MySQL 里，列名必须一致：

| 列 | 说明 |
|---|---|
| `employee_id` | 主键 |
| `employee_uid` | 32 位 UID，**密码校验必需**，为空的人登不上 |
| `login_name` | 登录名，本服务拿它当账号名 |
| `actual_name` | 姓名（显示名） |
| `email` / `phone` | 联系信息，可空 |
| `administrator_flag` | `1` = 管理员，`0` = 普通用户 |
| `disabled_flag` | `1` = 停用 |
| `deleted_flag` | `1` = 已删除（视为不存在） |
| `login_pwd` | argon2id 哈希，按下面规则生成 |

**密码生成规则**（不是对明文直接 argon2）：

```java
String raw = password + "_" + employeeUid.toUpperCase() + "_" + employeeUid.toLowerCase();
String loginPwd = Argon2PasswordEncoder.defaultsForSpringSecurity_v5_8().encode(raw);
```

服务端校验时先按这条算，再兜一层裸明文（兼容早期自建账号）。

### 1.5 本地账号怎么加 / 删

```bash

  -e DATABASE_URL='postgresql+psycopg://kb:<系统库密码>@kb-pg-sandbox:5432/skeleton' \
```

`--role admin|user`，密码至少 6 位。

| 项 | 说明 |
|---|---|

## 2 问数接口

### 2.1 两个入口

| 接口 | 用途 |
|---|---|
| `POST /api/ask/data` | **只查数作答**：不分线、不读文件、不出文件、不拟办。外部对接用这个 |
| `POST /api/ask` | 通用入口：先判断是「问数」还是「干活」（写通知 / PPT / Excel），再走对应链路 |

两者请求与响应结构相同。

### 2.2 请求

```bash
curl -X POST $BASE/api/ask/data \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"上个月全市线损率多少？"}'
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 用户原话。错字、简称、漏时间地点由服务端补 |
| `session_id` | string | 否 | 不传由服务端生成并回传；多轮必须原样带回 |
| `today` | string | 否 | 业务日期 `YYYY-MM-DD`（别名 `business_date`），不传取服务器当天 |
| `model` | string | 否 | 指定模型，不传用运行配置里的 |
| `max_steps` | int | 否 | 模型循环上限，默认 100 |
| `history_turns` | int | 否 | 带最近几轮上下文，`0` = 不用 |
| `uid` / `user_code` | string | 否 | 业务侧用户标识，落库用，默认取登录人 |
| `user_name` | string | 否 | 显示名，默认取登录人 |
| `channel` | string | 否 | 来源渠道（`web` / `api` …） |
| `file_ids` | string[] | 否 | 引用已上传文件（`/api/files` 返回的 `file_id`） |
| `kb_ids` | int[] | 否 | 知识库检索范围，不传用「参与智能问答」标记的库 |
| `stream` | bool | 否 | `true` 立刻回 `task_id` |

`Content-Type: multipart/form-data` 也支持：文本字段同上，文件字段直接上传，服务端先落 `file_id` 再提问。

### 2.3 响应（实测字段）

```json
{
  "answer": "两水供电所 2026年10月当月线损率未采集；1-10月累计 2.22%。",
  "session_id": "s_9f3c2a7b",
  "qa_id": 11,
  "input_question": "两水供电所的线损率是多少？",
  "fixed_question": "两水供电所的线损率是多少？",
  "today": "2026-11-18",
  "user_name": "管理员",
  "model": "qwen3.8-max",
  "steps": 3,
  "sql_query_count": 2,
  "db_query_count": 2,
  "kb_query_count": 0,
  "no_db_query": false,
  "unverified": false,
  "elapsed_ms": 4100,
  "timings": {"namefix_ms": 0, "completion_ms": 0, "loop_ms": 4100},
  "trace": [
    {"seq":1,"kind":"route","tool":"router","result":{"lane":"ask_db"}},
    {"seq":2,"kind":"namefix","tool":"name_fix","result":{"used":false}},
    {"seq":3,"kind":"confirm","tool":"confirm","result":{"used":true,"passed":"model"}},
    {"seq":4,"kind":"system","result":{"chars":1397}},
    {"seq":5,"kind":"tool","tool":"run_sql","args":{"sql":"select ..."},
     "result":{"columns":["..."],"rows":[{"...":1}],"row_count":2}},
    {"seq":6,"kind":"answer","content":"..."}
  ],
  "task_draft": null
}
```

| 字段 | 说明 |
|---|---|
| `answer` | **回答正文**（纯文本），直接展示 |
| `session_id` | **会话 id**，多轮对话下次原样回传 |
| `qa_id` | 本轮落库 id，打分用 |
| `input_question` / `fixed_question` | 用户原话 / 纠错补全后的问句 |
| `steps` | 模型循环轮数 |
| `sql_query_count` | 本轮跑了几条 SQL；**0 表示没查库** |
| `db_query_count` / `kb_query_count` | 查业务库 / 检索知识库次数 |
| `no_db_query` | 模型判断这次不用查库 |
| `unverified` | `true` = 证据不足没给结论（不是故障，是真没查到） |
| `elapsed_ms` / `timings` | 总耗时 / 分阶段耗时 |
| `trace` | 过程轨迹，**调试用**；`kind` 只有 `route`/`namefix`/`complete`/`confirm`/`system`/`tool`/`answer` |
| `task_draft` | 拟办任务草稿（有「办一件事」意图时才有），必须人工确认才建任务 |

HTTP 一律 200；答不出来时 `answer` 是人话（如「按口径没查到」）。

### 2.4 流式

```bash
# ① 发起
curl -X POST $BASE/api/ask/data -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"question":"…","stream":true}'
# → {"task_id":"t_7f3a","stream":true,"session_id":"s_…"}

# ② 轮询进度
curl "$BASE/api/ask/progress?task_id=t_7f3a" -H "Authorization: Bearer $TOKEN"
# → {"done":false,"steps":[…],"elapsed_ms":1200,"session_id":"s_…"}
#   done=true 时多一个 result（= 2.3 的完整响应）

# ③ 停止
curl -X POST "$BASE/api/ask/stop?task_id=t_7f3a" -H "Authorization: Bearer $TOKEN"
# → {"ok":true}
```

### 2.5 问数排错

| 现象 | 多半是 | 怎么查 |
|---|---|---|
| `answer` 是「模型这次没答上来…」 | 模型端点不可用 / 模型名不对 | `GET $BASE/api/health` 看 `model` / `channel` |
| `sql_query_count = 0` | 查数口径没配，或模型判断不用查 | 见 5.1 |
| `answer` 说「按口径没查到」+ `unverified=true` | 口径里没这张表 / 这列，或该期间没数据 | 见 5.1 |
| 401 / 403 | token、权限 | 见 1.2 |

## 5 业务规则配置（页面「提示词」）

### 5.1 查数口径 `GET/PUT /api/v1/prompts/material/fetch`

**这是问数能不能答出来的关键**：告诉模型去哪张表、哪一列、什么口径。

```bash
curl -X PUT $BASE/api/v1/prompts/material/fetch \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"sections":[
        {"section":"01 数据源与表","body":"业务库 MySQL，指标在 t_xxx：售电量 sales_volume…"},
        {"section":"02 时间与口径","body":"stat_month 是 yyyyMM；同一月两行 summary_type…"},
        {"section":"03 单位","body":"售电量换成亿千瓦时；比率不能加总"} ]}'
```

`GET` 返回 `{slot, sections:[{id, section, body, sort_no, enabled, pinned}], chars}`。

写口径的四条硬要求：表名 + 列名 + 中文含义一个不漏；时间字段格式与「当月 / 累计」怎么取；删除标记要不要带；单位怎么换算。**口径里不要写库名**（连哪个库由 4.1 决定）。

### 5.2 材料（口径 / 作答规则）管理

| 接口 | 说明 |
|---|---|
| `GET /api/v1/prompts/material/{slot}` | 某一份材料正文与分节（`slot` = `fetch` / `answer`） |
| `PUT /api/v1/prompts/material/{slot}` | 整份覆盖保存（`{"sections":[…]}`） |
| `POST /api/v1/prompts/material/{slot}/section` | 新增一节 `{section, body, pinned}` |
| `POST /api/v1/prompts/material/section/{sec_id}` | 就地保存某一节正文 |
| `DELETE /api/v1/prompts/material/section/{sec_id}` | 删一节（默认软删） |
| `POST /api/v1/prompts/material/section/{sec_id}/restore` | 恢复软删的节 |

## 11 对接最小清单

1. `POST $BASE/api/v1/auth/login` 拿 token（或让统一账号系统调 `sso/login`）；
2. 配两件事：**业务库连接**（4.1）、**查数口径**（5.1）—— 不配问数一定答不出来；
3. `POST $BASE/api/ask/data` 提问，取 `answer` / `session_id` / `qa_id`；
4. 多轮把 `session_id` 回传；打分用 `qa_id` 调 `/api/feedback`；
5. 存活探测打 `GET $BASE/health`；
6. 答不准时看 `unverified` 与 `sql_query_count`，再回 5.1 补口径。
