# 接口文档

统一知识库与智能问数平台 —— HTTP 接口说明。共 **76 个接口**，分两个前缀区。

> **办公文档能力（2026-10-19 新增）单独成册**：`/api/files`、`/api/ask`（带文件）、`/api/docs/jobs`
> 的完整字段、错误码、示例、联调清单见 **`docs/01-接口/办公文档接口文档.md`**（v1.0）。本文档不含这三组接口。

---

## 一、基础信息

| 项 | 值 |
|---|---|
| 基址 | `http://<主机>:8200`（默认端口 **8200**） |
| 知识库与管理面 | 前缀 **`/api/v1`** |
| 问数智能体面 | 前缀 **`/api`**（**无 v1**） |
| 内容类型 | `application/json`（上传文档与语音为 `multipart/form-data` / 原始二进制） |
| 时间格式 | **两类接口不一样，见下** |

> ⚠️ **时间字段的两套口径**（2026-10-20 起）
>
> | 接口 | 格式 | 示例 | 前端怎么处理 |
> |---|---|---|---|
> | 对话历史 `/api/sessions`、`/api/history` | 本地时间字符串 | `2026-10-20 13:01:38` | **直接显示**，不要再做时区换算 |
> | 知识库/文档 `/api/v1/*` | ISO8601 带时区 | `2026-10-19T15:02:11+08:00` | 交给 `dayjs()`/`new Date()` 即可 |
>
> 对话历史类此前返回的是**不带时区标识的 UTC**，按本地时间直接显示会差 8 小时
> （`05:01` 实际是 `13:01`），已修正为本地时间。若你为此写过 `+8` 补偿，请去掉。

> ⚠️ **两个前缀不要混用**：把 `/api/sessions` 写成 `/api/v1/api/sessions` 会 404。

## 二、认证

**方式**：JWT Bearer。除下表外的接口**均需登录**。

| 无需认证 | 说明 |
|---|---|
| `POST /api/v1/auth/login` | 登录换取 token |
| `GET /api/v1/system/health` | 健康检查 |
| `GET /health` | 统一健康检查（知识库 + 问数） |
| `POST /api/v1/auth/change-password` | 已停用（密码由 HR 系统维护） |

**登录**

```http
POST /api/v1/auth/login
Content-Type: application/json

{"username": "ycy", "password": "********"}
```

```json
{"access_token": "eyJhbGciOiJIUzI1NiIs..."}
```

| 字段 | 说明 |
|---|---|
| `username` | HR 员工账号（`dlj_data.t_employee`） |
| `password` | 明文密码；服务端按 HR 规则校验 argon2 |

**带 token 调用**

```http
GET /api/v1/auth/me
Authorization: Bearer <access_token>
```

**Token 有效期**：默认 **720 分钟**（`ACCESS_TOKEN_EXPIRE_MINUTES`）。过期返回 `401 INVALID_TOKEN`，需重新登录。

**身份与权限**：登录后会得到 `roles`（`admin` / `user`）与 `permissions`（权限码列表）。
`admin = administrator_flag=1`（HR 侧决定），本系统不提供改角色入口。

## 三、通用响应约定

**成功**：直接返回业务 JSON（对象或数组），**不套一层 `data`**。

**失败**：HTTP 状态码 + 统一结构

```json
{"detail": {"code": "BAD_CREDENTIALS", "message": "用户名或密码错误"}}
```

| HTTP | 常见 `code` | 含义 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数不合法 |
| 401 | `NOT_AUTHENTICATED` / `INVALID_TOKEN` / `BAD_CREDENTIALS` | 未登录 / 凭证过期 / 账号密码错 |
| 403 | `NO_PERMISSION` / `NOT_OWNER` | 权限不足 / 非本人资源 |
| 404 | `NOT_FOUND` / `FILE_MISSING` | 资源不存在 / 原件已从磁盘丢失 |
| 409 | `DUPLICATE` / `CONFLICT` | 重复上传 / 状态冲突 |
| 500 | `INTERNAL_ERROR` | 服务端异常 |

**列表接口**：`limit=0`（或省略）= **全部返回**（受 `API_MAX_ROWS` 防呆上限保护）；
`limit>0` 为分页。会话列表额外返回 `total` / `returned` / `truncated`。

## 四、典型调用流程

### 场景 1：上传文档并入库（异步）

```text
① POST /api/v1/auth/login                       → 拿 token
② POST /api/v1/kb/{kb_id}/documents             → 上传，返回 202 + task_id
③ GET  /api/v1/tasks/{task_id}                  → 轮询，直到 status=success/failed
④ GET  /api/v1/documents/{doc_id}/chunks        → 检查切片是否符合预期
```

> 入库是 **BackgroundTasks 异步**的（无 Redis/Celery）。⚠️ **后端进程重启会丢未完成任务**，
> 任务记录仍在，可手动重跑（`POST /api/v1/documents/{doc_id}/reindex`）。

### 场景 2：问数（带历史）

```text
① POST /api/v1/auth/login
② POST /api/ask    {"question": "...", "session_id": "s_xxx"}     → 拿到 answer + qa_id
③ POST /api/ask    同 session_id 继续追问                          → 自动继承上一轮时间/地点口径
④ GET  /api/sessions                                              → 我的会话列表
⑤ GET  /api/history?session_id=s_xxx&with_steps=true              → 该会话完整记录
⑥ POST /api/feedback {"qa_id": 123, "feedback": 1}                → 点赞/点踩
```

⚠️ **`session_id` 由客户端保存并回传**（页面存在 `localStorage.secretary_session`）。
不传则服务端生成新的，**每轮都会变成新会话**，多轮上下文与历史会断。

### 场景 3：切换检索范围

```json
POST /api/ask
{
  "question": "环潭供电所上月线损情况",
  "kb_ids": [1, 2],          // 只在这些知识库里检索；不传 = 用「参与智能问答」标记的库
  "model": "qwen3.8-max",    // 可选，见 GET /api/models
  "max_steps": 20,           // 可选，限制模型工具调用轮数上限
  "want_page": true          // 可选，额外生成单页 HTML 分析大屏
}
```

### 6.1 核心问答

| 方法 | 路径 | 说明 |
|---|---|---|

`POST /api/ask` 请求字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `question` | ✅ | 用户原话（无需预处理） |
| `session_id` | | 会话 ID；**不传则新建**，多轮上下文与历史靠它串起来 |
| `kb_ids` | | 本次检索的知识库 ID 数组；不传 = 用配置默认 |
| `model` | | 指定模型 id；不传 = 服务端默认 |
| `max_steps` | | 模型工具调用轮数上限 |
| `want_page` | | 是否额外生成单页 HTML 分析大屏 |
| `history_turns` | | 本轮带几轮上下文（`0` = 完全不带） |
| `uid` | | ⚠️ **已废弃**：身份一律以服务端登录态为准，传了也会被忽略 |

响应关键字段：

| 字段 | 说明 |
|---|---|
| `answer` | 回答正文 |
| `session_id` | 会话 ID（首问由服务端生成，**客户端必须保存并回传**） |
| `qa_id` | 本轮记录主键；**为 `null` 说明这轮没落库**（历史里查不到） |
| `model` / `steps` / `db_query_count` / `kb_query_count` | 本轮实际用的模型与工具调用情况 |
| `elapsed_ms` / `timings` | 总耗时与分段耗时（纠错 / 循环 / 页面） |
| `scope` | 本轮口径（时间 / 地点，及是否沿用上一轮） |
| `trace` | 工具调用轨迹 |
| `recorded_as_gap` | 是否记入「知识缺口」清单 |

## 八、最小调用示例（curl）

```bash
# 登录
TOKEN=$(curl -s -X POST http://127.0.0.1:8200/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"<账号>","password":"<密码>"}' | \
  python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

# 提问
curl -s -X POST http://127.0.0.1:8200/api/ask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"环潭供电所上月线损情况"}'

# 我的会话列表
curl -s http://127.0.0.1:8200/api/sessions -H "Authorization: Bearer $TOKEN"
```

> ⚠️ Windows 下用 curl 直接发中文 JSON 容易因编码变成「问题为空」，**建议用文件传正文**
> （`--data-binary @body.json`，文件存 UTF-8）或用 Python/Postman。

## 九、对接注意事项

1. **`session_id` 必须由客户端持久化**，否则多轮上下文与历史记录都串不起来。
2. **`qa_id` 为 `null` = 这轮没落库**。排查"没有历史记录"先看这个字段，再看后端窗口的 `[qa_log] 落库失败`。
3. **上传后必轮询任务接口**，不要假设上传即入库完成。
4. **切换模型的 `MODEL_CHANNEL` 或 embedding 模型后必须重建索引**，否则检索结果混乱。
5. 检索/问答的可见范围**由服务端按登录身份决定**，客户端传什么都不影响（也不应试图影响）。
6. 文档删除是**软删除**（`deleted_flag`），审计与历史仍可追溯。
