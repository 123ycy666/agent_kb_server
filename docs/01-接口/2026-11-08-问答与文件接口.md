# 问答与文件接口（v5 · 2026-11-08）

> 给内网对接用。页面与接口同端口（容器 8200 / 对外 80）。页面：`/agent/`；接口前缀 `/api`。
> 认证：`Authorization: Bearer <JWT>`（统一员工账号签发）。除 `/api/health` 外都要令牌，未带 401。
> 本版对应：七步链路 + 四个文件工具（读文件 / 取知识库 / 出文件 / 跑脚本）+ 实时步骤 + 停止生成；报告技能组已整块下线。

## 0. 本版变了什么

| 类别 | 变化 |
|---|---|
| 新增 | `POST /api/ask` 支持 `stream:true`（后台跑，立刻返回 `task_id`） |
| 新增 | `GET /api/ask/progress`（边跑边看每一步）、`POST /api/ask/stop`（停止生成） |
| 新增 | `result.artifacts`：本轮产出的文件清单（名字 / 字节 / file_id / 下载地址 / 自检结论） |
| 新增 | 历史 `GET /api/history?with_steps=1` 的步骤里带 `output_text`（产物 url 在里面，可回放文件卡片） |

| 修复 | 附件发送：`file_ids` 与问题一起走，模型据此调 `read_file` |
| 下线 | `POST /api/report`、`/api/report/notice`、`GET /api/report/meta`、`POST /api/skill/run`、`/api/skill/title`、`GET /api/statechange`、`/api/triggers`、`/api/skills` |
| 变更 | 未知 `/api/*` 一律回 404 JSON（以前被前端兜底页接成 200 HTML） |

## 1. 提问

### `POST /api/ask`

| 入参（JSON） | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 用户原话。空 → 直接回 `{"answer":"问题为空"}`，不调模型 |
| `file_ids` | string[] | 否 | 先调 `POST /api/files` 上传得到 |
| `session_id` | string | 否 | 不传则服务端生成；同一场会话传同一个即可续问 |
| `stream` | bool | 否 | `true` → 立刻返回 `task_id`，之后轮询 progress |
| `model` | string | 否 | 缺省用配置里的模型 |
| `profile` | string | 否 | 提问人身份/关注口径 |
| `history_turns` | int | 否 | 读几轮上下文；0 = 不读 |
| `today` | string | 否 | 业务上的"今天"（`YYYY-MM-DD`）。第 5 步「问题确定」用它：原话没带时间时，定稿按**上一个自然月**补（传 `2026-11-11` → `2026年10月`）；不传取系统当天 |
| `scope` | string | 否 | 上游强制的数据范围，只记录 |
| `kb_ids` | int[] | 否 | 检索范围；不传用库里 `qa_enabled` 的库 |
| `want_page` / `page_mode` | bool / string | 非 stream 时用 | 生成分析页面（本版页面不依赖） |

流式返回：

```json
{"task_id": "t_cd09a7f53e68", "stream": true, "session_id": "s_fa96..."}
```

非流式返回（`stream` 省略）是完整结果对象，字段见 §1.4。

### `GET /api/ask/progress?task_id=`

边跑边读，`steps` 就是执行轨迹；`done=true` 时把完整结果一起给出来。

```json
{
  "done": false,
  "elapsed_ms": 12030,
  "session_id": "s_fa96...",
  "steps": [
    {"seq": 1, "kind": "intent",  "tool": "intent",   "result": {"use_db": false, "use_file": true, "make_file": true, "reason": "…"}},
    {"seq": 2, "kind": "namefix", "tool": "name_fix", "result": {"used": false}},
    {"seq": 5, "kind": "system",  "tool": "system",   "result": {"chars": 854, "has_caliber": false}},
    {"seq": 6, "kind": "tools",   "tool": "toolset",  "result": {"tools": ["kb_search","read_file","kb_read","make_file","run_code"]}},
    {"seq": 9, "kind": "tool",    "tool": "read_file", "ms": 1, "result": {"blocks": [...], "next_offset": 36}},
    {"seq": 14, "kind": "tool",   "tool": "make_file", "ms": 1029, "result": {"name": "…pptx", "bytes": 42622, "url": "/api/files/f_c418…/download", "self_check": {"verdict": "通过"}}},
    {"seq": 15, "kind": "answer", "content": "汇报 PPT 已做好…"}
  ]
}
```

`steps[].kind`：`intent` / `namefix` / `complete` / `confirm` / `rules` / `system` / `tools` / `tool` / `progress` / `final` / `answer`。
任务不存在或超过 30 分钟：`404 {"done":true,"steps":[],"error":"任务不存在或已过期"}`。

### `POST /api/ask/stop?task_id=`

把这一问标记为停止：模型循环下一轮开头收手，用已查到的内容回一句。

```json
{"ok": true, "task_id": "t_cd09a7f53e68"}
```

停止后 `answer` 为 `（已停止生成）`（实测）。任务不存在 → 404。

### 1.4 结果对象（`result`）

| 字段 | 说明 |
|---|---|
| `answer` | 最终回答正文 |
| `artifacts` | **本版新增**。本轮产出的文件：`[{kind, name, bytes, file_id, url, self_check}]`（`run_code` 的产物在 `outputs` 里也会并进来） |
| `trace` | 完整轨迹（同 progress 的 steps） |
| `session_id` / `qa_id` | 落库后的会话与本次问答主键 |
| `fixed_question` / `completed_question` | 纠错后、补全后的问法 |
| `qtype` | `查数` / `分析`（只用于是否出分析页面） |
| `db_query_count` / `sql_query_count` / `kb_query_count` | 各类工具调用次数 |
| `no_db_query` | 本轮有没有查业务库 |
| `elapsed_ms` | 总耗时 |
| `files` | 本轮带的文件（名字/字数/file_id） |
| `history_used` | 读到的上下文轮数 |
| `page_html` / `page_token` | 分析页面（本版页面不用） |

## 2. 会话与历史

| 接口 | 说明 |
|---|---|
| `GET /api/sessions?limit=&offset=&all_users=` | 我的会话列表（管理员可 `all_users=1`）。返回 `{total, returned, sessions:[{session_id,title,create_time,last_msg_at,msg_count}], can_view_all, all_users}` |
| `GET /api/history?session_id=&with_steps=1` | 某场会话的全部消息。返回 `{session, total, returned, messages:[{direction, content, model, steps?...}]}`。`direction=1` 用户、`2` AI |
| `POST /api/sessions/{session_id}/delete` | 软删（仅本人）。成功 `{ok:true}`；不是自己的 → 404 |

`with_steps=1` 时每条 AI 消息带 `steps`（每条含 `step_no / step_kind / tool_name / input_text / output_text / cost_ms / status`）。
**产物就在 `output_text` 里**（`make_file` 那一步的 JSON 含 `name`/`bytes`/`url`/`self_check`），页面据此在历史里还原文件卡片。

> 2026-11-08 修：步骤原来在后台线程写，读完立刻刷新会读不到；已改同步。`output_text` 也补进查询了。

## 3. 文件

| 接口 | 说明 |
|---|---|
| `POST /api/files` | multipart：`file`（必填）、`purpose=chat|task`。返回 `{file_id, name, ext, size, parsed:{ok,chars,blocks}}` |
| `GET /api/files?page=&page_size=` | 我的文件列表（上传的 + 产出的）。返回 `{items:[{file_id,name,ext,size,created_at,parsed}], total, page, page_size}` |
| `GET /api/files/{file_id}/download` | 下载原件（产物也走这里）。必须带 Authorization 头，裸链接 401 |
| `GET /api/files/{file_id}/blocks` | 解析结果（段落/表格，带章节与段号） |
| `DELETE /api/files/{file_id}` | 删除（含解析结果） |

存储位置（本地部署）：

```
server/data/doc_files/u<用户号>/<file_id>/orig.<ext>   ← 原件 / 产物
server/data/doc_files/u<用户号>/<file_id>/parsed.json ← 解析出来的块
server/data/doc_files/u<用户号>/<file_id>/meta.json   ← 名字/大小/sha256/解析状态
server/data/agent_out/<会话>/f<时间戳>/out/<文件名>    ← 生成时的任务目录（留档）
```

上传/产物都是“文件”，都能下载；页面的「我的文件」就是 `GET /api/files`。

## 4. 工具（模型自己调，供排障与对接看）

| 工具 | 参数 | 返回要点 |
|---|---|---|
| `run_sql` | `sql`（字符串**或字符串数组**） | 单条 → `{rows, row_count}`；数组 → `{multi:true, count, results:[...]}`，框架并发跑（最多 6） |
| `describe_table` | `table` | 字段清单（字段名/中文名/说明） |
| `find_column` | `keyword` | 命中字段 |
| `kb_search` | `query`, `top_k` | 切片（带文档名与分数） |
| `kb_read` | `doc_id` 或 `doc_name`, `offset`, `limit` | 文档全文分块，`next_offset` 为 `null` 表示读完 |
| `read_file` | `file_id`, `offset`, `limit` | 上传文件的分块（段落号/章节/正文）；**`next_offset` 按实际给出的块数算**，单次最多 6000 字；到末尾会带一句“已到末尾，不要重复读” |
| `make_file` | `kind`（docx/pptx/xlsx）, `spec`, `self_check` | 生成 → 自检（inspect_docx / inspect_deck / inspect_workbook）→ 落成文件，返回 `{name, bytes, file_id, url, self_check:{verdict, tail}}`；自检不过直接返回错误、不给文件 |
| `run_code` | `code`, `timeout` | 沙箱跑 python（白名单 import、独立子进程、超时即杀），产物从 `out/` 取 |

工具怎么拿到文件内容：user 消息里只放**文件清单 + file_id**，模型调 `read_file` 分页读，正文经工具结果进入上下文（不再整篇塞进提示词）。

## 6. 约定与错误码

| 情形 | 返回 |
|---|---|
| 未带 / 令牌无效 | `401` |
| 选了不可用的知识库 | `403 {"answer":"所选知识库不可用（不存在、已停用或没有权限）"}` |
| 问题为空 | `200 {"answer":"问题为空","trace":[]}` |
| 任务不存在 / 过期 | `404 {"error":"任务不存在或已过期"}` |
| 未知 `/api/*` | `404 {"error":"接口不存在","path":"/api/xxx"}` |
| 模型不可用 | `200`，`answer` 是人话说明（网关没这个模型 / 连不上），同时落库留痕 |

其它：返回里的时间都是 ISO 字符串；`Decimal` 统一转字符串（`default=str`）；页面 `/agent/` 响应头 `Cache-Control: no-store`，改完前端刷新即生效。
