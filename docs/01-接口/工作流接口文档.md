# 工作流页面接口文档（前端对接，v2 2026-11-07）

| 项 | 值 |
|---|---|
| 基址 | `/api/workflows`（不带 v1，前端用 `agentHttp`） |
| 鉴权 | `Authorization: Bearer <JWT>`，全部接口都要登录 |
| 时间 | ISO 8601 带时区，如 `2026-11-07T08:30:12+08:00` |
| 错误体 | `{"detail": {"code": "...", "message": "...", "detail": null}}` |
| 代码 | `server/app/workflow/api.py`（30 个接口） |
| 数据 | 独立库 `ad_wf`：`wf_doc` / `wf_item` / `wf_notify` 等 9 张表 |

**长耗时接口**：`/docs/{id}/dry-run`、`/run`、`/schedules/{id}/dry-run`、`/schedules/{id}/run` 会真调模型，**单份文档 1~4 分钟**。它们不阻塞其它请求（后端已丢线程池），前端自己给 loading 和 300s 超时。

---

## 一 页面与接口对照

| 页签 | 用到的接口 |
|---|---|
| 规则文档 | `GET /templates/{work_type}`、`GET /docs`、`POST /docs`、`GET /docs/{id}`、`PUT /docs/{id}`、`DELETE /docs/{id}`、`POST /docs/{id}/duplicate`、`GET /docs/{id}/export`、`POST /docs/{id}/import`、`GET /docs/{id}/versions/{version}` |
| 规则文档 · 测试 | `POST /docs/{id}/dry-run`、`GET /runs/{run_id}` |
| 规则文档 · 运行 | `POST /run` |
| 定时任务 | `GET /schedules`、`POST /schedules`、`PUT /schedules/{sid}`、`POST /schedules/{sid}/dry-run`、`POST /schedules/{sid}/run`、`DELETE /schedules/{sid}` |
| 运行记录 | `GET /runs`、`GET /runs/{id}` |
| 结果（预警） | `GET /items/overview`、`GET /items`、`GET /items/{id}`、`POST /items/{id}/close`、`POST /items/{id}/chat` |
| 通知 | `GET /notifications/mine`、`POST /notifications/{id}/read`、`GET /notifications` |
| 运行参数 | `GET /params`、`PUT /params` |

## 二 规则文档

### 2.1 `GET /templates/{work_type}` 空文档模板

`work_type`：`detect`（取数，六节） / `send`（发送，七节）。

```json
{"work_type": "detect", "label": "取数工作流",
 "sections": [{"key": "goal", "title": "一 目的", "hint": "…", "example": "…"},
              {"key": "what", "title": "二 管什么", "hint": "…", "example": "…"}]}
```

编辑器按 `sections` 的顺序与标题渲染；`hint` 是占位提示，`example` 是示例文本。

### 2.2 `GET /docs` 文档列表

参数：`work_type`（可选，`detect` / `send`）。

```json
{"items": [{"id": 1, "name": "预算花不完", "work_type": "detect", "work_type_label": "取数工作流",
            "alert_type": "预算", "enabled": true, "scope_level": "station",
            "pair_doc_id": null, "version": 10, "missing": [], "complete": true,
            "updated_at": "2026-11-07T10:12:00+08:00",
            "schedules": [{"id": 1, "name": "每天 08:00 取数"}]}]}
```

- `missing` 非空 = 还有节没填，列表标黄；`complete` = 是否填完。
- `pair_doc_id`：发送文档指向它对应的取数文档 id；取数文档为 null。
- `schedules`：挂在哪些定时方案上。

### 2.3 `POST /docs` 新建

请求：`{"name": "某判据", "work_type": "detect", "alert_type": "预算", "scope_level": "station"}`

返回同列表一项（`doc` 为各节空串）。`409 NAME_TAKEN` 名称重复。

### 2.4 `GET /docs/{id}` 详情

在列表一项基础上多两块：

```json
{"sections": [{"key": "goal", "title": "一 目的", "hint": "…", "example": "…"}],
 "versions": [{"version": 10, "updated_by": "admin", "at": "2026-11-07T10:12:00+08:00"}]}
```

`doc` 是 `{节 key: 正文}`，键同 `sections[].key`。

### 2.5 `PUT /docs/{id}` 保存（version+1）

请求（都可选，只传要改的）：

```json
{"name": "预算花不完", "alert_type": "预算", "scope_level": "station",
 "pair_doc_id": 1, "doc": {"goal": "…", "what": "…", "data": "…", "calc": "…",
                            "judge": "…", "store": "…"},
 "enabled": true, "disabled_reason": null, "schedule_id": null}
```

返回文档详情，多一个 `detached_from`：传 `enabled=false` 时后端会把它从所有定时方案上摘掉，这里回方案名。

### 2.6 `DELETE /docs/{id}` 删除（逻辑删）

返回 `{"ok": true}`。删掉的文档不再出现在列表与调度里。

### 2.7 `POST /docs/{id}/duplicate` 复制

请求：`{"name": "副本名"}`（不传则自动加「副本」）。返回新文档，`enabled=false`。

### 2.8 `GET /docs/{id}/export` 导出 markdown

直接回文件流：`Content-Type: text/markdown; charset=utf-8`，`Content-Disposition` 带 UTF-8 文件名。

### 2.9 `POST /docs/{id}/import` 从 markdown 导入

请求：`{"markdown": "## 一 目的\n…\n## 二 管什么\n…"}`

按 `## 标题` 切节，标题对上的覆盖那一节，对不上的忽略。返回文档详情。

### 2.10 `GET /docs/{id}/versions/{version}` 看历史正文

返回 `{"version": 9, "doc": {"goal": "…"}}`。

### 2.11 `POST /docs/{id}/dry-run` 试跑（不写库）

请求：`{"today": "2026-11-07"}`（可选，覆盖"今天"）。

返回一轮结果：

```json
{"run_id": 12, "status": "ok", "steps": 8, "elapsed_s": 76.4,
 "checked_n": 47, "hit_n": 45, "dry": true}
```

文档没填完 → `422 DOC_INCOMPLETE`，`missing` 列出缺的节。

### 2.12 `POST /run` 真跑一份文档

请求：`{"doc_id": 1, "dry": false}`。返回同上，但会写结果表与通知表。同样 1~4 分钟。

## 三 定时任务

### 3.1 `GET /schedules` 方案列表

```json
{"items": [{"id": 1, "name": "每天 08:00 取数", "cron": "0 8 * * *", "crons": ["0 8 * * *"],
            "timezone": "Asia/Shanghai", "enabled": false, "note": null,
            "doc_count": 9, "doc_ids": [1,2,3], "doc_names": ["预算花不完", "…"],
            "next": ["2026-11-08 08:00"], "cron_error": ""}],
 "status": {"running": true, "jobs": 2}}
```

- `crons`：一份方案可挂多个时间点（8 点一次、9 点再一次就写两个）；`cron` 是第一个。
- `next`：未来 5 次触发时间，`YYYY-MM-DD HH:MM`。

### 3.2 `POST /schedules` 新建

请求：`{"name": "每天 08:00 取数", "crons": ["0 8 * * *"], "enabled": true,
"note": "", "doc_ids": [1,2,3]}`

- 名称与时间必填；cron 不合法 → `422 BAD_CRON`。
- `doc_ids` 里若有已停用文档 → `422 DOC_DISABLED`。
- 返回同 3.1 一项。

### 3.3 `PUT /schedules/{sid}` 改（热重载，立即生效）

请求同上，字段都可选；`doc_ids` 传了就整体替换挂载关系。

### 3.4 `POST /schedules/{sid}/dry-run` 试跑方案下所有文档

```json
{"schedule": "每天 08:00 取数", "dry": true,
 "docs": [{"doc": "预算花不完", "run_id": 13, "status": "ok", "checked_n": 47, "hit_n": 45},
          {"doc": "某文档", "status": "skipped", "reason": "缺节：一 目的"}]}
```

停用的文档、缺节的文档都跳过并在 `reason` 里写明。

### 3.5 `POST /schedules/{sid}/run` 立即跑该方案（多份并行）

```json
{"schedule": "每天 08:00 取数", "results": [{"doc": "预算花不完", "run_id": 14, "status": "ok"}]}
```

### 3.6 `DELETE /schedules/{sid}`

还挂着文档时拒绝：`409 SCHEDULE_IN_USE`，`docs` 列出是哪些。

## 四 运行记录

### 4.1 `GET /runs` 批次列表

参数：`doc_id`、`status`（`running` / `ok` / `failed`）、`limit`（默认 50）、`offset`。

```json
{"total": 5, "items": [{"id": 5, "doc_id": 10, "doc_name": "预算花不完 · 发送",
  "doc_version": 4, "work_type": "send", "trigger": "manual", "status": "ok", "dry_run": false,
  "started_at": "…", "finished_at": "…", "data_as_of": "2026-11-07",
  "checked_n": 45, "hit_n": 0, "new_n": 0, "closed_n": 0, "sent_n": 50, "error": null}]}
```

`trigger`：`cron` / `manual` / `test` / `dry`。取数看 `checked_n` `hit_n`，发送看 `sent_n`。

### 4.2 `GET /runs/{id}` 一轮的步骤留痕

在 4.1 一项基础上多：

```json
{"logs": [{"seq": 3, "at": "…", "kind": "sql",
            "payload": {"sql": "SELECT …", "rows": 47, "error": null}},
           {"seq": 9, "at": "…", "kind": "tool",
            "payload": {"tool": "send", "args": "…", "ok": true, "out": "…"}}],
 "doc_snapshot": {"goal": "…"},
 "sections": [{"key": "goal", "title": "一 目的"}]}
```

`kind`：`read_doc` / `sql` / `tool` / `error`。`doc_snapshot` 是那一轮跑的文档正文（历史版本对不上就用当前正文）。

## 五 结果（预警事项）

### 5.1 `GET /items/overview` 概览

```json
{"alert_types": [{"alert_type": "预算", "total": 45}],
 "tiers": {"high": 41, "mid": 4},
 "unread": 2,
 "last_run": {"doc_name": "预算花不完", "finished_at": "…", "status": "ok", "hit_n": 45}}
```

`unread` 是当前登录人的未读通知数（红点用它）；`last_run` 用来显示"数据更新于"。

### 5.2 `GET /items` 结果列表

参数：`status`（默认 `open`）、`doc_id`、`alert_type`、`tier`、`level`、`unit_name`、`county_name`、`q`、`limit`（≤500）、`offset`。

```json
{"total": 45, "items": [{
  "id": 1, "doc_id": 1, "doc_name": "预算花不完", "alert_type": "预算",
  "object_key": "1", "object_name": "环潭供电所",
  "unit_name": "环潭供电所", "county_name": "随县供电公司",
  "value": 0.0, "value_unit": "%", "threshold": 60.0, "tier": "high",
  "reliable": true, "status": "open", "close_reason": null,
  "detail": {"分配额": 1068903.35, "已花": 0, "预计结余": 1068903.35},
  "evidence": {"分配额": "budget_result.budget_amount", "数据截止日": "2026-11-07"},
  "first_seen": "…", "last_seen": "…", "sent_at": "…", "task_id": null}]}
```

前端渲染约定：`value` + `value_unit` 一起显示（`%` 直接加百分号，`元` 按万，`天` 后加"天"）；`tier` 只分色（high 红 / mid 橙 / low 灰）；`reliable=false` 标"数据不全"；`sent_at` 空 = 还没通知过。

### 5.3 `GET /items/{id}` 详情

在 5.2 一项基础上多 `notifications`：哪些通知覆盖了这条结果。

```json
{"notifications": [{"id": 77, "level": "station", "scope_name": "厉山供电所",
  "message": "厉山供电所今年预算只能花到 0%", "recipient_login": "sz015",
  "recipient_name": "…", "role_code": "所长", "sent_at": "…", "read_at": null}]}
```

### 5.4 `POST /items/{id}/close` 手工关闭

请求：`{"reason": "已核实"}`（必填，≤32 字）。返回关闭后的结果。

### 5.5 `POST /items/{id}/chat` 结果进对话

返回 `{"session_id": "wf-item-1-admin", "chat_store": "ok", "item": {…}}`；`chat_store=unavailable` 表示会话表不可用。

## 六 通知

### 6.1 `GET /notifications/mine` 我的通知

参数：`unread=1`、`alert_type`、`level`、`limit`（≤50）、`offset`。登录人从 JWT 取，不接受前端传登录名。

```json
{"total": 2, "unread": 2, "items": [
  {"id": 5, "level": "city", "alert_type": "预算", "scope_name": "全市",
   "message": "全市 45 所预算到年底花不完",
   "alert_ids": [1, 2, 3], "alert_count": 3, "doc_id": 10,
   "recipient_login": "daping", "recipient_name": "…", "role_code": "财务主管",
   "sent_at": "…", "read_at": null, "reason": "市级汇总", "channel": "station"}]}
```

`message` 就是收件人看到的那一句，前端不要再拼单位、数量、阈值；`alert_ids[0]` 是最差那条，点开用它拉详情。

### 6.2 `POST /notifications/{id}/read` 标已读

无请求体。返回 `{"ok": true, "id": 5, "read_at": "…"}`。幂等；标别人的 → `403`；不存在 → `404`。

### 6.3 `GET /notifications` 发送记录（管理看全部）

参数 `limit` / `offset`，返回结构同 6.1（不带登录人过滤）。

## 七 运行参数

### 7.1 `GET /params`

```json
{"items": [{"key": "msg_max_chars", "value": "30", "note": "一条通知最多多少字"},
           {"key": "no_repeat_days", "value": "1", "note": "同一收件人同一层面同一类多少天内不重发"}]}
```

与预警相关的键：`msg_max_chars` 一句话字数上限、`msg_banned_words` 禁词、`msg_max_separators` 顿号上限、`msg_max_numbers` 数字个数上限、`user_query_sql` / `user_filter_unit` / `user_filter_role` 找账号的 SQL 与过滤片段、`no_repeat_days` 去重天数、`max_steps` 单轮最多几步、`max_items_per_run` 单轮最多写几条。

### 7.2 `PUT /params` 改参数

请求：`{"items": {"msg_max_chars": "30", "no_repeat_days": "2"}}`，返回同 7.1。

## 八 错误码

| HTTP | code | 含义 |
|---|---|---|
| 401 | `unauthorized` | 没带 token 或过期 |
| 403 | `forbidden` | 标别人的通知 |
| 404 | `DOC_NOT_FOUND` / `SCHEDULE_NOT_FOUND` / `RUN_NOT_FOUND` / `ITEM_NOT_FOUND` / `NOTIFY_NOT_FOUND` / `VERSION_NOT_FOUND` | 对象不存在 |
| 409 | `NAME_TAKEN` / `SCHEDULE_IN_USE` | 名称重复 / 方案还挂着文档 |
| 422 | `NO_NAME` / `BAD_CRON` / `DOC_INCOMPLETE` / `DOC_DISABLED` / `BAD_SCHEDULE` / `NO_REASON` / `EMPTY` | 参数或文档不完整 |
| 500 | `RUN_FAILED` | 跑一轮失败，`message` 带异常类型与摘要 |
