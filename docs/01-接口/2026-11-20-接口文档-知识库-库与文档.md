### 2.1 `POST /api/v1/kb/{kb_id}/documents` — 上传文档（异步受理）

**概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/v1/kb/{kb_id}/documents` |
| 鉴权 | `Authorization: Bearer <access_token>`；权限码 `doc:upload`（`admin` 与 `user` 都有） |
| Content-Type | `multipart/form-data` |
| 成功状态码 | **202**（受理即返回，不代表已入库） |
| 调用三步 | ① 本接口拿 `task_id`；② 轮询 `GET /api/v1/tasks/{task_id}`（任务线，不在本文范围）直到 `status` 为 `done` 或 `failed`；③ 从 `task.result` 取 `doc_id` / `chunk_count` / `conflict_count` / `conflict_docs` / `conflict_status`。前端 `docApi.uploadAndWait`（`web/src/api/index.ts`）就是这套封装，`Kb.tsx` 的 `DocsTab.upload` 只调它 |
| 冲突检测触发 | 不需要额外调用：入库完成后后台自动跑一次 `detect_conflicts`，结论写回**同一条任务**。`conflict_status=checking` 表示还在判（文档此时已经可检索），`done`/`failed` 为终态；`result.conflict_count > 0` 时该文档的冲突切片已被隔离，需到冲突线处理 |

**请求参数**（multipart 字段）

| 字段 | 类型 | 必填 | 代码实际行为 |
|---|---|---|---|
| `file` | file | 是 | 扩展名必须在 `parsers.SUPPORTED_EXTENSIONS` 内，否则 400 |
| `is_public` | bool（表单字符串 `true`/`false`） | 否 | 默认 `false` = 私有（仅上传者本人可见可检索）；不做「默认公开」 |
| `tags` | string | 否 | 标签 JSON 数组字符串，如 `["行政","预算"]`，默认 `[]`；不是数组 / 不是合法 JSON → 400 `BAD_TAGS` |
| 文件大小 | — | — | 上限 `MAX_UPLOAD_MB`（本次 100 MB），超出 → 400 `FILE_TOO_LARGE`（读文件时按上限 +1 做熔断） |

**响应字段**（`UploadAcceptedResponse`）

| 字段 | 类型 | 实查值 | 说明 |
|---|---|---|---|
| `task_id` | string(uuid) | `b78a7c7f-507c-4644-a447-5c9fbb782634` | ★ 轮询任务用 |
| `status` | string | `accepted` | 固定值 |
| `message` | string | `已受理，正在后台解析与向量化；可轮询任务状态获取最终结果` | 固定文案 |
| `doc_id` | int \| null | `null` | 受理时还没有文档，恒 `null`；真实 doc_id 在 `task.result.doc_id` |
| `conflict_count` | int | `0` | 恒 0，真值在 `task.result.conflict_count` |
| `conflict_docs` | string[] | `[]` | 恒空，真值在 `task.result.conflict_docs` |
| `warnings` | string[] | `[]` | 恒空，入库告警在 `task.result.note`（`；` 分隔的字符串） |

轮询到的任务（`GET /api/v1/tasks/{task_id}`）里与本线相关的字段：`status`（`pending`/`running`/`done`/`failed`）、`progress`、`stage`（完成时 `ready`）、`error_msg`（失败原因）、`result.doc_id`、`result.chunk_count`、`result.version_no`、`result.is_new_version`、`result.chunk_stats`、`result.parse_meta`、`result.conflict_status`、`result.conflict_count`、`result.conflict_docs`、`result.note`。失败时 `result` 为 `null`。

**错误码**

| 状态码 | code | 触发条件 | 返回体 |
|---|---|---|---|
| 400 | `UNSUPPORTED_FORMAT` | 扩展名不支持（如 `.exe`） | `{"detail": {"code": "UNSUPPORTED_FORMAT", "message": "不支持的文件格式。支持：.csv, .docx, .markdown, .md, .pdf, .pptm, .pptx, .txt, .xls, .xlsm, .xlsx", "detail": null}}` |

**请求参数**（`SearchRequest`）

| 字段 | 类型 | 必填 | 代码实际行为 |
|---|---|---|---|
| `query` | string | 是 | 1–1024；空串 → 422 |
| `kb_ids` | int[] | 是 | `min_length=1`；空数组 / 缺失 → 422。不存在的库 id 只是召回为空，不报错 |
| `tag_filters` | string[] | 否 | 默认 `[]`；**全部命中（AND）** 语义，pre-filter（`document_chunk.tags @> ARRAY[...]`），不参与相关性打分 |
| `top_k` | int | 否 | 默认 5，1–50 |
| `recall_k` | int | 否 | 默认 60，10–500；向量路 / 关键词路各自的召回数 |
| `rerank` | bool | 否 | 默认 `true`；`false` 直接用融合分排序 |
| `include_conflict` | bool | 否 | 默认 `false`；`true` 时把「因冲突被隔离」的切片（`retired_reason='conflict'`）也算进召回与父块聚合 |
| `catalog_id` | int \| null | 否 | 默认 `null`。**2026-11-17 新增**：给一个目录 id，按其 `path` 前缀取整棵子树（`kb.catalog`），只在该子树内召回；取不到目录时退化为只看这一个 id |

行为要点（`server/app/services/retrieval/search.py`，按执行顺序）：

1. 权限由后端注入，调用方参数无法绕过：检索视图 = 公开 + 自己上传（管理员在检索时同样受限）。
2. 目录层裁范围（2026-11-17）：只召回 `document.is_active=true`、`document.status='active'` 的文档；非管理员另需 `secrecy ∈ {public, internal}` 或本人上传。
3. 向量路只取 `document_chunk.embedding_model` 等于当前档位（本次 `online/text-embedding-v4`）且 `is_retrievable=true` 的切片 —— 模型不一致的库会静默返回 0 条（本次 `单位制度库` 的切片模型是 `text-embedding-v4`，检索该库返回 0 条）。
4. 向量路 + 关键词路（`tsvector`，OR 语义）双路召回，RRF 融合（`fused = Σ 1/(60+rank)`），再按「文档名命中长度」加权。
5. 版本压制：同一 `root_id` 只保留最新版本的全部切片。
6. `rerank=true` 时调精排；精排抛错 → `degraded=true` + `degraded_reason`，仍返回结果。
7. `parent_content` 在检索时动态聚合（同 `doc_id` + `heading_path` 且可检索的兄弟切片），隔离 / 覆盖 / 复活自动生效。
8. 空结果且传了 `tag_filters` 时给 `filter_notice`（`baseline_total` = 去掉标签条件后的可选切片数）。
9. 结果补出处（2026-11-17）：`catalog_path` / `doc_no` / `doc_status` / `effective_date`，从 `kb.document` 左连 `kb.catalog` 取。

### 5.5 `POST /api/v1/conflicts/{conflict_id}/resolve` — 处理冲突

**概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/v1/conflicts/{conflict_id}/resolve` |
| 鉴权 | `Authorization: Bearer <access_token>`；权限码 `conflict:resolve` + **只能处理自己上传文档的冲突**（`admin` 不受限） |
| Content-Type | `application/json` |
| 成功状态码 | 200 |

**请求参数**

| 字段 | 类型 | 必填 | 代码实际行为 |
|---|---|---|---|
| `conflict_id` | int（path） | 是 | 不存在 → 404 |
| `resolution` | string | 是 | `overwrite` \| `keep_old` \| `coexist` \| `cancel` \| `ignore`（正则校验，其它值 → 422） |
| `note` | string \| null | 否 | 只写进审计 `detail.note`，不影响行为 |

五个取值的行为（`conflicts.py` 的 `resolve_conflict`）：

| 取值 | 对新文档 | 对旧文档 | 冲突行 | `message` |
|---|---|---|---|---|
| `overwrite` | `has_conflict=false`，本次冲突切片恢复可检索 | 只隔离**冲突涉及的那一片**（`is_retrievable=false`, `retired_reason='overwrite'`, `superseded_by=新文档 id`）；旧文档**全部**切片都被隔离时才整篇 `is_active=false` | `status=resolved` | `已用新文档覆盖旧版本` |
| `keep_old` | **删除**新文档（先写冲突决策再删，避免外键级联把冲突行带走后 UPDATE 0 行报 500） | 不变；若新文档曾取代过别的版本，一并回滚复活 | 随 `new_doc_id` 外键级联消失，决策只留审计 | `已保留旧文档并丢弃新上传` |
| `cancel` | 同 `keep_old`（删除新文档） | 同 `keep_old` | 同上 | `已取消本次上传` |
| `coexist` | `has_conflict=false`，解除本文档因冲突被隔离的切片 | 不变 | `status=resolved` | `已保留双方，冲突标记解除` |
| `ignore` | `has_conflict=false`，解除隔离切片 | 不变 | `status=ignored` | `已忽略该冲突` |

`overwrite`/`coexist`/`ignore` 收尾时若该新文档已无 `pending` 冲突，自动把 `has_conflict` 置回 `false`。

**响应字段**（`OkResponse`）

| 字段 | 类型 | 实查值 | 说明 |
|---|---|---|---|
| `ok` | bool | `true` | |
| `message` | string | `已保留双方，冲突标记解除` | 按 `resolution` 取固定文案（见上表） |
| `warnings` | string[] | `[]` | 恒空 |

**错误码**

| 状态码 | code | 触发条件 | 返回体 |
|---|---|---|---|
| 404 | `CONFLICT_NOT_FOUND` | 冲突 id 不存在 | `{"detail": {"code": "CONFLICT_NOT_FOUND", "message": "冲突记录不存在", "detail": null}}` |
| 404 | `DOC_NOT_FOUND` | 冲突行在、但新文档已不存在 | `{"detail": {"code": "DOC_NOT_FOUND", "message": "新文档不存在", "detail": null}}` |
| 403 | `NOT_OWNER` | 新文档不是自己上传的（且非管理员） | `{"detail": {"code": "NOT_OWNER", "message": "只能处理自己上传文档的冲突；如需处理他人文档请联系管理员", "detail": null}}` |
| 422 | `VALIDATION_ERROR` | `resolution` 传 `merge` 等 | `{"detail": {"code": "VALIDATION_ERROR", "message": "请求参数校验失败", "detail": [{"type": "string_pattern_mismatch", "loc": ["body", "resolution"], "msg": "String should match pattern '^(overwrite|keep_old|coexist|cancel|ignore)$'", "input": "merge", "ctx": {"pattern": "^(overwrite|keep_old|coexist|cancel|ignore)$"}}]}}` |

**实查原文示例**

**`coexist`（证据条目 `conflict_resolve_coexist`）**

```json
{
  "ok": true,
  "message": "已保留双方，冲突标记解除",
  "warnings": []
}
```

**`keep_old`（证据条目 `conflict_resolve_keep_old`）**

```json

  "message": "已保留旧文档并丢弃新上传",
  "warnings": []

```
