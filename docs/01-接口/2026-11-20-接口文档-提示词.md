**概述**

| 项 | 值 |

## 2. PUT /api/v1/prompts/texts/{key}

**概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `PUT /api/v1/prompts/texts/{key}` |
| 鉴权 | `Authorization: Bearer <access_token>` |
| Content-Type | 请求：`application/json`；响应：`application/json` |

**请求参数**

| 字段 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `key` | path | string | 是 | 只接受下面 6 个键。`style` / `tools` 在 HEAD 已不是文本键（不在 `TEXT_KEYS`），传了回 500「未知的提示词」；问数线工具定义的读接口是 `GET /prompts/tools`，主智能体的工具开关在 `PUT /api/agent/config` |
| `body` | body | object | 是 | 请求体必须是 JSON 对象；裸文本或坏 JSON → 400「请求体不是 JSON」 |
| `body.body` | body | string | 否 | 覆盖值正文。缺省或 `null` 按 `""` 写入 |

`key` 取值与保存时的结构校验（代码 `prompt_text.save`）：

| `key` | 是否做 JSON 校验 | 校验不通过时的 `error` 原文 |
|---|---|---|
| `identity` | 否，纯文本 | — |
| `confirm` | 否，纯文本 | — |
| `agent_style` | 否，纯文本 | — |
| `askfill` | 是，必须是 JSON 对象 | `补问法要 JSON 对象（{"on": true, "default": "情况怎么样", …}）` |
| `agent_skills` | 是，必须是 JSON 对象 | `技能范围要 JSON 对象（{"mode":"all\|off\|selected","names":[…] }）` |
| `agent_tools` | 是，必须是 JSON 数组 | `这个 key 要 JSON 数组（["说法", …]）` |

`body.body` 为空串或全空白时**不做** JSON 校验，直接写入空串（等于清空覆盖值，`overridden` 随之为 `false`）。

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 成功为 `true`；失败时响应里没有这个字段 |
| `key` | string | 回显键名 |
| `version_no` | int | 写入后的版本号 = 原 `version_no` + 1（首次写入为 `1`） |
| `error` | string | 仅失败时出现，是唯一字段 |

**错误码**

| 状态码 | `detail.code` | 触发条件 |
|---|---|---|
| 400 | 无（响应体只有 `error`） | 请求体不是 JSON 对象（实测发裸 `abc` → `{"error":"请求体不是 JSON"}`） |
| 401 | `NOT_AUTHENTICATED` | 没带 `Authorization` |
| 500 | 无（响应体只有 `error`） | ① `key` 不在 `TEXT_KEYS`（实测 `nosuchkey` / `style` / `tools` 都是这条）；② JSON 键的结构校验不通过（实测 `agent_skills` 传 `[]`）；③ 写库异常（`保存失败：…`） |

**实查示例**

请求（把 `agent_style` 的当前值 `""` 原样写回）：

```json
{
  "body": ""
}
```

响应：

```json
{
  "ok": true,
  "key": "agent_style",
  "version_no": 9
}
```

`agent_skills` 传数组（结构校验不通过，未写库）：

```json
{
  "body": "[]"
}
```

```json
{
  "error": "技能范围要 JSON 对象（{\"mode\":\"all|off|selected\",\"names\":[…] }）"
}
```

旧键名 `style`：

```json
{
  "body": "x"
}
```

```json
{
  "error": "未知的提示词：style"
}
```

| Content-Type | 请求：`application/json`；响应：`application/json` |

**请求参数**

| 字段 | 位置 | 类型 | 必填 | 说明 |

## 13. GET /api/agent/config

**概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `GET /api/agent/config` |
| 鉴权 | `Authorization: Bearer <access_token>` |
| Content-Type | 请求：无请求体；响应：`application/json` |

**请求参数**

无。

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `style` | string | 回答风格，即文本键 `agent_style` 的值；空串 = 未配（中性） |
| `tools` | array | 主智能体的全部内置工具与开关 |
| `tools[].name` | string | 工具名，如 `read_file` / `make_file` / `read_skill` / `list_skills` / `search_kb` / `query_data` / `db_schema` / `remember` / `recall`（实测 9 个） |
| `tools[].on` | bool | `false` = 被关掉（文本键 `agent_tools` 里列了它） |
| `tools[].when_not` | string | 从工具 docstring 的「别用在」那行取的原句（页面只读展示）；没有该行时为空串 |
| `skills.mode` | string | 技能读取范围，即文本键 `agent_skills` 的 `mode`：`all` / `off` / `selected`；没配时 `all` |
| `skills.names` | array | `mode=selected` 时生效的技能名清单；否则 `[]` |
| `skills.available` | array | 当前账号可用技能名（实测 5 个），页面「只给指定的」列表用 |
| `identity` | string | 身份正文（文本键 `identity` 的原值）。**占位符不替换**：实测原样是 `你是{SITE_FULL}（{SITE_NAME}）的…` |
| `model.name` | string | 当前模型名 |
| `model.max_turns` | int | 单轮最多工具回合数 |
| `model.context_budget` | int | 上下文预算（token） |
| `model.compact_at` | number | 压缩阈值占预算的比例（0~1 的小数） |

**错误码**

| 状态码 | `detail.code` | 触发条件 |
|---|---|---|
| 401 | `NOT_AUTHENTICATED` | 没带 `Authorization`（代码路径，实测未覆盖） |

## 14. PUT /api/agent/config

**概述**

| 项 | 值 |
|---|---|
| 方法 / 路径 | `PUT /api/agent/config` |
| 鉴权 | `Authorization: Bearer <access_token>` |
| Content-Type | 请求：`application/json`；响应：`application/json` |

**请求参数**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `style` | string \| null | 否 | 写文本键 `agent_style`。不传或 `null` = 不改 |
| `tools_off` | string[] \| null | 否 | 要**关掉**的工具名数组（不是"打开"清单），`json.dumps` 后写文本键 `agent_tools`。传 `[]` = 一个都不关 |
| `skills` | object \| null | 否 | 写文本键 `agent_skills`，结构 `{"mode": …, "names": […]}`；`mode` 只认 `all` / `off` / `selected` |

三个字段互相独立：只提交哪个就只改哪个，没提交的保持原值。三个都不提交（`{}`）返回 `{}`，不写库。

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `style` | object | 仅当提交了 `style` 才出现，值是 `PUT /prompts/texts/agent_style` 的返回：`{ok, key, version_no}` |
| `tools` | object | 仅当提交了 `tools_off` 才出现，值是 `PUT /prompts/texts/agent_tools` 的返回：`{ok, key, version_no}` |
| `skills` | object | 仅当提交了 `skills` 才出现，值是 `PUT /prompts/texts/agent_skills` 的返回：`{ok, key, version_no}` |

某一项写库失败时，该字段的值变成 `{"error":"…"}`，整体仍是 200 —— 前端要逐字段看有没有 `error`（`AgentConfigPanel.save` 就是这么判的）。

**错误码**

| 状态码 | `detail.code` | 触发条件 |
|---|---|---|
| 200 | 字段内 `error` | 该文本键写库失败，`error` 挂在对应字段里（代码路径，实测未覆盖） |
| 401 | `NOT_AUTHENTICATED` | 没带 `Authorization` |
| 422 | `VALIDATION_ERROR` | 字段类型不对，实测 `{"style": 123}` → `detail.detail[0].msg` = `Input should be a valid string` |

**实查示例**

请求（`skills` 用 GET 拿到的当前值写回）：

```json
{
  "skills": {
    "mode": "all",
    "names": []
  }
}
```

响应：

```json
{
  "skills": {
    "ok": true,
    "key": "agent_skills",
    "version_no": 2
  }
}
```

三个字段都不提交：

```json
{}
```

```json
{}
```

类型不对：

```json
{
  "style": 123
}
```

```json
{
  "detail": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数校验失败",
    "detail": [
      {
        "type": "string_type",
        "loc": [
          "body",
          "style"
        ],
        "msg": "Input should be a valid string",
        "input": 123
      }
    ]
  }
}
```
