# 预警前端对接说明（2026-11-07）

> 给前端做「预警列表 / 我的通知」用：怎么拿数据、字段怎么变、页面哪里要跟着改。
> 接口细节见 `预警数据接口-前端取数.md`；文档编辑、定时任务那些见 `工作流接口文档.md`。

---

## 一 从零接通：三步

**1）登录拿 token**（与其它页面同一套登录，token 放后续请求头）

```
Authorization: Bearer <JWT>
```

**2）进页面先拉概览**（一个请求就能把顶部卡片、红点、数据时间都填上）

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8200/api/workflows/items/overview"
```

```json
{"alert_types":[{"alert_type":"预算","total":45}],
 "tiers":{"high":41,"mid":4},"unread":1,
 "last_run":{"doc_name":"预算花不完","finished_at":"2026-11-07T08:12:00+08:00","status":"ok","hit_n":45}}
```

**3）拉列表 + 拉我的通知**

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8200/api/workflows/items?status=open&alert_type=%E9%A2%84%E7%AE%97&limit=20&offset=0"

curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8200/api/workflows/notifications/mine?unread=1&limit=20"
```

点开通知先标已读，再拉那一条的详情：

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8200/api/workflows/notifications/20/read"

curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8200/api/workflows/items/3"
```

## 二 后端这次变了什么

| 项 | 之前 | 现在 |
|---|---|---|
| 数据表 | `wf_item`（25 列，标题/正文/层面键） | `wf_item` 21 列：加 `unit_name` 归属所、`county_name` 归属县、`value_unit` 单位；删 `title`/`body`/`seen_times`/`op`/`scope_type`/`scope_key` |
| 流水表 | `wf_result` 每轮每对象一行 | **删了**，过程只在运行日志里 |
| 通知表 | `wf_notify.item_id` 单条 + `wf_notify_item` 关系表 | `wf_notify.alert_ids` 数组（第一个是最差那条）；关系表删了 |
| 通知接口 | 只有 `GET /notifications` | 新增 `GET /notifications/mine`、`POST /notifications/{id}/read` |
| 概览接口 | 无 | 新增 `GET /items/overview` |
| 结果详情 | 返回 `history`（30 轮流水）、`notifies` | 不再有 `history`；`notifies` 改名 `notifications`，字段换成 `level/scope_name/message/recipient_login/recipient_name/role_code/sent_at/read_at` |

## 三 页面要改的地方（工作流页 → 事项页签）

| 位置 | 旧 | 新 |
|---|---|---|
| 列表「事项」列 | `dataIndex: 'title'` | `dataIndex: 'doc_name'`，列名建议「判据」 |
| 列表「次数」列 | `dataIndex: 'seen_times'` | 改 `sent_at`，列名「已通知」 |
| 抽屉标题 | `detail?.title` | `detail?.object_name` |
| 当前值 / 阈值 | `${value} / ${op} ${threshold}` | `${value}${value_unit} / ${threshold}`（`op` 已删） |
| 首见 / 最近 / 次数 | 三项 | 首见 / 最近 / 已通知（`sent_at`） |
| 「历史（最近 30 轮）」卡 | `detail.history` | **整块删掉**——后端不再存过程 |
| 「发送记录」卡 | `detail.notifies`，键 `name`/`login` | `detail.notifications`，键 `level+scope_name`、`recipient_name+recipient_login+role_code`、`message`、`read_at` |
| 新增「归属所 / 县」 | 无 | `unit_name` / `county_name`（工单、台区类靠它归到所和县） |

以上已在 `web/src/pages/Workflows.tsx` 与 `web/src/api/workflows.ts` 改完，`tsc` 通过；`web/dist` 还没重新构建。

## 四 渲染约定（不要自己发挥）

1. **数值**：一律 `value` + `value_unit`。`%` 直接加百分号（`42` → `42%`）；`元` 建议按万显示；`天` 后加"天"。
2. **档位**：`tier` 只用来分色（high 红 / mid 橙 / low 灰），**不要**显示 `high/mid/low` 字样，也不要写"超过阈值"。
3. **一句话**：通知的 `message` 就是给人看的那句，前端原样显示，不要再拼单位、条数、阈值。
4. **时间**：ISO 8601 带时区，直接格式化，不要自己加 8 小时。
5. **空态**：`total=0` 且 `last_run` 有值 → 「今日无预警」；`last_run` 为空 → 「取数还没跑过」。
6. **轮询**：列表进页面拉一次，之后 60 秒；红点用 `/notifications/mine?unread=1&limit=1` 每 30 秒；页面隐藏时停。
