# 预警实时数据接口文档（前端对接，2026-11-07）

| 项 | 值 |
|---|---|
| 版本 | v3（对应「结果表 + 每人版本」两张表的最终结构） |
| 基址 | `/api/workflows`（不带 v1） |
| 鉴权 | `Authorization: Bearer <JWT>`，全部接口都要登录 |
| 时间 | ISO 8601 带时区，如 `2026-11-07T08:30:12+08:00` |
| 错误体 | `{"detail": {"code": "...", "message": "..."}}` |
| 数据表 | `wf_item`（预警结果，21 列）、`wf_notify`（每人版本，14 列） |
| 实时方式 | 无推送，前端轮询；建议 30 秒一次，页面隐藏时停 |

> 「我的通知」的登录人一律从 JWT 取（= `t_employee.login_name`），不接受前端传登录名。

---

## 一 页面与接口

| 页面 | 接口 |
|---|---|
| 预警列表 | `GET /items` |
| 顶部计数与未读红点 | `GET /items/overview` |
| 结果详情（明细、依据、被通知记录） | `GET /items/{id}` |
| 我的通知 | `GET /notifications/mine`、`POST /notifications/{id}/read` |
| 发送记录（管理看全部） | `GET /notifications` |

---

## 二 `GET /items` 预警结果列表

**参数**（全部可选）

| 参数 | 说明 |
|---|---|
| `status` | `open`（默认） / `closed` |
| `doc_id` | 按判据筛 |
| `alert_type` | `预算` / `指标` / `审批` |
| `tier` | `high` / `mid` / `low` |
| `level` | `station` 时配合 `unit_name` 用；`county` 配合 `county_name` |
| `unit_name` / `county_name` | 模糊匹配，所级传所名、县级传县名 |
| `q` | 在对象名、判据名上模糊匹配 |
| `limit` / `offset` | 默认 100 / 0，`limit` 上限 500 |

**响应**

```json
{
  "total": 38,
  "items": [
    {
      "id": 1024, "doc_id": 3, "doc_name": "预算花不完", "alert_type": "预算",
      "object_key": "3", "object_name": "厉山供电所",
      "unit_name": "厉山供电所", "county_name": "随县",
      "value": 42.0, "value_unit": "%", "threshold": 60.0, "tier": "mid",
      "reliable": true, "status": "open", "close_reason": null,
      "first_seen": "2026-10-20T08:12:00+08:00", "last_seen": "2026-11-07T08:12:00+08:00",
      "sent_at": "2026-11-07T08:30:12+08:00",
      "detail": {"分配额": 2800000, "已花": 1176000, "预计结余": 690000, "时间进度": 85},
      "evidence": {"分配额": "budget_result.budget_amount", "数据截止日": "2026-11-07"},
      "task_id": null
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `value` + `value_unit` | 当前值按单位渲染：`%` 直接加百分号，`元` 前端按万显示，`天` 后加"天" |
| `tier` | 只用来分色（high 红 / mid 橙 / low 灰），不要当文字展示 |
| `reliable` | false 标"数据不全"，不给操作按钮 |
| `sent_at` | 空 = 还没通知过 |
| `detail` | 明细，键名随判据不同，按 key-value 平铺展示 |

## 三 `GET /items/overview` 概览

```json
{
  "alert_types": [{"alert_type": "预算", "total": 45}, {"alert_type": "指标", "total": 12},
                  {"alert_type": "审批", "total": 27}],
  "tiers": {"high": 31, "mid": 40, "low": 13},
  "unread": 2,
  "last_run": {"doc_name": "预算花不完", "finished_at": "2026-11-07T08:12:00+08:00",
               "status": "ok", "hit_n": 45}
}
```

- `total` 是 `status=open` 的结果条数；`unread` 是当前登录人的未读通知数（红点用它）。
- `last_run` 是最近一轮取数，页面显示"数据更新于"。

## 四 `GET /items/{id}` 结果详情

```json
{
  "id": 1024, "…同列表一项…": "",
  "notifications": [
    {"id": 77, "level": "station", "scope_name": "厉山供电所",
     "message": "厉山供电所今年预算到年底结余 69 万",
     "recipient_login": "sz015", "recipient_name": "王xx", "role_code": "所长",
     "sent_at": "2026-11-07T08:30:12+08:00", "read_at": null}
  ]
}
```

`notifications` = 哪些通知覆盖了这条结果（查 `alert_ids` 含本 id）。同一条结果可能被所级、县级、市级各用过一次。

失败：`404` 结果不存在。

## 五 `GET /notifications/mine` 我的通知

**参数**：`unread=1` 只回未读；`alert_type`、`level` 可选；`limit`（默认 20，上限 50）、`offset`。

```json
{
  "total": 2, "unread": 2,
  "items": [
    {"id": 77, "level": "station", "alert_type": "预算", "scope_name": "厉山供电所",
     "message": "厉山供电所今年预算到年底结余 69 万",
     "alert_ids": [1024], "alert_count": 1, "doc_id": 17,
     "recipient_login": "sz015", "recipient_name": "王xx", "role_code": "所长",
     "sent_at": "2026-11-07T08:30:12+08:00", "read_at": null, "channel": "station"},
    {"id": 78, "level": "county", "alert_type": "预算", "scope_name": "随县",
     "message": "本县 4 所预算到年底花不完",
     "alert_ids": [1024, 1031, 1044, 1052], "alert_count": 4, "doc_id": 17,
     "recipient_login": "cwb001", "recipient_name": "李x", "role_code": "县公司财务部",
     "sent_at": "2026-11-07T08:30:20+08:00", "read_at": null, "channel": "station"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `message` | 就这一句，前端**不要**再拼单位、数量、阈值 |
| `level` + `scope_name` | 层面与范围，用于分组标签（本所 / 本县 / 全市） |
| `alert_ids` | 覆盖哪几条结果，第一个是最差那条；`alert_count` 是长度 |
| `read_at` | 空 = 未读 |

排序：`sent_at` 倒序。

---

## 六 `POST /notifications/{id}/read` 标已读

请求体：无。响应：`{"ok": true, "id": 77, "read_at": "2026-11-07T09:01:05+08:00"}`

- 幂等：已读再调一次，`read_at` 不变，仍返回 `ok=true`。
- `403` 标别人的通知；`404` 通知不存在。

---

## 七 前端约定

1. 顶部红点：每 30 秒 `GET /notifications/mine?unread=1&limit=1`，取 `unread`。
2. 打开通知：先 `POST /{id}/read`，再 `GET /items/{alert_ids[0]}` 拉最差那条详情。
3. 列表页显示"数据更新于"用 `/items/overview` 的 `last_run.finished_at`，不自己算新鲜度。
4. 时间一律按 ISO 8601 带时区渲染，不要自己加 8 小时。
5. 空态：`total=0` 且 `last_run` 有值 → "暂无预警"；`last_run` 为空 → "取数还没跑过"。

---

## 八 错误码

| HTTP | code | 含义 |
|---|---|---|
| 401 | `unauthorized` | 没带 token 或过期 |
| 403 | `forbidden` | 标别人的通知 |
| 404 | `not_found` | 结果或通知不存在 |
| 422 | `bad_request` | 参数不合法（`limit` 超上限等） |
| 500 | `internal_error` | 库查询失败 |
