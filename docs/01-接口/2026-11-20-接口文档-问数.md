## 1 `POST /api/ask` — 提问（默认入口）

### 1.1 概述

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/ask` |
| 鉴权 | `Authorization: Bearer <access_token>`，token 由 `POST /api/v1/auth/login` 取得；缺失 → 401 |
| Content-Type | `application/json`；`multipart/form-data`（问题 + 文件一步式） |
| 成功状态码 | 200（模型不可用时也是 200，`answer` 是错误文案） |
| 实测耗时 | 6202 ~ 8125 ms |
| 响应模型声明 | `app/schemas/agent.py` 的 `AskResponse`（纯声明，路由返回 `Response`，不做过滤） |

### 1.2 请求参数

| 字段 | 类型 | 必填 | 代码实际行为 |
|---|---|---|---|
| `question` | string | 是 | 用户原话；去空白后为空 → 200 `{"answer": "问题为空", "trace": []}`，不建会话、不落库 |
| `session_id` | string | 否 | 不传则由服务端生成 `s_` + 32 位 hex；多轮对话原样回传 |
| `kb_ids` | int[] | 否 | 检索范围；服务端按「库存在且 `status=active`」过滤，非数字项忽略；显式传了但全部无效 → 403 |
| `model` | string | 否 | 覆盖模型；不传用库里的运行配置，再缺省用 `.env`（本次实查 `deepseek-v4.1-flash`） |
| `max_steps` | int | 否 | 模型循环步数上限 |
| `profile` | string | 否 | 收下，不参与回答 |
| `scope` / `business_scope` | string | 否 | 收下，不参与回答 |
| `today` / `business_date` | string | 否 | 业务日期 `YYYY-MM-DD`；不传取服务器当天（本次 `2026-11-20`，同时写进 `trace` 里 `kind=confirm` 那一步的 `ask_time`） |
| `history_turns` | int | 否 | 读同一会话最近 N 轮当上下文；`0` = 不用上下文 |
| `uid` / `user_code` | string | 否 | 业务用户标识，落库用；不传用登录名 |
| `user_name` | string | 否 | 显示名；不传用登录人显示名，回在响应 `user_name` |
| `channel` | string | 否 | 来源渠道，落库用；默认 `web` |
| `file_ids` | string[] / string | 否 | 引用已上传文件（`/api/files` 的 `file_id`）；数组、单串、逗号分隔都收 |
| `alert_id` | string | 否 | 带进拟办（`task_draft`）的预警 id |
| `want_screen` | bool | 否 | 大屏跳转意图识别；只有配置了 `SCREEN_PREVIEW_URL` 才调 |
| `want_page` | bool | 否 | 收下，不生效（响应 `page_html` / `page_token` 恒为 `""`） |
| `page_mode` | string | 否 | `async` 收下，不生效 |
| `stream` | bool | 否 | `true` → 立刻返回 `{"task_id","stream":true,"session_id"}`，改用 §3 轮询 / §4 停止 |
| 文件字段（`multipart`） | file | 否 | 与文本字段平铺；服务端先存成 `file_id` 再提问，解析失败只回 `doc_warnings` |

### 1.3 响应字段

| 字段 | 类型 | 实查值 | 说明 |
|---|---|---|---|
| `answer` | string | 见示例 | ★ 回答正文（纯文本） |
| `session_id` | string | `s_e42ae58505964cf3a6b12d2cf7c1a3c4` | ★ 会话 id，多轮原样回传 |
| `qa_id` | int \| null | `454` | 本轮落库主键（`t_chat_query_trace.id`），评价与「四件套」用它；落库失败为 `null` |
| `input_question` | string | `上个月全市线损率是多少？` | 用户原话 |
| `fixed_question` | string | 同上 | 纠错/补全后的问题，未改动即等于原话 |
| `name_fix_used` | bool | `false` | 名称/错字纠错是否命中 |
| `today` | string | `2026-11-20` | 本轮业务日期 |
| `model` | string | `deepseek-v4.1-flash` | 实际使用的模型 |
| `steps` | int | `2` | 模型循环轮数 |
| `db_query_count` | int | `1` | 查业务库次数 |
| `sql_query_count` | int | `1` | 执行 SQL 条数（= `db_query_count`） |

| `qtype` | string | `查数` | 固定值 |
| `elapsed_ms` | int | `6590` | 总耗时（毫秒） |

| `history_used` | int | `0` | 取到的历史轮数 |

| `artifacts` | array | `[]` | 产物清单，恒为 `[]` |
| `personal` | object | `{"rules": [], "rules_chars": 0, "overflow": ""}` | 个人规则命中情况 |
| `rules_loaded` | int | `0` | — |
| `history_injected` | int | `0` | — |
| `summary_used` | bool | `false` | 是否注入会话摘要 |
| `unverified` | bool | `false` | `true` = 证据不足而拒答，是正常行为不是故障 |
| `summary_queued` | bool | `false` | 是否投递了会话摘要任务 |
| `user_name` | string | `kbadmin` | 提问者显示名（路由层补上，`ask()` 不产出） |
| `trace` | array | 见示例 | 过程轨迹，调试用。`kind` ∈ `route` / `namefix` / `complete`（补全表命中才有）/ `confirm` / `system` / `tool` / `answer` / `compose` / `final` |

### 1.4 错误码

| 状态码 | 触发条件 | 返回体（实查原文） |
|---|---|---|
| 200 | `question` 为空或全空白 | `{"answer": "问题为空", "trace": []}` |
| 200 | 模型不可用（网关无此模型 / 连不上） | 正常响应结构，`answer` 是错误文案，`trace` 为 `[]`，`no_db_query` 为 `true`，`db_query_count` 为 `0`，`elapsed_ms` 为 `0`；仍落库并回 `qa_id` |
| 200 | 空现场（库里没有任何业务配置） | 见 1.6 |
| 401 | 没带 token / token 无效或过期 | `{"detail": {"code": "NOT_AUTHENTICATED", "message": "缺少访问凭证", "detail": null}}`（token 无效时为 `INVALID_TOKEN` / `登录凭证无效或已过期`） |
| 403 | `kb_ids` 显式传了，但全部不存在 / 已停用 | `{"answer": "所选知识库不可用（不存在、已停用或没有权限）", "trace": [], "session_id": "s_08fd124437274e50952adb94e799709d"}` |

## 2 `POST /api/ask/data` — 只问数

### 2.1 概述

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/ask/data` |
| 鉴权 | 同 §1.1（缺 token → 401） |
| Content-Type | `application/json`（`multipart/form-data` 也收，但文件被丢弃，见 2.3） |
| 成功状态码 | 200 |
| 实测耗时 | 5811 ~ 5982 ms（同步）；流式提交 747 ms 返回 `task_id` |
| 与 `/api/ask` 的差别 | 内核以 `force_data=True` 调用：不进入口分线、不读文件、不出文件、不拟办 |

### 2.2 请求参数

与 §1.2 完全相同的字段与语义。差异只有两处，均由 `force_data` 决定：

| 字段 | 类型 | 必填 | 代码实际行为 |
|---|---|---|---|
| `question` | string | 是 | 同 §1.2 |
| `file_ids` / `multipart` 文件 | string[] / file | 否 | **被忽略**，并在响应 `doc_warnings` 里回一条 `本接口只问数：忽略随附的 N 个文件` |
| `alert_id` | string | 否 | 收下，但本接口不拟办，等于无效 |
| 其余字段 | — | — | 同 §1.2（含 `stream`、`kb_ids`、`session_id`） |

### 2.3 响应字段

与 §1.3 同一套字段。差异：

| `elapsed_ms` | int \| null | — |

| 条件 | 类型 | 实查值 | 含义 |
|---|---|---|---|

## 7 删除会话（两个路径，同一段逻辑）

### 7.1 概述

| 项 | 值 |
|---|---|
| 方法 / 路径 | `DELETE /api/sessions/{session_id}` 与 `POST /api/sessions/{session_id}/delete` |
| 鉴权 | 同 §1.1，且必须匹配会话归属（不符 → 404，不返回 403） |
| Content-Type | 无请求体 |
| 成功状态码 | 200 `{"ok": true, "session_id": "..."}` |
| 实测耗时 | 170 ~ 286 ms |
| 删除语义 | 软删：`t_chat_session` / `t_chat_message` / `t_chat_query_trace` 打 `deleted_flag=1`；列表与历史立刻看不到，数据仍在 |

### 7.2 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `session_id` | path | string | 是 | 会话 id；空白 → 400 |

### 7.3 响应字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | `true` = 删成功（受影响行数 > 0） |
| `session_id` | string | 原样回传 |
| `error` | string | 失败时出现：`会话不存在或不属于当前用户` / `缺少 session_id` / `异常类名: 消息` |

### 7.4 错误码

| 状态码 | 触发条件 | 返回体（实查原文） |
|---|---|---|
| 200 | 删除成功 | `{"ok": true, "session_id": "s_239aa088a84d4673969e8a64217311e3"}` |
| 400 | `session_id` 为空白 | `{"error": "缺少 session_id"}` |
| 404 | 会话不存在 / 已软删 / 不属于当前用户 | `{"error": "会话不存在或不属于当前用户", "session_id": "s_does_not_exist"}` |
| 500 | 删除抛异常 | `{"error": "异常类名: 消息", "session_id": "<原样回传>"}` |
| 401 | 没带 token | `{"detail": {"code": "NOT_AUTHENTICATED", "message": "缺少访问凭证", "detail": null}}` |

## 8 `POST /api/feedback` — 给回答打评价

### 8.1 概述

| 项 | 值 |
|---|---|
| 方法 / 路径 | `POST /api/feedback` |
| 鉴权 | 同 §1.1 |
| Content-Type | `application/json` |
| 成功状态码 | 200（`qa_id` 不存在也是 200，看 `ok` / `updated`） |
| 实测耗时 | 12 ~ 211 ms |

### 8.2 请求参数

| 字段 | 类型 | 必填 | 代码实际行为 |
|---|---|---|---|
| `qa_id` | int | 是 | 取 `/api/ask` 响应的 `qa_id`；缺失 → 400，非整数 → 400 |
| `feedback` | int | 是 | `1` = 赞，`0` = 踩；缺失或非整数 → 400。**传其它整数不报错**：库内按「等于 1 才是赞」落 `0`，但响应里原样回传传入值 |
| `note` | string | 否 | 评语，落 `t_chat_query_trace.feedback_note` |

### 8.3 响应字段

| 字段 | 类型 | 实查值 | 说明 |
|---|---|---|---|
| `ok` | bool | `true` | `updated > 0` |
| `updated` | int | `1` | 受影响行数；`qa_id` 不存在时为 `0` |
| `qa_id` | int | `455` | 原样回传 |
| `feedback` | int | `1` / `5` | 原样回传**请求里的** `feedback` 整数，不是落库后的 `0/1`（传 `5` 的响应回 `5`，事后再查 `GET /api/history`，该 `qa_id=455` 的 `feedback` 是 `0`） |

### 8.4 错误码

| 状态码 | 触发条件 | 返回体（实查原文） |
|---|---|---|
| 200 | 成功 | `{"ok": true, "updated": 1, "qa_id": 455, "feedback": 1}` |
| 200 | `qa_id` 查不到 / 已软删 | `{"ok": false, "updated": 0, "qa_id": 999999, "feedback": 1}` |
| 400 | 缺 `qa_id` | `{"error": "缺少 qa_id（取 /api/ask 返回里的 qa_id）"}` |
| 400 | `qa_id` 不是整数 | `{"error": "qa_id 必须是整数"}` |
| 400 | 缺 `feedback` | `{"error": "feedback 必须是 1（赞）或 0（踩）"}` |
| 500 | 写库抛异常 | `{"error": "异常类名: 消息"}` |
| 401 | 没带 token | `{"detail": {"code": "NOT_AUTHENTICATED", "message": "缺少访问凭证", "detail": null}}` |

### 8.5 实查示例

赞（`feedback-赞` 原文）：

```json
{"ok": true, "updated": 1, "qa_id": 457, "feedback": 1}
```

传 `feedback: 5`（`feedback-feedback=5` 原文，同一 `qa_id`）：

```json

```

```json

```
