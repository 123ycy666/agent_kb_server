# 预警数据接口（前端取数用，2026-11-07）

> 这是给「预警展示」用的子集：只讲前端**拿预警数据**的三个接口。
> 编辑文档、跑工作流、定时方案那些在 `docs/01-接口/工作流接口文档.md`。
> 前端「我的通知」拿的是通知接口，见本文第五节。

| 项 | 值 |
|---|---|
| 基址 | `/api/workflows` |
| 鉴权 | `Authorization: Bearer <JWT>`（登录后拿到的那个 token） |
| 数据来源 | 独立库 `ad_wf` 的 `wf_item` 表，由取数工作流每天写一次 |
| 实时性 | 没有推送；数据每天一轮，前端按需拉或 30 秒轮询 |

---

## 一 三个接口，分别对应哪个界面位置

| 界面位置 | 接口 | 干什么 |
|---|---|---|
| 顶部卡片 / 红点 | `GET /items/overview` | 三类各多少条、档位分布、未读数、数据更新到什么时候 |
| 预警列表页 | `GET /items` | 分页列表，可按类、层面、档位、所、县筛 |
| 点开某一条 | `GET /items/{id}` | 明细、依据、被谁通知过 |

---

## 二 `GET /items` 预警列表

**参数**（都可选，不传默认 `status=open`、`limit=100`）

| 参数 | 取值 | 说明 |
|---|---|---|
| `status` | `open` / `closed` | 默认 open（问题还在） |
| `alert_type` | 类名 | 类由文档定，如 预算 / 指标 / 审批 |
| `tier` | `high` / `mid` / `low` | 档位 |
| `level` | `station` / `county` | 配 `unit_name` 用所级、配 `county_name` 用县级 |
| `unit_name` | 单位名，模糊 | 如 `厉山` |
| `county_name` | 县名，模糊 | 如 `随县` |
| `q` | 关键字 | 在对象名、判据名上模糊 |
| `limit` / `offset` | 1~500 / ≥0 | 分页 |

**返回**

```json
{
  "total": 45,
  "items": [
    {
      "id": 1,
      "doc_id": 1,
      "doc_name": "预算花不完",
      "alert_type": "预算",
      "object_key": "1",
      "object_name": "环潭供电所",
      "unit_name": "环潭供电所",
      "county_name": "随县供电公司",
      "value": 0.0,
      "value_unit": "%",
      "threshold": 60.0,
      "tier": "high",
      "reliable": true,
      "status": "open",
      "close_reason": null,
      "detail": {"分配额": 1068903.35, "已花": 0, "预计结余": 1068903.35},
      "evidence": {"分配额": "budget_result.budget_amount", "数据截止日": "2026-11-07"},
      "first_seen": "2026-11-07T08:12:00+08:00",
      "last_seen": "2026-11-07T08:12:00+08:00",
      "sent_at": "2026-11-07T08:30:20+08:00",
      "task_id": null
    }
  ]
}
```

**字段怎么用**

| 字段 | 前端怎么处理 |
|---|---|
| `object_name` | 列表主标题（哪个所 / 哪张工单 / 哪个台区） |
| `doc_name` | 副标题：这是哪条判据算出来的 |
| `value` + `value_unit` | 数值列。`%` 直接加百分号；`元` 建议按万显示；`天` 后加"天" |
| `tier` | 只管颜色：high 红 / mid 橙 / low 灰。**不要**当文字展示（口径规定句子和界面都不出现英文档位） |
| `reliable` | false 时标「数据不全」，不提供操作按钮 |
| `status` / `close_reason` | 已关闭的显示原因（数据恢复 / 人工关闭） |
| `sent_at` | 空 = 还没通知过；非空 = 已发过通知 |
| `detail` | 键名随判据不同，按 key-value 平铺，不要写死字段名 |
| `evidence` | 折叠块「数据来源」 |

## 三 `GET /items/overview` 概览

```json
{
  "alert_types": [{"alert_type": "预算", "total": 45}],
  "tiers": {"high": 41, "mid": 4},
  "unread": 2,
  "last_run": {"doc_name": "预算花不完", "finished_at": "2026-11-07T08:12:00+08:00",
               "status": "ok", "hit_n": 45}
}
```

- `alert_types[]`：当前 `open` 的条数，按类拆。
- `tiers`：档位分布。
- `unread`：**当前登录人**的未读通知数（红点用它）。
- `last_run`：页面上「数据更新于 …」就用它的 `finished_at`；`last_run` 为空 = 取数还没跑过。

## 四 `GET /items/{id}` 详情

第三节列表一项的全部字段，加一段 `notifications`（这条结果被谁通知过）：

```json
{
  "id": 1, "…同上…": "",
  "notifications": [
    {"id": 6, "level": "station", "scope_name": "环潭供电所",
     "message": "环潭供电所今年预算只能花到 0%",
     "recipient_login": "sz013", "recipient_name": "…", "role_code": "所长",
     "sent_at": "2026-11-07T08:30:20+08:00", "read_at": null}
  ]
}
```

失败：`404 ITEM_NOT_FOUND`。

## 五 通知（红点与「我的通知」）

| 接口 | 用途 |
|---|---|
| `GET /notifications/mine?unread=1&limit=20` | 我的通知列表；`unread` 计数也在这个返回里 |
| `POST /notifications/{id}/read` | 点开就标已读（幂等，标别人的返回 403） |

```json
{"total": 2, "unread": 2, "items": [
  {"id": 5, "level": "city", "alert_type": "预算", "scope_name": "全市",
   "message": "全市 45 所预算到年底花不完",
   "alert_ids": [1, 2, 3], "alert_count": 3,
   "sent_at": "…", "read_at": null}]}
```

- `message` 就是那**一句**，直接显示，前端不要再拼单位、数量、阈值。
- 点开：先 `POST /{id}/read`，再用 `alert_ids[0]` 调 `GET /items/{id}` 看最差那条，其余用 `alert_ids` 逐个拉。

---

## 六 前端调用要点

1. **轮询**：预警列表进入页面拉一次，之后 60 秒一次；红点用 `GET /notifications/mine?unread=1&limit=1` 每 30 秒一次。页面隐藏时停。
2. **空态**：`total=0` 且 `last_run` 有值 → 「今日无预警」；`last_run` 为空 → 「取数还没跑过」。
3. **时间**：所有时间都是带时区的 ISO 8601，直接显示，不要自己加 8 小时。
4. **不要自己算阈值**：`threshold` 只用于详情里展示判断依据，列表上不写「超过 xx」。
5. **不要按 `tier` 文案**：档位只分色，文字一律用 `message` 或 `doc_name`。
