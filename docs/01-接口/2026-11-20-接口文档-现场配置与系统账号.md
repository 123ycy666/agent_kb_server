## 0. 通用约定

| 项 | 说明 |
|---|---|
| Base URL | 相对路径调用：`api/v1/*` 与 `api/*`。站点前缀（`/` 或 `/sandbox/`）由 nginx 剥，包内不写死前缀 |
| 编码 | 请求/响应均 UTF-8，`Content-Type: application/json` |
| 鉴权 | 三条通道，见 0.1 |
| Token 有效期 | 12 小时（`expires_in` = 43200 秒） |
| 时间 | 本地时间字符串 `YYYY-MM-DD HH:mm:ss`（`checked_at` 等） |
| 错误体 | `{"detail":{"code","message","detail"}}`，见 0.2 |
| 未知接口 | `404 {"error":"接口不存在","path":"/api/v1/no-such-thing"}` |

### 0.1 鉴权通道

| 通道 | 请求头 | 覆盖接口 | 令牌来源 |
|---|---|---|---|
| 用户 JWT | `Authorization: Bearer <access_token>` | 全部业务接口 | `POST /api/v1/auth/login` |
| 现场未就绪免登录 | 无 | `/api/v1/site/*` 四个接口 | — |
| 系统账号 | `X-Internal-Token: <令牌>` | `/api/internal/*`、`/api/alerts/*`；也可换 token（3.2） | 服务配置 `.env` 的 `INTERNAL_SERVICE_TOKEN` |

- JWT 载荷含 `sid`（现场标识），密钥按现场派生：**切现场后旧 token 一律 401**。

```json
{ "sub": "2", "iat": 1795161748, "typ": "access", "sid": "127.0.0.1:5433/ad_new", "username": "kbadmin" }
```

- 系统令牌为空时服务端不校验（本地开发）；线上必须配。
- 系统令牌在**服务级**，切现场不受影响。

### 0.2 统一错误体

```json
{ "detail": { "code": "NOT_AUTHENTICATED", "message": "缺少访问凭证", "detail": null } }
```

参数校验失败为 `422`，`detail.detail` 是字段错误数组：

```json
{
  "detail": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数校验失败",
    "detail": [ { "type": "string_too_short", "loc": ["body", "new_password"],
                  "msg": "String should have at least 6 characters" } ]
  }
}
```

两个历史例外（不要按统一体解析）：

| 接口 | 状态码 | 响应体 |
|---|---|---|
| `POST /api/alerts/daily` 令牌不对 | 401 | `{"status":"unauthorized","error":"内部令牌不正确"}` |
| 任意未匹配的 `/api*` 路径 | 404 | `{"error":"接口不存在","path":"..."}` |

### 0.3 现场就绪门

当前现场未配置或连不上时，除下列白名单外，所有 `/api*` 一律 `503`：

| 放行 | 说明 |
|---|---|
| `/api/v1/site/*` | 现场配置自己的四个接口 |
| `/health`、`/docs`、`/redoc`、`/openapi.json`、`/api` | 探活与文档 |
| 非 `/api` 路径 | 前端静态资源与 SPA 兜底 |

```json
{ "detail": { "code": "SITE_NOT_CONFIGURED",
              "message": "该现场尚未配置或数据库连接失败，请先完成「现场配置」" } }
```

实测：`GET /api/v1/kb`、`POST /api/ask`、`GET /api/sessions`、`GET /api/alerts/health` 在降级实例上均为
`503` + 上面这个体。

## 1. 现场状态与配置

### 1.1 当前现场状态 `GET /api/v1/site/status`

| 项 | 值 |
|---|---|
| 方法/路径 | `GET /api/v1/site/status` |
| 鉴权 | 无（降级时前端靠它决定只出配置页） |
| Content-Type | `application/json` |

响应字段：

|---|---|---|

### 1.3 保存现场配置 `PUT /api/v1/site/config`

| 项 | 值 |
|---|---|
| 方法/路径 | `PUT /api/v1/site/config` |
| 鉴权 | 现场就绪后**仅管理员**；未就绪时免登录 |
| Content-Type | `application/json` |

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pg` | object | 是 | 产品库 `{host, port, dbname, user, password}`；`dbname` 必填 |
| `admin` | object | 否 | 初始管理员 `{username, password}`；账号已存在且有口令时**只跳过、不覆盖** |
| `wf_database` | string\|null | 否 | 工作流库名；不填＝用当前现场自己的库 |
| `mysql` | object | 否 | 业务库 `{db_host, db_port, db_name, db_user, db_password}`；只存非空项 |
| `model` | object | 否 | `{model_channel, llm_base_url, llm_api_key, llm_model}`；只存非空项 |

行为：先试连产品库 —— 连不上**不写引导文件、不切库**；连上才建结构、建初始管理员、重绑连接、清缓存。

响应字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 是否切成功 |
| `error` | string | 失败原因（仅 `ok:false`） |
| `status` | object | 同 1.1；失败时携带**目标现场**，便于显示试过哪个库 |
| `admin` | object | `{"created": true, "username": "admin"}` 或 `{"skipped": true, "reason": "管理员已存在，口令未改"}` |
| `pg_detail` | string | 产品库版本与库名，如 `PostgreSQL 16.14 | 库 ad_empty` |
| `saved` | int | 写入的业务库/模型配置条数 |
| `runtime` | object | 本次落库的业务库/模型项 |
| `warning` | string | 引导文件不可写时出现：本次只在内存生效，重启回退 |

失败分支为 `200` + `ok:false`（不是 4xx）：

```json
{
  "ok": false,
  "error": "连不上产品库：ConnectionTimeout: connection timeout expired",
  "status": { "configured": true, "ok": false,
              "error": "连不上产品库：ConnectionTimeout: connection timeout expired",
              "site_id": "127.0.0.1:5999/nope_db",
              "site": { "host": "127.0.0.1", "port": 5999, "dbname": "nope_db", "user": "kb" },
              "business_empty": true, "system_token_configured": true }
}
```

成功（实查，空库 `ad_empty`）：

```json
{
  "ok": true,
  "status": { "configured": true, "ok": true, "error": "", "site_id": "127.0.0.1:5433/ad_empty",
              "site": { "host": "127.0.0.1", "port": 5433, "dbname": "ad_empty", "user": "kb" },
              "business_empty": true, "system_token_configured": true },
  "saved": 0,
  "admin": { "created": true, "username": "admin" },
  "pg_detail": "PostgreSQL 16.14 | 库 ad_empty",
  "runtime": {}
}
```

错误码：

| 状态码 | `detail.code` | 触发条件 |
|---|---|---|
| 400 | `BAD_BODY` | 请求体不是 JSON / 不是对象 |
| 400 | `BAD_PG` | 缺 `pg` 或缺 `pg.dbname` |
| 401 | `NOT_AUTHENTICATED` | 已就绪但未带 JWT |
| 403 | `NO_PERMISSION` | 已就绪但不是管理员 |

## 3. 认证

### 3.1 登录 `POST /api/v1/auth/login`

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /api/v1/auth/login` |
| 鉴权 | 无 |
| Content-Type | `application/json` |

请求体：`username`（string）、`password`（string）。

账号判定顺序（2026-11-19 起）：

1. 当前现场库里的账号口令（`app_user.password_hash` 非空且校验通过）—— 现场配置页种出来的管理员走这条；
2. 业务库 `t_employee`（argon2id，只读）；
3. 都不通 → `401 BAD_CREDENTIALS`。

响应字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `access_token` | string | JWT，载荷含 `sid` |
| `token_type` | string | `bearer` |
| `expires_in` | int | 43200 秒 |
| `user` | object | `{id, username, display_name}` |
| `roles` | array | 角色码，如 `["admin"]` |
| `permissions` | array | 权限码，见下方实测 |

实测：

### 3.2 免密换 token `POST /api/v1/auth/sso/login`

| 项 | 值 |
|---|---|
| 方法/路径 | `POST /api/v1/auth/sso/login` |
| 鉴权 | `X-SSO-Key`（服务配了 `SSO_LOGIN_KEY` 时必需）或 `X-Internal-Token` |
| Content-Type | `application/json` |

请求体：`username`（string，登录名）。**不校验口令**。

账号判定顺序：业务库 `t_employee` → 当前现场库账号（骨架/新现场没有 HR 库时）→ 都没有
`401 USER_NOT_FOUND`。响应字段与 3.1 同（`access_token`/`token_type`/`expires_in`/`user`/`roles`/`permissions`）。

实测（带 `X-Internal-Token`）：

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIiwi...",
  "token_type": "bearer",
  "expires_in": 43200,
  "user": { "id": 1, "username": "admin", "display_name": "管理员" },
  "roles": ["admin"],
  "permissions": ["audit:read", "conflict:read", "conflict:resolve", "doc:delete", "doc:read",
                  "doc:tag", "doc:update", "doc:upload", "kb:create", "kb:delete", "kb:read",
                  "kb:update", "search:query", "system:config", "system:scan", "tag:manage",
                  "tag:read", "user:manage", "user:read"]
}
```

错误码：

| 状态码 | `detail.code` | 触发条件 |
|---|---|---|
| 404 | `SSO_DISABLED` | `.env` 的 `SSO_LOGIN_ENABLED=false` |
| 401 | `BAD_SSO_KEY` | 配了 `SSO_LOGIN_KEY` 且 `X-SSO-Key` 不符（带系统令牌可免） |
| 401 | `USER_NOT_FOUND` | 账号不存在或已停用 |

> 实测边界：服务未配 `SSO_LOGIN_KEY` 时，本接口不带头也返回 `200` 和 token（与 3.1 的实测同体，仅 `access_token` 不同）。要挡掉必须配 `SSO_LOGIN_KEY`，或 `SSO_LOGIN_ENABLED=false`。

## 4. 会话历史（含步骤） `GET /api/history`

| 项 | 值 |
|---|---|
| 方法/路径 | `GET /api/history?session_id=<id>&limit=<n>&with_steps=true` |
| 鉴权 | `Authorization: Bearer <access_token>` |
| Content-Type | `application/json` |

请求参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | string | 是 | 会话 id |
| `limit` | int | 否 | 不传（或 0）＝按防呆上限取（响应里 `limit` 给实际值，实测 5000）；`>0`＝按 `seq_no` 正序取**最早**的 N 条 |
| `with_steps` | bool | 否 | `true` 时 `steps` 换成步骤数组（见下），默认 `false` |

响应字段：`session`（object，会话行）、`messages`（array）、`total`（本会话消息总数）、`returned`（本次返回条数）、`limit`（实际生效上限）、`truncated`（bool，是否被上限截断）。

`messages[]` 元素（实测键）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `seq_no` / `direction` / `sender_type` / `reply_to_id` / `msg_type` / `sender_id` | int\|null | 消息定位；`sender_type=2` 为助手 |
| `content` | string | 正文 |
| `model` / `latency_ms` / `elapsed_ms` / `create_time` | — | 模型与耗时；`create_time` 为本地时间字符串 |
| `qa_id` | int\|null | 关联问答 id，取步骤用 |
| `fixed_question` / `completed_question` | string\|null | 纠错 / 补全结果 |
| `period_type` / `period_key` / `time_text` / `time_is_default` / `place` / `place_is_default` | — | 时间与口径解析结果 |
| `name_fix_used` / `completion_used` / `db_query_count` / `sql_query_count` / `kb_query_count` / `no_db_query` / `unverified` / `is_gap` | int\|null | 过程标记 |
| `feedback` / `feedback_note` | — | 评价 |
| `steps` | int\|array\|null | **类型随参数变化**：`with_steps=false` 时是整数（该次问答的步骤数，实测 `3`）；`with_steps=true` 时是步骤数组；用户消息恒为 `null` |

`steps[]` 元素：

| 字段 | 类型 | 说明 |
|---|---|---|
| `trace_id` | int | 所属问答 id |
| `step_no` | int | 步骤序号，从 1 开始 |
| `step_kind` | string | 步骤类型：`route` / `namefix` / … |
| `round_no` | int\|null | 轮次 |
| `tool_name` | string | 工具名 |
| `input_text` | string\|null | 入参，**JSON 字符串**（`"null"` 表示无参数） |
| `output_text` | string | 出参，**JSON 字符串** |
| `sql_text` | string\|null | 执行过的 SQL |
| `result_rows` | int\|null | 影响/返回行数 |
| `cost_ms` / `model_ms` | int\|null | 耗时 |
| `status` | int | 0 为正常 |
| `error_msg` | string\|null | 失败原因 |

实测（`with_steps=true`，一场 2 条消息的会话；助手那条共 8 步，`steps` 只在下面展开两条）：

## 5. 形状未变、语义变化

| 接口 | 变化 |
|---|---|
| 所有 `/api*` | 现场未就绪 → `503 SITE_NOT_CONFIGURED`（0.3） |
| 所有带 JWT 的接口 | token 绑 `sid`，切现场后旧 token 一律 `401 NOT_AUTHENTICATED`，前端需跳登录 |
| `POST /api/ask` | 空现场（`business_empty=true`）时不查库、不编数字，返回 `{"answer":"该现场尚未配置业务内容，暂时无法取数。…","site_empty":true,"hint":"该现场尚未配置","session_id":"…","qa_id":null,"trace":[],"steps":[],"files":[],"evidence":{}}` |
| `GET /api/v1/runtime/config` | `defaults.db_host/db_port/db_name/db_user` 现在给的是**实际生效**那组；`values` 仍是页面存的值 |
| `GET /api/v1/auth/me` | 增加 `sid` 校验后，跨现场旧 token 由 200 变 401 |

## 6. 错误码总表

| 状态码 | `code` | 出处 | 含义 |
|---|---|---|---|
| 400 | `BAD_BODY` | PUT `/site/config` | 请求体不是 JSON 对象 |
| 400 | `BAD_PG` | PUT `/site/config` | 缺产品库连接或缺 `dbname` |
| 400 | `BAD_TARGET` | POST `/site/test` | `target` 不在 pg / mysql / model |
| 400 | （非统一体）`error:"缺少 session_id"` | GET `/api/history` | 未传 `session_id` |
| 400 | `PASSWORD_MANAGED_BY_HR` | POST `/auth/change-password` | 口令由人力资源系统管理（本系统改不了） |
| 401 | `NOT_AUTHENTICATED` | 全部带 JWT 的接口 | 未带凭证或 token 失效 |
| 401 | `BAD_CREDENTIALS` | POST `/auth/login` | 账号或口令错 |
| 401 | `BAD_SSO_KEY` | POST `/auth/sso/login` | `X-SSO-Key` 不符 |
| 401 | `USER_NOT_FOUND` | POST `/auth/sso/login` | 账号不存在或已停用 |
| 401 | `BAD_INTERNAL_TOKEN` | `/api/internal/*`、`/api/alerts/health` | 系统令牌不符 |
| 401 | （非统一体）`status:"unauthorized"` | POST `/api/alerts/daily` | 系统令牌不符 |
| 403 | `NO_PERMISSION` | `/api/v1/site/config`、`/test` | 已就绪但不是管理员 |
| 404 | `SSO_DISABLED` | POST `/auth/sso/login` | 免密登录未启用 |
| 404 | （非统一体）`error:"接口不存在"` | 任意未匹配 `/api*` | 路径不存在 |
| 404 | （非统一体）`error:"session 不存在"` | GET `/api/history` | 会话不存在或不属于当前用户 |
| 422 | `VALIDATION_ERROR` | 所有带 schema 的接口 | 参数校验失败 |
| 500 | `INTERNAL_ERROR` | 全部 | 未预期异常 |
| 503 | `SITE_NOT_CONFIGURED` | 除 0.3 白名单外全部 `/api*` | 现场未配置或连不上 |
