# 工作流接口文档（前端对接，2026-11-23）

| 项 | 值 |
|---|---|
| 基址 | `/api/flows`（不带 v1，前端用 `agentHttp`） |
| 鉴权 | `Authorization: Bearer <JWT>`，全部接口都要登录 |
| 时间 | ISO 8601 带时区，如 `2026-11-23T17:28:12+08:00` |
| 错误体 | `{"detail": {"code": "...", "message": "...", "errors": [...]}}` |
| 代码 | `server/app/wf/api.py`（20 个接口） |
| 数据 | 预警库 `ad_wf`：`wf_flow` / `wf_flow_version` / `wf_trigger` / `wf_trigger_flow` / `wf_flow_run` |

**长耗时接口**：`/docs` 相关的 `dry-run` 会真的查一次业务库，`run` 会查库并回填。单份文档在 432 行的表上约 1~2 秒，大表按行数增长。前端给 300 秒超时。

**业务库**：预警读写的是「现场配置」里的「预警业务库」，与问数用的库可以不是同一个。

|---|---|

| 运行记录 | `GET /runs`、`GET /runs/{rid}` |

## 二 文档结构（spec）

一份文档 = 一个工作流。保存时按下面五段校验，少一个槽不存、多一个槽不认。

```json
{
  "source": {
    "db": "biz",
    "tables": [{"table": "t_power_project_settle", "alias": "t1", "columns": ["project_code"]}],
    "joins": [{"left": "t1.a", "right": "t2.b", "type": "inner"}],
    "filter": {"op": "AND", "items": [{"kind": "cond", "ref": "t1.project_code", "op": "notnull"}]},
    "limit": 200000
  },
  "calc": {
    "grain": [{"name": "项目编码", "ref": "t1.project_code"}],
    "fields": [{"name": "D", "expr": "datediff(t1.due_date, today())"}],
    "row_policy": "first",
    "order_ref": ""
  },
  "judge": {
    "rules": [{"when": [{"ref": "D", "op": "lt", "value": 0}], "op": "AND", "then": {"hit": true, "tier": "high"}}],
    "default": {"hit": false, "tier": ""}
  },
  "write": {
    "db": "biz",
    "table": "t_power_project_settle",
    "mode": "update",
    "key": [{"target": "project_code", "from": "项目编码"}],
    "map": [{"target": "status", "from": "状态"}],
    "miss": "keep"
  },
  "note": ""
}
```

**source 取数**

| 槽位 | 取值 | 约束 |
|---|---|---|
| `db` | `biz` / `fw` | 来源表都在同一个库 |
| `tables[].table` | 元数据里登记的表 | 表不存在 → 422 |
| `tables[].alias` | 引用用的前缀，如 `t1` | 别名不可重复 |
| `tables[].columns` | 该表的列 | 列不存在 → 422 |
| `joins[]` | `left` / `right` 用 `别名.列`，`type` 取 `inner` / `left` | 两边不能是同一张表 |
| `filter.items[]` | `{"kind":"cond","ref","op","value"}` 或 `{"kind":"group","op","items":[]}` | `op` 见下表 |
| `limit` | 默认 200000，上限 500000 | — |

条件运算 `op`：`isnull`、`notnull`、`eq`、`ne`、`gt`、`ge`、`lt`、`le`、`in`、`notin`、`contains`、`starts`、`ends`。`isnull` / `notnull` 不取值。

**calc 计算**

| 槽位 | 取值 |
|---|---|
| `grain[]` | `name` 是结果里的列名，`ref` 是来源列（`别名.列` 或唯一时的裸列名） |
| `fields[]` | `name` 与 `expr`；`expr` 可引用来源列和前面已算出的列 |
| `row_policy` | `first` / `latest` / `max` / `min` |
| `order_ref` | `row_policy` 不是 `first` 时，按这一列取行 |

表达式可用：列名、数字、字符串 `"..."`、`+ − × ÷`、`today()`、`now()`、`datediff(a,b)`、`round(x,n)`、`abs`、`min`、`max`、`sum`、`avg`、`count`、`coalesce`、`ifnull`、`upper`、`lower`、`concat`、`substr`、`isnull`、条件式 `A if 条件 else B`。

**judge 判断**

| 槽位 | 取值 |
|---|---|
| `rules[]` | 从上往下匹配，第一条成立即出结论 |
| `rules[].when[]` | 条件数组，`ref` 可以是计算结果名，也可以是本轮取到的列 |
| `rules[].op` | `AND`（默认）/ `OR` |
| `rules[].then` | `{"hit": true/false, "tier": "自定义档位"}` |
| `default` | 都不命中时的结论 |

至少一条规则。

**write 回填**

| 槽位 | 取值 | 约束 |
|---|---|---|
| `db` / `table` | 目标库与表 | 表不存在 → 422 |
| `mode` | `update` / `upsert` / `insert` | — |
| `key[]` | `target` 是目标列，`from` 是取值列 | 必须盖住目标表的唯一键，否则 422 |
| `map[]` | `target` 目标列，取 `from`（结果列）或 `value`（固定值） | 至少一列 |
| `miss` | 本期只支持 `keep`：本轮没算到的行保留原值 | — |

**note**：自由文本，编译时附在 SQL 注释里。

## 三 元数据

### 3.1 `GET /meta/dbs` 可选的库

```json
[{"value": "biz", "label": "业务库"}, {"value": "fw", "label": "预警库"}]
```

### 3.2 `GET /meta/tables` 表清单

参数：`db`（默认 `biz`）、`keyword`（按表名或表注释模糊匹配）。

```json
{"db": "biz", "items": [{"db": "biz", "name": "t_power_project_settle",
  "comment": "项目结算与决算台账", "column_count": 61, "key": ["project_code"]}]}
```

`key` 是推荐的匹配键：优先业务唯一键，其次主键。

### 3.3 `GET /meta/columns` 某表的列

参数：`db`、`table`。

```json
{"db": "biz", "table": "t_power_project_settle", "comment": "项目结算与决算台账",
 "columns": [{"name": "project_code", "type": "varchar(32)", "nullable": false, "comment": "项目编码"}],
 "key": ["project_code"]}
```

元数据缓存 5 分钟；`POST /meta/refresh` 立即失效。

### 3.4 `POST /meta/refresh` 重读元数据

参数：`db`（可选，缺省清全部）。返回 `{"ok": true, "refreshed": "all"}`。

## 四 工作流文档

### 4.1 `GET /` 列表

```json
{"items": [{
  "id": 4, "name": "项目结算与决算到期未完成", "enabled": true, "version": 4,
  "updated_by": "admin", "updated_at": "2026-11-23T17:28:12+08:00",
  "summary": {"source_tables": ["t_power_project_settle"],
              "target": "业务库.t_power_project_settle",
              "target_table": "t_power_project_settle",
              "target_columns": ["final_color", "final_status"], "mode": "update"},
  "complete": true, "note": "",
  "last_run": {"id": 12, "status": "ok", "at": "2026-11-23T17:28:12+08:00",
               "selected_n": 10, "hit_n": 7, "written_n": 10, "elapsed_ms": 1592, "dry_run": false}
}]}
```

`complete=false` 表示还没填完，不能在定时任务里挂载。列表不带 `spec` 和 `errors`。

### 4.2 `POST /` 新建

请求：`{"name": "某工作流"}`，`spec` 可选（不传就是空五段）。

返回同 4.3。`409 NAME_TAKEN` 名字重复；`422 NO_NAME` 缺名字。

### 4.3 `GET /{id}` 详情

在列表一项基础上多三块：

```json
{"spec": {"source": {}, "calc": {}, "judge": {}, "write": {}, "note": ""},
 "errors": [{"section": "calc", "slot": "grain", "message": "至少要选一个分组列"}],
 "versions": [{"version": 4, "updated_by": "admin", "at": "2026-11-23T17:28:12+08:00"}],
 "templates": {"cond_ops": [{"value": "eq", "label": "等于"}], "row_policy": [], "mode": [], "join": []}}
```

`errors[].section` 取值：`source` / `calc` / `judge` / `write`，前端按段显示红标。

### 4.4 `PUT /{id}` 保存

请求（都可选，只传要改的）：`{"name": "...", "spec": {...}, "enabled": true}`。

- 传了 `spec` 或把 `enabled` 置真时会先校验；不过就 `422 SPEC_INVALID`，`detail.errors` 列出全部槽位问题。
- `spec` 有变化时 `version` 加一，并写一条历史版本。
- 只改名字不受校验影响。

### 4.5 `DELETE /{id}` 删除

逻辑删，并从所有定时任务上摘掉。返回 `{"ok": true}`。

### 4.6 `POST /{id}/duplicate` 复制

不传参数。新文档 `enabled=false`，名字自动加「副本」。返回文档详情。

## 五 编译与执行

### 5.1 `POST /{id}/compile` 编译预览

不查库。能编译返回 200：

```json
{"ok": true, "errors": [],
 "select_preview": "SELECT `t1`.`project_code` AS `t1__project_code` ...",
 "write_preview": "UPDATE `t_power_project_settle` SET `final_color` = ? WHERE `project_code` = ?;",
 "select": {"db": "biz", "sql": "SELECT ... %s", "params": []},
 "write": {"db": "biz", "table": "t_power_project_settle", "mode": "update",
           "key": [{"target": "project_code", "from": "项目编码"}], "map": [], "miss": "keep"}}
```

填不全时返回 `422 SPEC_INVALID`，`errors` 同 4.3。

### 5.2 `POST /{id}/dry-run` 试跑

只取数与判断，不写库。返回：

```json
{"run_id": 13, "status": "ok", "dry": true, "selected_n": 10, "hit_n": 7,
 "written_n": 0, "updated": 0, "inserted": 0, "elapsed_ms": 1592,
 "sql": "SELECT ...", "write_sql": "UPDATE ...",
 "sample": [{"项目编码": "1715M0250002", "Wf": 180, "Df": 29, "Pf": 16.1,
             "决算颜色": "红", "决算状态": "紧急", "hit": true, "tier": "high"}]}
```

`sample` 是前 20 行计算结果。`422 SPEC_INVALID` / `500 RUN_FAILED`。

### 5.3 `POST /{id}/run` 正式跑

查库 → 判断 → 回填，同一事务。返回结构同 5.2，`dry=false`，`written_n` 是实际写入行数。

- `422 FLOW_DISABLED`：工作流没启用。
- `422 SPEC_INVALID`：文档没填对。
- `500 RUN_FAILED`：连不上库或 SQL 报错，`message` 带异常摘要。

## 六 定时任务（触发器）

### 6.1 规则结构

```json
{"unit": "week", "dow": [1, 3], "dom": [], "times": ["09:00", "17:30"]}
```

| 字段 | 取值 |
|---|---|
| `unit` | `day`（每天）/ `week`（每周）/ `month`（每月） |
| `dow` | `unit=week` 时必填，1~7 表示周一到周日，可多选 |
| `dom` | `unit=month` 时必填，1~28 号，可多选 |
| `times` | `HH:mm`，可多个 |

多个时间点与多个星期几/号会组合展开成多条 cron。

### 6.2 `GET /triggers` 列表

```json
{"items": [{"id": 2, "name": "每天跑结算", "enabled": true,
  "times": ["08:00"], "rule": {"unit": "week", "dow": [1, 3], "dom": [], "times": ["09:00"]},
  "rule_text": "周一、周三 09:00", "note": "",
  "next": ["2026-11-25 09:00", "2026-11-30 09:00", "2026-12-02 09:00"],
  "flows": [{"id": 4, "name": "项目结算与决算到期未完成", "enabled": true}],
  "last": {"id": 12, "status": "ok", "at": "2026-11-23T17:28:12+08:00", "written_n": 10}}],
 "status": {"running": true, "jobs": [{"id": "wf-2-0", "next": "2026-11-25 09:00:00+08:00"}]}}
```

### 6.3 `POST /triggers` 新建

```json
{"name": "每天跑结算", "rule": {"unit": "day", "dow": [], "dom": [], "times": ["08:00"]},
 "flow_ids": [4], "enabled": true, "note": ""}
```

`times` 可以直接传（等价于 `rule.times`，且 `unit` 默认 `day`）。`409 NAME_TAKEN`、`422 NO_NAME`。

### 6.4 `PUT /triggers/{tid}` 改

字段都可选。传 `flow_ids` 就整体替换挂载关系；顺序即执行顺序。保存后热重载，不重启进程。

### 6.5 `DELETE /triggers/{tid}`

连同挂载关系一起删。返回 `{"ok": true}`。

### 6.6 `POST /triggers/{tid}/run` 立刻跑一次

按顺序跑该触发器下所有启用的工作流：

```json
{"trigger": "每天跑结算",
 "results": [{"flow": "项目结算与决算到期未完成", "run_id": 14, "status": "ok",
              "hit_n": 7, "written_n": 10}]}
```

停用的工作流返回 `{"flow": "...", "status": "skipped", "reason": "工作流已停用"}`；单个失败不影响后面的。

## 七 运行记录

### 7.1 `GET /runs` 列表

参数：`flow_id`（可选）、`limit`（默认 100，上限 500）。

```json
{"items": [{"id": 12, "flow_id": 4, "flow_name": "项目结算与决算到期未完成",
  "flow_version": 4, "trigger": "manual", "status": "ok", "dry_run": false,
  "started_at": "2026-11-23T17:28:12+08:00", "finished_at": "2026-11-23T17:28:13+08:00",
  "elapsed_ms": 1592, "selected_n": 10, "hit_n": 7, "written_n": 10, "error": null}]}
```

`trigger`：`manual` / `cron` / `test`。`status`：`ok` / `failed` / `running`。

### 7.2 `GET /runs/{rid}` 一轮详情

多一个 `sql_text`：这一轮编译出的取数 SQL 原文（参数已内联），排错看它。

## 八 错误码

| HTTP | code | 含义 |
|---|---|---|
| 401 | `unauthorized` | 没带 token 或过期 |
| 404 | `FLOW_NOT_FOUND` / `TRIGGER_NOT_FOUND` / `RUN_NOT_FOUND` / `TABLE_NOT_FOUND` | 对象不存在 |
| 409 | `NAME_TAKEN` | 名字重复 |
| 422 | `NO_NAME` / `SPEC_INVALID` / `FLOW_DISABLED` | 缺名字 / 文档没填对 / 工作流没启用 |
| 500 | `RUN_FAILED` | 跑一轮失败，`message` 带异常类型与摘要 |

`SPEC_INVALID` 的响应体带 `errors`：

```json
{"detail": {"code": "SPEC_INVALID", "message": "文档还没填对：至少要选一个分组列",
  "errors": [{"section": "calc", "slot": "grain", "message": "至少要选一个分组列"}]}}
```
