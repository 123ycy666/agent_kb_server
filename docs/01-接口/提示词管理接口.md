# 提示词管理接口（2026-11-02）

> 给内网对接用。**所有接口和前端页面在同一个端口上**（容器 8200 / 对外 80），不需要另开端口。
> 前端页面是 `/prompts`；接口统一前缀 `/api/v1/prompts`。

## 一、单端口与转发

内网只有一个端口能过时，把**页面和接口都转给同一个后端**即可：

```nginx
location / {
    proxy_pass http://127.0.0.1:8200;      # 前端 /prompts 与 /api/v1/prompts 都走这里
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
}
```

- 前端是 SPA，`/prompts` 这类路径由后端回 `index.html`（已做好 catch-all），**不需要额外的 try_files**。
- 接口是 `/api/v1/prompts/*`，与页面同域同端口，浏览器和内网系统都不用手工拼端口。

## 二、鉴权

和现有管理面一致：`Authorization: Bearer <JWT>`。

```bash
# 拿 token
curl -s -X POST http://<host>/api/v1/auth/login \
     -H 'Content-Type: application/json' \
     -d '{"username":"admin","password":"***"}'
```

之后每个请求带 `-H "Authorization: Bearer $TOKEN"`。

## 三、接口清单

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/prompts/overview` | **一次拿全**：节点树 + 四份材料 + 补全表 + 代码提示词 + 注入字数 |
| GET | `/api/v1/prompts/tree` | 12 个节点 + 每节点挂的材料（含正文、字数、注入时机） |
| GET | `/api/v1/prompts/material/{slot}` | 某一份的分节（slot = `fetch` / `judge` / `answer` / `check`） |
| PUT | `/api/v1/prompts/material/{slot}` | 整份保存（body: `{"sections":[{"section","body","pinned"}]}`） |
| POST | `/api/v1/prompts/material/{slot}/section` | 新增一节（body: `{"section","body","pinned"}`） |
| DELETE | `/api/v1/prompts/material/section/{id}` | 真删一节 |
| POST | `/api/v1/prompts/material/{slot}/import` | 贴 markdown 按标题切节并覆盖这一份（body: `{"text"}`） |
| GET | `/api/v1/prompts/complete` | 补全表（13 条：问法 → 标准口径） |
| PUT | `/api/v1/prompts/complete` | 整表保存（body: `{"rows":[{"kind","match_text","fill_text","priority"}]}`） |
| GET | `/api/v1/prompts/texts` | 身份 / 汇报口吻 / 模式做法 / 词表的当前值与默认值 |
| PUT | `/api/v1/prompts/texts/{key}` | 保存覆盖值（key = `identity`/`answer_format`/`modes`/`keywords`） |
| DELETE | `/api/v1/prompts/texts/{key}` | 恢复成代码默认值 |
| GET | `/api/v1/prompts/preview?mode=data` | 基础提示词按层返回（红线/优先级/身份/模式/格式） |

## 四、典型调用

**① 一把拿全（内网系统的首选）**

```bash
curl -s http://<host>/api/v1/prompts/overview -H "Authorization: Bearer $TOKEN"
```

返回里 `nodes` 是流程树（每份材料带 `body`），`materials` 是四份的字数概览，`complete` 是补全表，`texts` 是代码提示词，`inject` 是两处注入字数。

**② 改一节正文**

```bash
# 先取到 id
curl -s http://<host>/api/v1/prompts/material/judge -H "Authorization: Bearer $TOKEN"
# 再整份保存（只改目标那节，其余原样回传）
curl -s -X PUT http://<host>/api/v1/prompts/material/judge \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"sections":[{"section":"八、审批停留（积压）","body":"...","pinned":true}]}'
```

**③ 加一节 / 删一节**

```bash
curl -s -X POST http://<host>/api/v1/prompts/material/judge/section \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"section":"二十三、新的审批条件","body":"...","pinned":true}'

curl -s -X DELETE http://<host>/api/v1/prompts/material/section/123 \
  -H "Authorization: Bearer $TOKEN"
```

**④ 改补全表**

```bash
curl -s -X PUT http://<host>/api/v1/prompts/complete \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"rows":[{"kind":"norm","match_text":"情况怎么样","fill_text":"六项指标 + 预算执行","priority":10}]}'
```

## 五、生效时间

- 写接口都会清缓存，**下一轮问答立刻用新值**，不用重启。
- 唯一例外：`prompt_text`（身份 / 汇报口吻 / 模式做法 / 词表）在进程内有 60 秒缓存，最迟 1 分钟。
- 知识库上传的资料不受影响：资料仍走检索，规则走这份接口。

## 六、状态码

| 码 | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数不对（比如 markdown 切不出小节、JSON 格式错） |
| 401 | 没登录 / token 过期 |
| 404 | slot 写错（只接受 fetch / judge / answer / check） |
| 500 | 写库失败（响应 `{"error":"..."}` 里有原因） |
