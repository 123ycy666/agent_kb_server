# 提示词管理接口（v5，2026-11-08）

> 给内网对接用。**页面和接口同一个端口**（容器 8200 / 对外 80），不另开端口。
> 页面：`/prompts`；接口前缀：`/api/v1/prompts`。
> 本版对应代码：七步流程 + 时间地点补全整块删除 + **软删 / 导出导入 / 事实清单**（线上 `47.121.183.81`）。

## 0. 这一版改了什么（先看这段）

**〇、v5（2026-11-08）：文本键多了一个「工具说明」，第 1 步判据改成三布尔，报告技能下线。**

| 类别 | 变化 |
|---|---|
| 新增文本键 | `tools`（工具说明）。空 = 用代码里的默认段；只在**给了工具**的那一轮注入 system（聊天轮不注入）。默认段内容：先 `kb_search` 搜做法再动手、命中就 `kb_read` 取全文、读文件用 `read_file` 分页读、出文件用 `make_file`、能用结构化参数就别写 `run_code` |
| 文本键清单 | `identity` / `redlines` / `priority` / `intent` / `confirm` / `modes` / `keywords` / **`tools`**（自 v3 删掉 7 个时间键后，这是第 8 个） |
| `intent` 语义 | 第 1 步判**三个布尔**：`查库=是/否`、`读文件=是/否`、`出文件=是/否` + `理由`。框空 → 用代码默认判据（现为「默认查库=是」，带具体业务对象/指标就查库） |
| `confirm` 语义 | 第 5 步「问题确定」。框空 → 把六行事实清单（本轮原话 / 更正后 / 补问法后 / 补全表命中 / 最近几轮）原样下发；框有内容 → 模型产出**一句确定的问题** |
| 注入规则 | 查数口径只在 `查库=是` 的轮次注入；工具说明只在给了工具时注入；收尾那次调用换成「回答规则」材料（口径不再漏进收尾 system） |
| 下线 | 报告技能组（`/api/report*`、`/api/skill/*`、`/api/skills`、`/api/triggers`、`/api/statechange`）与 `report.py`、`skills.html`。它们不是提示词页的一部分，但页面里的入口按钮一并删了 |
| 不变 | 提示词页接口路径一律不变（`/api/v1/prompts/*`），只加了 `tools` 这个键 |

**一、v4（2026-11-05）：软删 + 导入导出 + 收尾只看事实清单。**

| 类别 | 变化 |
|---|---|
| 删除 | `DELETE /material/section/{id}` 默认改成**软删**（`enabled=false`，可恢复）；`?hard=1` 才真删 |
| 恢复 | 新增 `POST /material/section/{id}/restore`、`POST /complete/{id}/restore` |
| 已删除 | 新增 `GET /material/{slot}/deleted`；`GET /complete` 多返回一个 `deleted` 数组 |
| 补全表 | `PUT /complete` 从「整表 DELETE 再插」改成「带 id 原地更新 + 没提交的软删」，行数不再膨胀 |
| 导出 | 新增 `GET /export`（全部）与 `GET /export?slot=fetch`（单份），`text/markdown` 附件 |
| 导入 | 新增 `POST /import`，格式与导出**完全对称**，只覆盖文件里出现的块 |
| tree 字段 | 材料多返回 `slot` / `sections` / `pinned` / `deleted`（页面显示「N 节（必带 M）｜已删 K」） |
| 流程文字 | 第 5 步「问题确定」不再固定四行定稿，产物是**一句整理好的问题**（框空 = 资料原样下传）；第 7 步「回答」前先落**事实清单**，只按清单写正文 |

**二、v3（2026-11-03）：问答流程从 8 步变 7 步，时间地点补全整块删除。**

| 类别 | 变化 |
|---|---|
| 删除的能力 | **时间地点补全**（相对时间词换算、默认年月、默认全市）全部移除，代码不再替你算。要补什么在「补全表」里自己配 |
| 删除的接口数据 | `GET /texts` 里 7 个时间键全部消失：`time_month_rel` / `time_year_rel` / `time_year_off` / `time_whole_city` / `time_strip_head` / `time_strip_tail` / `time_ytd` |
| 删除的节点 | 原第 5 步「算时间地点」不再存在，节点编号 1~7 |
| 删除的页面 | 「时间地点规则」抽屉、入口按钮、节点材料全部去掉 |
| 保留 | `/api/ask` 的 `scope` 入参仍接收（业务系统传的强制范围），但**只记录、不再注入提示词**；返回体 `scope` 字段在，值为空骨架，老调用方不会报错 |
| 变更 | 所有接口响应里的 `datetime` 是 ISO 字符串（`2026-11-03T16:20:10`） |

**三、可编辑文本键从 13 个变 7 个**（v5 起 8 个，多了 `tools`）：`identity` / `redlines` / `priority` / `intent` / `confirm` / `modes` / `keywords` / `tools`。

一句话给对接方：**v3 少了 1 个节点和 7 个时间键；v4 换的是删除语义（软删可恢复）与导入导出；v5 只加了 1 个文本键 `tools`（工具说明）并改了三布尔判据文案，接口路径全程只增不改。**

## 一、单端口与转发

```nginx
location / {
    proxy_pass http://127.0.0.1:8200;      # /prompts 与 /api/v1/prompts 都走这里
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
}
```

- 前端是 SPA，`/prompts` 由后端回 `index.html`（catch-all 已做），不需要 `try_files`。
- 接口同域同端口，浏览器和内网系统都不用拼端口。

## 三、流程结构（七步）

`GET /tree` 与 `GET /overview` 返回的就是这张表。`editable=true` 的材料点了能改，`false` 只能看。

| no | 节点 | 说明 | 挂的材料（key ｜ 可编辑 ｜ 存在哪 ｜ 什么时候用） |
|---|---|---|---|
| 1 | 接手这句话 | 用户原话 + 最近几轮问答 | `base.identity` 身份 ｜ ✓ ｜ prompt_text:identity ｜ 每条消息<br>`base.redlines` 红线 ｜ ✓ ｜ prompt_text:redlines ｜ 填了才注入<br>`base.priority` 优先级 ｜ ✓ ｜ prompt_text:priority ｜ 填了才注入 |
| 2 | 要不要走预处理 | 走 = 纠错 + 补全；不走直接去干活 | `base.intent` ① 要不要走预处理 ｜ ✓ ｜ prompt_text:intent ｜ 每次调用一次模型 |
| 3 | 纠错 | 错别字 / 单位 / 站名改成库里的标准名 | `nc.typo` ② 纠错词典 ｜ ✓（走词表接口）｜ 表 `t_nc_typo` 等 ｜ 预处理：代码读 |
| 4 | 补问法 + 查补全表 | 补默认问法；拿原问题和补后问题去表里找命中（**只查不改**）。**时间地点也在这里配** | `mat.complete` ③ 补全表 ｜ ✓ ｜ 表 `complete_rule` ｜ 预处理：代码读 |
| 5 | 问题确定 | 把资料整理成**一句**能直接往下问的问题（地区 + 时间 + 原话 + 兜底的方面）；框空 = 不整理，资料原样下传 | `base.confirm` ④ 问题确定 ｜ ✓ ｜ prompt_text:confirm ｜ 每次调用一次模型 |
| 6 | 干活（主循环） | 拿定稿自己决定查字段 / 查知识库 / 查数 / 写文档；信息不够就反问 | `mat.fetch` ⑤ 查数口径 ｜ ✓ ｜ 表 `prompt_material(slot=fetch)` ｜ 循环里<br>`semantic.tables` 数据表清单 ｜ ✗ ｜ 业务库字典 ｜ 循环里<br>`semantic.columns` 字段说明 ｜ ✗ ｜ `describe_table` 按需取<br>`semantic.codes` 字典表 ｜ ✗ ｜ 业务库码表 |
| 7 | 回答 | 先把这一轮查到的事实列成清单，再只按清单 + 回答规则写正文（原始工具结果不进收尾） | `mat.answer` ⑥ 回答规则 ｜ ✓ ｜ 表 `prompt_material(slot=answer)` ｜ 写回答时 |

材料节点返回的字段：

```json
{"key":"base.intent","name":"① 要不要走预处理","editable":true,"always":false,
 "when":"第 2 步：每次调用一次模型判断","textKey":"intent",
 "chars":0,"body":"","slot":"","sections":0,"pinned":0,"deleted":0}
```

- `textKey` 非空 → 该材料正文存在 `prompt_text`，用 `PUT /texts/{key}` 保存。
- `textKey` 为空且 `editable=true` → 存在表里（`prompt_material` 用 `/material/{slot}`，补全表用 `/complete`，纠错词典用 `/lexicon/*`）。
- `editable=false` → 代码/业务库生成，只读展示。

### 3.1 页面上现在有什么（`/prompts`）

页面渲染完全由 `GET /tree` 驱动，前端不写死节点。

- **左侧**：七个节点卡片，每张卡片右侧是该节点挂的材料按钮（显示字数 + 注入时机 + `N 节（必带 M）｜已删 K`）。`editable=true` 的按钮是蓝框，点了进编辑抽屉；`editable=false` 显示锁图标。
- **顶部按钮**：刷新 / 纠错词典 / 补全表 / 数据表 / **导出 md** / **导入 md**。
- **抽屉（四种）**：
  1. **文本键抽屉**（材料带 `textKey`）：身份、红线、优先级、① 要不要走预处理、④ 问题确定 —— 单框纯文本，「保存」「恢复默认」「导入」。
  2. **材料抽屉**（`prompt_material`）：⑤ 查数口径、⑥ 回答规则 —— 按小节编辑，可加节、删节（软删）、搜索节、↑↓ 调序，顶部显示「共 N 节，必带 M 节；必带合计 X 字」，「导出 md」「上传 md 覆盖」。
  3. **补全表抽屉**（`complete_rule`）：整表编辑（类型 / 匹配 / 补成什么 / 优先级），加行、删行（软删）、「导入」「保存」。
  4. **纠错词典抽屉**：四张表页签（错别字纠正 / 术语与别名 / 歧义确认 / 标准词表），搜索、新增一条、行内改、软删。
- 材料和补全表都有「已删除」区，点「恢复」即回到可用状态。

## 五、关键接口的请求 / 响应

### 5.1 `GET /texts`（7 个键）

```json
{"ok":true,"items":[
 {"key":"identity","name":"身份","chars":311,"overridden":false,"body":"…","default":"…"},
 {"key":"redlines","name":"红线（S0，纯文本；不填就不注入）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"priority","name":"谁说了算（S1，纯文本；不填就不注入）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"intent","name":"① 要不要走预处理（空 = 全部走：纠错+补全）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"confirm","name":"④ 问题确定（空 = 不归整，原样往下传）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"modes","name":"模式做法（JSON）","chars":0,"overridden":false,"body":"…","default":"…"},
 {"key":"keywords","name":"业务词表 / 题型词表（JSON）","chars":0,"overridden":false,"body":"","default":""}
]}
```

- `body` = 当前生效值（没覆盖就是默认值），`default` = 代码里的默认值。
- `overridden=true` 表示页面存过覆盖值，`DELETE /texts/{key}` 可恢复默认。
- **JSON 键**（`modes`/`keywords`）保存时校验：`modes` 要对象，`keywords` 要数组；写坏返回 400。

### 5.2 `PUT /texts/{key}`

```bash
curl -s -X PUT http://<host>/api/v1/prompts/texts/intent \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"body":"你是分流器。要问业务的事（哪怕有错别字）回「走」；只是打招呼、闲聊，或要求已经说清楚，回「不走」。只回一个词。"}'
```

响应：`{"ok":true,"key":"intent","version_no":2}`；JSON 写坏返回 400 + `{"error":"JSON 格式不对：…"}`。

### 5.3 `GET /complete` / `PUT /complete`

```json
{"ok":true,
 "rows":[{"id":1,"kind":"norm","match_text":"本月情况","fill_text":"10月情况","priority":10,"enabled":true}],
 "preview":"【补全表】（代码读，不进提示词）\n类型 ｜ 匹配 ｜ 补成什么\n…"}
```

```bash
curl -s -X PUT http://<host>/api/v1/prompts/complete \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"rows":[{"kind":"norm","match_text":"本月情况","fill_text":"10月情况","priority":10}]}'
```

- 整表覆盖：先删后插，**同一事务**，失败回滚（不会出现"删了没插回去"）。
- `kind`：`norm`（归一）/ `fill`（补缺）；`match_text`、`fill_text` 为空的条目会被丢弃。
- 命中只作参考：第 4 步查出命中条目交给第 5 步，**不替换用户问题**。

### 5.4 `GET /lexicon` 与 `/lexicon/{key}`

```json
{"ok":true,"tables":[{"key":"typo","name":"错别字纠正","note":"…","rows":105,
 "cols":[{"key":"wrong","label":"错误写法"},{"key":"right_word","label":"正确写法"}]}]}
```

```json
{"ok":true,"key":"typo","name":"错别字纠正","total":105,"limit":50,"offset":0,
 "cols":[{"key":"wrong","label":"错误写法"}],
 "rows":[{"id":105,"wrong":"十八个点五","right_word":"18.5","org":"全部","update_time":"2026-09-20T18:27:10"}]}
```

- 四张表：`typo` / `term` / `ambiguous` / `wordlist`；查询参数 `q`、`limit`（默认 50）、`offset`。
- 删除是软删（`deleted_flag=1`）。

### 5.5 `GET /tree` 节选

```json

 {"id":"p6","no":6,"name":"干活（主循环）","desc":"…","materials":[ … ]},
 {"id":"p7","no":7,"name":"回答","desc":"…","materials":[
   {"key":"mat.answer","name":"⑥ 回答规则","editable":true,"always":false,
    "when":"第 7 步写回答时","textKey":"","chars":0,"body":""}]}

```

### 5.6 `GET /overview`

```json
{"ok":true,
 "nodes":[ … 同 /tree … ],
 "materials":[{"slot":"fetch","name":"查数口径","sections":0,"chars":0}, "…"],
 "texts":[ … 同 /texts … ],
 "complete":[],
 "inject":{"loop_block":0,"final_block":0},
 "actor":{"username":"admin","is_admin":true}}
```

- `inject.loop_block` = 第 6 步注入的材料字数（`fetch` + `judge`）。
- `inject.final_block` = 第 7 步注入的材料字数（只有 `answer`）。

### 5.7 `/api/ask` 的 `scope` 入参（保留但不注入）

```json
{"question":"本月情况","scope":"洪山供电所","session_id":"..."}
```

- 仍接收，**只记录在返回体 `scope` 字段里**（值为空骨架：时间各项为空、`place` 为空串）。
- 时间/地点补全已删除：不再把「本月」换算成月份，也不补默认年份和全市。要补就写补全表。

## 六、典型调用

**① 一把拿全（对接首选）**


**⑥ 导出 / 导入（v4）**

```bash
# 全部导出（材料 + 文本键 + 补全表，一个 md 文件）
curl -s http://<host>/api/v1/prompts/export -H "Authorization: Bearer $TOKEN" -o 提示词.md

# 只导一份材料
curl -s 'http://<host>/api/v1/prompts/export?slot=fetch' -H "Authorization: Bearer $TOKEN"

# 导回（只覆盖文件里出现的块，没出现的块一行不动）
curl -s -X POST http://<host>/api/v1/prompts/import \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d "$(jq -Rs '{text: .}' 提示词.md)"
```

返回：

```json
{"ok":true,"materials":{"fetch":3,"answer":1},"texts":["identity","modes","confirm"],
 "complete":3,"skipped":[]}
```

导出格式（导入认同一套）：

```markdown
# 查数口径
## 一、表说明：每张表是什么 （必带）
正文…

# 身份（identity）
正文…

# 补全表
| 类型 | 匹配 | 补成 | 优先级 |
|---|---|---|---|
| 归一 | 情况 | 预算分配总额，预算执行率 | 10 |
```

- 材料块标题用 slot 中文名（`查数口径` / `判定标准` / `作答规则` / `自检清单`），前面带「⑤」这类序号也认。
- 文本键块标题是 `名称（key）`，整个块覆盖这个 key。
- 补全表用四列表格；单元格里的换行写成 `\n`、竖线写成 `\|`，导回时还原。
- 正文里以 `#` 开头的行导出时会转义成 `\#`，导回还原 —— 不然会被当成新的块。
- 同名节/条目**原地更新**（id 不变），反复导入不会把表撑大；空块跳过不写。

## 九、给老对接方的迁移清单
