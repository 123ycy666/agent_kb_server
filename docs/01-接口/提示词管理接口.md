# 提示词管理接口（v2，2026-11-03）

> 给内网对接用。**页面和接口同一个端口**（容器 8200 / 对外 80），不另开端口。
> 页面：`/prompts`；接口前缀：`/api/v1/prompts`。
> 本版对应代码：`bf51cad`（线上 `47.121.183.81` 已部署）。

## 0. 这一版改了什么（先看这段）

**问答流程结构改了：12 个节点 → 8 个节点。** 节点定义在 `prompt_tree.NODES`，接口返回的树随之变化。

| 类别 | 变化 |
|---|---|
| 新增接口 | 无（`/complete` 是恢复，不是新建） |
| 恢复接口 | `GET /api/v1/prompts/complete`、`PUT /api/v1/prompts/complete`（补全表回来，第 4 步要用） |
| 变更多处 | `GET /tree`、`GET /overview`：节点 8 个，材料键随结构变（见第三节） |
| 变更 | `GET /texts`：可编辑文本键从 4 个变 **13 个**（新增 `intent`、`confirm`、红线/优先级纳入、时间地点规则六个键；**删除 `answer_format`**） |
| 变更 | 所有接口的响应里，`datetime` 字段改成 ISO 字符串（`2026-11-03T16:20:10`）。之前带 `update_time` 的接口会 500，已修 |
| 删除的节点 | 原 9「要不要判（判定标准）」、11「自检」、12「交付」不再出现在树里；材料 `mat.judge` / `mat.check` 仍在库里、仍可用接口读写，只是树里不挂 |
| 删除的材料 | `base.format`（汇报口吻）在树里没了，`answer_format` 文本键删了 —— 现在回答规则走 `answer` 这份材料 |
| 删除的能力 | 红线 / 优先级 / 判定标准 / 自检清单 / 汇报口吻 **不再由代码写死**，全部是页面可填的空位 |

一句话给对接方：**树上少 4 个节点、多两个可编辑文本键（`intent`/`confirm`）、补全表接口回来了、时间戳变字符串。**

## 一、单端口与转发

```nginx
location / {
    proxy_pass http://127.0.0.1:8200;      # /prompts 与 /api/v1/prompts 都走这里
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
}
```

- 前端是 SPA，`/prompts` 由后端回 `index.html`（catch-all 已做），不需要 `try_files`。
- 接口同域同端口，浏览器和内网系统都不用拼端口。

## 三、流程结构（八步）

`GET /tree` 与 `GET /overview` 返回的就是这张表。`editable=true` 的材料点了能改，`false` 的只能看。

| no | 节点 | 说明 | 挂的材料（key ｜ 可编辑 ｜ 存在哪 ｜ 什么时候用） |
|---|---|---|---|
| 1 | 接手这句话 | 用户原话 + 最近几轮问答 | `base.identity` 身份 ｜ ✓ ｜ prompt_text:identity ｜ 每条消息<br>`base.redlines` 红线 ｜ ✓ ｜ prompt_text:redlines ｜ 填了才注入<br>`base.priority` 优先级 ｜ ✓ ｜ prompt_text:priority ｜ 填了才注入 |
| 2 | 要不要走预处理 | 走 = 纠错 + 补全 + 补时间地点；不走直接去干活 | `base.intent` ① 要不要走预处理 ｜ ✓ ｜ prompt_text:intent ｜ 每次调用一次模型 |
| 3 | 纠错 | 错别字 / 单位 / 站名改成库里的标准名 | `nc.typo` ② 纠错词典 ｜ ✓（走词表接口）｜ 表 `t_nc_typo` 等 ｜ 预处理：代码读 |
| 4 | 补问法 + 查补全表 | 补默认问法；拿原问题和补后问题去表里找命中（**只查不改**） | `mat.complete` ④ 补全表 ｜ ✓ ｜ 表 `complete_rule` ｜ 预处理：代码读 |
| 5 | 算时间地点 | 上个月 → 2026年10月；没说就默认上一个月 / 全市 | `time.scope` ⑤ 时间地点规则 ｜ ✓ ｜ prompt_text:time_*（六个键）｜ 预处理：代码算 |
| 6 | 问题确定 | 揉成四行定稿：要什么 / 时间 / 范围 / 其它要求 | `base.confirm` ⑥ 问题确定 ｜ ✓ ｜ prompt_text:confirm ｜ 每次调用一次模型 |
| 7 | 干活（主循环） | 拿定稿自己决定查字段 / 查知识库 / 查数 / 写文档；信息不够就反问 | `mat.fetch` ⑦ 查数口径 ｜ ✓ ｜ 表 `prompt_material(slot=fetch)` ｜ 循环里<br>`semantic.tables` 数据表清单 ｜ ✗ ｜ 业务库字典 ｜ 循环里<br>`semantic.columns` 字段说明 ｜ ✗ ｜ `describe_table` 按需取<br>`semantic.codes` 字典表 ｜ ✗ ｜ 业务库码表 |
| 8 | 回答 | 拿查回来的信息，按回答规则写成回答 | `mat.answer` ⑧ 回答规则 ｜ ✓ ｜ 表 `prompt_material(slot=answer)` ｜ 写回答时 |

材料节点返回的字段：

```json
{"key":"base.intent","name":"① 要不要走预处理","editable":true,"always":false,
 "when":"第 1 步：每次调用一次模型判断","textKey":"intent","chars":0,"body":""}
```

- `textKey` 非空 → 该材料正文存在 `prompt_text`，用 `PUT /texts/{key}` 保存。
- `textKey` 为空且 `editable=true` → 存在表里（`prompt_material` 用 `/material/{slot}`，补全表用 `/complete`，纠错词典用 `/lexicon/*`）。
- `editable=false` → 代码/业务库生成，只读展示。

### 3.1 页面上现在有什么（`/prompts`）

页面渲染完全由 `GET /tree` 驱动，前端不写死节点。现在的样子：

- **左侧**：八个节点卡片，每张卡片右侧是该节点挂的材料按钮（显示字数 + 注入时机）。`editable=true` 的按钮是蓝框，点了进编辑抽屉；`editable=false` 显示锁图标，点开只能看。
- **顶部按钮**：刷新 / 纠错词典 / 补全表 / 数据表。
- **抽屉（四种）**：
  1. **文本键抽屉**（材料带 `textKey`）：身份、红线、优先级、① 要不要走预处理、⑥ 问题确定 —— 单框纯文本，「保存」「恢复默认」。
  2. **材料抽屉**（`prompt_material`）：⑦ 查数口径、⑧ 回答规则 —— 按小节编辑，可加节、删节、上传 md 按标题切。
  3. **补全表抽屉**（`complete_rule`）：整表编辑（类型 / 匹配 / 补成什么 / 优先级），加行、删行、「保存」整表覆盖。
  4. **时间地点规则抽屉**：六个 `time_*` 键并排编辑，「保存全部」，每项可单独「恢复默认」。
  5. **纠错词典抽屉**：四张表页签（错别字纠正 / 术语与别名 / 歧义确认 / 标准词表），搜索、新增一条、行内改、软删。

## 五、关键接口的请求 / 响应

### 5.1 `GET /texts`（13 个键）

```json
{"ok":true,"items":[
 {"key":"identity","name":"身份","chars":311,"overridden":false,"body":"…","default":"…"},
 {"key":"redlines","name":"红线（S0，纯文本；不填就不注入）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"priority","name":"谁说了算（S1，纯文本；不填就不注入）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"intent","name":"① 要不要走预处理（空 = 全部走：纠错+补全+补时间地点）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"confirm","name":"⑥ 问题确定（空 = 不归整，原样往下传）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"modes","name":"模式做法（JSON）","chars":0,"overridden":false,"body":"…","default":"…"},
 {"key":"keywords","name":"业务词表 / 题型词表（JSON）","chars":0,"overridden":false,"body":"","default":""},
 {"key":"time_month_rel","name":"时间：相对月份词（JSON：[[\"上个月\",-1],…]）","chars":0,"overridden":false,"body":"[…]","default":"[…]"},
 {"key":"time_year_rel","name":"时间：本年表达（JSON）","chars":0,"overridden":false,"body":"[…]","default":"[…]"},
 {"key":"time_year_off","name":"时间：年份词偏移（JSON 对象）","chars":0,"overridden":false,"body":"{…}","default":"{…}"},
 {"key":"time_whole_city","name":"地点：明说全市的说法（JSON）","chars":0,"overridden":false,"body":"[…]","default":"[…]"},
 {"key":"time_strip_head","name":"地点：单位名要去掉的前缀（JSON）","chars":0,"overridden":false,"body":"[…]","default":"[…]"},
 {"key":"time_strip_tail","name":"地点：单位名要去掉的后缀（JSON）","chars":0,"overridden":false,"body":"[…]","default":"[…]"}
]}
```

- `body` = 当前生效值（没覆盖就是默认值），`default` = 代码里的默认值。
- `overridden=true` 表示页面存过覆盖值，`DELETE /texts/{key}` 可恢复默认。
- **JSON 键**（`modes`/`keywords`/`time_*`）保存时会被校验：`modes`、`time_year_off` 要对象，其余要数组；`time_month_rel` 要 `[["说法", 偏移], …]`。

### 5.2 `PUT /texts/{key}`

```bash
curl -s -X PUT http://<host>/api/v1/prompts/texts/intent \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"body":"你是分流器。要问业务的事（哪怕有错别字）回「走」；只是打招呼、闲聊，或要求已经说清楚，回「不走」。只回一个词。"}'
```

响应：`{"ok":true,"key":"intent","version_no":2}`；JSON 写坏返回 400 + `{"error":"JSON 格式不对：…"}`。

### 5.3 `GET /complete` / `PUT /complete`

```json
{"ok":true,
 "rows":[{"id":1,"kind":"norm","match_text":"情况怎么样","fill_text":"从六项指标 + 预算执行分析","priority":10,"enabled":true}],
 "preview":"【补全表】（代码读，不进提示词）\n类型 ｜ 匹配 ｜ 补成什么\n…"}
```

```bash
curl -s -X PUT http://<host>/api/v1/prompts/complete \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"rows":[{"kind":"norm","match_text":"情况怎么样","fill_text":"从六项指标 + 预算执行分析","priority":10}]}'
```

- 整表覆盖：先删后插，**同一事务**，失败回滚（不会出现"删了没插回去"）。
- `kind`：`norm`（归一）/ `fill`（补缺）；`match_text`、`fill_text` 为空的条目会被丢弃。
- 命中只作参考：第 4 步查出命中条目交给第 6 步，**不替换用户问题**。

### 5.4 `GET /lexicon` 与 `/lexicon/{key}`

```json
{"ok":true,"tables":[{"key":"typo","name":"错别字纠正","note":"…","rows":105,
 "cols":[{"key":"wrong","label":"错误写法"},{"key":"right_word","label":"正确写法"}]}]}
```

```json
{"ok":true,"key":"typo","name":"错别字纠正","total":105,"limit":50,"offset":0,
 "cols":[{"key":"wrong","label":"错误写法"}],
 "rows":[{"id":105,"wrong":"十八个点五","right_word":"18.5","org":"全部","update_time":"2026-09-20T18:27:10"}]}
```

- 四张表：`typo`（错别字纠正）/ `term`（术语与别名）/ `ambiguous`（歧义确认）/ `wordlist`（标准词表）。
- 查询参数：`q`（模糊搜索）、`limit`（默认 50）、`offset`。
- 删除是软删（`deleted_flag=1`），列表里不再出现。

### 5.6 `GET /overview`

```json
{"ok":true,
 "nodes":[ … 同 /tree … ],
 "materials":[{"slot":"fetch","name":"查数口径","sections":0,"chars":0}, "…"],
 "texts":[ … 同 /texts … ],
```

## 七、生效时间

| 改的是 | 生效时间 |
|---|---|
| `prompt_material`（材料） | **立即**（写接口清缓存） |
| `complete_rule`（补全表） | **立即** |
| `prompt_text`（身份 / 红线 / 优先级 / 意图 / 问题确定 / 模式做法 / 时间地点规则） | **最迟 60 秒**（进程内缓存） |
| `t_nc_*`（纠错词典） | **最迟 60 秒**（纠错引擎会自己发现词典变了） |
| 数据表中文名/说明覆盖 | 立即 |

不需要重启服务。

## 八、状态码

| 码 | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数不对（JSON 写坏、`sections` 不是数组、markdown 切不出小节、词表必填项缺） |
| 401 | 没登录 / token 过期 |
| 404 | `slot` 写错（只接受 `fetch`/`judge`/`answer`/`check`）或词表 key 不在四张表里 |
| 500 | 写库失败（响应 `{"error":"…"}` 里有原因；`_jr` 已统一处理 datetime，不会再因为 `update_time` 500） |

## 九、给老对接方的迁移清单

1. 按树渲染的地方：节点从 12 个变 8 个，`no` 1~8，不要按旧的 `p9/p10/p11/p12` 找节点。
2. 读 `texts` 的地方：`answer_format` 已删，改读 `mat.answer` 材料；新增 `intent`、`confirm`、`redlines`、`priority`、六个 `time_*`。
3. 依赖 `overview.complete` 的地方：字段回来了，结构不变（`id/kind/match_text/fill_text/priority`）。
4. 解析时间字段的地方：现在是 ISO 字符串（`2026-11-03T16:20:10`），不是 `datetime` 对象，也不再是 `2026-11-03 16:20:10` 的空格格式。
5. `preview` 的 `?mode=` 现在只有 `general` 有正文（业务三段已清空）；传 `data` 只会返回空的 L2。
