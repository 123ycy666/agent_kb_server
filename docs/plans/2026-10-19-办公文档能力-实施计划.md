# 实施计划：办公文档能力（读 → 审 → 写）

> 依据：`docs/superpowers/specs/2026-10-19-办公文档与文书能力-design.md`（场景与架构）
> 接口：`docs/办公文档能力-接口设计.md`（已定稿 v1）

## 目标

让内网用户能**把文件丢进来，直接问、直接要结果、直接拿回 word/excel**：
① 长文速读（20 页文件 → 一页纸要点 + 待办清单 + 出处）
② 公文纠错 + 格式合规
③ 表格审查
④ 按模板生成报告 / 汇报提纲

## 验收判据（一眼能判，逐条打勾）

| # | 判据 | 怎么验 |
|---|---|---|
| V1 | 上传一份 20 页 docx，返回 `chars>15000`、`blocks>100`、`preview` 非空 | `curl POST /api/files` |
| V2 | 同一问题带 `file_ids` 问，回答里的时限/金额**能在原文按 `section+para_no` 找到** | 抽 3 条人工核对 |
| V3 | 提交 `digest` 任务，轮询到 `done`，`outputs` 里有 docx 且能下载打开 | 下载后用 WPS/Word 打开 |
| V4 | 文件里没有的东西，回答写"文件中未提及"，不编 | 故意问一个文件里没有的数字 |
| V5 | 不支持格式 / 扫描件，报 `UNSUPPORTED_FORMAT` / `PARSE_FAILED`，不 500 | 传 .exe 与扫描 PDF |
| V6 | 别人的 file_id 用不了（`FILE_NOT_FOUND`） | 换账号调 |
| V7 | 现有 `/api/ask` 纯 JSON 调用行为不变 | 跑现有回归 `server/tests/` |

## 边界（本轮不做）

- 扫描件 OCR、`.doc/.wps` 自写解析（走 WPS COM 兜底）、修订痕迹、PPT 自动美化、pandas。

## 根因与改动记录（为什么改、改的是根因）

| 现象 | 复现 | 根因 | 改法 |
|---|---|---|---|
| 问「上报时限」，明明文件写了「10月31日前报送」，召回却漏掉 | `test_doc_context` 第 1 项 FAIL（首版） | 字面 bigram 匹配：问句「上报」≠ 原文「报送」（公文常用同义词） | 不是加特例，而是把 10 组业务同义词做成**数据表** `_SYNONYMS`；同义词是领域数据，不是分支逻辑 |
| 问句太泛（「这文件说什么」）时只返回开头三段，时限/责任落在背后 | 同上（兜底分支永远取前 3 块） | 兜底按"文档顺序"取，等于只给开头 | 改成**每节首段各取一份**，覆盖全文结构 |
| `test_doc_jobs` 加 `proofread` 后 1 项 FAIL | 加入纠错任务类型后 | 测试把 `proofread` 当成"未支持类型"的样例 | 换个真正不存在的 `no_such_task`；产品行为不变 |
| 表格审查把「执行率 50%」这种文本百分比报成"文本数字" | `test_table` 首轮输出里出现「执行率」5 处 | `_NUM_TEXT` 把带 `%` 的字符串也当数字文本 | 排除以 `%` 结尾的值（表里存文本百分比很常见，报了是噪声）；同时把 mock 报的单元格从"列首行"改成**真正出问题的行** |
| `doc_files.save` 收到非字节内容时抛 `sha256(TypeError)` | 测试里 `write_bytes()` 的返回值被当内容传入 | 没做入参类型校验 | `save()` 加 `BAD_CONTENT` 人话报错（这是产品侧的健壮性，不只是改测试） |
