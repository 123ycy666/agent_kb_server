# 预警四类 + 任务流转 · 接口文档（v1，2026-10-19）

> **这份文档是后端交付契约**：字段、状态、错误码、调用顺序。
> 前端只做三件事：**渲染**、**调这些接口**、**轮询未读**。
> 设计依据：`docs/superpowers/specs/2026-10-19-预警四类归并与任务流转-design.md`
> 数据表：`server/app/models/dispatch.py` / `db/dispatch_tables.sql`（10 张）

---

## 0 交付边界（先说清楚，避免返工）

| 谁做 | 做什么 |
|---|---|
| **后端（本次已交付）** | 四类预警扫描与查询、预警卡片、**点预警进对话**（建会话 + 写卡片 + 首段话）、AI 拟办/建议/报告/润色、任务下发/接单/方案/回执/催办/升级/自动核销、站内通知、统计与健康检查 |
| **前端（要接）** | 预警列表页、点击跳转到对话页并渲染卡片、下发确认页、我的任务/任务详情、通知中心。所有数据都来自下面这些接口 |
| **外部定时任务** | 每天调 `POST /api/alerts/scan`；每 10 分钟调 `POST /api/dispatch/tick`（或由服务内部循环代跑） |

**"点击预警 → 自动在对话框发一条 → 出详情"不需要前端自己想内容**：
前端点一下调 `POST /api/alerts/{id}/chat`，后端把**卡片消息**和**首段 AI 话**都写进会话并返回，前端把返回的 `messages` 渲染出来即可；重复点会复用同一会话。

## 1 鉴权

| 通道 | 用法 | 适用 |
|---|---|---|
| 用户 JWT | `Authorization: Bearer <token>` | 全部 `/api/alerts`、`/api/tasks`、`/api/dispatch/{stats,notices,health}` |
| 内部令牌 | `X-Internal-Token: <INTERNAL_SERVICE_TOKEN>` | `POST /api/alerts/scan`、`POST /api/dispatch/tick` |

- **不接受调用方传 `role` / `scope`**：一律用登录账号现查（`alert_scope`）；查不到就 `status=unknown` 且返回空，**绝不默认全市**。
- 用户能看到的预警 = `assignee_role == 我的角色` **且** 在账号范围内（所级只看本所、县级看本县、市级看全市）。

```json
  "seen_times": 1,
  "task_id": null,
  "closed_at": null,
  "close_reason": null

```

**字段口径**

| 字段 | 取值 | 说明 |
|---|---|---|
| `type` / `category` | `budget` `project` `review` `metric` | 四类，**只有这四个值**（DB CHECK 兜底） |
| `subtype` | 13 个子判据（见 §3） | 前端按需展示，不必硬编码 |
| `scope_key` | 所=`t_power_company.id`；县=`t_department.id`；市=`city` | **不是**部门 id（两水：所 42 / 部门 56） |
| `status` | `open` `dispatched` `closed` `ignored` `resolved` | 数据恢复正常 → `resolved`（close_reason=resolved_by_data） |
| `data` | JSONB | 数字全部在这里；卡片/AI 都只引用它 |
| `verify_hint` | 核销规则 | 下发时预填，发起人可改（§7） |
| `days_open` | 首次命中到今天 | 没处理会一直涨，但**不重复发通知** |

## 3 四类与 13 个子判据

| category | subtype | 名称 | 默认级别 | 频率 | 默认核销 |
|---|---|---|---|---|---|
| budget | `budget.underspend` | 预算花不完 | high | 日 | 自动 |
| budget | `budget.overrun` | 预算超支风险 | high | 日 | 自动 |
| project | `project.approval_stay` | 审批停留超期 | high/mid | 日 | 自动 |
| project | `project.approved_not_started` | 已批未开工 | mid | 日 | 自动 |
| project | `project.exec_stalled` | 施工停滞 | high | 日 | 自动 |
| project | `project.acceptance_overdue` | 完工未上报 | mid | 日 | 自动（**默认关**） |
| project | `project.amount_structure` | 申报金额存疑 | low | 周 | 自动（**默认关**） |
| review | `review.low_roi` | 投入产出偏低 | mid | 年 | 人工 |
| review | `review.no_effect` | 投入未见效 | mid | 年 | 人工（**默认关**） |
| review | `review.not_reviewed` | 完工未复盘 | low | 月 | 人工 |
| metric | `metric.deteriorated` | 指标同比恶化 | mid | 月 | 自动 |
| metric | `metric.threshold` | 指标越阈值 | mid | 月 | 自动 |
| metric | `metric.stale` | 指标数据过期 | low | 月 | 自动（**默认关**） |

**默认关的原因**写在 `server/app/dispatch_rules.py` 的 `note` 里（缺字段/常驻噪音），不是"没做完"。

## 5 接口细节

### 5.1 `POST /api/alerts/scan`

请求头：`X-Internal-Token`

```json
{"accounts": ["sngdssz", "xgscwb"], "cadence": "daily", "today": "2026-10-19", "trigger": "cron"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `accounts` | 否 | 不传=全部有效业务账号（有角色的） |
| `cadence` | 否 | `daily`（默认）/`weekly`/`monthly`/`yearly`/`all` |
| `today` | 否 | 业务日期，便于回放 |
| `trigger` | 否 | 记录用：`cron`/`manual`/`api` |

响应：

```json
{"run_id": 12, "run_key": "cron-daily-2026-10-19-ab12cd34",
 "cadence": "daily", "today": "2026-10-19",
 "found": 63, "new": 12, "resolved": 5,
 "accounts": 121, "groups": 61, "errors": []}
```

**幂等**：同一 `dedupe_key` 只更新 `last_seen`，不新增；本轮没命中的 `open` 项自动 `resolved`。

### 5.2 `GET /api/alerts`

Query：`category` `subtype` `status` `level` `today` `limit`(1~200) `offset`

响应：

```json
{"account": "sngdssz", "scope": "两水供电所", "scope_type": "station",
 "role_code": "sz", "today": "2026-10-19", "status": "ok",
 "total": 2, "items": [ {...alert...} ]}
```

`status`：`ok` / `unknown`（账号解析失败，`items=[]` 且带 `error`）。

### 5.3 `POST /api/alerts/{id}/chat` —— 前端就靠这个"点预警进对话"

请求（可选 body）：

```json
{"today": "2026-10-19"}
```

响应：

```json
{
  "session_id": "alert-1001-8f3a2b1c",
  "chat_store": "ok",
  "alert": { ...完整 alert... },
  "advice": [ {"action": "...", "evidence": "...", "expected": "..."}, "..." ],
  "ai_used": false,
  "messages": [
    {"seq_no": 1, "sender_type": 3, "msg_type": 2,
     "content": "**两水供电所：...**",
     "meta": {"kind": "alert_card", "alert_id": 1001, "card": {...}}},
    {"seq_no": 2, "sender_type": 2, "msg_type": 1,
     "content": "**两水供电所：...**\n\n**关键数字**：...\n\n**我建议这么做**：...",
     "meta": {"kind": "ai_brief", "ai_used": false}}
  ]
}
```

**前端接法**

1. 列表点击 → `POST /api/alerts/{id}/chat`
2. 用现有 AgentChat 组件把 `messages` 追加到会话：`meta.kind == "alert_card"` 的渲染成卡片，其余按 Markdown
3. 把 `messages` 的 `seq_no` 当作续聊起点，之后走现有 `/api/ask`（带 `session_id`）
4. 建议 chips：`advice` 三条；点「帮我发起」→ §5.5
5. 重复点开：后端返回同一 `session_id`，`messages` 不会重复增加

`chat_store`：`ok` / `unavailable`（PG 里没有 `t_chat_*` 表时降级，仍返回卡片与首段话）。

```json
 "recommend": {
   "role": "sz", "dept_id": 56, "level": "station",
   "reason": "本所预算/项目由所长承办",
   "candidates": [{"employee_id": 2045075..., "login_name": "sngdssz",
                   "name": "两水供电所所长", "dept_id": 56}],
   "fallback": null,
   "tried": [{"dept_id": 56, "dept_name": "两水供电所", "n": 1}]
 },
 "options": [{"option": 1, "action": "...", "evidence": "...", "expected": "..."}],

              "verifier_type": "auto", "verify_rule": {...}}
}
```

`dispatch` 请求（确认页提交）：

```json
{
  "assignees": [
    {"employee_id": 2045075192169291001, "part": "owner"},
    {"employee_id": 2044600606679294107, "part": "cc"}
  ],
  "title": "两水供电所 2026 年预算执行整改",
  "requirement": "11-19 前把执行率提到 80%；3 天内提交实施方案",
  "reply_due_at": "2026-10-22T18:00:00+08:00",
  "due_at": "2026-11-19T23:59:59+08:00",
  "require_plan": 1,
  "verifier_type": "auto",
  "verify_rule": {"kind": "budget_rate", "station_ids": [42], "year": 2026,
                  "op": ">=", "target": 0.8, "close_when_met": true},
  "task_type": "alert",
  "idempotency_key": "9b1c0f0e-..."
}
```

- `part`：`owner`（主责，可多人，至少 1 个）/ `collaborator`（协办）/ `cc`（抄送）
- 不传 `reply_due_at`：按级别默认（high 24h / mid 72h / low 168h）
- 不传 `due_at`：按子判据默认（30 天）
- 不传 `verify_rule`：用预警的 `verify_hint`
- 同一 `idempotency_key` 重复提交 → 返回同一个任务（不会重复下发/重复通知）

响应：任务详情（同 §6.2）。

### 5.6 `GET /api/tasks`

Query：`role`（`mine` 默认 / `created` / `cc` / `all` 仅 admin）、`status`、`category`、`limit`、`offset`

```json
{"role": "mine", "total": 3, "items": [ {...task...} ]}
```

### 5.7 任务动作（12~30）

| 接口 | 谁 | 前置状态 | 结果 | 关键 body |
|---|---|---|---|---|
| accept | 主责 | open | doing | — |
| decline | 主责 | open | 留 open + 升级 | `{"reason": "..."}` |
| plan | 主责 | open/doing | doing（可多版本） | `{"content": "...", "items": []}` |
| plan/accept | 发起人/上级/admin | doing | 方案生效 | — |
| plan/reject | 发起人/上级/admin | doing | 退回 | — |
| reply | 主责 | open/doing | verify | `{"content": "...", "attachments": []}` |
| close | 发起人/上级/admin | verify | closed（human_confirmed） | `{"conclusion": "...", "reason": "human_confirmed"}` |
| reopen | 发起人/admin | closed（7 天内） | doing | — |
| transfer | 主责/发起人/上级 | 非终态 | 加新主责，原主责降协办 | `{"to_employee_id": 123}` |
| subtask | 主责/发起人/上级 | 非终态 | 生成子任务 | 同下发 body |
| urge | 发起人/上级/admin | 非终态 | 通知主责 | `{"note": "..."}` |
| supervise | 发起人/上级/admin | 非终态 | 督办通知（不改状态） | `{"note": "..."}` |
| escalate | 发起人/上级/admin | 非终态 | 升级一级 | `{"note": "..."}` |
| cancel | 发起人/admin | draft/open/doing/verify | cancelled | `{"note": "..."}` |
| archive | 发起人/admin | closed | archived_flag=1 | — |

**协办/抄送**可以看详情、提意见，但**不能**接单/回执/提交方案（会 403）。

### 5.8 AI 4 个接口

| 接口 | 返回 | 说明 |
|---|---|---|
| `/ai/advice` | `{"markdown", "steps": [...], "ai_used"}` | 执行侧"怎么干" |
| `/ai/plan` | `{"draft", "markdown", "ai_used"}` | 实施方案草稿，执行人改后 `POST /plan` |
| `/ai/report` | `{"markdown", "ai_used"}` | 上报报告骨架；docx 导出后续接 |
| `/ai/polish` | `{"content", "ai_used"}` | 只改措辞；**出现原文没有的数字会整段丢弃** |

`ai_used=false` 表示走了规则模板（模型不可用/被关闭），**不影响返回可用**。

### 5.9 `POST /api/dispatch/tick`

请求头：`X-Internal-Token`。幂等。

```json
{"checked": 3, "urged": 1, "escalated": 1, "closed": 0, "transferred": 0,
 "at": "2026-10-19T08:00:00+00:00"}
```

做的事：① 催办（回执前 4h / 超期每 24h 一次）② 升级（宽限后一级，**每天最多一次，level 上限 2**）
③ 自动核销（规则实测达标 → closed/auto_verified）④ 停用账号转派 ⑤ 通知去重。

### 5.10 通知

```json
{"total": 5, "unread": 2,
 "items": [{"id": 9, "task_id": 1, "notice_type": "assign",
            "title": "【新任务】...", "content": "...",
            "read": 0, "sent_at": "..."}]}
```

`notice_type`：`assign` `urge` `escalate` `supervise` `plan` `reply` `verify` `close` `reopen` `comment`

## 6 状态机

```
 [draft] ──confirm──> [open] ──accept──> [doing] ──submit──> [verify] ──pass──> [closed]
    │                   │ ↺decline          │  ▲                │
    │                   │ 留 open + 升级     └──┼────────────────┘  fail 退回 doing
    └──cancel──> [cancelled]  ←── cancel ──（open/doing/verify，需发起人）
```

| 迁移 | 允许 | 拒绝码 |
|---|---|---|
| draft → open / cancelled | ✅ | — |
| open → doing / cancelled | ✅ | — |
| doing → verify / cancelled | ✅ | — |
| verify → closed / doing / cancelled | ✅ | — |
| closed → doing（reopen，7 天内） | ✅ | 超 7 天 `REOPEN_EXPIRED` |
| 其它（如 open → closed、doing → closed） | ❌ | `INVALID_TRANSITION` 409 |

**两个标志位不是状态**：`escalate_level`（0→1→2）、`overdue_flag`（0/1）。

## 7 核销规则 `verify_rule`

| kind | 参数 | 判定 |
|---|---|---|
| `budget_rate` | `station_ids` `year` `op` `target` | 已审批/分配 与 target 比较 |
| `audit_node` | `station_ids` `node` `op` `target` | 该节点待处理件数 |
| `status_count` | `station_ids` `status` `year` `op` `target` | 某状态工单数（如状态 3 清零） |
| `metric_value` | `scope_type` `scope_key` `metric_code` `period_type` `op` `target` | 最新快照值 |
| `task_tree` | `require_child_closed` | 子任务是否全闭环 |
| `manual` | `evidence` | 只走人工核销 |

- `close_when_met=false`：达标只记录进度，到 `due_at` 才闭环
- **数据取不到** → `passed=null`，任务**不闭环**，转人工（`verify_state=unavailable`）

## 8 错误码

| HTTP | code | 场景 |
|---|---|---|
| 400 | `DISPATCH_OFF`（503） | `DISPATCH_ON=0` 时新接口关闭 |
| 401 | `UNAUTHORIZED` | 内部令牌缺失/错误 |
| 403 | `UNKNOWN_ACCOUNT` | 账号解析失败 |
| 403 | `NOT_PARTICIPANT` | 非参与人 / 角色不对 |
| 404 | `ALERT_NOT_FOUND` / `TASK_NOT_FOUND` / `NOTICE_NOT_FOUND` / `PLAN_NOT_FOUND` | 不存在或无权 |
| 409 | `INVALID_TRANSITION` / `STATE_CONFLICT` / `REOPEN_EXPIRED` | 状态不允许 |
| 422 | `NO_ASSIGNEE` / `NO_OWNER` / `BAD_ASSIGNEE` / `BAD_PART` | 下发参数错 |
| 500 | `SCAN_FAILED` / `TICK_FAILED` / `INTERNAL_ERROR` | 服务端异常 |

错误体统一为：`{"detail": {"code": "...", "message": "...", "detail": ...}}`

## 11 示例：一条预算预警从发现到闭环（curl）

```bash
# 1) 扫描（内部定时任务）
curl -X POST http://127.0.0.1:8200/api/alerts/scan \
  -H "X-Internal-Token: $INTERNAL_SERVICE_TOKEN" -H "Content-Type: application/json" \
  -d '{"cadence":"daily","today":"2026-10-19"}'

# 2) 我的预警
curl "http://127.0.0.1:8200/api/alerts?today=2026-10-19" -H "Authorization: Bearer $JWT"

# 3) 点开（前端点击）
curl -X POST http://127.0.0.1:8200/api/alerts/1001/chat -H "Authorization: Bearer $JWT"

# 4) 确认页
curl -X POST http://127.0.0.1:8200/api/alerts/1001/dispatch/preview -H "Authorization: Bearer $JWT"

# 5) 下发
curl -X POST http://127.0.0.1:8200/api/alerts/1001/dispatch \
  -H "Authorization: Bearer $JWT" -H "Content-Type: application/json" \
  -d '{"assignees":[{"employee_id":2045075192169291001,"part":"owner"}],
       "requirement":"11-19 前执行率 80%","verify_rule":{"kind":"budget_rate","station_ids":[42],"year":2026,"op":">=","target":0.8},
       "idempotency_key":"demo-1"}'

# 6) 承办人接单 / 回执
curl -X POST http://127.0.0.1:8200/api/tasks/2001/accept -H "Authorization: Bearer $JWT"
curl -X POST http://127.0.0.1:8200/api/tasks/2001/reply -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" -d '{"content":"已完成整改，附回执"}'

# 7) 定时 tick（每 10 分钟）
curl -X POST http://127.0.0.1:8200/api/dispatch/tick -H "X-Internal-Token: $INTERNAL_SERVICE_TOKEN"
```
