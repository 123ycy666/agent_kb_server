# 内网打包清单

**用途**：把本项目交付给内网部署人员时，需要打包哪些文件、哪些不要打。

---

## 一、结论速览

| 档位 | 内容 |
|---|---|
| ✅ **运行必需** | `server/`（排除 `__pycache__`/`*.pyc`/`output/`）、`web/dist/`、`docker/`、`deploy/`、`docker-compose*.yml`、`.env.example`、`启动全部.bat`、`启动知识库后端.bat`、`README.md`、`docs/` |
| ⭕ **建议一并带** | `web/src` + `web/package.json` + `web/vite.config.ts` + `web/tsconfig.json`（日后维护前端用）、`server/requirements.txt`、`server/pyproject.toml`、`server/scripts/`、`server/tests/` |
| ❌ **绝对不要打包** | `web/node_modules/`、`__pycache__/`、`*.pyc`、`.git/`、`.workbuddy/`、`server/app/output/`、`.venv/`、`web/dist-ssr/`、`data/uploads/`（除非要迁移数据）、**真实 `.env`**（含密钥） |

---

## 二、逐项说明

### ✅ 运行必需

| 路径 | 为什么必需 |
|---|---|
| `server/app/` | 后端全部代码。**其中两个子目录是运行时内容，不能少**：<br>· `server/app/secretary/skills/`（技能文档，代码运行时读取）<br>· `server/app/secretary/static/`（问答/语音/技能台三个页面） |
| `web/dist/` | 前端构建产物，由后端托管。**缺了首页白屏** |
| `docker/initdb/01-extensions.sql` | 容器首次启动自动装 pgvector |
| `deploy/nginx/kb.conf` | 需要域名/HTTPS 时用 |
| `docker-compose.yml` / `docker-compose.prod.yml` | PostgreSQL 编排 |
| `.env.example` | 配置模板（**发模板，不发真实 `.env`**） |
| `启动全部.bat` / `启动知识库后端.bat` | Windows 一键启动 |
| `README.md` / `docs/` | 说明书（含接口文档、本部署指南） |

### ⭕ 建议一并带（便于日后在网内维护）

| 路径 | 说明 |
|---|---|
| `web/src/` + `package.json` + `vite.config.ts` + `tsconfig.json` | 前端源码（体积小）。不带也能跑，但以后改界面就得回头找源码 |
| `server/requirements.txt` | **离线装依赖必需**（配合出网机器 `pip download` 出的 `wheels/`） |
| `server/pyproject.toml` | 依赖声明（与 requirements 一致） |
| `server/scripts/` | 运维脚本：重置库、重切片、修孤儿数据、导种子文档 |
| `server/tests/` | 回归/验收脚本（验收时能自证功能正常） |

### ❌ 绝对不要打包

| 路径 | 原因 |
|---|---|
| `web/node_modules/` | 体积巨大（十万级文件），且是源码依赖；运行时用不到（`dist` 已是编译产物） |
| `__pycache__/`、`*.pyc` | 编译缓存，跨机器/跨版本可能不兼容 |
| `.git/` | 版本库历史，体积大。**除非**你希望对方能 `git log` / 回滚 |
| `.workbuddy/` | 本地协作记忆与备份，与部署无关 |
| `server/app/output/` | 运行时产物（知识缺口清单、语音临时音频），已是 `.gitignore` 项 |
| `.venv/` | 虚拟环境，跨机器无效 |
| **真实 `.env`** | **含数据库密码与模型 Key**。只发 `.env.example` |
| `data/uploads/` | 用户上传原件。**新部署不需要**；只有要**迁移现有数据**时才带 |

> `data/seed_docs/`（3 个种子文档）**可选**：想开箱就有演示数据就带上，体积很小。

## 三、打包命令（Windows，robocopy）

```bat
:: 假设源码在 D:\src\合并系统+统一用户表，输出到 D:\dist\kb-delivery
robocopy "D:\src\合并系统+统一用户表" "D:\dist\kb-delivery" /E ^
  /XD node_modules __pycache__ .git .workbuddy .venv dist-ssr .vite output ^
  /XF *.pyc *.pyo *.log .env ^
  /NFL /NDL /NJH /NJS

:: dist-ssr / output 已排除；data/uploads 里的原件按需保留
:: 若是「全新部署」，清掉上传原件（保留空目录结构）：
del /Q "D:\dist\kb-delivery\data\uploads\*" 2>nul
for /d %d in ("D:\dist\kb-delivery\data\uploads\*") do rd /s /q "%d" 2>nul
```

> ⚠️ `/XD` 里的 `output` 会把**任何叫 output 的目录**排除，包括 `server/app/output`（正是我们要排除的）。
> 若你还想同时排除 `.git` 但保留 `dist`，注意别把 `dist` 写进 `/XD` —— `dist` 是**必需**的。

**Linux/macOS 打包（tar，等价效果）**

```bash
tar --exclude='*/node_modules' --exclude='*/__pycache__' --exclude='*.pyc' \
    --exclude='.git' --exclude='.workbuddy' --exclude='.venv' \
    --exclude='server/app/output' --exclude='.env' \
    -czf kb-delivery.tar.gz .
```

## 四、交付包核对表

打完包后，逐项确认（**打勾才发**）：

- [ ] `server/app/main.py` 存在
- [ ] `server/app/secretary/skills/` 里有 **15 个左右 `.md`**（技能文档，少了功能会缺）
- [ ] `server/app/secretary/static/` 里有 `index.html` / `asr.html` / `skills.html`
- [ ] `web/dist/index.html` **和** `web/dist/assets/` 存在
- [ ] `server/requirements.txt` 存在
- [ ] `docker-compose.yml` 与 `docker/initdb/01-extensions.sql` 存在
- [ ] `.env.example` 存在（`.env` **不在**包里）
- [ ] `web/node_modules/` **不在**包里
- [ ] 包内**搜不到** `kb_dev_pwd` 之外的测试密钥；搜不到真实 `.env`
- [ ] （离线装依赖时）`wheels/` 目录已一并放入

**快速自检命令**

```bat
:: 确认不该有的东西确实没打进去
dir /s /b D:\dist\kb-delivery | findstr /I "node_modules .pyc .env"
:: 以上应无输出（.env.example 例外，见下）
dir /s /b D:\dist\kb-delivery | findstr /I "\.env$"
:: 应无输出 = 没有真实 .env
```

## 五、部署方收到后的操作顺序

```text
① 解压到部署目录（路径避免中文，例如 D:\kb）
② copy .env.example .env，按《内网部署指南》第 3 步填写
③ 装 PostgreSQL（docker compose up -d）+ 确认 pgvector
④ 确认 MySQL 只读账号可连
⑤ 离线装 Python 依赖（wheels）
⑥ 启动：双击 启动全部.bat  或  cd server && python -m uvicorn app.main:app --host 0.0.0.0 --port 8200
⑦ 按《内网部署指南》第 9 节「验证清单」逐项确认
⑧ 配常驻运行（NSSM / systemd）
```

**随包必须一起说明的三件事**（否则部署方一定会踩）：

1. **库名必须是 `ad_new`**（与 `.env` 的 `DATABASE_URL` 一致）。
2. **`MODEL_CHANNEL=local`，并配好 `LOCAL_MODELS`**（内网实际部署了哪几个模型就写哪几个）。
3. **改了配置/代码必须重启后端**（启动命令没有 `--reload`）。

## 六、如果要**迁移现有数据**（不只是全新部署）

除了上面的包，还需要：

| 额外内容 | 怎么做 |
|---|---|
| 内容库 | `pg_dump "postgresql://kb:<密码>@127.0.0.1:5433/ad_new" -Fc -f ad_new.dump`，对方 `pg_restore` |
| 上传原件 | 打包 `data/uploads/` 整个目录（历史对话的「下载原文件」依赖它） |
| 纠错词典 / 缺口清单 | 词典在 PG（随 pg_dump 一起走）；缺口清单是 `server/app/output/gaps/gaps.jsonl`，需要就单独拷 |
| 配置 | 真实 `.env` **不要随包发**，走单独的安全通道传给部署方 |
