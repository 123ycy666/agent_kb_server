# 使用说明

> 面向使用者（非开发）。开发与架构说明见 `README.md` 与《设计方案》。

---

## 一、先把三个概念搞清楚

这三条决定了整个系统的行为，理解了就不会踩坑。

### 1. 只有两种角色

| 角色 | 能做什么 |
|---|---|
| **管理员**（admin） | 建知识库、管理用户、看审计；**可管理全部文档**（改 / 删任意文档） |
| **普通用户**（user） | 上传文档、打标签、检索 |

不存在"自定义角色"。上线前如果需要更多角色，得改代码——这是刻意做的取舍。

### 2. 文档只有两种可见性

| 可见性 | 谁能看到、能搜到 |
|---|---|
| **公开**（public） | **所有人**（含管理员、普通用户） |
| **私有**（private） | **只有上传者本人**（管理员能在文档列表看到，但**检索不到**） |

> ⚠️ **默认是私有**。不打开"公开"开关，你的文档别人搜不到。
>
> ⚠️ **管理员检索时也受同样限制**。管理员的"全知"只用于管理事务（排查、处理、删除），
> 不污染日常检索结果。所以：**管理员在文档列表能看到某份私有文档，但用检索是搜不到的**——
> 这是设计如此，不是 bug。

### 3. 标签就是"说明词"，不是结构化字段

给文档挂上 `行政`、`预算` 这类词就行，**不用提前创建**——直接输入，系统自动记住，
下次可以下拉选择。

检索时按标签筛选，多个标签是**"同时包含"**（逐层收窄）。例如勾选 `行政` + `预算`，
只会返回**同时**带这两个标签的文档。

## 二、启动系统

```bash
# 1) 数据库（PostgreSQL + pgvector + Redis）
cd <项目根目录>
docker compose up -d

# 2) 后端
cd server
python -m uvicorn app.main:app --port 8000

# 3) 前端
cd web
npm run dev
```

打开 http://127.0.0.1:5173 ，用 `admin` / `admin123456` 登录。

> 数据库映射到宿主机 **5433** 端口（避免与本机 5432 冲突）、Redis 映射到 **6380**。

## 三、走一遍完整流程（约 5 分钟）

这条路径能让你最快理解系统的价值。

### 第 1 步：建知识库

**知识库** 页 → 新建。只有管理员能建。

### 第 2 步：上传文档

进入知识库 → **上传文档**：

- 拖入文件（支持 pdf / docx / **xlsx / xlsm / xls（含 2003 旧版）** / md / txt / csv）
- **是否公开**：打开 = 所有人可见可搜；不打开 = 只有自己
- **标签**：直接输入，如 `行政`、`预算`（回车确认，可多个）

点"开始上传"，弹窗会逐个显示结果：

- `✓ 文件名：已解析入库，未发现冲突`
- `⚠ 文件名：检出 N 处冲突，与《XXX》矛盾｜已暂停参与检索，请到「冲突管理」处理`

## 三之二、文件存在哪里 / 怎么拿回来

| 内容 | 位置 |
|---|---|
| **原始文件** | `data/uploads/kb_{知识库ID}/{时间戳}_{原文件名}`（可用 `.env` 的 `UPLOAD_DIR` 改） |
| **切片 / 向量 / 关键词索引** | PostgreSQL `document_chunk` 表（不落文件） |

**拿回原件**：文档列表的 ⬇ 按钮，或文档详情里的「下载原文件」。

> ⚠️ 权限与"删除"一致：**上传者本人 或 管理员**。
> 刻意不给"能看到就能下载"—— 可见性代表"可读"，下载是"拿走原件"，风险等级不同。

**详情页还会显示该文档的存储路径**，排障时能直接确认"文件到底存哪了、是否被人为删掉"。

> ⚠️ **原文件可以被外部删掉**（比如有人清理磁盘目录）。
> 这时**检索、问答、冲突检测都不受影响**（它们只读数据库），
> 只有"下载原文件"会提示文件已丢失。遇到这种情况重新上传一次即可。

### 第 3 步：检索

**检索测试** 页 → 选择知识库 → 输入问题，例如：

- 「员工迟到怎么处罚」
- 「打卡时间要求」
- 「信息安全有哪些要求」

结果卡片会标注这条是**向量**、**关键词**还是**双路（hybrid）**召回的——
试试搜纯数字（如 `800`），能看到关键词路的优势。

### 第 4 步：验证可见性隔离（最能说明系统价值）

1. **用户管理** 页 → 新建两个用户 `user_a`、`user_b`（角色选"普通用户"）
2. 用 `user_a` 登录 → 上传一份**不公开**的文档（例如"薪酬表"）
3. 分别登录验证：
   - `user_a`：**搜得到**、点得开
   - `user_b`：**搜不到**、直接访问详情返回 **404**
   - `admin`：**文档列表能看到**，但**检索搜不到**

## 四、日常操作

| 想做什么 | 去哪里 | 谁能做 |
|---|---|---|
| 改文档的公开 / 私有 | 文档列表的 🔒 / 🌐 按钮 | 上传者本人 或 管理员 |
| 改文档标签 | 文档列表的 🏷 按钮 | 上传者本人 或 管理员 |
| 删除文档 | 文档列表的删除按钮 | 上传者本人 或 管理员 |
| **下载原文件** | 文档列表的 ⬇ 按钮 / 详情页 | 上传者本人 或 管理员 |
| 重命名 / 删除标签 | 标签管理 | 管理员 |
| 查看冲突并处理 | 冲突管理 | 该文档上传者 或 管理员 |
| 重建索引 | 知识库列表的 ⟳ | 管理员 |

> **标签重命名**会同步改写所有文档上的标签值；**删除标签**会从所有文档上摘除它
> （不影响文档内容本身）。

## 五、切换真实模型（可选）

默认是 `mock` 档（零依赖，用确定性伪向量跑通链路，**语义效果不是真的**）。

要获得真实检索效果，编辑 `.env`：

```bash
PROVIDER_MODE=online
ALIYUN_API_KEY=sk-xxx      # 阿里云百炼（Embedding + Rerank）
DEEPSEEK_API_KEY=sk-xxx    # DeepSeek（LLM，用于冲突判定）
```

改完**重启后端**。也可以在界的"模型配置"页测试连接（填进去的 Key 只用于测试，不落盘）。

### ⚠️ 切换模型后必须重建索引

不同模型的向量**不在同一个数学空间**，即使维度相同也不能混用。

**切换后必须**：知识库列表 → 点 ⟳ 重建索引。不做这一步的现象是
**"什么都搜不到，但也不报错"**——这是最容易踩的坑。

系统已在切换时提示受影响的切片数，但需要你手动触发重建。

## 六、常见问题

### 搜不到我上传的文档？

按顺序排查：

1. **文档是"私有"吗？** 私有只有你自己能搜到（这是设计）
2. **是不是刚切换过模型？** → 去重建索引
3. **当前账号有权限看这份文档吗？** 文档列表里能看到，检索才可能搜到

### 同事搜不到我传的文档？

检查这份文档是否**打开"公开"开关**。没打开就是只有你自己可见。

### 检索结果为空，但列表里明明有文档？

看检索页的提示文案——系统会告诉你"去掉标签条件后范围内有多少条记录"，
通常就是**标签筛选条件太严**（多标签是"同时包含"）。

### 上传失败，提示某文件解析异常？

看错误信息里的具体原因。若提示与"删除文件"相关，那是清理环节的容错提示，
真正的失败原因在它前面一句。

## 七、自检与验收

不需要数据库即可跑核心逻辑自检：

```bash
cd server
python tests/selfcheck.py     # 49 项
```

完整端到端（需要数据库与后端已启动）：

```bash
cd server
python tests/e2e_check.py     # 64 项，结束后自动清理测试数据
```

### 重置数据库

表结构发生不兼容变更时（或想回到干净环境）：

```bash
cd server
python scripts/reset_db.py    # 会二次确认；--yes 跳过确认
```

> ⚠️ **会清空所有数据**。可选先备份 `data/uploads/`。

### 导入示例文档

```bash
cd server
python scripts/import_seed_docs.py    # 把 data/seed_docs/ 下的文档导入「公司制度」库
```
