# 判据规则（全系统唯一的规则文档）

> **全系统只维护这一份规则文档。** 原来的《分析规则》《问法归一》已并入本文档，不再单独维护；
> 技能文档里的「从哪几方面答」也已抽进第二十节。业务方定了正式口径就改这里，问答与技能同时生效。
>
> **两条路径都读它**：普通问答（不带任何技能 ID）检索本文档，命中就按它判断与组织回答；
> 技能调用把本文档整篇注入。
>
> **结构**：零 怎么用 ｜ 一～十三 判断标准 ｜ 十四～十七 自查 / 输出格式 / 硬规则 / 起始阈值 ｜ 十八～二十 回答规则。

## 零、拿到问题先看这一节

> **先记住这五条口径**（业务确认，2026-09-24）：
> ① **已审批 = 工单状态 3、6、7**（3 审核通过待施工 / 6 施工中 / 7 完成待验收）。**状态 2 不算** —— 它在审批流里（按项目类型分别送县公司运检部或营销部审核，审完才进 3）；不算 0/1/2/4/5/9。
> ② **实际投入 = 已审批工单的预算金额**（`reality_*` 字段没有数据，一律不用）。
> ③ **执行率 = 当年已审批预算合计 ÷ 当年分配预算**；分配预算取该所该年 `deleted_flag=0` 的唯一有效行。
> ④ **同年度、同层级对齐**；占比 >100% 或余额为负 = 口径没对齐，回去重算，**不许把负数写给人看**。
> ⑤ **空集就是答案**：第一次查到 0 行就按 0 行答，**不许摘掉时间/状态/范围条件再查一遍凑数**。

### 0.1 先分流：查数，还是分析

- **查数题**（问某个数、一份清单、排名、占比）：**取到数直接答** —— 不给判断、不加分析、不编标准。
  格式照第十五、十六节；涉及比较与排名的照第十八节。
- **分析题**（要下判断、找原因、看趋势、比大小、判是否异常 / 是否合理）：按 0.2 把思路理清，按 0.3 取舍该写哪几段。

### 0.2 分析题的思路五步（按这个顺序想，不必都写进回答）

1. **定对象与范围**：分析谁（哪张单 / 哪个所 / 哪个指标）、哪个期间。期间按问题的统计范围，不许自己缩到某个月。
2. **取数**：现状值 + 对比值（同期 / 上期）+ 需要的时间序列，一次查全。
3. **找标准**：在本文档里找该场景的阈值；找不到就明确写「无判定标准，仅呈现事实」。
4. **比标准下判断**：给出「是/否 + 差多少 / 超多少」。
5. **给建议**：落到具体的人或岗位；没把握就写「建议核实」，不许编原因。

### 0.3 分析题该写什么（按问题的实际需要取舍，不是填空）

> 分析题**没有固定段数**。先想清楚「领导看完要能做什么决定」，再决定写哪几段。
> 下面几条是**好回答通常具备的**，按题目需要取用 —— **宁可少写一段，也不要为了凑段写废话**。

- **先给判断**：第一句就说清是什么情况（是/不是、超没超、差多少、谁最差）；不能只把数摆出来让领导自己看。
- **依据要落地**：支撑判断的数字写清期间与范围，并且是查到的；推算的要标「推算」。
- **判断要有出处**：用了哪条判据（本文档哪一节、哪个阈值）；本文档没写标准的，就写「无判定标准，仅呈现事实」，不许自己编一个标准。
- **要落到动作**：告诉谁该做什么、多少、什么时候做完；做完能达到什么程度（能推算的给数，标「推算」）。
- **按题型取舍**：只问一个数就只给数（见 20.0 查数题）；问判断就别只报数；问怎么做就把动作写具体；问预测就给区间与参照。

**一条底线**：结论与依据成对出现 —— 只有结论没有数字、或只有数字没有判断，都算没答完。

### 0.4 三个「逾期」不要混（问「逾期」先分清是哪一个）

| 问的是 | 判据 | 看哪节 |
|---|---|---|
| 审批卡了很久、没人处理 | 停留天数分档：≤15 天正常 / 16–90 天偏慢 / **>90 天积压** | 第八节 |
| 一般环节停留太久 | 停留 **>30 天** 越阈 | 第十一节、十七 17.5 |
| 项目超了计划完工日 | 已过计划完工日 **15 天以上**且未完工（有计划完工日才判） | 第七节 |
| **没有计划完工日** | **一律不许判「逾期」**，改按同类在办时长：超 P75 偏慢、超 P90 危险 | 十七 17.2 |

### 0.5 分层与纪律由**提示词**给定，这里只讲「每一层怎么答准」

> 分层（L1 情况 / L2 原因 / L3 对策 / L4 预测）、「问到哪层答哪层」、长度上限 —— 这些每次都用的纪律
> **固定在提示词里注入**，本文档不重复。
> 本节往下讲的是**检索面的事**：每一层要答准，需要哪些数据、怎么关联、哪些坑。

### 0.6 拿到问题先拆（单点 / 多点）

| 类型 | 判据 | 怎么做 |
|---|---|---|
| **单点** | 一个数、一份清单、一个状态 | 直接查、直接答 |
| **多点** | 要拼 2+ 个数据源，或跨期 / 跨表 | **先拆成 2~4 个子问题**，把互不依赖的查询**一次发出**，再汇总成一段话 |

模糊问题（「XX 所今年怎么样」）属多点：拆成「资金与执行 / 审批与进度 / 六项指标 / 合规」几块，取完再合成一段，**不要为了凑满四块去查没被问的东西**。

**L1 里问「成效 / 好不好」时一律要给同期对比。** 先查 `t_power_ai_metric_comparison`（station / district / city 三级都有）；
真查不到才写「同期未查得」，**不许只给一个静态值、也不许不查就说查不到**。

**同期取不到时的降级链（逐档降，且必须写明用的是哪一档，不许直接说"无法判定"就收尾）：**

1. **本期（当年累计）vs 去年同期**（`period_type='yearToDate'`，如 202609 vs 202509）—— 首选；
2. 去年同期那一档没有值（实测：station 级 202609 的 `base_value` 是空的）→ 退到**最近一个有值的年度同比**
   （`period_type='year'`，如 **2025 vs 2024**，实测所有所的年度同比都有值），写明「用 2025 年对比 2024 年」；
3. 年度同比也没有 → 用**该所 vs 全市同期**做横向对照（写明"全市 2.61%，该所 3.65%"）；
4. 三档都没有，才写「同期数据未查得」，并说明缺的是哪一档。
**问到 L3（怎么办）时，必须回答「接下来该怎么办」** —— 那时候只做现状描述、不给动作才算不合格。L1 只问情况时不要给对策。

### 0.7 站在领导视角：多个数据拼起来还原一件事（L2 / L3 的核心）

- **一个问题往往不是一个数据变化能看出来的**：多个数据同时变化才导致了这个结果。别做「查一个数 → 跟另一个数比 → 下结论」这种单点对比。
- **至少两个数据源拼接**（金额 ∥ 时间 ∥ 考评指标 ∥ 项目合规 ∥ 成效），说明它们**共同**指向什么问题，而不是并列罗列。
- 常见拼法：
  · 「钱花得慢」×「审批停留长」×「储备项目少」→ 才能说清卡在哪一环；
  · 「指标没改善」×「往年也投了同类项目」×「缺陷类型重复」→ 才能说清是投得不够还是投错方向；
  · 「投诉 / 意见工单多」×「停电时长长」×「跳闸多」×「线损高」→ 共同指向该所最重的问题。
- 说不出「这几个数之间是什么关系」，就说明还没分析，只是查了数。

### 0.8 建议怎么来（L3：剩余的钱该往哪投）

> 例：分配额一大笔、当年只用掉一小部分、审批环节还卡着一大笔 —— 不能只回「加快审批」，
> 要回答**剩下的钱该往哪投、为什么投那儿**。

1. **算偏重度**：把该范围的六项指标跟**全市（或同类所）**比、再跟**去年同期**比，排出「哪几项明显偏重」。
2. **叠加问题导向指标**：意见工单 / 投诉、停电时长、故障跳闸、线损、低电压 —— 这几项**共同指向**的问题才是真问题。
3. **用往年数据验证方向**：该所过去 2~3 年**在哪类缺陷上花过钱**、投完之后对应指标有没有改善。
   - 一直投同类、指标没动 → 说明**投法或方向有问题**，要换打法；
   - 指标在改善 → 结论是**继续加投**。
4. **落到可执行的优先级**：写成「剩余 X 万元 → 优先投【哪一项】（理由：该指标现在是多少、跟全市比排第几、跟去年同期比是升是降、往年投同类之后有没有改善）→ 其次【哪一项】……」。**括号里的数全部现查，不许套用示例里的数。**
5. **每条建议必须有：对象 + 金额（能给就给）+ 指向的指标 + 依据**。禁止「加强管理」「提高效率」这类没有对象的建议。

### 0.9 禁止的反模式（出现即不合格）

1. **问了 L1 却把对策 / 预测一起铺出来**（没问的先不说）；反过来，问了 L3 却只复述情况不给动作。
2. 只给一个维度就收尾（只报金额、或只报条数、或只说「情况正常」）。
3. 拿查到的数硬往问题上凑，不做拼接、说不出数之间的关系。
3. 分析完不给「下一步该怎么办」。
4. 成效只给本期、不给同期对比。
5. 用「基本符合」「情况良好」这类没有依据的话代替逐条结论。
6. 同一场会话里前后口径不一致（上一轮按所，这一轮变全市还不说明）。

## 三、预算执行

| # | 规则 | 来源 |

| 1 | **已审批 = 工单状态 3、6、7**：3 审核通过待施工、6 施工中、7 施工完成待验收。**2 审核中不算** —— 状态 2 表示这单还在审批流里（按项目类型分别送县公司运检部或营销部审核，审完才进 3）。**不算**：0 草稿、1 提交审核、2 审核中、4 已驳回、5 已取消、9 驳回已修改 | 业务变更（2026-10-14 甲方口径：审核通过以县公司运检部 / 营销部为准，状态 2 不计入已审批） |

| 4 | **先自查年度对齐**（分配与已审批必须同年同层级）。对齐后 **≤100%** 正常；**>100% 或余额为负 → 如实报**「已审批已超出当年分配预算 X 万元」并提示需核实（分配额未更新 / 工单跨年 / 重复申报）；**绝对不许用「含往年结转」解释掉**，也**不许静默当成正常**。**分配预算只取供电所级分配结果**（t_power_company_budget_result，该所 + 年度 + deleted_flag=0 的唯一有效行）；**全市 = 各所分配额之和，不是公司级总预算表**（两张表对不上，只能取所级） | 实测：曾因跨年未对齐算出 300% 以上的占比 |
| 5 | **分配、已审批、执行率一律现查，禁止背数**：分配 = 该范围当年**各所分配额之和**（所级表、deleted_flag=0）；已审批 = 当年状态 3,6,7 的工单**预算金额合计**；执行率 = 已审批 ÷ 分配。**业务库每天在更新，规则文档里不存任何业务数** | 业务确认 |
| 6 | **达标判据**：设 P = 当年已过时间比例（已过天数 ÷ 全年天数）。<br>已审批占比 **< P × 0.6** → 未达标；**P × 0.6 ≤ 占比 < P** → 进度偏慢，按当前速度难达标；**占比 ≥ P** → 正常或超前 | 起始约定 |
| 7 | 说「未达标」必须同时给出：**差多少、剩多少时间、按当前速度能不能完成**。**禁止只写一句「未达到任务标准」就收尾**；**也不要把内部的 0.6 系数换算成「45% 基准线」写给人看**，直接说「已过 X%、执行 Y%、缺口 Z 个百分点」（X / Y / Z 都用现查的数） | 实测：历史上只给结论；暴露内部阈值让人看不懂 |
| 8 | **原因判定**（按未审批项目数量三选一）：未审批数 = 0 且分配 > 0 → **没有项目可审批**（源头储备不足）；未审批数 > 0 → **项目有，卡在审批**（**必须同时给「已批 X 个 / 未批 Y 个」两个数**，只给一个不算） | 实测 |
| 9 | **建议必须从原因推出来、一一对应**：无项目 → 补储备（列出从哪些对象找：高损台区、频繁跳闸线路、低电压台区）；卡审批 → 清积压（卡在哪个节点、多少个、先清金额大的）；批了未完工 → 推施工；正常 → 只写保持节奏 + 风险点 | 实测 |
| 10 | **禁止的废话**：「加强管理」「提高效率」「高度重视」；每条建议必须有**对象和量** | 实测 |
| 11 | 不越权：超出提问人权限的事不提（如无权限不提跨所调剂），确需上级决策写成「需上级明确 X」 | 起始约定 |

| 13 | **执行率 = 该范围当年已审批工单预算合计 ÷ 该范围当年分配预算**（分配预算取该所该年 deleted_flag=0 的**唯一有效行**）。**分母是分配预算，不是已审批金额** | 业务确认 |

| 3 | 申报金额 > 余额 → **先明说超了多少**，再给两条出路：拆分为余额以内的核心内容；申请追加/统筹 | 实测 |
| 4 | 分配金额查不到或为 0 → 写「本年度未查得分配金额」，**不许拿 0 当分母算占比** | 实测 |
| 5 | **「装得下」只对还没批的单判**（状态 0 草稿 / 1 提交审核 / 2 审核中）。状态已经是 **3 / 6 / 7** 的单，**它自己的金额已经在「已审批」里了**，再拿「剩余余额」去比它 = 重复扣一次，必然算出"超余额" —— 这种单直接答「该单已是审核通过待施工 / 施工完成待验收，**无需再批**」，**不要再算装不装得下** | 实测：已批的单又被拿去跟剩余余额比，得出"超余额"却仍写"可以批" |

## 五、审批条件（六条，逐条给「符合 / 不符合 + 依据」）

| # | 判据 | 不符合时怎么说 | 来源 |
|---|---|---|---|
| 1 | **有工单载体** —— 每笔预算都有对应的缺陷工单 | 指出缺哪张载体 | 起始约定 |
| 2 | **预算装得下** —— 该所当年度可用余额 ≥ 申报金额（按第四节的算法） | 说清超多少、给两条出路 | 实测 |
| 3 | **类型匹配** —— 缺陷类型与实际治理对象一致（按第六节的对应表） | 指出建议归哪一类、为什么 | 起始约定 |
| 4 | **明细完整** —— 工程费、物资费都填了，且**工程费 + 物资费 = 申报总额**。核对必须用**精确到元**的原值，**不许拿四舍五入后的万元相加**（四舍五入出来的 0.01 万不是差异）；真差异的判据是**差额超过总额的 1%** | 指出缺哪一项、差多少 | 起始约定 |
| 5 | **工期合理** —— 有计划开完工时间；跨年的要有说明 | 指出缺时间或跨年问题 | 起始约定 |
| 6 | **金额可比** —— 不显著高于同类项目（按第八节） | 给出同类分布（最低/中位/最高）和偏差 | 实测 |

**问「全市 / 所有 / 有哪些单不符合」时**：必须**全量扫**（不许只挑一个所/一张单当样本），
先给总数（N 张），再按**不符合的原因分类计数**（卡在六条里的哪几条、各几张），最后列前几条明细。
**只答一个所就收尾 = 没答。**

**一律不许写「基本符合」。** 六条必须**逐条**给结论和依据。
**每条先给结论，且结论只有三种：符合 / 不符合 / 无法判定。结论必须和后面的依据一致** —— 依据里写了「未超余额」就不能标「不符合」，写了「差异对得上」就不能标「不符合」。拿不准就标「无法判定」，不要先写一个不符合再圆回来。
**「无法判定」要说清是数据没有，不是项目不合格**（例如工期字段全库 99% 是空的）。

| 编号 | 中文 | 编号 | 中文 |

| 1 | 线缆类-导线 | 11 | 线缆类-其他 |
| 2 / 19 | 台区线损 | 12 | 10kV线损 |
| 3 | 设备老化 | 13 | 设备类-其他 |
| 4 | 线缆类-杆塔 | 14 | 设备类-开关类 |
| 5 | 其他 | 16 | 设备类-环网柜 |
| 6 | 线缆类-电缆 | 17 | 电缆分支箱 |
| 7 | 树障 | 18 | 表计故障 |
| 8 | 设备类-柱上变压器 | 20 | 对地距离不足 |
| 9 | 表计故障 | 10 | 对地距离不足 |

**编号 15 在字典里登记的中文就是「缺陷类型」**（等于没填）—— 判「类型匹配」时视为**未明确**，照实写「类型未登记（编号 15）」，不要空着，也不要替它编一个类型名。

**「其他」（编号 5）等于没填类型**，判「类型匹配」时应视为「未明确」。

## 七、进度异常

| # | 异常 | 判据 | 来源 |
|---|---|---|---|
| 1 | **超期** | 已过计划完工日 **15 天**以上仍未完工；分档 **15–30 / 31–90 / 90 天以上**。**注意：该字段绝大多数是空的，这条当前基本用不了** —— 没填就写「无法判定」，改用审批停留天数 | 实测 |
| 2 | **落后** | 已过计划工期一半，状态仍停在「审核通过待施工」之前。落后一档 = 停在审核中；落后两档 = 停在草稿或提交审核 | 起始约定 |
| 3 | **停滞** | 需要「状态最后变更时间」，距今 **30 天**以上。**本库没有这个字段**（只有 create_time 和 update_time）→ **停滞一律写「无法判定」，不许拿 update_time 当替身** | 实测：拿 update_time 算会得出一片假信号（同一次批量更新造成的）；不锁死会让同一个问题两轮结论天差地别 |
| 4 | **钱花了没动** | 金额（= 预算金额 budget_total，实际投入字段没有数据）排本所**前 10 位**，且状态停在「审核通过待施工 / 施工中」**超过 90 天** | 起始约定 |
| 5 | **年内完不成** | 按当前进度估算所需天数 > 当年剩余天数 | 起始约定 |
| 6 | **计划完工日缺失** | **缺就写「无法判定」，不设占比阈值、也不当异常**，同时把缺失数量作为数据质量反馈报出 | 实测：绝大多数没填 |

## 八、审批停留（积压）

| # | 规则 | 来源 |
|---|---|---|
| 1 | **数据来源**：审批节点在表 t_work_order_audit_task（node_name 节点名、create_time 进入节点时间）。**只有 task_status = 0（待处理）才算待办**；1 处理中、2 已完成、3 已驳回都不算。**这个字段是有的，不许说「缺少进入节点时间字段」就跳过计算** | 实测：待处理与已完成数量相当，混了就把「已完成」当积压 |
| 2 | **停留天数 = 系统当天 − 进入当前节点的日期**（上游就算给了「统计截止」，也算到系统当天；「统计截止」只用来写「截至 X 月」这句话）；查不到进入时间用创建时间兜底并注明是估算 | 实测 |
| 2.1 | **上游传来的「变更时间」就是进入本节点的时间，不是今天。** 「今天」一律用系统当前日期；**不许把变更时间当成统计截止日**，否则刚转来的积压件会被算成「停留不足 1 天」 | 实测：曾把早就进节点、已卡很久的件说成「停留不足 1 天」 |
| 2.2 | 没填进入时间、也查不到记录 → 写「无法判定停留天数」，**不要补 0** | 起始约定 |
| 3 | 分档：正常 **≤ 15 天** / 偏慢 **16–90 天** / **积压 > 90 天** | 起始约定（历史遗留会把均值拉到完全不能用，所以分档、不取均值） |
| 4 | 排序：**先按停留最久，其次按金额大** | 起始约定 |
| 5 | 上游传来的那张单据：如果它进到的正是当前角色的节点，**必须单独点出来**；不在也要说一句「这一张当前不在本节点」 | 实测 |

## 九、金额合理性（离群）

| # | 规则 | 来源 |
|---|---|---|
| 1 | 申请金额**高于同类历史最高值**，或**高于同类中位数 2 倍** → 判**离群**，必须给出可比项目清单 | 实测 |
| 2 | 可比范围**一档一档来，不许跳档**：先 **同所 + 同缺陷类型 + 近两年**；样本不足 5 个再退到 **同公司**；再不足才退到 **全市**。**三档都要报数，样本不够才退档，并且要写明为什么退**。这一段固定这么写：「同所同类型近两年 N 个（不足 5 个）→ 同公司 M 个 → 本次按【X 档】比，样本 K 个」。**只写一个「全市」而不说前两档有几个，算没答**。跳档会改变结论（实测同一张单子换档后从「离群」变「合理」），所以用哪一档必须让人看得见 | 实测：换档会换结论（同所样本的最高值与全市样本的差一个量级） |
| 3 | 可比样本**少于 5 个**要明说「样本不足，仅供参考」，**不许下「显著偏高/偏低」这种结论**。可以陈述事实「高于已查得的 N 个同类项目的最高值 X 万元」，但结论必须写成「需人工复核」，**不许既说偏高又说无法判定** | 起始约定 |
| 4 | **必须给分布**（最低 / 中位 / 最高），不许只给一个平均数；并给出本项目排在同类的前百分之多少 | 实测 |
| 5 | 说「偏高」必须写清**拿哪几个同类项目比的** | 实测 |

## 十、数据质量

| # | 项 | 判据 | 来源 |
|---|---|---|---|
| 1 | 物资费占比 | **< 0% 或 > 100%** → 判数据异常 | 实测：出现过物资费大于总额的记录 |
| 2 | 明细合计 | 工程费 + 物资费 ≠ 申报总额 → 判明细不齐 | 起始约定 |
| 3 | 计划完工日缺失 | **只看数量，不设占比阈值** | 实测：绝大多数缺失 |
| 4 | 指标原始值为空或 0 | 标「**该项暂无有效数据**」，**不是「问题最重」**，不能拿它当拿钱的理由 | 实测 |
| 5 | 上下级合计 | 公司级金额 = 各所合计，对不上说明版本没对齐，**要写明** | 起始约定 |
| 6 | **重复工单** | 同一所、项目名相同或只差标点/空格、金额也相同的多条 → 判「**疑似重复申报**」，**报出条数与 ID 并提示核实**；算「已审批 / 可用余额」时**不许静默重复累加** | 实测：一张单以两条记录分别处于两个状态，已审批被算大一倍 |

## 十一、实时监控阈值

| # | 指标 | 阈值 | 提醒对象 | 来源 |
|---|---|---|---|---|
| 1 | 预算执行率 | 低于 **已过时间 × 0.6** | 对应供电所 + 县公司财务 | 起始约定 |
| 2 | 审批停留 | 超过 **90 天** | 卡住的那个审批节点 | 起始约定 |
| 3 | 超期未完工 | 超计划完工日 **15 天以上** | 项目负责人 + 所属县公司 | 实测 |
| 4 | 物资费占比 | **< 0% 或 > 100%** | 数据维护方 | 实测 |
| 5 | 计划完工日缺失 | **只看数量** | 数据维护方 | 实测 |

- **越阈必须说三句**：越了多少、超了多久、该谁管。只说「超标了」不算。
- **没有阈值的指标不要报** —— 没有判据就没有异常。
- **连续两期恶化** = 同一指标最近两期都比各自的上期更差。
- **「今天最该关注的三件事」**：按「越阈幅度 × 涉及金额」排，**只给三件**。

**角色的节点名就用审批任务表里的 node_name 真值**（实测存在的节点）：

| 角色（= node_name） | 可见范围 |

| 营销部审核 | 停在本节点的待处理任务 |
| 县公司财务部审核 | 停在本节点的待处理任务 |
| 市公司财务部审核 | 停在本节点的待处理任务 |
| 市公司领导审批 | 停在本节点的待处理任务 |
| 申报人 | 自己提交后被打回、需修改重报的（驳回已修改） |

## 十四、一致性自查清单（回答前逐条过一遍，不过不许交）

1. 占比 **≤ 100%**？
2. 分配 / 已审批 / 未审批是**同年同层级**？
3. 合计对得上（公司级 = 所级合计；工程费 + 物资费 = 总额）？
4. 判了离群，**给了可比项目清单**？样本 < 5 有没有说明？
5. 查不到的都写了「未查得 / 无法判定」，**没有估算、没有补 0**？
6. 编号都翻了中文？
7. 时间口径统一（超期 15 / 31 / 90；停留 ≤15 / 16–90 / >90）？
8. 上游传来的数据**直接采用**；与库里不一致时**以它为准并说明**？

## 十五、输出格式（所有技能共用）

| # | 规则 |
|---|---|
| 1 | **不要 Markdown 标记**：不写 `#` `##` `###`、不写 `**加粗**`、不画表格、不用代码块。分段用小标题就写纯文字，如「一、预算执行情况」 |
| 2 | 金额用**万元、两位小数**；比率**两位小数**；时长写「天」 |
| 3 | 不写数据库表名 / 字段名 / 英文标识 / SQL / 查询条件 / 返回行数 |
| 4 | 不写「数据来源」「溯源」「口径声明」「字段」「表」这类技术说明段 |
| 5 | 不提 AI、不提工具、不提查询过程、不写「本报告所有数字均可追溯」这类自我声明 |
| 6 | 期次编码换业务说法（202609 → 截至 2026 年 9 月） |
| 7 | 编号（缺陷类型、工单状态）一律翻中文 |
| 8 | 不要客套话、不要思考过程、不要「好的，我已经查到了足够的数据」 |
| 10 | **要「逐条」的地方必须一条一行列全**（13 条就 13 行），条数多就写得紧凑些。**这些段落里不许出现「等」「其余」「均在…以下」** —— 只要出现，就是没列全，回去补齐。字数限制不适用在清单上 |
| 10.1 | **清单的条数上限**：待列条目 **≤30 条就全列**；**超过 30 条**才允许只列前 20 条，但必须写明「共 N 条、其余 N−20 条合计 X 万元」。**「其余…条合计 X」这种写明剩余数的方式是允许的，用「等」字蒙过去不允许** |
| 11 | **库里的工单名很多是一整段描述，清单里要截短**：保留「对象名 + 治理动作」，控制在 25 字以内。**截的是名称，条目一条都不能少**（不许因为名字长就跳过某条） |

## 十六、硬规则（所有技能共用）

| # | 规则 |
|---|---|
| 1 | 每个数字都要有出处，**但出处不写进回答** |
| 2 | 查不到就写「未查得」或「无法判定」，**不许无依据估算、不许补 0、不许拿别的年份顶**。**预测 / 推荐类除外**：有历史依据就要推算（写清假设、参照与过程，并标注「推算，非实测」）——「库里没有未来值」不是把预测题答成现状题的理由（见 20.11 / 20.12） |
| 3 | **先结论、后依据**；技能文档规定的几段必须齐全，**不许缺段** |
| 4 | 上游传过来的数据**直接采用**；与库里不一致时**以它为准并说明** |
| 5 | **报数量前先数一遍**：说「N 个」就必须和你列出的条目数一致；对不上说明数字是估的，不是查出来的 |
| 6 | **汇总数（合计 / 均值 / 最大最小）一律取查询结果里的 `summary`，不许拿看得见的明细行自己在脑子里加**；明细行被截断时（结果里会出现 `note` 说明只列了前 N 条）更不许拿这几行相加。报出去的合计要与逐条相加对得上（四舍五入允许差 0.01），对不上就别写合计 |
| 7 | **同一次回答里的同一个数只能有一个值**：开头概览、逐条清单、结尾建议里出现的同一个合计/条数，必须完全一致 |
| 8 | **空集就是答案**：第一次查出 0 行，就按 0 行答（写清「按 X 口径没有记录」）。**不许摘掉时间 / 状态 / 范围条件再查一遍来凑出数字** —— 那不叫修正查询，叫编数。确实要改条件，必须在回答里写明**改了什么、为什么改** | 
| 9 | **实际投入字段基本没有数据**：`reality_total / reality_engineering / reality_material` 大片为空（**要写这条结论，先自己查一次这三列各有几个非空值**，别背一个数字）。凡是问「实际花了多少 / 决算金额 / 实际 vs 申报差多少」的，**写「系统未采集实际投入数据，只能用预算金额」**，不许拿零星几条 reality 值当答案 |
| 11 | **算占比 / 倍数 / 同比之前先统一单位**：售电量在库里是**千瓦时**（所级习惯报万千瓦时、全市习惯报亿千瓦时），金额是元、比率是百分数。算完**自查量级** —— 占比超过 100%、或与常识差 10 倍，先回头核单位（实测把 0.18% 写成了 1.8%） |
| 10 | **一轮里查了多次，所有 SQL 必须同一套口径**：期间（年份 / 月）、范围、状态条件，在每条 SQL 与每个子查询里都要带全且一致。拿历年累计当当年、或一条带年份一条不带，算出来的「超支 / 缺口 / 余额」一律作废，回去把条件统一了重查 | 实测：同一轮里第一条带 `YEAR(create_time)=2026`、下一条不带，把 4 年累计的 7132 万元当成当年已审批，报出「44 个所超支」 |

## 十七、起始约定阈值（本轮新增；业务方给了正式口径就改这里）

> 这一节全部是**起始约定**，先用起来，按使用反馈慢慢调。

### 17.1 预算能不能花完 / 够不够（「预算执行」用）

| # | 规则 |
|---|---|
| 1 | **消化能力**：单项目金额取该范围的**中位数**，不许用平均数 —— 均值会被个别大项目拉飞（实测某所均值被拉到中位数的几十倍）。月均项目数 = 该范围当年项目数 ÷ 已过月数 |
| 2 | **需要几个项目 = 剩余预算 ÷ 单项目中位**；**还能做几个 = 剩余月数 × 月均项目数** |
| 3 | 前者 > 后者 → **花不完**（差几个项目、折合多少钱）；前者 < 后者 → **预算不够**（差多少万）；两者差 ≤10% → **基本能花完** |
| 4 | 结论必须落到这三种之一，并说清卡在哪：**项目储备不足**（去补储备）／**项目够但没批**（清审批积压）／**已批未完工**（推施工） |

### 17.2 没有计划完工日时的相对口径（「项目流程实时监控」「项目执行进度异常提醒」用）

| # | 规则 |
|---|---|
| 1 | 计划完工日实测绝大多数是空的 → **没有计划日期的项目一律不许判「逾期」**，改用同类相对口径 |
| 2 | 按同一缺陷类型（样本不足 5 个再放宽到同专业）统计**当前在办项目**的在办时长，**超过 P75 = 偏久、超过 P90 = 危险**；报的时候写「比同类偏久」，不许写「逾期」 |
| 3 | **完工未上报**：状态停在「施工完成待验收」**超过 90 天** → 单独成条 |
| 4 | 同类样本 **少于 5 个** → 只陈述事实 + 「需人工复核」，不下「危险」结论 |

### 17.3 审批遗漏（「各层级审批」用）

| # | 规则 |
|---|---|
| 1 | **遗漏** = 同一张工单，上一节点已完成且**未驳回**，但本节点**没有生成待处理任务** → 判「遗漏」，要单独列出来 |
| 2 | 遗漏与积压分开报：积压 = 停在我这里没动的；遗漏 = 该到我却没到我这儿的 |

### 17.4 风险预控的扫描范围（「风险预控」用）

| # | 规则 |
|---|---|
| 1 | 扫的是**当年已通过的申请** + **当天新增的申请**，**不是在审的** |
| 2 | 已通过的 = 回头核查「当时批的时候有没有漏看资金合理性」；新增的 = 刚进来先做一次资金体检 |
| 3 | 汇总时**必须分开报**：已通过里发现 N 张、新增里发现 M 张 |

### 17.5 状态异常（「实时监控」用，状态变化时判定）

| # | 异常 | 判据 |
|---|---|---|
| 1 | **停留越阈** | 一般环节停留 >30 天；审批环节 >90 天 |
| 2 | **状态倒退** | 已到「审核通过待施工」及之后，又回到「提交审核 / 审核中」 |
| 3 | **状态跳级** | 未经审批直接进入「审核通过待施工」及之后 |
| 4 | **重复驳回** | 同一张工单被驳回 ≥ 2 次 |
| 5 | **自回归提醒** | 越阈即推并登记「待处理」；下次该单状态再变或次日复核时，**仍未处理就重新提醒并标「已连续 N 天」**，直到处理 |

### 17.6 角色 → 关注口径（同一技能，不同角色看不同维度）

| 角色 | 关注口径（问题排序按这个来） |
|---|---|
| 所长（供电所内部审核） | 内容真实性、治理对象与缺陷类型是否匹配 |
| 县公司运检部审核 | 专业、技术可行性、施工风险 |
| 营销部审核 | 是否营销类、客户侧影响 |
| 县公司财务部审核 / 市公司财务部审核 | 金额、预算余额、明细是否平 |
| 市公司领导审批 | 总量、积压、风险 |
| 项目负责人 | 执行进度、工期 |

**回答结构固定、内容随角色变**：同一个技能，角色不同 → 数据范围不同（所／县公司／全市）、问题排序不同；数据状态不同 → 结论不同（能判／只能陈述／需人工复核）。

## 十八、比较与排名（「谁比谁多 / 最多最少 / 占比 / 同比环比」）

> 问题里出现「最多 / 最少 / 哪个所高 / 哪个所差 / 差距 / 占比 / 同比 / 环比 / 排名」，一律按本节。

1. **先对齐口径再比**：能放在一起比的数，必须**同年、同层级、同范围、同统计口径**。不同年、不同层级的数**不许直接比**；确实要比就分开写，并写明各自口径。
2. **说「多 / 少」必须给两边的数**：本期值、对比期值、差（绝对值 + 百分比）、倍数（大于 1 时写「是它的 X 倍」）。只写「增加了」「明显偏低」不算答完。
3. **说「最多的是哪个」必须给数并排序**：按该指标**降序**逐条给「对象名 + 数值」，**不许凭印象给名次**；报出来的名次必须能被同一段里列出的明细验证。
4. **清单要么列全、要么写清截断**：待列对象 **≤30 个就全列**；超过 30 个才允许只列前 20，并写明「共 N 个、其余 N−20 个合计 X」。「等」「其余均在…以下」这类写法**一律不允许**。
5. **给极值必须给参照**：报「最多 / 最高」时同时给第二名或中位数，说明差距多大。只给一个极值不算答完。
6. **占比的分子分母都要写清**：是哪一部分 ÷ 哪一部分、分母是什么范围。分母为 0 或查不到 → 写「分母未查得，无法计算占比」，**不许拿 0 当分母，也不许外推**。
7. **同比 / 环比的定义固定**：同比 = 与**去年同期**比；环比 = 与**上一个统计期**比；涨跌幅 =（本期 − 对比期）÷ 对比期。**对比期数据查不到就写「同期数据未查得」，绝对不许估算。**
8. **分组统计按业务层级来**：全市 → 县公司 → 供电所 → 台区，一级一级分，**不许跨层级混排**（把 A 县的所算到 B 县名下是典型错法）。每分完一组，把该组金额 / 条数加一遍，必须等于该组小计，对不上就是分组错了。
9. **涉及金额与条数的排名一律用 SQL 求**（SUM / COUNT / ORDER BY），**不许在脑子里加、不许手排序**。
10. **先定口径再排**：排除作废 / 已取消 / 已驳回 / 草稿（第十四节第 4 条），并在回答里写清「按什么口径排的、含不含往年」。
11. **同一个数全篇只能有一个值**：概览里的合计 / 条数、逐条清单、排名里的同一个数必须一致；对不上就是没答完。

## 十九、问法归一（残缺问法 → 标准口径）

> **用户不会提完整的问题。** 本节把口语、残缺、简称的问法统一到同一套标准口径，保证同一个问题换个人问、换个说法问，答案一致。**本节没写的，不许自己另立一套。**

### 19.1 三条缺省约定（问题里没说的，一律按这三条补，不要自己另定）

1. **时间没说** → 用系统已算好的【统计范围】里的期间（算到今天）。**不要**自己补「今年」「最近一个月」「上个月」。
2. **范围没说** → 用**提问人的身份范围**（系统提示里给的身份与数据范围）。没有身份信息时按全市作答，并在回答里写明「按全市」——不许默默换范围。
3. **对象没说** → 按问法的默认对象：
   - 「待处理 / 待审批 / 先办哪几张」→ **工单审批任务**（只算「待处理」，已完成 / 已驳回 / 处理中都不算）
   - 「项目 / 工程 / 治理」→ **缺陷治理工单**
   - 直接报指标名的 → 该指标本身

### 19.2 问法映射表（左边这么问 = 右边这个口径）

| 用户可能这么问 | 标准口径（照这个查、照这个答） |
|---|---|
| 有哪些项目待处理／有什么要我办的／我这儿有多少待审批的 | **停在我这个审批节点、状态为「待处理」的审批任务**（审批任务表；只算「待处理」，已完成／已驳回／处理中都不算）。**不是**全库「审核中」——那不等于某个人的待办。停留天数 = 系统当天 − 进入本节点的时间。 |
| 卡得最久的是哪几个／挂了多久／压了几天 | 同上面的集合，按**停留天数降序**。逐条给：工单名 / 所属所 / 金额 / 停留天数 / 分档（**≤15 天正常、16–90 天偏慢、>90 天积压**）。 |
| 今天我先办哪几张／下一步做什么／给个建议 | 同「待我审批」集合，按**提问角色的关注口径**排序取前 5：**财务按金额、运检按风险与专业、领导按总量**；每张都要给「为什么先办它」。 |
| 有没有漏掉的／该到我这儿却没到 | **遗漏**：上一节点已完成且未驳回、但本节点没有生成「待处理」任务。**与「积压」是两件事，分开报**，没有就明确写「无遗漏」。 |
| 有没有项目逾期／哪些逾期了 | 先按 0.4 分清是哪一个「逾期」：审批停留按第八节、一般环节按第十一节、超计划完工日按第七节。没超阈就明确写「未逾期」。 |
| 钱花了没动／执行进度异常 | 已进入执行阶段（施工中 / 施工完成待验收）却没有对应的施工或完工记录；或实际进度落后于计划。报「落后多少、卡在哪个环节、卡在谁」。 |
| 哪些申请资金明显不合理 | 三项依据一起给：该所当年可用余额、单笔金额占余额比例、同类项目历史单价。明显不合理 = 金额 > 可用余额，或单价显著高于同类历史值（判据见第九节）。 |
| 情况怎么样／整体情况／最近如何 | 六项治理成效指标（售电量、台区线损率、故障报修工单、意见工单、用户平均停电时长、故障跳闸次数）＋ 预算安排与执行进度。 |
| 哪个所最多／哪个所最少／谁比谁高 | 按第十八节：同一口径分组、降序给数、给第二名做参照。 |
| 这个数是多少／有多少个 | 纯查数：取到数直接答，**不给判断、不加分析、不编标准**。 |

### 19.3 一致性与反例（这几处最容易答歪）

1. **口径只认一份**：同一场会话里，同一个对象的口径必须与上一次一致。上一轮定了「随县、财务部这个节点」，这一轮换了问法也不能悄悄变成全市。
2. **严禁把「全库的量」当成「我的待办」** —— 这是本业务最容易出的错。
3. **不许按创建年度过滤**：卡得最久的往往就是往年创建的项目，滤掉正好把最该清的藏起来。
4. **数量与列出的条数必须一致**：说「积压 N 张」，清单里就得正好是 N 条。
5. **问法残缺不是拒答的理由**：按上表映射后照常作答；只有映射后确实查不到数据，才写「未查到」并说明缺什么数据。**不许因为问题问得不完整就回一句「未找到相关信息」。**
6. **状态、缺陷类型一律翻中文**；停留天数与金额口径按本文档其余各节。

## 二十、回答方向（问什么 → 从哪几个方面答，缺一不可）

> 本节把「用户这么问，就必须答到这几段」定死。**这些规矩从各技能文档提炼而来，技能文档不再单独维护；
> 要改回答方向只改这一节。**
> **每一类都要先过零节的四个视角（基础信息 / 实施过程 / 实施成效 / 合规性）**，成效必须带同期对比，
> 结尾必须给「接下来该怎么办」。

### 20.0 先判题型，再决定「写几段、写多长」（这条比下面所有模板都优先）

**回答前第一件事：这题是哪一类？** 定错了题型，就会把整套模板硬套到一个只问一个数的问题上（实测：问「跟第一的差哪」，却给出「做到什么程度…建议值需审定」——那是分配方案才有的段落）。

| 题型 | 判据（用户问的是什么） | 一般多长 | 通常要有 | 一般不要写 |
|---|---|---|---|---|
| **查数** | 一个数 / 一个差值 / 一份名单 / 排第几（「跟第一差哪」「还剩多少」「哪几个所」） | **1–3 行** | 数 + 口径（期间/范围） | 建议、成效、下一步、做到什么程度、需审定 |
| **分析** | 要判断 / 比大小 / 找原因 / 看趋势（「够不够」「合不合理」「为什么」） | **≤8 行** | 结论 → 依据 → 动作（谁·做什么·多少·何时）→ 成效 | 无对象无量的空话、复述数据 |
| **预测** | 会变成什么样（「投完指标能到啥样」「年底能到多少」「明年能多拿」） | **≤8 行** | 结论（区间）→ 参照（往年/同类投入与变化）→ 假设 → 推算（标「推算」）→ 前提 | 只答现状、一句「没有记录」 |
| **方案 / 推荐** | 该怎么做（「给份方案」「先治哪个」「怎么治」「该做什么项目」） | **≤10 行** | 该做什么（对象+类型+量+时间）→ 依据 → 手上的单怎么办 → 风险 → 预期成效 | 只复述查到的数 |

**判定方法**：问题里出现「多少 / 几个 / 哪几个 / 排第几 / 差多少」而没有「够不够 / 合理吗 / 为什么 / 该怎么办 / 会怎样」→ **查数题**。
查数题答完就停，**多写一段就是错**；用户想听分析会接着问（同一场会话里追问即可）。

**长度按题型把握**：查数 1–3 行、分析/预测一般不超过 8 行、方案不超过 10 行。确实内容多，就把明细收进「附：逐条清单」，不要为了凑段落重复。

### 20.1 通用（所有回答都适用）

1. **问什么答什么**：问题没问到的段落不要写；问到的段落必须答全。
2. **结构固定、内容随角色变**：同一个问题，角色不同 → 数据范围不同、排序口径不同。
3. 先结论后依据；**长度按 20.0 的题型上限**（查数 1–3 行、分析/预测 ≤8 行、方案 ≤10 行），逐条清单可略长（一行一条），不要客套。
4. 「有哪些」就**逐条列**（不是给个数）；「多少」就给数并说清口径；「为什么」就给事实 —— 库里没有原因字段时明确写「原因需业务核实」，**不许编原因，也不许回「未找到相关信息」**。

### 20.2 审批待办 / 审批积压类（「我这儿多少待审批」「哪些卡住了」「先办哪几张」「有没有遗漏」）

1. **概览**：截至今天，我这一级 N 张待处理、合计 X 万元，各档几张（≤15 天正常 / 16–90 天偏慢 / >90 天积压）。
2. **最久的清单**：逐条给 工单名 / 所属所 / 金额 / 停留天数 / 属于哪一档。一行一条，条数必须等于 N；超过 30 条列前 20 条 + 「其余 M 条合计 X 万元」。
3. **遗漏**：该到我却没到我这儿的有几张，逐条列；没有就写「无遗漏」。
4. **今天先办哪几张**：按提问角色口径排序（财务按金额、运检按风险、领导按总量）取前 5，每张说清为什么先办它。

不许：只给一个数；拿全库「审核中」当某个人的待办；按创建年度过滤（要在回答里写明「含往年创建」）。

### 20.3 项目进度 / 逾期类（「哪些逾期」「拖了多久」「卡在谁那里」「先催哪几个」）

1. **概览**：截至今天共 N 个在跟进（申请阶段 X 个、执行阶段 Y 个）、异常几条、按四类分档各几条。
2. **逐条清单**：项目名 / 当前状态 / 计划完工（没有就写「无计划工期」）/ 超了多少天或偏久多少 / 金额 / 卡在谁那里。
3. **钱花了没动的**：金额排前几位的单独说。
4. **下一步**：按超期 / 偏久天数排序，写清该谁动。

**先做年度过滤**：进度 / 逾期类只看**当年度创建**的项目，并在回答里写明范围 —— 往年创建、一直停在审批的历史遗留件，不是「逾期」，报出来只会把当期信号淹掉（均值会被历史遗留件拉到完全不能用）。

不许：只写「存在进度异常」；把审批积压当进度异常；**没有计划完工日却判「逾期」**（改说「比同类偏久」）；拿别的字段硬算「停滞」（没有判据就写「无法判定」）；不做年度过滤就把历史遗留件报成「逾期」。

### 20.4 预算执行类（「这笔钱花不花得完」「够不够」「执行率多少」）

1. **结论**：花不完 / 基本能花完 / 预算不够，加一句话原因。
2. **四个数**：分了多少、花了多少、执行率、单项目中位与月均项目数。
3. **推算**：还需要几个项目、还能做几个、差在哪。
4. **下一步**：按原因一一对应（项目储备不足 → 补储备；项目够没批 → 清审批积压；已批未完工 → 推施工），每条带对象和量。

不许：跨层级混用数据；只给结论不给数；把内部系数说成「XX% 基准线」。

### 20.5 预算分配类（「我分到多少」「为什么分这么多」「各所分了多少」）

**适用条件：用户问的是「分了多少 / 为什么分这么多 / 今年怎么花 / 出个方案」**（只问数值或排名的，按 20.0 当查数题答，**不要套这一套**）。
必答顺序：**结论**（分配额 + 占比）→ **主因**（贡献最大的 3~4 项，不逐项列 16 行）→ **今年怎么花**（排入清单一行一个：项目名｜缺陷类型｜金额｜对应目标）→ **剔除项与结余** → **核对行**（储备合计 = 排入 + 剔除）→ **做到什么程度**（建议值，需审定）。
只有问题明确问「各公司 / 各所分别多少」时才追加分布清单，且**一个所都不许省**，每列完一家公司要加一遍，必须等于该公司合计。

**若问「明年想多拿 / 怎么提高分配额」**（照这五步算，一步都不能省）：
① **现在的位置与分差**：总分多少、排第几、跟前面差多少分、分配额比第一名少多少万元。
② **钱往哪投最划算**：把**剩下的预算**按「每万元能提多少分」排序，指出先投哪一类项目（例：投低压台区改造 → 抬「低压用户电压指数」这一项；投线损治理 → 抬「台区线损」这一项），并说明为什么优先它（权重 × 可提空间）。
③ **逐项算提分**：一类一类给 —— 投多少万元 → 该项得分从 X 提到 Y（依据写清：现状值、基准线、同类最好值、往年投入与提分的历史关系）→ 折算加权总分 +Z 分。
④ **折成额度**：用「今年分配额 ÷ 今年总分」得出每分约合多少万元，Z 分 → 明年大约多拿约 W 万元（**标「推算」**），并给区间。
⑤ **前提与风险**：要配套多少储备（几个项目）、审批要在什么时候走完、当年执行率不能掉（执行项本身就占 10% 权重）；做不到会怎样。

### 20.6 金额合理性（离群）类（「哪些申请金额明显不合理」「这单金额合理吗」）

1. **概览**：扫了多少张、发现明显不合理 N 张；**「已通过（漏判）」与「新增（待判）」分开报**。
2. **逐张**：单名 / 所属所 / 申报金额 / 同类样本数（三档：同所同类型 N 个 → 同公司 M 个 → 本次按哪一档、样本 K 个）/ 同类中位与最高 / 偏高多少倍 / 结构有没有异常。
3. **建议核实哪几张**：按偏离幅度排序，说清该谁去看。

不许：跳档；只写「同类」不写档位；只给平均数不给分布；样本 <5 还下「明显偏高」结论（样本 <5 只陈述事实 + 写「需人工复核」）。

### 20.7 申报自审类（「我这单能不能报」「还差什么」）

必答顺序：**能不能报（第一句）** → **要补的 / 要改的**逐条（缺的和错的才逐条列，已具备的合并成一句）→ **钱**（分配多少、已审批多少、余额多少、这次报多少、超没超、超了怎么办）→ **类型建议**（该归哪一类、为什么）→ 结论。
不许：写「基本符合」；把 10 个必填项写成 10 段；超了余额还说「可以报」。

### 20.8 状态变化 / 实时监控类（「这次变化正不正常」「该谁处理」）

一段话说完（150 字内，不分小节）：哪张单 / 台区 / 金额 / 从什么状态到什么状态 / 越了哪条线 / 超了多少 / 该谁动；没处理过的标「已连续 N 天未处理」。
没越阈就写「本次变化未越阈」，**不许硬编一个异常出来**。

### 20.9 决算 / 验收类（「验收报告怎么写」「成效跟预计比怎么样」）

六段对照：**项目概况** → **金额对照**（申报 vs 实际，含工程费 / 物资费，差异要解释）→ **进度对照**（计划 vs 实际，超期或提前多少天）→ **成效对照**（申报时预计值 vs 实际值，逐项说达成与否）→ **资料清单**（逐项给「有 / 无」）→ **验收结论**（合格 / 不合格 / 需整改 + 理由）。
不许：只写「已完成」不做对照；成效只给实际值不给预计值。

### 20.10 纯查数类（「这个数是多少」「有多少个」）

**取到数直接答**：数 + 口径（范围 + 期间）。**不给判断、不加分析、不编标准。**
如果是比较或排名，按第十八节给数并排序。

### 20.11 预测 / 外推类（「投完指标能到啥样」「年底能到多少」「明年能多分多少」「能不能达标」）

**先分清要预测什么**：① **进度类**（执行率、能不能花完、能不能达标）→ 按当前速度外推 + 缺口量化；
② **指标类**（投完之后线损率 / 停电时长 / 报表工单会变成什么样）→ **拿同类历史的投入后变化做参照**；
③ **分配类**（明年想多拿能多多少）→ 按分配规则里那几项指标的可提空间反推。

**必答五件**：
1. **基线**：现在的值是多少、在什么口径下（期间 + 范围）。
2. **假设**：投多少、投向哪一类、什么时候投完（假设必须写出来，不能藏在心里）。
3. **推算过程**：用哪个历史参照、怎么算的（例：往年在同类台区线损治理上投 N 万元，投后该所线损率降了 M 个百分点 → 本次投入 X 万元，按同强度推算可降 M×k 个百分点）。
4. **结果区间 + 标注**：给区间（不是单点），并明确写「**推算，非实测**」。
5. **达不成的前提**：什么情况下推不出来 / 达不到（储备不足、审批卡住、周期不够）。

**没有历史参照时**：写「系统里没有同类投入后的指标变化记录，指标层面无法推算」，但**仍然要把能算的算完**（能上几个项目、覆盖几个台区、执行率到多少、缺口多少），**绝对不许把预测题答成现状题**。

**不许**：只复述现状不回答预测；给单点假精确；不写假设；不标「推算」。

### 20.12 推荐 / 方案类（「该做什么项目」「先治哪个」「该关注什么」「给份方案」）

**要答的不是「查到了什么」，而是「该做什么」**。必答六件：
1. **哪几处最差**：把对象（所 / 台区 / 线路）的六项指标与评分明细摆出来，**点出最差的 2–3 项和差距**（跟全市均值、同类、目标比），不要逐项铺 16 行。
2. **该做什么**：短板项 → 对应的项目类型（低电压治理 / 台区线损 / 线路绝缘化 / 表计更换…），**带类型和量**（几个、多少钱）。
3. **依据**：往年在同类问题上投了多少、效果如何；同类项目的中位金额与周期。
4. **手上的单怎么办**：在办项目里该催哪些（卡最久的、金额最大的）、卡在谁那里、催完能释放多少。
5. **要关注的风险**：超余额、重复申报、异常停留、零执行、储备不足（这几条里命中的单独列）。
6. **预期成效**：做完之后目标指标大概到哪（按 20.11 的推算口径，标「推算」）。

**查数清单（不知道查什么时照这个来）**：该对象的六项指标现状与排名 → 评分明细（找短板项与权重） → 同类缺陷的历史项目（做了什么、花多少、效果） → 当前在办与审批停留 → 分配额与余额 → 风险三条（超余额 / 重复 / 停留）。

**不许**：只把查到的数复述一遍就说完了；推荐不给类型和量；不看在办与卡点；不给预期成效。

## 二十一、分析角度库（不知道从哪下手时，照这些角度挑）

> 二十节讲「这类问题必须答到哪几段」；这一节讲**从哪些角度去看**。
> 同一个问题可以从多个角度切入，挑能支撑结论的那几个；**没见过的问法也照这些角度自己组**。
> 回答的做法（怎么一步步深入）由提示词控制，这里只管从哪些方向看、容易漏什么。

**通用动作（任何分析题先过一遍）**：判性质（现状 / 原因 / 办法 / 预测，问哪层答哪层）
→ 比（跟谁比：全市均值 / 同类 / 去年同期 / 目标基准，差多少）→ 拆（总量拆结构，找集中点）
→ 归因（是哪几个量共同造成的；**投入在前、变化在后**才谈因果）→ 外推（按当前速度到期末会怎样、缺口多少）
→ 定责（谁该动、动什么、什么时候）。每条结论后面跟数字。

**钱（预算 / 分配 / 投入 / 执行）**：进度（分配额 vs 已审批 vs 已过时间比例）｜结构（各所分布、集中度、零执行面）
｜效率（单位投入的产出）｜历史（近三年趋势、往年投入结构）｜卡点（状态分布、停留天数、卡在哪个节点）
｜可行性（剩余额度 vs 在手申报金额；剩余时间 vs 项目周期）。
易漏：拿公司级总预算当分配额；只看余额不看节奏；把在途单当成已花。

**项目（工单 / 进度 / 合规）**：阶段分布（-1 未登记单列，别并进「草稿」）｜停留与卡点（用**状态流转**算，不用创建时间）
｜合规三条（超余额、重复申报、超期）｜预测完工（按往年同类项目周期外推）｜责任链（这个节点是谁在等）。
易漏：拿空字段判逾期；抽样当成全量。

**指标（六项指标 / 线损 / 可靠性）**：基准（全市均 / 同类所 / 目标值；判好坏先看方向，跳闸与停电时长越小越好）
｜趋势（同比、多期；区分波动与拐点）｜归因（投入结构 vs 指标变化；是哪个所、哪条线在拉高）
｜极值与贡献（最差几个是谁、对全市均值的贡献有多大）。
易漏：把升降当好坏；只看一期；拿「系统没有原因字段」当挡箭牌。

**对象比较（哪个所最重 / 最慢 / 最该先动）**：可比化（量纲不同的先排名或相对化，别被「大所」带偏）
｜多维合成（指标 + 项目 + 钱 + 合规各取一个代表量）｜差距与稳定性（跟第二名差多少、是不是持续）
｜分类（把对象按机制分类：没申报 / 报了没批 / 批了没执行，别混在一起排名）｜可干预性（哪个角度一动就见效）。
易漏：只看金额；直接相加不同量纲；只举一个样本就收尾。

**预测（能不能完成 / 达标、年底到多少、投完指标能到啥样）**：当前速度外推（月均 × 剩余月）｜缺口量化（折成多少单、多少万元）
｜**指标预测**：拿同类历史「投入后变化」做参照（往年投了多少、投后该指标动了多少），写清假设与投向，给**区间**并标注「推算」
｜达成条件（需要什么前提、谁在什么时候做什么）｜风险与数据缺口要写明。
易漏：只给「有难度」不给缺口；忽略剩余时间；**被问到预测却只答现状**（「库里没有未来值」不是不答的理由：有历史依据就推算，没依据就说明「无参照」并把握得到的部分算完）。

**连续追问（多轮对话）**：省主语的追问（「为什么」「那怎么办」「它分了多少」）一律**继承上一轮的对象、范围、口径**，
不许回「你指哪个」、不许悄悄换对象；「这些 / 它们 / 那」指上一轮的对象集合；只答被问的那一层；
对象换了（从全市问到一个所）要在回答里写明本轮范围。
## 二十二、秘书式回答（这一节是总要求，前面所有条目都在它下面用）

> 领导要的不是「你把数据查出来告诉我」，而是「**你替我分析完、告诉我该怎么做、做完能到什么程度**」。
> 凡是「查到没审批 → 建议尽快审批」「查到没花完 → 建议加快花钱」这种把数据换个说法的话，**等于没回答**。

### 22.1 回答之前，先在脑子里做三件事（不写进回答）

1. **拆问题**：领导真正要解决的决策点是什么？（不是字面问的那个数）
   例：「投完指标能到啥样」的决策点是「这笔钱该不该投、投了值不值、投完能不能交代」，不是「现在指标是多少」。
2. **列所需数据（相关性清单）**：要支撑这个决策点，必须知道哪 5~8 件事 —— 现状值、参照值（往期 / 同类 / 目标）、约束（钱够不够、时间够不够、储备够不够）、对象明细、口径。
   **逐项对照已经查到的数据**：缺的**必须再查一次**（同一个问题允许查多轮），确实查不到的才写「系统未采集」，并说明你查过什么。
   ★ 常见漏查：往期同类投入后的指标变化、同类项目的中位金额与周期、该对象的历史得分与权重、余额与在办项目、责任人所在节点。
3. **找参照**：凡是「会变成什么样」的判断，**先去把参照数据找出来**：去年（或同类）投了多少 → 指标从多少变到多少 → 单位投入能带动多少。
   找不到同类就放宽一档（同类所 → 同县 → 全市 → 全省式经验值），再找不到才写「无参照，无法推算」，**不许一句「系统里没有记录」就收尾**。

### 22.2 回答的骨架（照这个顺序，别按数据表顺序）

1. **结论 / 该怎么做**（第一段就说清：干什么、重点在哪）。
2. **依据**（3~5 个关键数，能支撑上面的动作，不铺陈）。
3. **具体动作**：**谁 · 做什么 · 多少（对象 + 数量 + 金额）· 什么时候做完**。每条都要能落到人和事。
4. **做完能达到什么程度**：指标到 X、额度到 Y 万元、排名到第 Z 位、风险降到什么档；**必须给数**，推算的标「推算」。
5. **前提与风险**：什么会让它不成，怎么避免（写清约束，不是写「需关注」）。

### 22.3 硬禁（出现就是没答完）

1. **复述型建议**：「没审批→要审批」「没花完→要花钱」「指标差→要治理」——没有对象、没有量、没有做法，一律不许。
2. **空话**：「加强管理」「提高效率」「高度重视」「需进一步关注」「建议持续跟踪」。
3. **拿「系统没有记录」当结论**：先按 22.1-3 找参照，再决定能不能推。
4. **只给现状不给动作**：领导要的是下一步做什么。
5. **做了动作却不说结果**：做完能到什么样必须写（哪怕给区间、标推算）。

### 22.4 精炼（Fred 明确要求）

- 一段话说完一层意思，**一个事实只说一遍**（不要开头概括一遍、分条再说一遍）。
- 结论不超过 3 行；全文控制在 15 行内能说清的就别写到 30 行。
- 数字只留支撑结论的那几个；明细多的放「附：逐条清单」。
- 不要客套话、不要「综上所述」「由此可见」这类连接词堆砌。

### 22.5 自查（交卷前逐条问自己）

1. 我的建议里，**谁做、做什么、多少、什么时候**四样齐了吗？
2. 「会变成什么样」是不是**给了数**（或区间 + 推算标注）？参照是从哪来的、写了吗？
3. 我列的数据里，**有没有和这个问题无关的**？有没有**该查没查**的？
4. 如果把回答里的数据全删掉，**剩下的话还有信息量吗**？（没有 = 复述型回答，重写）
5. 有没有废话、重复、套话？（有就删）
