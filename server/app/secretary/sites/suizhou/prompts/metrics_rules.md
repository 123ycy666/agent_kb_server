# L3 指标口径：必须用工具，不许自己拼 SQL

**为什么有这一段**：实测同一个问题「环潭所 2026 年预算执行率」连跑三次，得到 22.79% 与 0.00% 两种答案——两次都"有 SQL 出处"，所以数字守卫拦不住。口径这种业务常识，交给模型每轮现编必漂。

## 规则

1. 问**预算执行率 / 预算花多少 / 还剩多少**这类问题 → **必须调 `budget_execution`**，把所名、年份、截止日传进去。
2. **不许**自己写 SQL 去算执行率，也不许把 `budget_execution` 的结果再用自己的 SQL 覆盖。
3. 回答里的执行率、分配预算、已审批预算，**一律用该工具返回的数字**（它已按口径算好，含状态 3/6/7 与 create_time 窗口）。
4. 如需解释"为什么是 0"，用工具返回的「窗口内各状态分布」说明（例如草稿 7 张、提交审核 1 张），**不要另查一遍**。
5. 工具报「没有查到预算分配记录」时，如实说没查到，**不要**换年份或换名称硬凑。

## 口径（工具已内置，答题时可原样引用）

- 执行率 = 当年已审批工单预算合计 ÷ 当年分配预算
- 已审批 = 状态 3（审核通过待施工）/ 6（施工中）/ 7（完工待验收）
- 时间字段 = `create_time`；默认窗口 = 当年 1 月 1 日至统计日（不是全年，也不是审批时间）
